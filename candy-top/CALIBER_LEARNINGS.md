# candy-top learnings

- Scaffold created 2026-10-07. Phase P-A (frame, theme, clock, quit, resize, fake sources) landed 2026-10-08.

## Architecture (P-A)

- `bin/candy-top` loads the config with `ConfigFile`, settles it with `Config::withTtyModeResolved()` and `withShownBoxesSettled(0)`, reads `HostInfo::detect()` once, loads the theme with `ThemeRegistry::new()->load()`, and runs `Program(App::start(...), ProgramOptions(useAltScreen: true, framerate: 20.0))`. Pass `--fake` to use the deterministic `Source\Fake\*` sources instead of the live `Collect\*` collectors. The fake mode is meant for demos and VHS tapes.
- `App` is the root TEA Model. It owns the frame: the layout, the box chrome, the title buttons and the clock. It also owns the cadence and the panel roster. `view()` returns a `View\Surface`, a mutable cell grid that lives for one render. It always has exactly `rows` lines of exactly `cols` cells, so a panel cannot break the line-diff renderer even if it computes a bad width.
- `View\FrameBuilder::layout()` ports btop `calcSizes` from the GPU build with zero GPUs. In that build the mem height subtracts the REAL cpu height. `minSize()`/`fits()` port `Term::get_min_size`. A terminal smaller than the minimum gets `View\SizeError`, btop's "Terminal size too small" notice. `q` and the box toggles 1-4 still work there.
- Coordinates: btop uses 1-based `Mv::to(row, col)`. Every `Rect`/`Layout` value is 0-based, so subtract 1 from BOTH axes when porting an offset. The clock junction goes at 0-based `x + w/2 - len/2` and the text starts one cell after it.

## Cadence

- Two one-shot `Cmd::tick`s are re-armed inside `update()` and never in `subscriptions()`, because tick ids lock the first closure they see.
  - `ClockTickMsg` fires on every wall-clock second. The time and uptime are read inside the Cmd, so `update()` and `view()` stay pure.
  - `DataTickMsg($generation)` fires every `update_ms`, default 2000.
- `+`/`-` bump `App::$generation`. The tick armed under the old period still fires, but `update()` ignores it. candy-core ticks cannot be cancelled, only made stale.
- Any config swap goes through `App::applyConfig(Config): [App, ?Cmd]`, never a bare `mutate(config:)`. A changed `update_ms` bumps the generation, and the returned Cmd carries the re-armed tick plus a `collect()` for every newly shown box. Dropping that Cmd leaves only the stale tick armed and stops data updates for good, so P-F callers must dispatch it.
- `+`/`-` do not step inside the key handler. The handler returns a Cmd that reads the injected clock and emits `Msg\UpdateStepMsg(direction, held, at)`, which keeps `update()` pure. `held` is btop's "all 50 `Input::history` keys are this key" check (`App::$keyRun >= HOLD_HISTORY`, counted on every KeyMsg AND every MouseMsg, because btop pushes `mouse_*` events into the history too, btop_input.cpp:193-195; a click mid-hold restarts the run). Holding steps 1000 ms instead of 100 when the previous step landed less than 200 ms earlier and `update_ms` is <= 86399000 for `+` or >= 2000 for `-` (btop_input.cpp cpu-box actions). `=` steps like `+` but never accelerates, as in btop.
- Toggling a box on (`1`-`4`) returns that panel's `collect()` Cmd, so the box is sampled at once instead of sitting empty until the next tick. This ports btop's `Runner::run("all", false, true)` after `toggle_box`.

## Panel extension seam (P-B..P-E build in parallel here)

- Implement `Panel\Panel` in a new file, `src/Panel/<Box>Panel.php`. The methods are:
  - `box()` returns the box name.
  - `collect(PanelContext)` returns a Cmd that samples its `Source\Source` and returns a `Msg\SampledMsg`. The context is built at call time (every tick, toggle-on and option write), so read sampling options such as `disks_filter`, `net_iface` or `proc_sorting` from `$context->config` there and capture them into the Cmd; never cache them from startup or an earlier `update()`.
  - `modal(PanelContext): bool` says the panel owns ALL input right now (P-E: `proc_filtering`).
  - `capturesKey(KeyMsg, PanelContext): bool` claims a key ahead of the App's global keys.
  - `update(Msg, PanelContext): PanelResult` returns the next panel, an optional Cmd and synchronous config writes (`PanelResult::$set`).
  - `paint(Region, PanelFrame)` draws the panel.
- Input precedence (btop_input.cpp:158-161, 217-222, 301-342; btop.cpp:180-198), checked in this order:
  1. `ctrl+c` always quits.
  2. Behind the size notice (or before the first WindowSizeMsg) only `q` and `1`-`4` act. Every other key and every mouse event is dropped, not broadcast; `+`/`-` do NOT step there.
  3. The first VISIBLE panel (layout order) whose `modal()` is true gets every key ALONE (`q`, `1`-`4`, `+`/`-`, `escape` included; claims are not consulted) and only bare left presses (Press + Left + no shift/alt/ctrl, btop's `[<0;...M`); wheel/motion/release, right/middle and modified presses are dropped without entering the hold history, as btop's filter collapses mouse input to `mouse_click`. Do NOT test `instanceof MouseClickMsg`: candy-core `InputReader` emits it for EVERY press, whatever the button or modifiers.
  4. Otherwise the first visible panel whose `capturesKey()` is true gets the key alone. `q` and `1`-`4` are never offered to `capturesKey()`, so no claim can disable quit or the box toggles (the modal tier above still receives them as text). P-E takes `+`/`-`/`=` while proc_tree is on (btop_input.cpp:491). Return false for anything you do not consume, or that global key stops working.
  5. Unclaimed keys reach `q`, `1`-`4`, `+`/`-`/`=`, then the broadcast. Mouse events, WindowSizeMsg and everything else are broadcast to every panel.
  `tests/Support/ClaimingPanel` (`claimWhen:`, `modalWhen:`, `sets:`, `emits:`, `->contexts`) is the test double.
- Input context: every `collect()`/`modal()`/`capturesKey()`/`update()` call gets a fresh `PanelContext` built by `App::context($box)` at that moment: the CURRENT `Config`, the CURRENT `Layout` and the panel's own absolute box (`null` while hidden or behind the size notice), plus `procSelectMax()` and `hit($mouseX, $mouseY)` (1-based mouse cells against the 0-based box). It is rebuilt after every toggle, option write and resize, so P-C/P-E never recompute the calcSizes port and must never cache it. Paint gets the same through `PanelFrame`.
- Config writes: key-driven writes go in `PanelResult::$set` (P-E `e`/`r`/`c`/`m`/`f`/sorting -> proc_tree, proc_reversed, proc_per_core, proc_mem_bytes, proc_filter, proc_filtering, proc_sorting; P-C `a`/`y` -> net_auto/net_sync). `App::deliver()` applies them INSIDE the same `update()` via `App::applyOptions()`: each entry is validated with `Config::with()` in order (a value btop would reject is dropped silently, the rest still apply), then the result goes through `applyConfig()`, so relayout, tick re-arm, newly-shown-box sampling and the colour profile all follow. In a broadcast each panel's writes apply before the next panel runs. Why synchronous: candy-core `Program::readInput()` dispatches every key of one read at once while Cmds are deferred through `futureTick`, so a Cmd-carried write lands a round-trip late and two `a` presses in one read would both toggle from the same stale value (btop's `Config::set` is immediate). `Msg\SetOptionMsg` stays ONLY for asynchronous producers (a Cmd that learns the value when it runs); it shares the same validation. The change is in memory only: P-A never writes `config.conf` at runtime, and persisting on exit / from the options menu is P-F.
- `applyConfig()` recomputes the colour profile with `App::profileFor()` (tty_mode -> Ansi, else truecolor -> TrueColor / Ansi256, the same rule `start()` uses) only when the derived profile changes, so an explicit `start()` profile survives unrelated changes. It keeps the palette: a tty_mode flip that should load the TTY theme needs ThemeRegistry I/O, so P-F pairs it with `withPalette()`.
- Registration is one line per box in `Panel\Panels::standard(HostInfo, Config, bool $fake)`, for example `'cpu' => PlaceholderPanel::new('cpu', $fake ? FakeCpu::new(..) : CollectorSource::of(Cpu::new())),`. Read startup options from the `Config` there; the fake sources take their interval from its `update_ms`. Each phase replaces exactly its own line. There are no parallel arrays and no shared loop, so P-B..P-E edits never conflict. Do not edit `App.php`.
- `Region` is clipped to the panel's box and includes the border rows. Use those rows to embed readouts and buttons, as btop does. Writes cannot spill into a neighbouring box.
- `PanelFrame` exposes the whole `Layout`, including the `cpuCores`, `netStats`, `memDivider`/`memWidth` and `procSelectMax` sub-geometry. It also exposes `Ink`, which holds theme escapes plus 101-stop gradients, and the `Border`, `Config` and `HostInfo`.
- Use `$region->ansi()` for pre-rendered SGR lines such as graph rows. It drops every escape except SGR. SGR is FOLDED into canonical state (attributes, fg, bg, underline colour) and stored as one escape per cell, so a later fg replaces the earlier one and `22` drops bold. `Surface::canonical()` gives the stored form, which is what `style()` assertions must compare against. Never append escapes to a style string: the earlier accumulate-until-reset version made a 200-cell gradient row go from 3.8 KB in to 325 KB out. Use `$region->put()` for plain untrusted text. It strips C0/C1 control characters, but still sanitize process names before they reach a Region.
- A panel that needs several collectors, such as cpu with freq, temp and battery, wraps them in `Source\SourceSet`. Its snapshot is a `Source\Samples`.
- btop #1858: the App only calls `collect()` and `paint()` for boxes in `shown_boxes`. A hidden panel still gets every broadcast Msg, but it must not build graphs or history until it is sampled.
- DualSampleGraph throws when the width or height is below 1. Clamp every graph dimension with `max(1, ...)` (btop #1614/#1858). The layout can hand you a 2-row box in odd combinations.
- `Panels::standard()` currently uses `PlaceholderPanel`, which only prints readouts. Each phase removes its box from it.

## Gotchas

- candy-core `Program` now repaints from scratch on `WindowSizeMsg` in non-inline mode. Before that fix, shrinking the terminal erased rows with `cursorTo(row > height)`, the terminal clamped that onto the new last row, and the bottom border vanished. Do NOT add a `clearScreen` Cmd on resize; it is not needed.
- DEC 2026 synchronized output is always on: candy-core `Renderer` wraps every frame. The `terminal_sync` config key is not honoured yet because ProgramOptions has no setting for it.
- Golden cell grids live in `tests/fixtures/frames/`. Regenerate them with `CANDY_TOP_UPDATE_GOLDENS=1 vendor/bin/phpunit tests/View/FrameSnapshotTest.php`, then review the diff. That run marks the tests incomplete. A missing golden FAILS without the env var; it is never written silently on first run.
- Button hotkeys (`FrameBuilder::hotkey($label, $key, $ink)`) light the first case-insensitive occurrence of the REAL key (`m`, `p`, `d`) in the translated label. When the label lacks that letter, the key is rendered in front of it. Never highlight the label's first letter.
- `bin/candy-top` is published through composer `"bin"`; its `--help` text is all `cli.help.*` Lang keys. It exits 1 with `cli.no_tty` when stdin or stdout is not a tty, as btop does. `--help` and the argument errors still work without a tty. tty mode auto-enables when `posix_ttyname(STDIN)` starts with `/dev/tty`, which covers `/dev/ttyS0` (btop.cpp `starts_with`).
- `tests/bootstrap.php` calls `LoopPin::pinStableClock()` only when `SugarCraft\Testing\LoopPin` autoloads. `candy-testing` is a require-dev, but a vendor installed before that will not have it. `refresh-deps.php --mode=linked` would wire it in, but it reverts every uncommitted `*/composer.json` (see below), so it was not run while P-A was uncommitted. `tests/Support/Harness` builds the deterministic app: a fixed clock, a Ryzen 8-core host and the fake sources.
- Samples run synchronously inside Cmds on the loop thread. A slow ProcList scan stalls input for as long as it takes, so P-E should budget it (plan R4: under 50 ms for 500 pids).
- `scripts/refresh-deps.php --mode=linked` reverts uncommitted `*/composer.json` edits through its `git checkout`. Run it before editing the manifest, or re-apply the edit afterwards.

## Deferred from P-A (deliberately)

- P-F: when a `1`-`4` toggle is refused because the result would not fit, btop shows the SizeError menu (`Menu::show(SizeError)`). P-A just ignores the key.
- P-F: overlays and menus (options, help, main menu, size-error menu, P-E's signal/kill popup) get ONE seam owned by the App: an `OverlayMsg` that pushes onto a menu stack held by `App`, introduced in P-F. While the stack is non-empty it sits ABOVE the modal tier (btop routes everything to `Menu::process` while `Menu::active`, and swaps to `Menu::mouse_mappings`). P-E's signal popup requests it by returning a Cmd/`PanelResult` that emits `OverlayMsg` once P-F lands; until then P-E must not draw popups into its own Region or invent a second modal mechanism.
- P-B: btop #1008 keeps the last valid reading when a collector briefly fails, instead of showing `n/a`. PlaceholderPanel currently replaces its snapshot on every sample.

## P-C net panel

- Files: `src/Panel/Net/NetPanel.php` (state + keys + mouse), `NetView.php` (paint), `NetButtons.php` (title-row button columns, shared by paint and mouse hit-test so they cannot drift), `Humanizer.php` (full btop `floating_humanizer`: bits/bytes, base-10 `kB`/`kb` vs binary, `shorten`, `/s` vs `ps`, `base_10_bitrate` override for bit rates only). `View\Units` stays the P-A subset; do not grow it for net.
- Selection is panel state (btop `Net::selected_iface`), re-picked ONLY when unset or vanished: `net_iface` when present, else the collector's `NetSnapshot::$selectedName` (connected first, then highest rx+tx). A runtime `net_iface` change does nothing while the selection is valid, as in btop. `b`/`n` cycle in `/proc/net/dev` order with wrap and are never persisted (btop has no `Config::set` there).
- `a`/`y` return `PanelResult::$set` with the flipped `net_auto`/`net_sync` (btop `Config::flip`). `z` is panel state: per-iface offsets = the totals at press time; a second `z` clears both; an offset above the running total drops (btop `offset > val + rollover`). The collector's own `Net::withZeroed()` is NOT used.
- `net_auto` is btop's AUTOSCALE flag, not interface auto-pick. Only while it is on is the selected iface's speed offered to `NetAutoScale` (with `withSync(net_sync)` read from the context every tick). `b`/`n`/`a`/`y` rescale AT ONCE with sugar-dash `NetAutoScale::rescaleNow()` over the (new) iface's history and the post-key net_auto/net_sync, mirroring btop's `Runner::run("net", no_update)` — the same frame draws against the new ceiling (with net_auto off it only `forceRescale()`s, leaving it armed). The vanished-iface re-pick inside a sample still uses `forceRescale()` + that tick's `offer()`, which is btop's in-collect order. `graphMax()` floors at 10 KiB even before the first rescale; with net_auto off it is `net_download/net_upload << 20 / 8`.
- History is kept per interface for every interface (btop's `bandwidth` deque lives in each `net_info`), capped at 1024; a vanished interface loses its history and offsets.
- #1008: UNMEASURED rates (the collector's first sample of an iface) never reach history or the scaler; the stats keep the last measured speed. An empty snapshot (failed `/proc/net/dev` read) keeps the previous one.
- Geometry is read from `Layout::$netStats` (b_x/b_y/b_width/b_height), falling back to `NetView::statsRect()` (the same btop formula, pinned equal to FrameBuilder by a test); graph sizes are `d = round((h-2)/2)`, `u = h-2-d` — download is `u` tall, upload `d` (btop's naming), both clamped >= 1 and width `max(1, w - b_width - 2)`. Under `swap_upload_download` the upload graph is on top and download inverts.
- Keys arrive via the broadcast (`capturesKey()` is false) because btop checks the net block LAST (after proc, cpu, mem). Mouse: only bare left presses on the title row, mapped through `NetButtons::targets()` (btop `mouse_mappings` b/n/z/a/y; `a` only when `w - i_size - 20 > 6`, `y` when `> 13`).
- `FakeNet` now has `lo`, `eth0` (192.0.2.10 / 2001:db8::10, the pick) and a disconnected `wlan0`; eth0's numbers are unchanged so the P-A placeholder goldens did not move.
- Goldens: `tests/fixtures/panels/net/*.txt` (box-cut plain grids + full-row SGR for truecolor and tty); regenerate with `CANDY_TOP_UPDATE_GOLDENS=1 vendor/bin/phpunit tests/Panel/Net/NetPanelPaintTest.php`.
- The title address goes through `NetView::displayIp()`: cut at `%` (inet_ntop never prints an IPv6 zone) and control characters stripped — never a character whitelist, which garbled `fe80::1%eth0`.
- Deviations: btop falls back to the MAC address (`/sys/class/net/<if>/address`) when an iface has no IP; the collector does not read it, so nothing is shown. btop freezes the graph of a disconnected iface until the next redraw; here graphs always rebuild from history. btop draws nothing but the box until the first bandwidth sample; here the buttons/stats appear from the first snapshot (speeds 0).

## P-B cpu/mem panels

- Files: `src/Panel/CpuPanel.php` + `src/Panel/Cpu/CpuView.php` (paint) + `Cpu/BatteryBadge.php` (P-D seam); `src/Panel/MemPanel.php` + `src/Panel/Mem/MemView.php` + `Mem/DisksSection.php` (P-D seam); shared helpers in `src/Panel/Gfx/` (`History`, `NamedSources`, `TintedGraph`, `PositionMeter`, `Just`, `Trans`); fakes `Source/Fake/FakeFreq.php`, `FakeTemp.php`. Roster lines: `CpuPanel::standard($host, $config, $fake)`, `MemPanel::standard($config, $fake)`.
- Coordinates: btop `Mv::to(y + r, x + c)` is local cell (r, c) of the box Region; cores-box offsets `Mv::to(b_y + r, b_x + c)` are (c.y + r, c.x + c) of `$frame->local($layout->cpuCores)`. The graph width is `W - b_width - 2` (btop `x + width - b_width - 3`, x = 1). The mid divider's `┤` lands on the cores-box left border, as in btop. `Mv::r(1)` gaps (mid-line labels, `up` + uptime) are skipped cells, so the underlying h_line/graph glyph shows (`total─▲▼─user`).
- Data: one Cmd samples cpu, freq, temp, gpu (+ the badge's battery) through `Gfx\NamedSources` (a SourceSet with accessors, so update() can split `next` back up). Members are chosen at collect time from the CURRENT config: freq only with show_cpu_freq or show_core_freq != off (and retuned with `Freq::withPerCore()` / `FakeFreq::withPerCore()`), temp only with check_temp, gpu unless show_gpu_info is Off. Mem samples memory (+ the disks section's source).
- #1008: every reading goes through `Gfx\History::push()`, which repeats the last good value for a negative/NaN sample and skips a series that never had one. Readouts read `History::last()`, so they hold too; load/uptime/freq label/GPU devices/MemorySnapshot keep their last measured value. Caps follow btop: `width*2` of the panel's OWN box (`Cpu::width` / `Mem::width` in btop's collectors; the cpu box spans the terminal), 512 before the first resize; cores and per-core freq 40, temps 20, gpu temp 18. Core dimming: a core that never measured is inactive; one that did keeps its last state through UNMEASURED (a sub-jiffy resample reads every core as Δ=0). btop instead reads `/sys/fs/cgroup/cpuset.cpus.effective` (active_cpus) — a Cpu collector addition if ever needed. GPU devices are merged field by field with the previous sample (`CpuPanel::holdDevice`), so a column shows while the value was EVER measured.
- Graph colour: `Gfx\TintedGraph` renders DualSampleGraph with a 101-stop MARKER ramp rgb(i,0,0) (+ rgb(0,0,1) for the underlay) in TrueColor and swaps each marker for `Ink::gradient()`/`inactive_fg`, so the library's glyph and colour-index law stays exact while the bytes follow the App's profile (TTY themes keep their ANSI indices). `Gfx\PositionMeter` is btop Draw::Meter through Ink: sugar-dash `Meter` position mode always emits TrueColor, which would put 24-bit escapes into TTY mode. GfxTest pins both to the dash output cell-for-cell in TrueColor.
- `Gfx\Just` = btop `rjust`/`ljust` with `limit = true` (truncates). `str_pad` never truncates — `8.94 GiB` in a 7-cell slot must print `8.94 Gi`, not eat the divider. A NEGATIVE width is btop's size_t wrap: the text prints whole (the Region clips); width 0 cuts to "". Don't wrap widths in `max(0, ...)`. `Gfx\Trans` = btop `trans()` (spaces are cursor moves): the mem values over the divider and the >8-char uptime use it. Bytes are formatted by P-C's `Panel\Net\Humanizer` (the one floating_humanizer port; `Humanizer::new($base10)->format($v, $shorten)`).
- Colour state: btop's `Fx::reset` is reset + main_fg + main_bg, which is the Surface base, so text written after a graph/meter uses sgr `''`, not `fg('main_fg')`. Bold set by a label (`GPU`) persists until a meter/graph reset — `gpuRows()` tracks it, so a one-column cores box (no meters) prints the whole GPU row bold. MemView tracks which colour the stream is in for each title (main_fg after Total/Swap/divider, '' after a meter, `title` after a mem_size <= 2 value).
- show_temps = check_temp && `HostInfo::hasSensors` (btop got_sensors). `HostInfo::hasSensors()` runs `Temp`'s get_sensors discovery, so only a real `temp*_input` (hwmon dir or its `device/`, coretemp platform) or a thermal zone counts — an empty or fan-only /sys/class/hwmon does not (fixtures `tests/fixtures/host-sensors/`). Until the first temp sample the meter row keeps the temp slot blank so the separator still meets the border. Per-core temps map core n -> sensor `n % sensors` unless `cpu_core_map` says otherwise (btop reads core ids from cpuinfo; we approximate).
- #1785 per-core freq: `value` adds ` 3.4G` (6 cells, `Freq::label()` compacted), `graph` adds ` ` + a 5-cell min/max-scaled history (maxValue = max-min, offset = -min) + the value (12 cells). - #1614: `CpuView::gpuGraphWidths()` ports d3389d7 exactly — `max(1, (W - (n-1)) / n)`, remainder to the last graph (`max(1, gw + drawable % n)`), one div_line column between. Like btop, the sum can exceed the graph area when n > W; the Region clips it.

Fields `gpu-totals|gpu-vram-totals|gpu-pwr-totals` draw one graph per GPU, `gpu-average|gpu-vram-total|gpu-pwr-total` one shared graph. Power % = watts / power.limit. `Gpu::withProcesses()` is NOT enabled (no per-process GPU memory is shown here).

- Keys: the cpu box claims nothing (btop's cpu block is `+`/`-`/`=`, App-owned). ## P-E proc panel

- `Panel\ProcPanel` (roster: `ProcPanel::new($fake ? FakeProcList::demo(cores) : CollectorSource::of(ProcList::new()))`) plus helpers in `src/Panel/Proc/`: `ProcTable` (filter + sort + tree → rows, memoised per `ProcTable::key(config, treeVersion)`), `ProcSorter` (btop proc_sorter incl. the cpu-lazy hog rotation, btop_shared.cpp:132-150, ported verbatim — every rotated row lands at the SAME offset, so the last hog pulled sits first), `ProcTree` (_tree_gen / tree_sort / _collect_prefixes / toggle_tree_collapse / _auto_collapse_oversized), `ProcFilter`, `ProcSelection` (Proc::selection + draw's bounds check + scrollbar math), `ProcView` (paint + `buttons()` mouse map), `DetailState`, `FilterEdit`, `ProcUnits` (floating_humanizer, integer-exact), `ProcEntry`.
- Sampling stays in the Cmd: `collect()` re-applies proc_per_core, proc_filter_kernel, #1823 io (only while the box is >= 90 wide or an `io *` sort is active) and the detailed pid to the source from the CURRENT config, via `ProcList::withPerCore/withFilterKernel/withIo/withDetail` (or the same methods on `FakeProcList`). `ProcSnapshot` gained `memTotal` (Mem% denominator) and `detail` (`Collect\ProcDetail`: #1546 cwd via readlink, elapsed, io totals — read for that one pid only).
- #1008: an UNMEASURED cpu reading keeps the pid's last good value (`ProcPanel::$carry`); a pid never measured reads 0. io is NEVER carried: UNMEASURED io means the collector was not reading io (columns off), EACCES, or the pid's first io sample, and all of those render "-" (never 0).
- Sort-tie stability: the panel keeps every entry in the last sorted order and feeds that to the next sort (btop sorts its persistent vector in place); new pids join at the end.
- btop quirk kept on purpose: `tree_sort`'s recursive call passes its collapsed flag in the `index_max` slot, so visibility in tree view is decided ONLY by `_tree_gen`'s `filtered` marks — a text-filter match under a non-matching parent shows at depth 0 with its whole subtree, and the children of a hidden parent get an empty indent header (which is why a matched last-child's own children indent by four cells).
- #1791a: with proc_aggregate off, tree siblings sort by BRANCH totals (own + every non-dead descendant), so collapsing a branch never moves it. btop sorts by the node's own value.
- Keys: everything except `+`/`-`/`=`/space/`C` arrives by broadcast (unclaimed keys); `capturesKey()` claims those five only while proc_tree is on AND a row is selected (btop's `keep_going` otherwise lets `+`/`-` step update_ms). `j`/`k`/`g`/`G`/`h`/`l` act only with vim_keys (btop gates them; plain `k` is the kill key). The filter is `modal()` (proc_filtering): Enter/Down keep it (Down also moves), Esc or a left click restores the old text, every edit writes proc_filter live.
- Writes: sort (left/right, wrapping through `Schema::PROC_SORTING`; an unknown value goes to the first on right, the last on left), `r`, `c`, `%`, `e`, `O`, `f`/`/`, delete, Enter (show_detailed) all return `PanelResult::$set`; the panel rebuilds its rows for the post-set config itself (`after()` mirrors App's validation) so the next paint hits the memo.
- Detailed view: Enter on a selected row opens it (selected -> 0, last_selected kept) and returns a collect Cmd so the cwd/io fill at once; Enter again closes it — proc_follow_detailed on restores the list around that pid (btop restore_detailed_pid), off restores last_selected. Follow mode (`F`) and pause (`u`) are not implemented, so the detail does not track the pid while open.
- Mouse: buttons are resolved first from `ProcView::buttons()` (same geometry the painter uses: f, delete, O, c, r, e, left, right, info_enter, hide=enter); then the list: wheel ±3, click selects, a click on the selected row opens the detail (or toggles the branch when it lands on the `[-]` marker: `depth*3 < x < depth*3+4`), the scrollbar column pages at its arrows, starts a drag on the thumb (Motion+Left = drag, Release ends it) and jumps proportionally elsewhere (`round(y*(n-max-2)/(max-2))`, a 2-row track divides by 1). Any other left click — anywhere on screen — clears the selection, as btop's unmapped `mouse_click` does.
- Rows are painted cell by cell from the L6 primitives (DistanceFade fade/metric blend, ProcGraphTracker 5x1 graphs on the graph_bg underlay, ProcRowComposer's label formatters) rather than `ProcRowComposer::row()`, because tree rows and #1823's IO columns have no slot there. btop's off-by-one fade (calc 0 on the row BELOW the bar) is kept.
- Wave U3 rendering: #1859 `proc_command_basename` applies to list rows only (sort, filter and the detail CMD keep the full command); #1873/U1b tag `[engine:name]` leads the command column, a KVM guest shows its guest name in the program column, `O` (proc_filter_containers) hides containers AND VMs, and the plain text filter also matches the container/VM name (an extension).
- Not drawn, deliberately: pause / follow / terminate / kill / signals / nice buttons and the pause/follow banner. `t`/`k`/`s`/`N` are left unhandled for P-F's overlay seam (signal popups are btop Menus); a button must not advertise a key that does nothing.
- `FilterEdit` is a small port of sugar-bits `Input\TextEdit` because candy-top does not require sugar-bits yet (adding it needs a composer update in a shared vendor). Swap it once P-F adds the dependency for OptionRow.
- Perf (R4, `tests/Panel/Proc/ProcBenchmarkTest.php`, group `benchmark`, incomplete instead of failing when over budget, assertion-free under CI): 500 FAKE pids at 120x40 run ~25-35 ms per sample+update+paint. Most of the paint cost is `View\Surface::put()` at ~4 µs per cluster (Width::nextCluster per character); a printable-ASCII fast path there would roughly halve every panel's paint.
- Real ProcList cost, measured on the dev host (1160 pids, busy machine, steady state after the first scan): ~58-63 ms before P-E's tuning, ~40-47 ms after (io on: ~85-100 ms → ~56-72 ms). The floor is the kernel: reading every `/proc/[pid]/stat` alone takes 20-33 ms (~20 µs each), every `/proc/[pid]/io` another ~20-25 ms, so a 1000+-pid host cannot meet R4's 50 ms with io columns on. Wins taken without changing output: numeric scandir + int sort instead of `Read::entries`' natsort + closure filter, direct `$root/$pid` paths, no regex per /proc/stat line or per io file. Already in place: cmdline/status/cgroup are read once per pid lifetime (keyed by starttime) and uid → user is cached for the collector's lifetime. The first scan pays the three static reads per pid (~185 ms on that host).
- Goldens: `tests/fixtures/panels/proc/*.txt` (chrome + panel, cropped to the box) and `*.sgr` (only the box's own cells, canonical style per change — another box's chrome never leaks in). Regenerate with `CANDY_TOP_UPDATE_GOLDENS=1 vendor/bin/phpunit tests/Panel/ProcPanelPaintTest.php`.
- IO columns: btop #1823 subtracts io_size + 1 (15) from cmd/tree but draws 14 cells; candy-top subtracts the 14 it draws so Cpu% stays at the same right edge with or without the IO columns (`ProcView::sizes()`).
- The detailed view needs a box of at least 30x14 (`ProcView::detailFits()`); in a smaller box the painter shows the list alone and ProcPanel's selectMax / mouse rows / button map use the full list too (`detailDrawn()`).
- Regex filter: `~` delimits the PCRE; `ProcFilter::escapeDelimiter()` escapes only UNESCAPED `~` (even backslash run in front), so a user's own `\~` and `\\~` keep their meaning. A modified wheel (shift/alt/ctrl) is ignored, as btop maps only the bare `[<64;`/`[<65;` codes.

### Deferred to P-F (proc)

- Mouse-mapping precedence: btop resolves a click against every box's `mouse_mappings` BEFORE Input::process, so clicking another box's button (cpu `menu`, mem `disks`, net `auto`) never reaches the proc handler. Here mouse events are broadcast, so such a click also reaches ProcPanel, which (like btop's unmapped `mouse_click` outside the list) clears the proc selection. Keeping btop's clear-on-outside-click; the fix belongs to the App-owned click map P-F introduces with the overlay seam (consume a click a panel's button claimed before broadcasting).
