# SugarLog Caliber Learnings

[syslog-levels] — The Level enum uses charmbracelet/log-aligned int deltas (-4/0/4/8/12) rather than sequential integers. These are deliberately NOT RFC 5424 severities; the aligned deltas keep threshold comparisons clean without value collisions. (2026-11 truth-flip: 'syslog-aligned' overstated it.)

[probe-color] — Color is a two-step decision and the environment knobs differ at each step. At construction the Logger consults Probe::colorProfile()->allowsColor(), which runs the sugar-colorprofile DetectionChain: CLICOLOR_FORCE (step 1) and FORCE_COLOR (step 2) outrank the passive NO_COLOR preference (step 3) — an intentional force-vs-preference asymmetry, not an oversight. At every emit the destination passes through ColorGate::allowsColor(), which knows exactly one override, CLICOLOR_FORCE (set, non-empty, and not exactly '0', via Probe::isForceColor), then stream-isatty; FORCE_COLOR has no effect there. Consequence: CLICOLOR_FORCE re-enables color in captured non-tty output (CI logs, redirected files), while NO_COLOR exported after the Logger was constructed neither plain-ifies the constructor-side profile nor the gate. Do not hard-code color decisions. (2026-11-13 truth-repair: an earlier entry claimed FORCE_COLOR was 'not a fleet knob' — it IS read, at construction step 2; see the ColorGate.php docblock and DetectionChain steps 1-3.)

[pattern:callerformatter-internal-skip] — `CallerFormatter::find()` walks `debug_backtrace(DEBUG_BACKTRACE_IGNORE_ARGS, 20)` to skip frames inside the `SugarCraft\Log` package and return "file:line" of the first external caller. Used by formatters to show the true log call site rather than internal library frames.

[pattern:hook-registry-callable] — `HookRegistry::onLevel(Level, callable): int` stores callbacks in a per-level array and returns a sequential int ID. `remove(int $id): void` deregisters a handler by dropping its slot outright (unset — no tombstone to skip). Removal by ID is intentional — never wrap the ID in `Closure::fromCallable`, which only accepts callables.

[pattern:partsorder-config-dto] — `PartsOrder` is a config DTO for log-part ordering: `list<PART_*>` consts (PART_TIMESTAMP, PART_LEVEL, PART_PREFIX, PART_CALLER, PART_MESSAGE, PART_FIELDS), a `readonly array $parts` property, nullable constructor defaulting to standard order, and static factories (`new()`, `syslog()`, `messageFirst()`; `default()` was renamed under P3-5). The constructor rejects unknown or duplicated parts by name (2026-11, M15). Immutable config DTO — plain constructor, no with* setters.

- Lang class now extends `SugarCraft\Core\I18n\Lang` — `t()` method inherited from base; NAMESPACE and DIR are the only per-lib constants.

[pattern:read-side] — (2026-11-27, P3-5a) `LogReader::new($path, LogFormat)->tail($n)` seeks to EOF and reads backwards in `CHUNK_BYTES` steps, so cost follows the lines asked for; `tests/Support/CountingReadStream.php` pins that it never reads the whole file. Blank lines are not records, a missing file is an empty tail (not an error), a directory or unreadable path throws. Unparseable lines come back as a `LogRecord` with a null level and the raw line as message. `LogFilter` compares scalar field values by written form (logfmt hands back strings). Rotation is deferred to plan decision D6.
[pattern:log-viewer] — (2026-11-27, P3-5b) `LogViewer` reads only inside Cmds (`init()` reads now and starts the ONE follow chain; `tick()` fires a `LogTickMsg` and the viewer decides then whether to read, so the chain uses the current reader and idles while paused; `refresh()` is a one-off read whose `LogTailMsg` is not `chained`, so it never forks a second chain) and reads go through `LogReader::follow()`: the first read (and the one after `withReader()`/`withFilter()`/an error) takes the last `tailSize` records the FILTER keeps, scanning back as far as needed, and later reads resume from a `LogCursor` (byte offset past the last complete line + inode) and APPEND every match since, capped at `maxRecords`. A cursor is only trusted while the inode matches, the file is not shorter, and a newline still sits before it; otherwise the read starts over from the tail (truncation, rotation). Unterminated last lines are left for the next read so none is taken twice. A resumed `LogTailMsg` carries its `from` cursor and is appended only while the viewer still holds that cursor, so a refresh beside a tick never duplicates lines. `LogTailMsg` carries the viewer id and a generation; `withFollow()` (on a change) and `withReader()` bump the generation so an in-flight read has its records dropped, but a chained read still reschedules, so the chain survives both setters with no Cmd from the caller. The filter also applies in `view()`, so a stricter filter narrows at once; `withFilter()` bumps the generation and clears the cursor so the next read re-scans through the new filter. Under opcache `!($x > 0.0)` can compile to `$x <= 0.0` and let NaN through: guard with `is_nan()`.

[naming:p3-5] — (2026-11-27) The banned `::default()` names were renamed with no alias: `PartsOrder::new()`, `Log::logger()` (shared facade logger; pairs with `setLogger()`), `Styles::shared()` (the process-wide singleton; not `new()`, since it does not build one). `Logger` keeps one spelling for the formatter and min level: `withFormatter()`/`withMinLevel()`; `setFormatter()`/`setMinLevel()` are gone.
[pattern:tail-window] — (2026-11-28, P3-5d) `LogTailWindow::new($path)->withWindowBytes($b)->lines($n)` returns `[list<string>, int]`: raw lines and the file size from the same handle. It keeps candy-code `Server/LogTail::tail()` rules exactly so that tail can move onto it: reads at most `WINDOW_BYTES` (256 KiB) from the end and drops the window's first line whenever the window starts after byte 0 (even on a line boundary), blank/whitespace lines count toward $n (only trailing newlines at EOF are trimmed), `\r` stays on the line, and a missing/unreadable/non-regular path is `[[], 0]`, checked by lstat like LogTail's `isRegular()`: a symlink at the path is refused even when it points at a regular file (never followed out of the state dir), and a fifo is refused before fopen, which would block. Unlike LogTail, $n = 0 is no lines and a negative $n throws. `LogReader::tail()` is untouched.
