- **`McpMessage`** covers all four JSON-RPC 2.0 packet types: request, response, notification, error. Factory methods: `request()`, `notification()`, `success()`, `error()`.
- **`McpMessage::parse()`** validates `jsonrpc: "2.0"` presence and returns `null` for malformed input — callers handle null gracefully.
- **Polling loop** with `usleep(10000)` (10 ms) waits up to 100 attempts for a matching response id — avoids blocking the TUI while still being responsive.
- **`ClaudeCodeMcpClient::forClaudeCode()`** factory provides the canonical `command: 'claude', args: ['--mcp']` invocation for the official Claude Code MCP server.
- **`disconnect()`** closes pipes and calls `proc_close()` in a loop; `__destruct()` ensures cleanup if the client is abandoned.
- `Renderer` holds a `?Buffer $previousFrame`; on each render it diffs against the prior frame and emits only delta ops via `DiffEncoder`.
- Reset `previousFrame` on window resize, cursor-position-lost, or first paint — diffing across these boundaries produces visual corruption.
- **Source:** step-27 ai/buffer-diff-consumers

- **[env]** Packagist API: `Authorization: Bearer <username>:<apiToken>` plus `Content-Type: application/json`. `POST /api/create-package` and `PUT /api/packages/<name>` need the MAIN token. `POST /api/update-package` also accepts the SAFE token. The API has no abandon or delete endpoint, so abandoning a package is a manual step in the web UI. The user gets the token with `grep -A1 packagist /home/sites/mystage/auth_login_credentials.txt`. Keep it in a shell variable only, and never write it to a file, a commit or a plan.
- **[gotcha]** A `find /home/sites -maxdepth 4 -name composer.json …` sweep for external `sugarcraft/*` consumers takes longer than 60s, so a `timeout 60` run gets `Terminated`. Run it in the background. The known consumers are phlix-console-client, php-dup-finder, webhooks.interserver.net, and provirted (through its `composer-tui.json` bundle).
- **[gotcha]** `scripts/refresh-deps.php` accepts only `--root`, `--status`/`--verify-only`, `--mode=published|linked`, `--force`, `--dry-run` and `--libs=a,b`. The DEFAULT mode is `published`, which resolves siblings from Packagist and so tests the last pushed master, not the working tree. Pass `--mode=linked --libs=<lib>,<dependents>` to scope a relink.
- **[gotcha]** In candy-code, `tests/Prompt/PromptSnapshotDriftTest.php` pins the byte length and sha256/16 of every system-prompt slot in `tests/fixtures/prompt-snapshots/system-sections.txt`. Any wording change in the prompt turns it red. To fix it, copy the "Actual manifest" from the failure message into the fixture, check that only the slots you meant to change moved, and explain the regeneration in the commit message, as the test's docblock requires.
- **[pattern]** To regenerate golden-render fixtures (candy-code `tests/Tui/MediaForm/*`, `SessionPickerGoldenTest`), run phpunit with `UPDATE_GOLDENS=1`, then review the fixture diff before you commit.
- **[convention]** candy-code has about 22 `*DriftTest.php` guards (find them with `find candy-code/tests -name '*Drift*Test.php'`). `DocFigureProseDriftTest` pins prose needles taken from `lang/en.php` and the docs. - **[gotcha]** candy-code's user config dir is a HOME-rooted dot-dir (`Cli\Bootstrap::configDirPath()` = `homePath() . '/.<app>'`), not XDG. It holds `config.json`, `hooks.yaml`, `mcp-trust.json`, `policy-snapshot.json`, `session.db`, `server/server.lock` (a flock singleton) and caches. Policy paths go through `trustedConfigDirPath()`, which refuses to run on an unowned or world-writable HOME. `PolicySnapshot` stores content fingerprints, not paths.
- **[gotcha]** The CI `composer audit` step for candy-code fails only on HIGH or CRITICAL advisories. `composer audit` has no `--ignore=ID` flag. To accept a specific advisory, record it in the lib manifest with `composer config audit.ignore --json '["GHSA-…"]'`, and give the reason in the PR.

- **[convention]** G-13 CLASS RULING (S-P10; S-V07/S-V08/S-L11 cite this): a string that reaches the end user (launch notice, CLI line, config/skill/hook refusal shown at startup, public HTTP page) has its FRAMING keyed through `Lang::t` in every `lang/*.php`; the VOCABULARY inside it stays untranslated technical tokens (file names like `SKILL.md`, config keys, scope/event names, `disabled: true`, paths, URLs, YAML type names from `get_debug_type`, upstream error text passed as `{reason}`). A purely operator-facing developer diagnostic (serve/daemon internals read from logs or a terminal by the operator, never a user surface) is deliberately NOT localized; mark it with a docblock at the seat saying "operator-only diagnostic, untranslated by G-13 ruling" (precedent: `Protocol/WebStrings.php`). Model-facing text (tool descriptions, prompt layers, tool errors) stays English as `Lang.php` already states. The `en` text must equal the old literal so message-regex tests keep passing. Applied: `cmd.mcp-auth.login.*` (OAuthLoopbackFlow), `host.skills.err.*` (SkillLoader/SkillFrontmatter), `hooks.err.*` (HookConfig/ClaudeSettingsHooks). OAuthClientRegistration `:800/:860` raw throws are exception text carried as `{reason}` inside the already-keyed `login.failed` line, so they are class-2 developer diagnostics and stay raw.
- **[convention]** `Message::notice` Lang-vs-English ruling (S-T02): a `Message::notice(...)` row is a USER-visible transcript row, so its framing goes through `Lang::t` (the old ~35/80 keyed/literal split was convention-by-accident, not design). Only genuinely model-facing text (tool descriptions, prompt layers, tool errors) and G-13 operator-only diagnostics stay literal. `background.task.*` keys cover `src/Background` + `BangShell`; both `Output: (none)` seats are MODEL-facing (announcement + BangShell user-role row sent to the model), so they are the English constant `BackgroundSession::OUTPUT_NONE` per G-13 and the `background.task.output.none` key was deleted from all locales.
- **[convention]** sugar-shlex boundary ruling (S-T12, candy-code-tools-015, rider R10 unbooked): `Permissions/ShellWords` (the pure quote/escape lexer) and `Permissions/ShellCompound` (compound-command splitting) stay APP-SIDE in candy-code until a second consumer exists; no `sugar-shlex` lib is created now (zero other consumers today, and the policy constants for read-only/compound handling are interleaved with the lexing). - **[convention]** RepoMap extraction revisit trigger (S-X10, candy-code-context-015): `src/RepoMap/` (ctags JSON extractor with version-stamped cache keys, PHP regex fallback, `SymbolGraph`/`PageRank` ranking, `TagCache` 0700 sqlite, aider-style `RepoMapBuilder`) is a clean separable engine whose deps are already only house pieces (`GitRunner`, `ProcessContainment`, `SqliteConnect`, `HomeDirectory`), but it has exactly one consumer, so it STAYS in candy-code and nothing ships. Revisit and extract to a `sugar-repomap` lib ONLY when a second consumer appears: a server-host split (candy-code-web / serve host needing the engine without the agent app) or a `candy-query` consumer. The risky edge of that move is producer-stamp byte-identity: the ctags version stamp and cache-key bytes must stay identical across the move or every existing `TagCache` entry is silently invalidated (or worse, mis-served), so pin the stamp bytes with a test before moving. - **[convention]** `Palette` stays app-local; no `sugar-quickpick` adoption (S-U10, owner ruling G-12=A, 2026-11-12). Bounded evaluation of `src/Palette/*` (5 files, 469 LOC: `PaletteState`, `PaletteCatalog`, `PaletteAction`, `PaletteEntry`, `PaletteEntryKind`) against `sugar-quickpick` found a poor fit, so the palette is NOT extracted and NOT rebuilt on `QuickPick`. Evidence: (1) the palette is a data tuple whose behaviour lives in Chat/Renderer/KeyboardHandler - `PaletteState` carries only `mode`/`query`/`selectedIndex`/`queryCursor`/`provider`, and the four modes (`root`, `providers`, `models`, `themes`) resolve their rows on demand in `Chat::paletteMatches()`, whereas `QuickPick` owns a flat item list plus its own filter, cursor and `show()`/`hide()` lifecycle; (2) key routing is the blocker - `QuickPick` decodes no input (host-defined `string $msg`), while the palette's keys are registered in `KeyBindingRegistry::palette()` (`CONTEXT_PALETTE`), opened by `Ctrl+P`/`Ctrl+K`, gated by `KeyboardHandler::paletteStandsDown()` / `paletteIsAbandoned()` and routed in `Chat::handlePaletteKey()` ahead of the ctrl arms, and `KeyBindingDriftTest` re-derives the documented key roster from that registry, so a second key vocabulary inside a library widget would fork the pinned source of truth; (3) the S-U01/S-U06 work is already app-specific and has no quickpick counterpart - the budget-fitted grouped window (`Renderer::paletteWindow()`, category headers, always contains the selection), the `PaletteState::MAX_QUERY_LENGTH` (192) cap with the renderer's trailing-ellipsis disclosure, a code-point caret spliced by the same rule as the draft (`Chat::inputCursorOffset()`), MRU-biased category-grouped root with relevance-flat typed queries (`Chat::paletteMru()`), `PaletteCatalog` merging action rows with slash-command prefill rows and tier badges, and per-mode pickers (provider -> model, theme seeded to the one in use); `QuickPick` has `filterAtCap()` and windowing but not these semantics; (4) the shared part is already shared - the palette matcher is `sugar-fuzzy`'s `SmithWatermanMatcher` (memoised in `Chat::paletteFuzzyMatches()`), and `candy-code/composer.json` has no `sugar-quickpick` require, so adoption would add a dependency for a widget shell the app would then bypass for input, ranking and painting. Revisit trigger: reopen only if (a) `sugar-quickpick` gains a host-key-registry hook (bindings declared by the host, not decoded or named in the widget) AND multi-mode/drill-down lists plus a grouped, budget-windowed render, or (b) a second app needs the same palette shape and a concrete duplicated-code diff exists; absent both, do not re-evaluate.
- **[convention]** Renderer ANSI tokenizer ruling (S-L07, candy-code-cli-007): `Renderer::insertAtColumn()`'s `preg_split` tokenizer (SGR/CSI + OSC + zone-sentinel + `\X` grapheme alternation) is a DELIBERATE fast-path; do not swap it for `sugar-ansi-parser`. Probe `prompt_kit/tools/probe-ansi-tokenizer.php` (PHP 8.3.6, 232-byte SGR row): regex 4.8 us vs `Parser::parseComplete` 290 us (about 60x slower), and the parser is not parity-capable: it dispatches escapes to handler callbacks instead of returning the original bytes (the regex split is lossless, `implode` equals the input, which the byte-exact insert needs), it emits one rune per `printChar` so a ZWJ family emoji is 7 runes vs 1 grapheme token (column math would split clusters), and it has no notion of the PUA zone sentinels (they print as ordinary runes). Revisit only if sugar-ansi-parser grows a lossless token-span API with grapheme segmentation and a measured speed within about 2x.
- **[convention]** HTTP error-message language law (S-V08, G-13): `Responses::error()` `message` on JSON/API surfaces is a developer-facing English diagnostic (`kind` is the contract); browser-facing page prose (StaticFiles no-UI notice + 405/404, SharePageController 405/404) is keyed `serve.notice.*` / `serve.share.*` / `serve.static.*` and rendered under the visitor's `Accept-Language` through `Server/Http/RequestLocale` (WebStrings ladder, containment-safe). `tests/Server/Http/ErrorMessageLanguageLawTest.php` fails on a new bare sentence literal in arg 3 outside its census; a new refusal either routes through a key or is listed there with its G-13 class-2 reason.
- **[convention]** `(s)` plural-idiom policy (S-L12, candy-code-cli-014, 2026-11-13): a lang string whose sentence names ONE counter takes a whole sentence per plural class, keys `<base>_one` / `<base>_other`, selected at the call site with `$n === 1 ? 'x_one' : 'x_other'` (precedent `cli.noticerow.*`; the `cli.doctor.*` single-counter rows were converted under S-L12 and pinned by `tests/LangDoctorPluralTest.php`). Languages without number agreement (ja/ko/zh-*) carry the same sentence under both keys; Russian puts the count at the sentence end (`...: {count}`) so no case agreement is needed. The `(s)` splice survives ONLY as an accepted diagnostic idiom where one sentence carries two or more counters (`cli.doctor.channels_store_ok`, `cli.doctor.otlp_degraded`) or in operator-only prose outside the converted rows; do not add new `(s)` rows for a single counter. A full select-plural parameter convention is a separate, unfunded program. Root `LOCALES.md` could state the idiom repo-wide; that is a closeout/report row, not edited from this lib.
- **[convention]** `with*()` immutability law (S-X06, owner ruling G-16 hybrid, 2026-11-13): a `with*()` NEVER mutates `$this` (service-side setters are `set*`/`attach*`: `EnhancedSessionStore::attachJsonlMirror`, `HookManager::setPromptBackend`/`setScriptSandbox`, `AgentLiveRegistry::setColorResolver`, `McpClient::setSandbox`); a wither with seven or more constructor inputs goes through ONE `mutate()` (`SugarCraft\Core\Concerns\Mutable`, or a class-local `mutate(array $changes)` where an input is a stored closure or a lazy memo: WebFetch, HttpHook, ScriptHook, EnvironmentBlock, the two providers) and names only what it changes; value objects below seven inputs may hand-carry and say so in a dated docblock line. `tests/Support/MutateDriftGuardTest.php` enforces all three plus constructor/property parity for every `Mutable` user. The root AGENTS.md sentence is a closeout row.
- **[pattern]** Frozen prompt layers (S-X03, G-15=A, 2026-11-13): a TURN detects `/clear`/compaction/rewind off its history (`SessionPromptMemo::observeTurn()`), but `/context` and `/context --raw` build the prompt with no turn, so `/clear` and every `/compact` route also call `Backend\RefreshesPromptLayers::refreshPromptLayers()` (`Chat::refreshFrozenPromptLayers()`; `EngineBackend` forgets the session's memo and refreshes the shared instruction loader). A session switch is still NOT a refresh point (ISS-054). Pinned by `tests/Chat/FrozenLayersRefreshTest.php`.
- **[convention]** argv grammars are per-app house convention (S-L06, candy-code-cli-006, 2026-11-13): `Cli/ArgvParser` stays candy-code's own; there is no shared parser library and none is proposed (extraction ranked HIGH-risk: every app's refusal copy, exit codes and `--` handling are pinned by its own goldens). A `sugar-argv` lib would need its own design pass first. The root `PROJECT_NAMES.md` row stating this is a closeout report row (root file, not edited from this lib).
- **[gotcha]** Windows proc_open pipes (2026-11-13, measured on Windows 11 / PHP 8.4.27): `stream_set_blocking($pipe, false)` answers FALSE and changes nothing, `stream_select()` reports every pipe ready at once, and `fread()` then blocks until the child exits, so any select-then-read loop loses its deadline on Windows. `fstat($pipe)['size']` IS the PeekNamedPipe byte count: read at most that much (`Support\WindowsPipes::readAvailable()`) and end the loop on the child's EXIT, not on EOF (feof cannot flip without a read that may block). `runCaptured()` has that arm. The other `stream_select` sites over child pipes (ProcessExecutor, ScriptRunner, DrainsStreamedChild, the provider invocations, MCP/LSP clients) have not been converted yet.
- **[gotcha]** Git-for-Windows bash backgrounds through MSYS fork emulation: the fork stub exits, so `sleep 40 &` has no living Windows parent and `taskkill /T` never reaches it (measured: both sleeps of `sleep 40 & sleep 40 & wait` survived a 2 s timeout). MSYS still tracks it in bash's process GROUP: `WindowsTaskKill::tree()` first runs `msysGroupKillArgv()` (resolve the pgid from `/proc/*/winpid` while bash lives, `taskkill /T`, then `kill -9 -- -PGID`) and falls back to plain taskkill for non-MSYS pids. `setMsysBashForTesting('')` keeps routing pins host-independent.
