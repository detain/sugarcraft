## 1. Executive summary

- The endpoint is already reachable and speakable: sugar-crush's sglang provider talks OpenAI-compat `/v1/chat/completions`, which the server serves. Tool declaration, tool-result pairing, streaming tool-call accumulation, and reasoning-field parsing are **already correct for Qwen** (verified by live probes).
- **Two hard blockers make every real session 400 right now:**
  1. **Multiple system messages.** The Qwen chat template raises `System message must be at the beginning.` (HTTP 400) if any `system` message appears at index > 0. sugar-crush emits 2+ system messages in normal sessions (launch notices, 70% context reminders, cancellations, compaction reports, title/compact one-shots) — see section 6.
  2. **Invalid reasoning effort.** `.sugar-crush/config.dev.json` pins `"reasoningEffort": "max"`. sglang's pydantic layer accepts `max`, but the **template** rejects anything outside `low|medium|xhigh` with a clean 400 — while thinking is on (the default). Every request would fail until the value becomes `low|medium|xhigh` (or `enable_thinking:false`).
- **A silent misfit:** the provider believes the context window is 196,608 tokens; the server advertises `context_length 1,000,000` (YaRN 4x over native 262,144) with `max_req_input_len 748,602`. Result: premature compaction tiers (70/85/95%) and wasted budget headroom.
- **Dead features on this path:** streamed usage is never requested or parsed (`stream_options.include_usage` absent; zero-choice usage chunk dropped), so `SUGARCRUSH_MAX` spend-capping and usage readout are dead on sglang streaming.
- **Important context:** `/home/my/sglang/opencode-system-merge-proxy.py` exists to merge multiple system messages for *opencode* only. sugar-crush talks to skynet2 **directly** (baseUrl `.../v1`), so that proxy protects nothing here — sugar-crush must fix serialization in its own provider (section 7, change P0-1).

## 3. Chat-template contract (from chat_template.jinja, verified live)

- **Reasoning control** via `chat_template_kwargs`: `enable_thinking` (undefined/true = thinking ON, emits open think tag in generation prompt; explicit false = empty think pair, no thinking). When on, `reasoning_effort` defaults to **xhigh** and MUST be one of `xhigh|medium|low` else the template raises (`Unexpected reasoning effort X. Supported types are xhigh (default), medium, and low.`). `xhigh`/`low` inject an effort-instruction paragraph at the top of the system block; `medium` injects none.
- **Tools**: when `tools` is present the template renders its OWN leading system block embedding the tool JSON schemas plus instructions for an XML function-call format (tool_call blocks wrapping `function=NAME` with `parameter=NAME` children), then appends the user's `messages[0]` system content after two newlines. So OpenAI-style `tools` param is standard; the server-side `qwen3_coder` parser converts the model's XML calls back into a normal `tool_calls` array.
- **System placement (THE rule):** a `system` role message at any position other than the very first raises `System message must be at the beginning.` System content must not contain image/video parts.
- **User/assistant/tool rendering:** user messages are plain blocks; tool responses (role `tool`) are grouped into user blocks wrapped in tool_response tags; a conversation with no real user query raises `No user query found in messages.` Assistant history renders `reasoning_content` in a think block when `preserve_thinking` is undefined/true (default TRUE) or the message is after the last user query, then `content`, then its tool_calls as XML blocks. Strings in `parameter` values pass raw; non-strings are `tojson`-ed.
- **Server splits**: the `qwen3` reasoning parser moves think content into `delta.reasoning_content` (non-streaming: `message.reasoning_content`); the `qwen3_coder` tool parser emits standard OpenAI `tool_calls` array with JSON-string `arguments`.

## 7. Required changes (ranked)

**P0 — without these the model 400s on every session**
1. **Single-system enforcement in `SglangProvider`** (mirror BedrockProvider.php:321-326 / VertexProvider.php:1670-1675): strip all `system` rows from converted history and merge their content (plus the prepended `systemPrompt`) into exactly ONE index-0 system message. The opencode proxy (`/home/my/sglang/opencode-system-merge-proxy.py`) proves this is THE fix pattern, but sugar-crush bypasses the proxy, so it belongs in the provider. Amend pinned tests `SglangProviderTest.php:402-446` + `SystemPromptTransmissionMatrixTest.php:687` deliberately.
2. **Effort sanitization for Qwen**: clamp/map `reasoning_effort` to `low|medium|xhigh` (map `high`/`max` to `xhigh`, `none` to the `enable_thinking:false` path) OR at minimum change `config.dev.json` to `"reasoningEffort":"xhigh"`. Today's `"max"` equals a guaranteed 400 (probe P4).
3. **Route effort via `chat_template_kwargs` + make kwargs settable**: add config key(s) (ProviderFactory.php:88-90) that populate `$extraTemplateKwargs` (currently a dead wire — gap 2) so `enable_thinking`/`preserve_thinking`/template-side `reasoning_effort` are reachable without code changes; keep top-level only for DeepSeek-family backends (docblock :691-697 argues the split).

**P1 — correctness/cost**
4. **Qwen model family predicate** beside `isDeepSeekV4()` (:765): context window 1,000,000 (effective input budget capped ~748k by `max_req_input_len`), default effort xhigh, and switch `config.dev.json` model to `Qwen/Qwen3.8-Flash-Next` (bare alias works per P12 but use the canonical id). Temperature: legacy 0.7 stays a sane default; top_p omission is fine.
5. **Streamed usage**: send `stream_options:{include_usage:true}` (stream arm of buildParams) and relax the chunk guard :524 to also accept zero-choice `usage` chunks; read flat `usage.reasoning_tokens`. Revives SUGARCRUSH_MAX + the usage bar.
6. **finish_reason completeness**: surface `length` (truncation warning — TruncationGuard machinery already exists) and flush-or-flag the tool-call buffer on `length/abort` so partial calls are not silently lost.

**P2 — polish**
7. **Parse error bodies**: on ClientException extract the `error.message` JSON field instead of relaying clipped raw text.
8. **Leading two-newline artifact** on `content` when thinking is on (P2): trim before display/goldens.
9. **Stray newline content deltas between parallel tool-call groups** (P7): tolerated today (concatenated into content); consider trimming content to empty when tool_calls are present on finish.

**P3 — optional / policy decisions**
10. **`preserve_thinking:false`** once kwargs plumbing exists — saves replayed-reasoning prompt tokens (P9 measures the cost; default is TRUE) — or conversely START replaying `reasoning_content` cross-turn for thinking continuity (server supports both).
11. **Cross-turn tool history**: currently flattened to assistant text (works and is template-legal per P9) — restoring real role:tool structure would strengthen multi-turn tool chains; bigger chassis change (Chat.php:2855-2861).
12. **Vision**: server does images (P13); if sugar-crush ever sends image parts, use `image_url` content arrays; bad payloads fail as opaque 500 — pre-validate client-side.

**Resolved suspicions (no action needed):** `separate_reasoning:true` hardcode is correct for Qwen (qwen3 parser delivers clean `reasoning_content`); assistant empty-content stripping is template-tolerant (P11); textual tool-call fallbacks are inert, so no double-parse risk.
