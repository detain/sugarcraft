# Caliber Learnings — sugar-spring

Accumulated patterns and gotchas from building this library.

---

[pattern:spring-preset-enum] — `SpringPreset` as backed enum case with `resolve(): SpringConfig` — Each preset case encodes tension/friction/mass triples that downstream consumers access via `resolve()` without needing to know the raw values. This keeps call sites at `Spring::fromPreset(SpringPreset::Wobbly)` rather than scattering magic numbers.

[pattern:springconfig-physics-translation] — `SpringConfig` translates tension/friction/mass to angularFrequency/dampingRatio — The constructor computes `ω = sqrt(tension/mass)` and `ζ = friction/(2*sqrt(tension*mass))` so that `Spring` receives the physically meaningful coefficients directly. This separates the user-facing "spring feel" parameters from the integration math. All three inputs must be finite and > 0 (a zero/negative tension or friction derives a spring that never settles or diverges — refused at the boundary, not silently clamped), and the derived pair is belt-checked finite before the readonly properties are published.

[pattern:cubic-bezier-newton-raphson-css] — `CubicBezier` uses Newton-Raphson with binary-search fallback per W3C spec — `solveCubicX()` runs up to 8 Newton iterations then falls back to binary subdivision (bounded by `MAX_SUBDIVISION_ITERATIONS`) when the derivative is too small. The solver only INVERTS x(t); monotone time mapping is guaranteed by the constructor's x1/x2 ∈ [0, 1] range check (the CSS spec's own precondition), not by the solver, and y may overshoot [0, 1] by design for back/elastic-style control points. See https://www.w3.org/TR/css-easing-3/#cubic-bezier-algo

[pattern:springchain-sequential] — `SpringChain` sequences springs so each stage activates only when the previous settles (position within 5e-4 of target AND velocity within 5e-4 of zero — `SpringChain::SETTLING_THRESHOLD`, public so call sites can consult the exact contract, deliberately looser than `Spring::SETTLING_THRESHOLD` of 1e-4). One `tick()` = one step of the active stage returning the ADVANCED chain (`self`) with FRESH positions readable via `currentPositions()`; callers MUST carry the returned chain (`$chain = $chain->tick()`) or the run never advances. The earlier shape returned `[positions, complete, newChain]` where `positions` was computed BEFORE the step — one frame stale, and dropping the third tuple element compiled into a silent infinite loop; `tick(): self` makes both states unrepresentable (the lib-reviews-1102 fix). `isComplete()` returns true when `activeIndex >= count(stages)`.

[pattern:reduced-motion-instant-snap] — `Spring::update()` checks the reduced-motion signal at call time and returns `[$target, 0.0]` instantly when it is set (after the finite-input guards — a non-finite target is refused even on the snap branch). The signal is ENV-ONLY: `Probe::reducedMotion()` (sugar-colorprofile) reads exactly `REDUCE_MOTION` / `PREFERS_REDUCED_MOTION` — no terminal query, no a11y-daemon channel — with explicit-negative polarity: `0`/`false`/`no`/`off` (any case) mean OFF, any other non-empty value means ON. A per-instance `?bool $reducedMotionOverride` constructor parameter (threaded by `Spring::fromPreset()`, `SpringConfig::spring()` and `springAt60Fps()`) pins the choice regardless of the environment. Scope: EVERYTHING SPRING-COMPOSED honors it — `Spring` directly, and `SpringChain`/`SpringCollection` for free because every stage/member is a Spring (chains snap within ~one tick per stage, collections in one tick). `Projectile` and the `Easing`/`CubicBezier` curves deliberately ignore it: pure functions of time with no target to snap to; gate them app-side by short-circuiting normalized time to `1.0` when `Probe::reducedMotion()`.

- Lang class now extends `SugarCraft\Core\I18n\Lang` — `t()` method inherited from base; NAMESPACE and DIR are the only per-lib constants. Both `Spring` and `Projectile` throw `Lang::t(...)` messages (projectile.* keys live in every `lang/*.php`); `LocaleParityTest` keeps all locales' key sets in lockstep with `en.php`.

[pattern:snapshot-testing-golden-file] — Numeric (JSON) trajectory output is pinned with sugar-testing's `GoldenFile::save()`/`load()` + plain `assertEquals` in `tests/GoldenRenderTest.php`; re-record with `UPDATE_GOLDENS=1 vendor/bin/phpunit` (no `--update-golden` flag exists). sugar-testing's `assertGolden*` helpers are ANSI/cell-grid specific — there is no generic `assertGolden` method. This pins canonical output so refactors are intentional rather than accidental regressions.

## 2026-10-24 — Accessor-deprecation era (bare twins)
- **[pattern:accessor-deprecation-era]** `SpringCollection::getTarget()` was renamed to its bare twin `target($id)`, kept as a one-line `@deprecated` BC forwarder marked `REMOVED-IN: 2.0.0` until sugar-spring v2.0.0. A `get`-prefixed getter can coexist with the fluent `withTarget()` builder and the deprecated in-place `setTarget()` shim — the bare form completes the collection's existing `get()`/`all()`/`has()` reader set instead of widening it. `tests/AccessorDeprecationTest.php` owns the census + inverse leg + README table; any further get* without those rows goes red.
- **[record:accessor-deprecation-dated-prose]** Full dated change record (moved out of the README on 2026-11-06 by PB-SPRING-8; the README section keeps only its heading, the table, and a neutral user-facing pointer): the rename took the unclaimed slot so the getter mirrors the collection's existing bare `get()` / `all()` / `has()` readers; the fluent `withTarget()` builder and the deprecated in-place `setTarget()` shim were untouched and a bare `target()` coexists with both cleanly. `tests/AccessorDeprecationTest.php` pins BC identity on a live collection (seeded spring, after retarget, original untouched), the forwarder shape (single return line + markers), a discovery-first `src/` census with an inverse leg that reddens any unmarked public `get*()`, and the README table agreement. `tick()` reads `$this->targets` directly, so there were no internal call sites to switch; the existing `SpringCollectionTest` needles stay green through the forwarder.
