# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha:spark:flush-resets-state]** `SugarCraft\Ansi\Parser\Parser::flush()` resets the parser to `State::Ground`. Any end-of-stream decision that depends on the parser having ended mid-sequence (e.g. `currentState() === State::Escape` to detect a trailing bare ESC) MUST capture the state **before** calling `flush()`. `StreamingInspector::finish()` originally checked `currentState()` *after* `flush()`, so the branch was permanently dead and a lone trailing ESC (`"\x1b"` with no following byte) was silently dropped. Capture `$stateBeforeFlush = $parser->currentState();` first, then flush, then decide. `AnsiHandler::parse()` already did this correctly — `finish()` did not.
- **[gotcha:spark:foreign-visibility]** `AnsiHandler` holds the end-of-stream tail state (`$segments`, `$ss3Buffered`, `$ss3Intermediate`) as `private`/`protected`. `StreamingInspector` is a **separate** class and cannot legally touch them — reaching in (`$this->handler->segments[] = ...`, or calling the `protected getSs3Intermediate()`) throws a fatal `\Error` at runtime, e.g. a dangling SS3 (`"\x1bO"` with no final byte) at end-of-stream. Fix: give `AnsiHandler` a **public** seam instead of exposing raw state. We added `AnsiHandler::finishPending(State $stateBeforeFlush)` which encapsulates the whole end-of-stream flush (buffered text → trailing bare ESC → dangling SS3) and is now shared by both the one-shot `parse()` and the streaming `finish()`, so the two paths stay byte-for-byte identical. Note `AnsiHandler` is `final`, so `protected` on it was meaningless anyway — removed the dead `getSs3Intermediate()`/`isSs3Buffered()` accessors.
- **[pattern:spark:one-shot-vs-streaming-parity]** `Inspector::parse()` (one-shot) and `StreamingInspector::feed()`/`finish()` (chunked) must produce the same segment stream for the same bytes. When touching either, prefer routing shared logic through one method on `AnsiHandler` (see `finishPending()`) rather than duplicating the tail handling — the streaming tests (`testStreamedC0IsIsolated`, `testStreamedApcKittyGraphics`, `testStreamedSgrUnderlineColonForm`) assert this parity by diffing against `Inspector::parse()`.
- **[pattern:spark:handler-owns-parser]** `AnsiHandler` now *owns* the candy-ansi `Parser` it feeds (`feed()` / `finish()`), and `StreamingInspector` drives it instead of holding its own. Two reasons: (1) the handler can then read `Parser::subparams()` while a CSI dispatch is in flight — the `Handler` interface hands it only a flattened `list<int>` that cannot distinguish `4:3` from `4;3`; (2) end-of-stream bookkeeping (state capture, `Parser::flush()`, tail emission) lives in one place, so one-shot and streaming cannot drift. `Parser::feed()` is stateful across calls, so a chunk-per-call driver would behave identically minus the byte window (next entry).
- **[gotcha:spark:separator-fidelity]** The raw CSI rebuild must preserve the input's own parameter separators: `;` stays `;`, `:` stays `:`, and an omitted parameter (`param()` reports it as `-1`) keeps its empty slot. Canonicalising `4;3` to `4:3` (which the old rebuild did) silently turns "underline + italic" into "curly underline" and reports bytes the sender never sent. Build the string from `Parser::subparams()` continuation flags and let `Inspector::describeSgr()` see the faithful string — its `4:N` handling then works because it is finally fed a real colon form.
- **[gotcha:spark:st-terminator-ghost]** candy-ansi dispatches a DCS/OSC/SOS/PM/APC when it meets the **ESC** of the `ESC \` terminator and *then* calls `escDispatch(0x5C)` for the backslash. If the handler emits that as an ordinary ESC sequence the stream grows a phantom `ESC \` segment after every ST-terminated string (and it carries a stale intermediate byte — the parser does not clear `cmd` when ESC leaves DcsString, so the ghost is `ESC SP \`). Consume **exactly one** such follow-up terminator (`$awaitingStringTerminator`, closed by `feed()` when the next byte is not the backslash and by every handler callback): a BEL that ended an OSC or a C1 `ST` that ended a DCS must leave a *later* standalone `ESC \` alone, so the window is one byte wide, not a latch. The old code got this backwards for OSC: one flag set to true and never cleared, which swallowed *every* later standalone `ESC \` in the stream. Byte fidelity requires the narrow window, not a latch.
- **[gotcha:spark:per-byte-feed-for-byte-window]** Reporting an unterminated sequence needs the bytes of the sequence still in flight, but `Handler` never sees introducer/parameter bytes — so `AnsiHandler::feed()` keeps a window that each dispatch clears. That only works if bytes reach the parser **one at a time**: with a whole chunk appended up front, a dispatch early in the chunk would wipe the bytes of the *next* (incomplete) sequence in the same chunk, and a stream like `"\x1bO\x1b[3"` would lose its tail again. Measured cost of per-byte feeding: 2.24 MB plain text 0.54 s → 1.02 s, 1.64 MB sequence-dense 1.67 s → 2.01 s — accepted for a debugging inspector whose contract is that nothing vanishes. A Ground-state fast path is possible but would duplicate candy-ansi's state-machine knowledge; do not add it unless profiling demands it.
- **[gotcha:spark:ss3-final-range]** `ESC O` may not absorb the next printable unconditionally: ECMA-48 §5.6 restricts the SS3 final byte to C6 (`0x40–0x7E`), so `ESC O` followed by a space, a UTF-8 multi-byte rune, a C0 byte, or another introducer means the sender abandoned the SS3. Emit the partial `ESC O` as its own segment (in stream order, *before* whatever follows — including a dangling trailing `ESC`) and re-process the offending byte as text. `InspectorTest` still pins the valid `ESC O X` → "SS3 X" case.
