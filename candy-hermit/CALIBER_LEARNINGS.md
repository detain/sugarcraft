# CALIBER_LEARNINGS — candy-hermit

Accumulated patterns and gotchas for this library.

[pattern:item-interface-numbered] — Structured `Item` interface (number() + value()) enables numbered lists with arbitrary ordinals, not just 1-based sequential indices. `FilteredItem` readonly impl satisfies the contract. Custom impls can encode database IDs, file paths, or any structured key alongside display text.

[pattern:filehistory-jsonl] — `FileHistory` stores one JSON-encoded item per line (`{"n":1,"v":"apple"}\n`) using `FILE_APPEND | LOCK_EX` for safe concurrent writes. Reading uses `fgets()` in a loop — line-based I/O avoids loading the entire file into memory for large histories.

[pattern:setfilterfn-post-fuzzy] — `setFilterFn(Closure): bool` is applied *after* the text-based fuzzy filter in `applyFilter()`. Both conditions must pass for an item to appear. This ordering lets you combine user typing (substring match) with programmatic filtering (e.g., category, date range, visibility flag).

[pattern:sigwinch-signalforwarder-attachsigwinchtofd] — Hermit's `attachSigwinch()` wires `SignalForwarder::attachSigwinchToFd()` to forward terminal resize events. The size-provider closure captures `$hermit` by value so it stays alive across the signal. On each SIGWINCH it calls `Tty::size()` via a private `ttySize()` method (exception-safe: falls back to 80×24 on non-interactive error) rather than stale env vars. The callback then invokes the stored `$onResize` closure with fresh (cols, rows). This pattern is safe for use in long-running TUI processes.

[pattern:border-style-composition-sprinkles] — Hermit's `withBorder()` and `withStyle()` accept `candy-sprinkles` `Border` and `Style` objects directly — composition rather than inheritance. Both are nullable; `null` means no decoration. The border/style is stored and can be queried back via `border()`/`style()` accessors. This follows the same composition pattern used in `sugar-boxer` and `sugar-stickers`.

[gotcha:int-cast-of-a-stream-is-a-resource-id-not-an-fd] — `SignalForwarder::attachSigwinchToFd()` wants a FILE DESCRIPTOR. `(int) \STDIN` gives PHP's resource id (`1`), which silently means STDOUT. On an interactive terminal fd0 and fd1 are the same device so the mistake renders as working code; redirect stdout and `ioctl(TIOCSWINSZ)` returns `ENOTTY`, `SignalForwarder` swallows the non-zero rc, and the user's `$onResize` never fires. Hermit now names it `Hermit::STDIN_DESCRIPTOR = 0`, asserted by `tests/HermitSigwinchTest.php`, whose token scan rejects any `(int)` cast of a standard stream in `src/`. Read `ioctl(TIOCSWINSZ)` as a precondition, not a detail: the forwarder invokes `$onResize` ONLY on rc === 0. `candy-core`'s equivalent fix lives in `Util\Tty\PosixBackend::descriptorForStream()`, which is `@internal` and therefore not callable from here.

[pattern:method-names-are-case-insensitive-in-php] — Renaming `View()` to `view()` is a source-compatible fix-up that needs NO delegation shim: PHP resolves method names case-insensitively, so every legacy `$hermit->View($bg)` still binds. Do not try to add a capitalised `@deprecated` wrapper alongside the lowercase method (the `model()`/`getModel()` pattern in candy-core) — two names differing only in case are a single declaration, and the second is a "Cannot redeclare" fatal. `HermitTest::testTheLegacyCapitalisedCallStillBindsToView` pins the binding; the rename was driven by PSR-1 plus the TEA `Model::view()` contract.

[gotcha:utf8-byte-ops-corrupt-a-codepoint-filter] — `backspace()` used `substr(-1)` and `type()` capped with `strlen()`, while `highlightMatches()` reads the filter in codepoints via `mb_str_split`. Deleting one byte of a two-byte `é` left a dangling `0xC3` lead byte, which `Width::of` then scored as garbage — and the byte cap charged multibyte input up to 4x. Both now use `mb_*` with explicit `'UTF-8'`. Granularity is CODEPOINT, not grapheme: `'👍🏽'` (one grapheme, two codepoints) takes two backspaces. Deliberate, because trimming codepoints keeps the filter byte-aligned with the matcher; a future grapheme trim must update `highlightMatches()` in the same commit. `mb_substr` also self-heals a malformed tail instead of reproducing it.

[deferred:setters-and-clone-boilerplate] — Two audit findings are KNOWN and intentionally NOT fixed here; they belong to a separate repo-wide consistency campaign because each churns every public signature in the lib. (1) Naming: in `src/Hermit.php`, 8 `set*()` builders (`setFilterFn`, `setItemFormatter`, `setMatchStyle`, `setOffset`, `setPrompt`, `setRanker`, `setWindowHeight`, `setWindowWidth`) coexist with 6 `with*()` builders (`withBorder`, `withHelpBar`, `withItems`, `withOnResize`, `withStatusBar`, `withStyle`), although all 14 are non-mutating. House convention is `with*`, so unifying means a breaking rename of 8 public methods. (2) Boilerplate: 31 hand-rolled `clone $this` sites across the lib — `Hermit.php` 23, `StatusBar.php` 4, `Concerns/Visible.php` 2, `HelpBar.php` 2 — vs candy-core's `Concerns\Mutable` `mutate()` idiom (canonical: `candy-sprinkles/src/Style.php`); with 14 setters sharing that body, the trait fold is the larger half of the same diff. Both were left untouched so this lane's commit stays reviewable as three behavioural fixes plus docs.

[declined:vhs-gifs-stay-committed] — Audit finding "untrack `basic.gif`/`interaction.gif`" (AGENTS.md says don't commit GIFs) was SKIPPED per owner ruling: the repo's actual practice is the opposite — `git ls-files '*/.vhs/*.gif'` counts 288 tracked GIFs tree-wide — so untracking two of them here is a repo-wide policy change, not this lane's call.
