# CALIBER_LEARNINGS — sugar-colorprofile

## Patterns

- `[probe-ssot]` — `Probe::colorProfile()` + `ColorProfile` enum is the SSOT for terminal-color env detection. Live consumers (derived 2026-10-23 from `use SugarCraft\ColorProfile\` imports): sugar-log, sugar-image, sugar-spring, sugar-video, candy-mdview — candy-codeshot and sugar-vterm do NOT import this library. Do not re-implement detection logic in consumers.

- `[infocmp-phase2]` — `Probe::colorProfile()` upgrades the `Ansi`/`Ansi256` chain rungs to `TrueColor` when `infocmp -1` reports a `Tc` or `RGB` capability NAME (name-position match via `Probe\TerminfoParser::hasCapName`, not a whole-output regex — a `des=` string containing "Tc" must not promote). Best-effort: `InfocmpBinary` resolves a fixed roster of absolute candidates (`/usr/bin/infocmp`, `/bin/infocmp`) through an `is_file() && is_executable()` gate — the binary is never looked up on `PATH` (PATH-hijack refusal, shared admission rule with sugar-image's `ChafaBinary`). Answers are memoized per process: `Probe::resetForTesting()` drains the exec door's memo and path together and `AsyncProbe::resetForTesting()` drains the slot table plus the CP-13 settled memo (2026-11-13 CP-42 renaming — the underscored `Probe::_reset()`/`AsyncProbe::_reset()` survive only as deprecated delegates until 2.0; PSR-12 camelCase and the sibling `InfocmpBinary::reset()` shape both reject the underscore, and the prior text of this very entry blessed it while also crediting `Probe` with clearing a memo that CP-11/12 had already moved into the exec door — the rules doc contradicted the code on two counts).

- **[pattern:async-gap]** (corrected 2026-10-23 — this entry used to claim the library was "entirely synchronous" and pointed at a *future* `AsyncProbe`; that was false at the time of correction. 2026-11-13 refresh: prior text claimed `react/event-loop` was pinned `^0.5` (end-of-life, "fleet upgrade is an owner call") and called the no-loop face "the blocking `shell_exec` path" — the manifest shows the arm was already `"^0.5 || ^1.2"` and has since been narrowed to `^1.2` (CP-15: `^0.5` was unsatisfiable anyway — react/child-process 0.6.7 requires `^1.2`, so the EOL floor was a phantom whose only effect was letting a resolver flip the lib to the sync face); and the sync face is a `proc_open` argv spawn (`Probe\InfocmpBinary`), never `shell_exec` — as written the entry would have caused a maintainer to decline an upgrade the manifest permits.) The library IS async-capable: `AsyncProbe::colorProfile()` spawns the infocmp check as a ReactPHP child process ONLY on a caller-supplied loop (CP-14 — the `react/event-loop` 1.x singleton is never picked up implicitly); a loopless call resolves in place through the bounded sync face, which remains the default for plain CLI callers. The bounded-child ladder is 5 s deadline → SIGTERM → 1 s grace → SIGKILL, the KILL timer cancelled on exit, stderr drained to an 8 KiB cap; spawn failures never reach an event handler (`react/child-process` emits no `'error'` on Process — the dead listener is gone per CP-15), they are caught at `start()`, which releases the concurrency slot and fail-opens to the chain. Consumers must declare `react/event-loop ^1.2`, `react/child-process`, `react/promise` (all in composer require). LoopPin duty: `tests/bootstrap.php` calls `sugar-testing`'s `LoopPin::pinStableClock()` guardedly (CP-01) — this suite's own timers ride private `StreamSelectLoop` instances post-CP-14, so the pin is preventive against future `Loop::get()` arms under ext-uv.

- Lang class now extends `SugarCraft\Core\I18n\Lang` — `t()` method inherited from base; NAMESPACE and DIR are the only per-lib constants.

- `[perceptual-distance]` — `ColorMath` (sRGB→linear→XYZ D65→Lab) + `DeltaE` (76/94/2000) + `ColorDistance` strategy enum + `NearestColor` matcher. Default strategy stays EUCLIDEAN so existing degradation is byte-for-byte unchanged; perceptual metrics are strictly opt-in. Palette Lab tables are memoized statically in `NearestColor`, fingerprint-guarded against the mutable `StandardColors` slots — while the slots are untouched the tables are the identical instance (hot-loop identity holds), and a reassignment lands on the next call instead of being frozen behind the first-build memo (never recompute `ColorMath::toLab()` per candidate inside a search loop: ≈40 % hot-loop overhead).

- `[gotcha:global-mutable-statics]` — `StandardColors` exposes its 16-color palette as `public static Color $black … $brightWhite`. These are process-global MUTABLES: one assignment anywhere rewrites the value for every reader, with nothing pinning reassignment. **DEPRECATION WINDOW opened 2026-10-24 (owner ruling 2b):** the writable properties are `@deprecated` and removed at the next major (`REMOVED-IN: 2.0.0`) in favour of an immutable constant-backed equivalent — but behaviour is byte-frozen meanwhile (reads/writes/consumers all keep working). New code reads the blessed NON-MUTATING API: `all()` (indexed 0–15, reads the live slots on every call — the old frozen first-build memo is gone, so reassignments are visible), `fromIndex(int)` (bounds-checked, throws `OutOfBoundsException` outside 0..15), `catalog()` (ordered names); construct fresh colors with `new Color($r, $g, $b)`, `Color::fromHex()`, or `Color::fromAnsi256Index($n)`; a private palette table is just a local `array` built from `all()` (the `Color` values are immutable, so a local array is already isolated without a second shared class). Do NOT mint a parallel `StandardPalette` VO — that duplicates the table and can silently drift from `all()`. Census guard: `StandardColorsDeprecationTest` pins (a) every deprecated static is still a live writable `Color` (no accidental neuter) and (b) the code's `@deprecated` count == the README-documented count. Separate, NOT re-litigated here: sugar-style `Style::setDefaultProfile` is a different process-global mutable ruled KEEP+LOUD-DOC.

- `[reserved-query-capabilities]` — `Capability::BracketedPaste` / `Capability::FocusEvents` are `@deprecated RESERVED`: vocabulary without a producer (phase 3 is a TERM_PROGRAM lookup table; the 2004/1004 query legs need raw-mode read-back the TUI layer owns). A real DA1/OSC query implementation is Phase-5 candidate #6 (DD-sized, sugar-pty coupling) — if it ever lands, `ProbeReportTest::testTheReservedQueryCapabilitiesAreNeverProduced` is the pin that must flip with it, plus the README capabilities footnote. Meanwhile consumers gating on the two cases can NEVER light up: do not "fix" the probe by answering from env heuristics.

- `[gotcha:fromAnsi256-lossy]` — FIXED 2026-10-23 (historical record). `Color::fromAnsi256Index()` once decoded the 6×6×6 cube with plain float division where `intdiv()` belongs, so indexes 16–231 came back wrong. The accessor is now intdiv-exact and `NearestColor::palette256()` is built FROM the accessor (the old hand-rolled table workaround is gone). Lesson kept: cube/grey-ramp decoding needs integer division per channel — pin the edge indexes (16/17/231), not just a sample.

- `[exemption:withProfile-inline-clone]` — DATED 2026-11-13 (CP-43, finding -052/CONV-05). `Palette::withProfile()` and `ProfileWriter::withProfile()` deliberately keep the inline `clone $this` + single-field write instead of the canonical `sugar-core` `Concerns\Mutable` / `Style.php` `mutate()` shape. The reviewer decision tree ran against the live code: `ProfileWriter` carries profile-bound LAZY state (`$degrade`, rebuilt via `??=` from the current profile — the clone MUST null it, an accompanying step the generic trait copy has no hook to express); a trait adoption would either fight the invalidation or need a per-field override — the deviation would outgrow the convention it serves. `Palette` fits the trait alone, but keeping the two same-named seams one shape (both documented, both verified single-field writes with the lazy leg stated inline) beats half a conversion. Behavior is exactly the pattern's intent today (verified); revisit wholesale in 2.0 when the nullable-sentinel vocabulary is reworked fleet-wide — the fleet audit greps `withProfile` sites and expects THIS paragraph, not a silent refactor.
