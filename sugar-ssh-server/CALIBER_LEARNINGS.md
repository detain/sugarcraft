# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Avoid `pcntl_fork()` inside PHPUnit tests — the PHP runtime carries opcache/mock state/FFI handles into the fork and tests hang silently (PHPUnit produced zero output for minutes). Spawn a small fixture PHP script (e.g. `tests/Foo/_fixtures/runner.php`) via `proc_open()` instead and drive its stdin/stdout pipes from the test.
- **[pattern]** When testing PTY-spawning code (`InProcessTransport`, `sugar-pty` consumers), guard tests with `requirePtySyscalls()` that skips on missing ext-ffi / ext-pcntl / unreadable `/dev/ptmx` — these are non-negotiable host requirements and CI must skip cleanly rather than fail.
- **[gotcha]** `Pty::read()` distinguishes `null` (timeout / no data yet) from `''` (EOF) — treat them differently. The pump loop's master-side reader should keep polling on `null`/`''` and only exit when the child has exited; do not bail on a single empty read or you'll race child output.
- **[gotcha:linux-no-auto-sighup-on-master-close]** Closing the PTY master in PHP/Linux does NOT auto-deliver `SIGHUP` to the slave-side child via lost-ctty (BSD-style behaviour I assumed). Children that ignore STDIN EOF (`sleep`, daemons, anything not reading stdin) keep running until reaped. The teardown sequence that actually works on Linux: (1) on stdin EOF / EPIPE / pump exit, send `SIGHUP` explicitly via `$child->kill(SIGHUP)`, (2) wait ~200 ms for graceful exit, (3) `$child->kill(SIGKILL)` if still alive, (4) close the PTY master (in a nested `finally`, so it runs even if `kill()` throws), (5) `child->wait()` reaps. Use `Contract\Child::kill()` (or `SugarCraft\Pty\Libc::kill()` for a bare pid, as `signalChild()` does), never a `function_exists('posix_kill')` guard: `Libc::kill()` falls back to libc kill(2) over FFI, so ext-posix is optional, while the guard silently skipped the whole teardown on hosts without ext-posix. Without the explicit kill, `wait()` blocks for the child's natural duration (5+ seconds for `sleep 5`) instead of the expected sub-second teardown. Canonical implementation in `InProcessTransport::runChild()`'s finally block.
- **[env]** Always wrap potentially-blocking `vendor/bin/phpunit` invocations with `timeout 60` (or longer) when developing PTY/IPC code — a hung pump loop produces zero output, no error, and you can't tell a hang from a slow test without the timeout.
- **[convention]** New i18n strings for a sugar-ssh-server error message must land in `lang/en.php` keyed under a dotted namespace (`transport.bad_stdin`, `bubbletea.bad_factory`, etc.) and looked up via `Lang::t('namespace.key')` — do not throw raw English strings from PHP.
- **[convention]** When `Session->cols`/`->rows` are 0 (ForceCommand deployments without COLUMNS/LINES set), fall back to 80×24 before passing to `Pty::spawn()`. A 0-width PTY confuses curses-based clients.
- **[gotcha]** Tests that signal a `proc_open()`-spawned PHP supervisor (e.g. driving SIGWINCH into `InProcessTransport`) are racy if you `usleep(150_000)` to wait for "child has started". PHP cold-start + autoloader + `Pty::spawn` can run 200–400 ms in CI, so the supervisor's signal handler is sometimes installed AFTER the test's `posix_kill(...,SIGWINCH)` — losing the first SIGWINCH entirely and only the post-mutation state is observed. Fix pattern: poll the child's side-effect file (e.g. an `stty size` log) until the FIRST baseline sample lands, then mutate state + signal, then poll for the post-state sample. Never use a fixed sleep as the synchronisation primitive in signal-driven tests.
- **[gotcha]** Manual signal-delivery debugging via `timeout 3 php fixture.php ... & SUP_PID=$!; kill -WINCH $SUP_PID` does NOT reach the supervisor — `kill` targets the `timeout` wrapper PID, not the inner PHP process, and `timeout` does not forward arbitrary signals. Drop the `timeout` wrapper (or pull the inner PID from `pgrep -P $SUP_PID`) when reproducing signal-handling bugs at the shell.
- **[gotcha]** `gh pr merge <n> --merge --delete-branch` immediately after `git push` of a follow-up commit can fail with `GraphQL: Pull Request is not mergeable` — GitHub's mergeability check hasn't re-evaluated yet. Wait a few seconds and retry the same `gh pr merge` call; do not switch to `--admin`, force-push, or rebase as a workaround.
- **[pattern:context-propagation]** When adding a `Context` parameter to an existing `Middleware::handle()` signature, update ALL anonymous middleware classes in tests AND all `Transport::run()` implementations simultaneously — the new Context is always the first parameter and `$next` closure always takes `(Context, Session)`. A partial update (middleware updated but transport not updated, or vice versa) causes type errors at runtime.
- **[pattern:channel-msg-dispatch]** SSH channel messages (pty-req, window-change, shell, exec, signal, env, break — RFC 4254) are dispatched through a `ChannelHandler` interface rather than handled inline in `InProcessTransport`. The 7 concrete Msg classes are all `final` and extend a common `ChannelMsg` base — new message types can be added by subclassing `ChannelMsg` and adding a handler method to `ChannelHandler`. The `DefaultChannelHandler` is the composition root for `ChildSpawner` — it calls `$spawner->runChild()` on shell/exec, not the transport.

- Lang class now extends `SugarCraft\Core\I18n\Lang` — `t()` method inherited from base; NAMESPACE and DIR are the only per-lib constants.
- **[rule:no-capability-probing]** SugarSshServer performs NO terminal-capability probing — sugar-colorprofile is not a dependency and nothing here calls `TerminalProbe`. If capability probing is ever added, route it through a terminal probe (handling `\Throwable` with lowest-common-denominator fallback) instead of raw `getenv()`/terminfo reads. Clarification that stays true: Session::fromEnvironment() reads SSH env vars (TERM, SSH_CONNECTION, etc.) as session METADATA — that is not capability probing and needs no routing.
- **[pattern:exit-status-plumbing]** `Transport::run():int` reports one of three answers: the child's own code when a child ran, `Server::EXIT_DENIED` (`129`) when a gate refused or the context died before anything was served, and `0` only when the walk ran out of middleware with nothing to spawn (machinery failures raise). `Server::resolveStatus()` is the single place that reads them, both transports call it, and ForceCommand callers `exit($server->serve())` so the answer rides sshd's channel-close → client `ssh` exit. Before audit MAJOR 9 the last case was the only other value any refusal could produce, which is how a denied `ssh host backup.sh` read as a successful backup to cron. Middleware that needs the spawner declares `implements Middleware, TransportAware` — the transport injects itself via the interface (`instanceof`), never `method_exists`.
- **[pattern:atomic-json-sidecar-lock]** A lock taken on a file that is later *replaced* is a lock on an unlinked inode. `RateLimit` used to `fopen('c+')` + `flock(LOCK_EX)` the bucket-map path and then publish through `AtomicJsonFile` (temp + rename): the first writer's rename moves the path to a new inode, so every sibling already blocked in `flock` wakes holding a lock over a file that no longer lives at that path, reads the stale pre-rename content through its own fd, and republishes it. Six parallel connects against `burst: 3` all got in (audit K2). Correct shape: hold the decision lock on a STABLE sidecar (`<state-path>.lock`, opened `'cb'` so it is never truncated, `chmod 0600`) across the whole read-decide-publish cycle, and let the payload stay atomic-rename published. `AtomicJsonFile::write()` takes its OWN hidden `.<basename>.lock` internally, so a decision lock on the payload's inode would self-deadlock inside the write even if renaming were not involved — use a differently named sidecar. Pin the invariant two ways: inode identity (sidecar stable, payload changes across publishes) and a `proc_open` barrier of siblings released together (accepts must equal burst).
- **[convention:client-visible-stderr]** Under `ForceCommand`, the child's fd 2 is SSH *extended-data* — it goes to the connecting client, not to journald. Anything a middleware writes to `$stderr` (rate-limit degradation notices, auth refusals) is user-facing text on an unauthenticated path: never echo an absolute path or internal posture detail into it. The corollary for a *logger*: a middleware whose default sink is 'the process stderr' is a middleware that mails the user their own audit trail and keeps nothing. `Logger` now resolves the sink instead of assuming it — `$SSH_SERVER_LOG` when set, explicit `Logger::toFile()` / `toStream()` / `toStderr()` factories, and a public `target()` so the boot sequence can log what it actually chose. Stamp the mode (0600) only on files YOU create; leave a pre-existing file's mode alone or you break a deliberate rotation setup.
- **[pattern:allowlist-pairing]** Two independent allowlists are a cross product, never a pairing. `Auth` had `users` and `keyFingerprints` checked as separate predicates, so any listed user could log in with any listed key (audit K4 — bob presenting alice's key authenticated AS alice). Where an authorisation decision must bind *subject* to *credential*, take one map (`name => list<credential>`) and refuse a name with no entry; keep the flat lists only as additional narrowing gates and say out loud in the docblock + README + admin guide that they are uncorrelated. Compare credential material with `hash_equals()` over every entry rather than `in_array()`, which returns on the first hit and makes list position measurable. Pin the shape twice: a documentation-bearing test that asserts the cross product still admits (so it cannot be "fixed" silently), and refusal tests per pairing case.

- **[pattern:default-closed-peer-chosen-exec]** When a request names the program the server runs, the peer is choosing it — so absence of policy must mean refusal, not permission. `DefaultChannelHandler` gates exec twice (exact-path `$allowedExec` + `$execGate` returning exactly `true`; a throwing gate refuses) and announces one path-free line. Shell requests stay ungated because they name no program: the interpreter comes from server-side config only. Pin the direction (`if (false)` around the gate → 9 reds), not just the happy path. (audit K1, 2026-11-03)
- **[pattern:loop-ownership]** A synchronous `await` inside a loop-driven process must end **its own** spin. `PromiseAwait::settle()` calls `Loop::run()`, so it has to `stop()` the moment the awaited promise is decided (both settle paths do), and the ceiling it arms is a watchdog that is cancelled in a `finally` — never left armed on a loop the class does not own. The pre-K10 shape ("run until the loop is quiescent") wedged a panel's listening socket forever and executed unrelated sessions' timers inside somebody's auth hop, so a documented timeout bounded nothing. Two corollaries the class docblock now states as laws: never call `settle()` from inside a loop you already run (the stop ends your application), and a spin that ends without a decision must raise rather than return quietly — silence would read as "auth finished".
- **[pattern:announce-the-no-op]** A security gate that silently forwards when its input is missing is worse than one that denies: the operator reads "configured" where there is nothing to check. `CertificateAuth` now writes `certificateauth.env_missing` on BOTH paths (refuse when `required`, announce then forward when optional) and names the variables it probed. Pair it with a delivery table in the README: `userKeys`/`keyFingerprints` pairing without sshd's `ExposeAuthInfo` is a total lockout, and only the announcement makes that visible during a `ssh -v` smoke test.
- **[pattern:surface-truth-pins]** A generated site page is only as honest as the `_data` body behind it, and nothing compiles prose: `sugar-ssh-server`'s API table advertised `InProcessTransport new(?PtySystem, ?ChannelHandler)` when the real constructor takes one optional argument and the handler is a setter. The documented call would have run, PHP would have dropped the extra argument, and a custom channel handler would have silently never been installed. Rows for `withProtocolMetadata()` ('after SSH handshake' — there is no handshake here), `KeyboardInteractive` ('RFC 4256'), `Keepalive` ('SSH keepalive messages') and a `multi-tenant` chip sat in the same file. Cure each fabricated row with a `tests/DocSurfaceTruthTest.php` leg asserting both halves — the phrase that must now appear and the fabrication that must not — and `markTestSkipped` when `docs/` is absent, because a standalone package checkout has no monorepo docs tree. (audit K8, 2026-11-03)
- **[pattern:contract-where-the-bug-lands]** When the defect lives in a dependency you must not edit, the honest cure is a written contract on every surface an embedder reads. `runChild()` flips the PTY master and STDIN non-blocking but leaves STDOUT alone; `sugar-pty`'s `PosixPump::pumpMasterToStdout()` counts a short `fwrite()` as success, so a non-blocking STDOUT truncates terminal output with no error. That missing line now reads as a deliberate invariant (method docblock + README section next to the transport choice + the admin guide's failure list), one `DocSurfaceTruthTest` leg asserting all three, and a named upstream fix instead of a silent local workaround. (audit K9, 2026-11-03)
- **[pattern:refusal-carries-a-code]** A middleware that stops a chain is either the terminal (a spawner, which records its child's code) or a refusal (which must say so). The walk cannot tell those apart from control flow alone — a terminal legitimately never calls `$next` — so refusal is *declared*: `Session::markRefused()`, set by every shipped gate on every deny branch, read once by `Server::resolveStatus()`. Status slots live on the Session the whole stack shares (mutable, deliberately, and carried across `with*()` rebuilds), never on the transport, where they would leak into the next `run()`.
- **[pattern:opt-in-chatter]** A middleware that writes to a session stream on every connection is printing into someone's terminal, not into a protocol field. `AuthMethods` now records `auth.methods` in the Context unconditionally and emits its `SSH_AUTH_METHODS` line only under `announce: true` (audit MAJOR 7). The five surfaces that had to move with the flag -- the class docblock, the README table row, the README sink note, the admin operational note (which had also been calling it "the RFC 4252 banner"), the dev guide and the generated site body -- are why the rule is: change a default, then grep the default's *description* before you commit. `tests/DocSurfaceTruthTest.php` pins the wording pair so a future half-move reddens the suite.
- **[pattern:encoding-fallback-not-deletion]** `json_encode()` refuses the whole document for one malformed UTF-8 byte, and the byte is usually peer-influenced (`TERM`, a program name, `SSH_ORIGINAL_COMMAND`). A logger that `return`s on `false` does not degrade a record, it deletes the record - so retry with `JSON_INVALID_UTF8_SUBSTITUTE` plus a `json_error` field and scalar-only values, and keep a final literal line for the case even that refuses. An odd row that says why it is odd beats a missing row.
- **[pattern:provenance-on-every-surface]** Sentences describing *where a field came from* are the ones nobody re-reads: five files here said protocol metadata arrives 'after the SSH handshake completes' although the library negotiates nothing, and the fabricated story (cross-host correlation, a client version sshd never exports) is exactly what an operator builds a dashboard on. Fix the sentence on every surface in one commit and forbid the old phrase in `DocSurfaceTruthTest`.
- **[pattern:label-is-not-terminal-state]** A config flag that names a terminal property the code cannot set must be contradicted out loud at the point of use. `KeyboardInteractive`'s `echo: false` cannot clear ECHO - sshd owns the terminal, and this library runs as a child of it - so the exchange now appends `keyboardinteractive.input_visible` whenever any prompt asks for silence, and the README, admin guide, site body and class docblock all say 'a label, not terminal state'. Upstream gap (reported, not fixed here): sugar-pty's `Contract\Termios` offers only `makeRaw()`, which also drops ICANON and ISIG, so a targeted no-echo toggle is sugar-pty work. Pin: `testThePromptExchangeTruthTravelsOnEverySurface`.
- **[pattern:canonical-sanitizer]** A library that already depends on sugar-core should not hand-roll a control-character filter. `Sanitize::untrusted()` removes CSI *and* OSC in both 8-bit and UTF-8-encoded forms without cutting continuation bytes; the hand-rolled version in `Auth::sanitize()` had a second pass that was dead code (the first pass had already eaten the ESC byte), let OSC payloads through as text, and deleted bytes rather than characters — `O\u{2019}Brien` came out as U+FFFD plus two `?`, invalid UTF-8 which then made `json_encode` refuse the log record carrying it. Two follow-ons worth remembering: a *display* sanitizer deliberately keeps newlines, so anything that must stay one line (a rejection notice) has to fold `\r\n`/`\n`/`\t` itself; and any string the peer asserts (username, fingerprint blob) needs a length cap before it is echoed anywhere — the cap here is `Auth::MAX_ECHOED_BYTES`, pinned by `testAnOverlongNameIsBoundedInTheNotice`.
- **[gotcha:example-cites-an-unshipped-file]** An example is documentation a reader executes. `examples/spawn-program.php` built a factory returning `run-program.php`, a file that never existed, and kept the body as a trailing comment around a fictional `MyApp` class - so the documented tour fataled and the only copy of the answer was not real code. Ship both halves of a paired example, or stop citing the missing one; a comment showing what a file would contain is not a substitute for the file. Pin the pair by asserting the cited path exists (audit MAJOR 16).
- **[pattern:locale-is-peer-input]** Locale detection reads `LANG`/`LC_ALL`/`LC_MESSAGES` - and in a `ForceCommand` child those arrive from the connecting peer whenever sshd's `AcceptEnv` allows them. A server that auto-detects lets the client choose the language the server answers in, next to the username it also chose. Ship the catalogues, pin the locale at entry-script start (`T::setLocale('de')`), and never detect on an internet-facing listener; keep a fail-closed roster of the keys that are still English placeholders (`ACCEPTED_UNTRANSLATED` in `tests/LangRosterTest.php`) so the list can only shrink.
