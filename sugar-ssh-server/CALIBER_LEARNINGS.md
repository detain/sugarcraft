# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Avoid `pcntl_fork()` inside PHPUnit tests — the PHP runtime carries opcache/mock state/FFI handles into the fork and tests hang silently (PHPUnit produced zero output for minutes). Spawn a small fixture PHP script (e.g. `tests/Foo/_fixtures/runner.php`) via `proc_open()` instead and drive its stdin/stdout pipes from the test.
- **[pattern]** When testing PTY-spawning code (`InProcessTransport`, `sugar-pty` consumers), guard tests with `requirePtySyscalls()` that skips on missing ext-ffi / ext-pcntl / unreadable `/dev/ptmx` — these are non-negotiable host requirements and CI must skip cleanly rather than fail.
- **[gotcha]** `Pty::read()` distinguishes `null` (timeout / no data yet) from `''` (EOF) — treat them differently. The pump loop's master-side reader should keep polling on `null`/`''` and only exit when the child has exited; do not bail on a single empty read or you'll race child output.
- **[gotcha:linux-no-auto-sighup-on-master-close]** Closing the PTY master in PHP/Linux does NOT auto-deliver `SIGHUP` to the slave-side child via lost-ctty (BSD-style behaviour I assumed). Children that ignore STDIN EOF (`sleep`, daemons, anything not reading stdin) keep running until reaped. The teardown sequence that actually works on Linux: (1) on stdin EOF / EPIPE / pump exit, send `SIGHUP` explicitly via `$child->kill(SIGHUP)`, (2) wait ~200 ms for graceful exit, (3) `$child->kill(SIGKILL)` if still alive, (4) close the PTY master (in a nested `finally`, so it runs even if `kill()` throws), (5) `child->wait()` reaps. Use `Contract\Child::kill()` (or `SugarCraft\Pty\Libc::kill()` for a bare pid, as `signalChild()` does), never a `function_exists('posix_kill')` guard: `Libc::kill()` falls back to libc kill(2) over FFI, so ext-posix is optional, while the guard silently skipped the whole teardown on hosts without ext-posix. Without the explicit kill, `wait()` blocks for the child's natural duration (5+ seconds for `sleep 5`) instead of the expected sub-second teardown. Canonical implementation in `InProcessTransport::runChild()`'s finally block.
- **[env]** Always wrap potentially-blocking `vendor/bin/phpunit` invocations with `timeout 60` (or longer) when developing PTY/IPC code — a hung pump loop produces zero output, no error, and you can't tell a hang from a slow test without the timeout.
- **[convention]** New i18n strings for a sugar-ssh-server error message must land in `lang/en.php` keyed under a dotted namespace (`transport.bad_stdin`, `bubbletea.bad_factory`, etc.) and looked up via `Lang::t('namespace.key')` — do not throw raw English strings from PHP.
- **[convention]** When `Session->cols`/`->rows` are 0 (ForceCommand deployments without COLUMNS/LINES set), fall back to 80×24 before passing to `Pty::spawn()` — caveat 5 in `plans/plan-sugar-ssh-server-pty.md`. A 0-width PTY confuses curses-based clients.
- **[gotcha]** Tests that signal a `proc_open()`-spawned PHP supervisor (e.g. driving SIGWINCH into `InProcessTransport`) are racy if you `usleep(150_000)` to wait for "child has started". PHP cold-start + autoloader + `Pty::spawn` can run 200–400 ms in CI, so the supervisor's signal handler is sometimes installed AFTER the test's `posix_kill(...,SIGWINCH)` — losing the first SIGWINCH entirely and only the post-mutation state is observed. Fix pattern: poll the child's side-effect file (e.g. an `stty size` log) until the FIRST baseline sample lands, then mutate state + signal, then poll for the post-state sample. Never use a fixed sleep as the synchronisation primitive in signal-driven tests.
- **[gotcha]** Manual signal-delivery debugging via `timeout 3 php fixture.php ... & SUP_PID=$!; kill -WINCH $SUP_PID` does NOT reach the supervisor — `kill` targets the `timeout` wrapper PID, not the inner PHP process, and `timeout` does not forward arbitrary signals. Drop the `timeout` wrapper (or pull the inner PID from `pgrep -P $SUP_PID`) when reproducing signal-handling bugs at the shell.
- **[gotcha]** `gh pr merge <n> --merge --delete-branch` immediately after `git push` of a follow-up commit can fail with `GraphQL: Pull Request is not mergeable` — GitHub's mergeability check hasn't re-evaluated yet. Wait a few seconds and retry the same `gh pr merge` call; do not switch to `--admin`, force-push, or rebase as a workaround.
- **[pattern:context-propagation]** When adding a `Context` parameter to an existing `Middleware::handle()` signature, update ALL anonymous middleware classes in tests AND all `Transport::run()` implementations simultaneously — the new Context is always the first parameter and `$next` closure always takes `(Context, Session)`. A partial update (middleware updated but transport not updated, or vice versa) causes type errors at runtime.
- **[pattern:channel-msg-dispatch]** SSH channel messages (pty-req, window-change, shell, exec, signal, env, break — RFC 4254) are dispatched through a `ChannelHandler` interface rather than handled inline in `InProcessTransport`. The 7 concrete Msg classes are all `final` and extend a common `ChannelMsg` base — new message types can be added by subclassing `ChannelMsg` and adding a handler method to `ChannelHandler`. The `DefaultChannelHandler` is the composition root for `ChildSpawner` — it calls `$spawner->runChild()` on shell/exec, not the transport.

- Lang class now extends `SugarCraft\Core\I18n\Lang` — `t()` method inherited from base; NAMESPACE and DIR are the only per-lib constants.
- **[rule:step-29]** SugarSshServer performs NO terminal-capability probing — sugar-colorprofile is not a dependency and nothing here calls `TerminalProbe`. If capability probing is ever added, route it through a terminal probe (handling `\Throwable` with lowest-common-denominator fallback) instead of raw `getenv()`/terminfo reads. Clarification that stays true: Session::fromEnvironment() reads SSH env vars (TERM, SSH_CONNECTION, etc.) as session METADATA — that is not capability probing and needs no routing.
- **[pattern:exit-status-plumbing]** `Transport::run():int` reports the child's exit code (0 when no child ran; machinery failures raise), `Server::serve():int` forwards it, and ForceCommand callers `exit($server->serve())` so the child's status rides sshd's channel-close → client `ssh` exit. Middleware that needs the spawner declares `implements Middleware, TransportAware` — the transport injects itself via the interface (`instanceof`), never `method_exists`.
- **[pattern:atomic-json-sidecar-lock]** A lock taken on a file that is later *replaced* is a lock on an unlinked inode. `RateLimit` used to `fopen('c+')` + `flock(LOCK_EX)` the bucket-map path and then publish through `AtomicJsonFile` (temp + rename): the first writer's rename moves the path to a new inode, so every sibling already blocked in `flock` wakes holding a lock over a file that no longer lives at that path, reads the stale pre-rename content through its own fd, and republishes it. Six parallel connects against `burst: 3` all got in (audit K2). Correct shape: hold the decision lock on a STABLE sidecar (`<state-path>.lock`, opened `'cb'` so it is never truncated, `chmod 0600`) across the whole read-decide-publish cycle, and let the payload stay atomic-rename published. `AtomicJsonFile::write()` takes its OWN hidden `.<basename>.lock` internally, so a decision lock on the payload's inode would self-deadlock inside the write even if renaming were not involved — use a differently named sidecar. Pin the invariant two ways: inode identity (sidecar stable, payload changes across publishes) and a `proc_open` barrier of siblings released together (accepts must equal burst).
- **[convention:client-visible-stderr]** Under `ForceCommand`, the child's fd 2 is SSH *extended-data* — it goes to the connecting client, not to journald. Anything a middleware writes to `$stderr` (rate-limit degradation notices, auth refusals) is user-facing text on an unauthenticated path: never echo an absolute path or internal posture detail into it. The corollary for a *logger*: a middleware whose default sink is 'the process stderr' is a middleware that mails the user their own audit trail and keeps nothing. `Logger` now resolves the sink instead of assuming it — `$SSH_SERVER_LOG` when set, explicit `Logger::toFile()` / `toStream()` / `toStderr()` factories, and a public `target()` so the boot sequence can log what it actually chose. Stamp the mode (0600) only on files YOU create; leave a pre-existing file's mode alone or you break a deliberate rotation setup.\n- **[pattern:allowlist-pairing]** Two independent allowlists are a cross product, never a pairing. `Auth` had `users` and `keyFingerprints` checked as separate predicates, so any listed user could log in with any listed key (audit K4 — bob presenting alice's key authenticated AS alice). Where an authorisation decision must bind *subject* to *credential*, take one map (`name => list<credential>`) and refuse a name with no entry; keep the flat lists only as additional narrowing gates and say out loud in the docblock + README + admin guide that they are uncorrelated. Compare credential material with `hash_equals()` over every entry rather than `in_array()`, which returns on the first hit and makes list position measurable. Pin the shape twice: a documentation-bearing test that asserts the cross product still admits (so it cannot be "fixed" silently), and refusal tests per pairing case.
