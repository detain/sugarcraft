Composite overlay views (modals, tooltips, toasts) on top of a base TUI frame. Render your models first, then let the compositor handle positioning, backdrop dimming, z-ordering, animated transitions and click-outside hit-testing.

Install

composer require sugarcraft/sugar-overlay

Quickstart

use SugarCraft\Overlay\{Position, Veil, VeilStack};

$baseView  = "underlying text\nmore underlying\ntext underneath";
$modalView = "[modal]";
$tooltip   = "Click to dismiss";

$veil = Veil::new()->withBackdrop(40);   // 40% dim — 60% brightness remains

// Composite a foreground string centered over a background string
echo $veil->composite($modalView, $baseView, Position::CENTER, Position::CENTER);

// Layer several overlays by z-index
$stack = VeilStack::new()
    ->add(Veil::new()->withContent($modalView)->withZIndex(1))
    ->add(Veil::new()->withContent($tooltip)->withZIndex(2)
        ->withPosition(Position::TOP, Position::RIGHT));
echo $stack->compositeAll($baseView);

Concepts

A veil is an immutable overlay description. It holds the foreground content, the anchor and offset, the backdrop dimming, the z-index and the optional animation. Veil::composite() takes a foreground string, a background string and the anchor, and returns one frame string. Nothing is drawn to a terminal. The host writes the frame.

The compositor works on cells, not bytes. ANSI and zone-marker envelopes take zero columns, and wide glyphs count as two. VeilStack layers several veils by ascending z-index. The shared RenderSession remembers the last full frame, so a redraw emits only the cells that changed. Because the session belongs to the veil, a program should keep one veil in its model rather than building a new one on every paint.

Tasks

  • Center a modal over a dimmed background. Call Veil::centered($modal, $base, 50), or build a veil with withBackdrop(40) and call composite() with Position::CENTER for both axes.
  • Stack a tooltip above a modal. Add each veil to a VeilStack with withZIndex(), then call compositeAll(). Higher z-indexes paint on top.
  • Animate an opening. Set withAnimation(AnimationKind::SLIDE) and call animate($fg, $bg, ..., $progress) on each tick, with progress from 0 to 1. Pass withReducedMotion(true) to jump straight to the settled frame.
  • Dismiss on a click outside the overlay. Mark interactive text with mark(), composite the frame, pass the rendered frame to scan(), and call isClickOutside($mouseMsg) on the returned veil. The zones survive later with*() calls.
  • Show text from users or the network. Pass it to withUntrustedContent(), which neutralizes control characters, forged zone sentinels and live OSC-8 links at set time. Raw withContent() and composite() payloads pass through verbatim.

What's in the box

PositioningNine anchors — Top, Right, Bottom, Left, Center and the four corners — plus X/Y offsets in cells (columns/rows).
Backdrop dimmingTruecolor opacity blend (0–100): every non-empty background line is wrapped in a computed dim pen during assembly (the blend does not compound across stacked veils — the first dim to touch a cell governs — and the pen assumes a light default foreground: on a terminal that renders dark text, the gray pen brightens that text instead of dimming it).
Animated transitionswithAnimation() + animate(…, $progress): SLIDE enters from the anchored edge, SCALE reveals lines from the center outward, and FADE brightens the overlay in from black through a truecolor gray pen (terminals cannot alpha-blend), returning the original bytes at full opacity. Progress is clamped to 0–1 and the scrim ramps with the animation; withReducedMotion() makes any progress emit the settled frame in one shot for hosts reading the platform preference (sugar-colorprofile's Probe::reducedMotion()).
VeilStackOrdered collection of veils rendered by ascending z-index; maxZIndex() / minZIndex() return null for an empty stack, since 0 is a real z-index.
Click-outside dismisswithClickOutsideDismiss() + scan() / isClickOutside() via sugar-mouse zones. The scanned zones travel with the veil across later with*() calls, so a click is judged against the frame that was on screen.
Buffer diffingcomposite() diffs against the previous frame and emits only changed cells. An empty background returns the overlay itself as the frame, and extended color operands saturate before any arithmetic runs: 38;2;r;g;b components and 38;5;n palette indices clamp to 0–255 each, so a hostile 38;5;300 cannot push the grayscale-ramp formula (38;5;232-255 is the grey ramp, not the 6×6×6 color cube) past the 0xRRGGBB range the cell model stores.
Border chromewithBorder() wraps veil content in a terminal border; when a border is configured the chrome applies to every composited frame — withAutoSize() is a deprecated no-op retained for source compatibility.
Untrusted contentwithUntrustedContent() sweeps payloads at set time: control characters, forged U+E000/U+E001 zone sentinels and live OSC-8 links are neutralised (CRLF/CR folded to LF, TAB to its measured four cells), while sugar-image's U+E002 marker band passes through untouched. Backgrounds are as attacker-reachable as foregrounds — both paths are documented trust boundaries. Raw withContent() and composite() payloads pass through verbatim — sweep hostile frames yourself with sugar-core Sanitize::untrustedForMarkedFrames() before mark(): the sweep strips every U+E000/U+E001 sentinel, legitimate zone markers included, so order matters — sweep, then mark, then render.

Accessibility

  • The keyboard half is yours, the geometry is not hidden — sugar-overlay ships no key handling by design: bind Esc/Enter to the same dismiss action isClickOutside() answers and keep focus movement inside sugar-focus / sugar-navstack. The clone returned by scan() publishes every zone's rect (zoneRects() / lastZoneRect($id)) in the same 1-based cell space hit() uses, so a focus ring and a click agree on one geometry by construction.
  • Announce with text, not chrome — when an overlay opens, the title line you emit is the screen-reader cue; a withBorder() frame only adds box-glyph noise for terminal readers and is a sighted-user affordance — users who want the box gone have Border::hidden() and Border::ascii() from sugar-style.
  • NO_COLOR is the host's choice — the renderer deliberately does not consult it, because the dim pen is color; a host that honors it emits the backdrop pre-striped and runs with withBackdrop(0) and no animation.
  • Reduced motion — withReducedMotion() makes animate() paint the settled frame in one shot (no dim sweep, no travel; the scrim ramps with the animation otherwise). The fleet-standard read is sugar-colorprofile's Probe::reducedMotion(), but it sees only environment variables — offer an in-app setting as well.

Keys and input

sugar-overlay has no key handling, by design. The host binds Esc and Enter to its own dismiss action, and it uses isClickOutside() for pointer dismissal. Mouse input comes from sugar-mouse, and scan() builds the zones. For focus movement, use sugar-focus or sugar-navstack. zoneRects() and lastZoneRect($id) publish each zone's rectangle in the same 1-based cell space that hit() uses, so a focus ring and a click agree on one geometry.

Theme, backdrop and color

The backdrop is the only color the compositor adds on its own. It dims each non-empty background line with a computed pen. The dimming does not compound across stacked veils, because the first dim to touch a cell governs. The pen assumes a light default foreground. On a terminal that renders dark text, the gray pen brightens that text instead, so set withBackdrop(0) there.

The renderer does not read NO_COLOR, because the dim pen is itself color. A host that honors NO_COLOR should pre-strip the backdrop, call withBackdrop(0) and skip animations. Borders and styles come from sugar-style, and Border::hidden() or Border::ascii() give a frame with no box glyphs.

Troubleshooting and FAQ

  • The background looks too dark, or dark text got brighter. The dim pen assumes a light default foreground. On a dark-text terminal, use withBackdrop(0) or pre-dim the background yourself.
  • A single-line overlay does not come back as raw text. It is placed at its anchor over the single-line background, unlike the upstream raw passthrough. The README's Divergences section records this on purpose.
  • An empty foreground still dims the screen. The backdrop ramp applies to every row, so an empty overlay over withBackdrop(n) with n above zero yields a dimmed canvas. This matches the README's divergence note.
  • isClickOutside() throws. Dismissal is on, but scan() has not run on the frame that is on screen. Call scan() on the rendered frame first.
  • scan() throws on duplicate zone ids. Each mark() id must be unique within one frame. Rename one of the marks.
  • VeilStack::add() throws OverflowException. A stack holds at most 256 layers. Remove stale veils with removeWhere() or clear().
  • Redraws show ghost cells after a cursor desync. Call resetPreviousFrame() to force a full frame, or withoutSession() for a full frame from a new session.

Upstream mapping

The surface mirrors the Go antecedent, rmhubbert/bubbletea-overlay. Two branches of its Composite() are deliberately not mirrored, and the README's Divergences section pins both with CompositeDeltaLawTest.

Architecture

The public classes are Veil, which is the immutable overlay description, and VeilStack, the ordered collection. RenderSession remembers the last frame and decides what to emit. It owns no terminal, and sugar-cellbuffer encodes the delta. MarkedFrame is the width algebra for one line, and it is the shared knife behind clipping and the security sweep. SgrWalker walks the SGR and OSC runs of a line, so their envelopes cost zero columns. Lines and Cluster split and step through text. Position carries the nine anchors, and the Animation namespace holds the Fade, Scale and Slide transitions.

The lib builds on the monorepo's cell model. sugar-cellbuffer provides the diff buffer, sugar-mouse provides the hit-testing scanner and marks, sugar-spring provides the cubic-bezier easing, sugar-style provides border and style chrome, and sugar-core provides the width measurement.

Changelog and versioning

The package ships no CHANGELOG file. The commit history of sugar-overlay/ in the monorepo is the record of changes. withAutoSize() is a deprecated no-op that remains for source compatibility.
