sugar-spring is a pure-math animation engine. It provides damped harmonic springs for smooth motion and controlled overshoot, a Newtonian projectile integrator for arcs and particle fields, CSS-compatible easing and cubic-bezier curves, and spring chains and collections that drive many values at once. It has no terminal I/O, no ReactPHP dependency and no render path: values go in, values come out, and your frame loop decides when to paint. The spring core mirrors charmbracelet/harmonica, the Go library for the same job, and the damped-oscillator math follows Ryan Juckett's spring physics articles.

Install

composer require sugarcraft/sugar-spring

Requires PHP 8.3 or newer. The package depends on sugarcraft/sugar-core and sugarcraft/sugar-colorprofile, and both track dev-master, so the plain command resolves only when dev stability is allowed. Pin the package with composer require sugarcraft/sugar-spring:@dev, or set minimum-stability to dev with prefer-stable set to true in the consuming manifest. At runtime the library reads one thing from sugar-colorprofile: the reduced-motion probe.

Quickstart

use SugarCraft\Spring\{Spring, Projectile, Point, Vector};

$spring = new Spring(
    deltaTime:        Spring::fps(60),
    angularFrequency: 6.0,
    dampingRatio:     1.0,    // critical: fastest approach, no overshoot
);

$pos = 0.0;
$vel = 0.0;
$target = 100.0;
$frame = 0;
while (!Spring::settled($pos, $vel, $target) && $frame < 600) {   // stop on settled(), not a fixed count
    [$pos, $vel] = $spring->update($pos, $vel, $target);
    $frame++;
}

$ball = Projectile::new(
    deltaTime:    Spring::fps(60),
    position:     Point::zero(),
    velocity:     new Vector(5.0, 10.0),   // +y is up: Projectile::gravity() is (0, -9.81, 0)
    acceleration: Projectile::gravity(),
);
for ($i = 0; $i < 60; $i++) {
    $ball = $ball->update();              // update() returns a NEW Projectile: reassign it
}

The quickstart prints nothing. Every value it computes lives in $pos, $vel and $ball, and your render code reads them. The three examples shipped with the package print what the same maths looks like (see Examples).

Concepts

A Spring is an immutable value. Its frame time (deltaTime), angular frequency and damping ratio are fixed at construction. update($pos, $vel, $target) returns the next [$pos, $vel] pair and keeps no state of its own. The caller owns the state and the clock: call update() once per frame, at the rate the spring was built for, and the motion tracks wall-clock time. The same applies to Projectile, whose update() returns a new projectile.

The frame time is baked in

Spring::fps(60) returns 1/60 of a second. A spring built with it advances one 60th of a second per update() call, so a loop that runs at 30 Hz stretches the animation to twice its length. Replays stay deterministic if you record tick counts rather than wall-clock time. For a real loop that measures frame time, rebuild the spring with the measured deltaTime each frame; coefficient setup is cheap, about a microsecond.

Done means settled, not a frame count

Spring::settled($pos, $vel, $target, $threshold) is the stop predicate. It needs the position within the threshold (default Spring::SETTLING_THRESHOLD, 1e-4) and the velocity below it. A position-only check gives false positives on under-damped springs, which cross the target at full speed and come back. A frame budget is only a safety cap: the Molasses preset alone needs 439 frames to settle at 60 fps.

Y-up coordinates

Projectile gravity points down the Y axis, and increasing Y means up the screen. Projectile::gravity() returns (0, -9.81, 0) and Projectile::terminalGravity() returns (0, -53, 0). Terminal renderers usually grow downward, so Projectile::gravityYDown() and terminalGravityYDown() keep the same magnitudes with the sign flipped.

Tasks

Animate a value one frame at a time

Step the spring once per paint and convert the position to a cell only when you draw:

use SugarCraft\Spring\Spring;

$spring = new Spring(Spring::fps(60), 6.0, 1.0);
$pos = 0.0;
$vel = 0.0;

// One update and one paint per frame. Never run a settle loop inside a frame.
[$pos, $vel] = $spring->update($pos, $vel, 100.0);
$cell = (int) round($pos);   // the integer cell to draw this frame

If $cell is unchanged from the previous frame, skip the repaint. Pass a cell-sized threshold such as 0.5 to settled() when the consumer renders at cell resolution, because a spring usually stops changing the frame well before it stops settling at 1e-4.

Pick a feel with a preset

use SugarCraft\Spring\{Spring, SpringPreset};

$spring = Spring::fromPreset(SpringPreset::Wobbly);                       // 60 fps by default
$slow   = Spring::fromPreset(SpringPreset::Molasses, Spring::fps(30));    // explicit frame time

The five presets and their measured settle times are in Configuration.

Stagger stages with a spring chain

A SpringChain runs one stage at a time. Each stage is a [Spring, position, velocity, target] tuple, and the next stage starts when the active one settles:

use SugarCraft\Spring\{Spring, SpringChain, SpringPreset};

$chain = (new SpringChain([]))
    ->withStage(Spring::fromPreset(SpringPreset::Gentle), 0.0, 0.0, 50.0)
    ->withStage(Spring::fromPreset(SpringPreset::Wobbly), 0.0, 0.0, 100.0)
    ->withStage(Spring::fromPreset(SpringPreset::Stiff),  0.0, 0.0, 75.0);

while (!$chain->isComplete()) {
    $chain = $chain->tick();              // reassign: tick() returns the advanced chain
    $positions = $chain->currentPositions();
}

Build the full stage list before the first tick(). withStage() restarts the new chain at stage 0, so calling it mid-run throws the progress away.

Drive many named values with a spring collection

use SugarCraft\Spring\{Spring, SpringCollection, SpringPreset};

$group = (new SpringCollection())
    ->withSpring('menu',  Spring::fromPreset(SpringPreset::Stiff),    0.0, 0.0, 40.0)
    ->withSpring('panel', Spring::fromPreset(SpringPreset::Molasses), 0.0, 0.0, 90.0);

$frame = 0;
while (!$group->settled() && $frame < 600) {
    $group = $group->tick();              // a new collection; every member advances
    $frame++;
}

echo sprintf("menu=%.2f panel=%.2f\n", $group->position('menu'), $group->position('panel'));

Read values with position($id), target($id), velocity($id) and all(). Ids that are not in the collection throw an OutOfBoundsException that names the id.

Re-aim a projectile between frames

use SugarCraft\Spring\{Point, Projectile, Spring, Vector};

$p = Projectile::new(Spring::fps(60), Point::zero(), new Vector(5.0, 10.0), Projectile::gravity());
$p = $p->withVelocity(new Vector(-2.0, 4.0));    // a new Projectile with one field swapped
$p = $p->update();                              // reassign: update() never mutates the receiver

Use a CSS-style timing curve

use SugarCraft\Spring\Easing\{CubicBezier, Easing};

$curve  = CubicBezier::easeOutCubic();        // control points 0.22, 0.61, 0.36, 1.00
$custom = new CubicBezier(0.25, 0.10, 0.25, 1.00);
$named  = Easing::CubicOut;                   // the same family as an enum case

$a = $curve->ease(0.5);
$b = $custom->ease(0.5);
$c = $named->ease(0.5);

Honour reduced motion in a non-spring curve

Projectile, Easing and CubicBezier are pure functions of time with no target to snap to, so they ignore the reduced-motion signal. Gate them in the application by jumping to the end of the motion when the user asks for less of it:

use SugarCraft\ColorProfile\Probe;
use SugarCraft\Spring\Easing\Easing;

$frame = 12;                                            // 12th frame of a 60-frame motion
$t = Probe::reducedMotion() ? 1.0 : $frame / 60.0;      // t = 1.0 is "already there"
$progress = Easing::CubicOut->ease($t);

Spring presets

Spring::fromPreset() builds a spring at 60 fps from one of five hand-tuned presets. The presets are not literal UIKit values. They were tuned against the react-spring-era tables, and every one is under-damped, so each overshoots a little. The settle times below were measured for a move from 0 to 100 at the default 1e-4 threshold:

PresetTensionFrictionMassζOvershootSettle at 60 fps
Gentle1001010.50about 16%174 frames (about 2.9 s)
Wobbly1801210.45about 21%141 frames (about 2.4 s)
Stiff5002010.45about 21%94 frames (about 1.6 s)
Slow50610.42about 23%292 frames (about 4.9 s)
Molasses30410.37about 29%439 frames (about 7.3 s)

No critically damped preset ships. Build one with dampingRatio: 1.0, or with new SpringConfig(...) and a friction of 2 * sqrt(tension * mass).

SpringConfig physical units

SpringConfig takes tension, friction and mass, which must all be finite and greater than zero, and derives the two numbers Spring consumes:

angularFrequency = sqrt(tension / mass)
dampingRatio     = friction / (2 * sqrt(tension * mass))
use SugarCraft\Spring\SpringConfig;

$config  = new SpringConfig(tension: 180.0, friction: 12.0, mass: 1.0);
$spring  = $config->spring();                                   // 1/60 s frame time
$pinned  = $config->spring(reducedMotionOverride: true);        // always snaps, env ignored
echo $config->angularFrequency;                                 // 13.416... (public readonly)

Extreme but finite triples are refused when the derived values are not finite, not positive or numerically degenerate. Past a damping ratio of about 226.5, the two over-damped roots collapse to one number and the spring would freeze.

Reduced-motion environment

VariableValueEffect
REDUCE_MOTIONunset, 0, false, no or off (any case)Off. Springs animate normally
REDUCE_MOTIONany other non-empty value, 1 includedOn. Springs snap to target
PREFERS_REDUCED_MOTIONsame rules as aboveConsulted after REDUCE_MOTION. Either variable reading on is enough, so an off value in one never cancels an on value in the other

The environment is read once per process, on the first update() that needs it, and the answer is remembered. Changing the variable later in the same process does not change behaviour until Spring::resetReducedMotionProbe() is called. A per-spring reducedMotionOverride is checked on every call and always wins over the memo. The lookup goes through SugarCraft\ColorProfile\Probe::reducedMotion(), and no terminal query or accessibility daemon is consulted.

Examples

The three examples live in examples/. None takes arguments, and each runs from the package root after composer install.

examples/spring.php

Drives the same target through three damping ratios and prints the rows side by side (see Quickstart for the output). Under REDUCE_MOTION every update() snaps to target, so the example prints flat lines and says so once.

php examples/spring.php

examples/projectile.php

Traces one two-dimensional arc over its first 90 frames (1.5 s at 60 fps). The initial velocity points up and to the right, and gravity bends it over. The example plots those samples as an ASCII curve, and the plot stops before the apex, so it shows only the rising half of the arc. Projectile ignores the reduced-motion signal by design, and the example prints one line when the variable is set.

php examples/projectile.php

examples/particle.php

Spawns 80 projectiles from the origin, each with a randomised velocity and a small position offset, runs 60 frames under Y-up gravity, and plots every frame position of each particle into one grid. The random generator is seeded with mt_srand(42), so the output is the same on every run.

php examples/particle.php

Troubleshooting

The constructor throws "dampingRatio must be > 0"

A damping ratio of zero is an oscillator that never settles, and a negative one diverges. Use a value above zero. 1.0 is critically damped and the fastest approach without overshoot.

The animation runs too fast or too slow

The frame time is fixed when the spring is built. If the loop calls update() at 30 Hz but the spring was built with Spring::fps(60), the motion takes twice as long. Build the spring with the rate you really call it at, or rebuild it each frame with the measured deltaTime (clamped, so a stall cannot teleport the value).

Values jump straight to the target

REDUCE_MOTION or PREFERS_REDUCED_MOTION is set to a value other than 0, false, no or off. This is deliberate. Pin the spring with reducedMotionOverride: false if the motion carries information the end state does not. Call Spring::resetReducedMotionProbe() if the variable changed after the first probe in the same process.

The chain or the projectile never moves

SpringChain::tick(), SpringCollection::tick() and Projectile::update() return a new value. Assign it back ($chain = $chain->tick();). Discarding the return value leaves the receiver untouched, and the loop replays the same frame forever.

A loop never settles on a small threshold

settled() needs both the position and the velocity within the threshold, and the default 1e-4 is finer than one terminal cell. Pass 0.5 when you render at cell resolution, and keep a frame cap such as $frame < 600 as an escape hatch.

normalize() throws a RuntimeException

Vector::normalize() has no honest answer for a zero-length or overflowed vector, so it throws RuntimeException, not InvalidArgumentException. Check length() first, or catch RuntimeException around the call.

Architecture

Pure values, no I/O

sugar-spring has no event loop, no ReactPHP, no ext-pcntl and no output path. Each step is a function of its inputs. update() takes (pos, vel, target) and returns a new pair, so a spring can be shared between several frame loops without any coordination.

Immutable state with checked doors

Constructors refuse bad input, and the with*() builders go through the same checks. A value that overflows to infinity mid-simulation is refused by the constructor that would have stored it, so a bad state never reaches the caller.

The reduced-motion memo

The environment is read at most once per process, and the result is memoised in a static. The per-spring override is evaluated on every call. The probe lives in sugar-colorprofile, and it is the only sugar-colorprofile call the spring path makes.

Messages in every locale

Exception messages go through SugarCraft\Spring\Lang::t(), which sits on the shared SugarCraft\Core\I18n machinery. Lookup runs exact locale, then base locale, then en, then the raw key. Set the locale once with SugarCraft\Core\I18n\T::setLocale('de').
