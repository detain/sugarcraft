A unified-diff engine the whole ecosystem can share: LCS line diffing, numbered context hunks, a GNU diff -u writer, and a scanner that numbers the rows of any patch. The engine was extracted from candy-code's BuildsUnifiedDiff trait, which now delegates to it, and the scan half of candy-code's DiffGutter also delegates here. Only the fixed-width gutter formatting stays in the app. First-party: there is no 1:1 Go counterpart.

Install

composer require sugarcraft/sugar-diff

The manifest requires PHP ^8.3 and ext-mbstring. Case folding goes through mb_strtolower(), with a byte-wise ASCII fallback for malformed input. There are no tagged releases yet, so consume dev-master.

Quickstart

use SugarCraft\Diff\Diff;
use SugarCraft\Diff\DiffOptions;
use SugarCraft\Diff\Reader\UnifiedScan;

$before = "Hello World\n";
$after  = "Hello PHP\n";
$diff = Diff::compute($before, $after);

$patchText = $diff->unified('file.txt');
echo $patchText;
// --- a/file.txt
// +++ b/file.txt
// @@ -1 +1 @@
// -Hello World
// +Hello PHP

// Options are immutable and fluent. Context width, whitespace folding and the
// GNU annotations are all opt-in.
$wide = Diff::compute($before, $after, DiffOptions::new()
    ->withContextLines(10)
    ->withIgnoreWhitespace()
    ->withNoNewlineAnnotation()
    ->withDevNullOnEmptySide());

// None of those four options changes this one-line edit, so the patch is the same:
echo $wide->unified('file.txt') === $patchText ? "same patch\n" : "wider patch\n";
// same patch

// Number the rows of an existing patch, for gutter or viewer support:
foreach (UnifiedScan::lines($patchText) as $row) {
    // $row->old, $row->new, $row->fileHeader, $row->kind (ScanRowKind enum)
}

Concepts

A diff has two sides. The old side is the removed side and sits on the left. The new side is the added side and sits on the right. Diff::compute() trims the common prefix and suffix, runs an LCS over the lines of the middle, and groups the changes into Hunks with a window of context around each one. Every row is a Line with a LineKind of Equal, Delete or Insert, verbatim text, and the old and new line numbers.

The row model is lazy. compute() materializes Line rows only for hunk bodies (changes plus context) and keeps the full operation sequence as one packed byte per row. A one-line change in a large file therefore retains hunk-sized state, not one object per input line. lines() derives the whole row sequence on demand and memoizes it. addedLines() and removedLines() count the packed bytes without building any rows.

The engine is non-visual. It emits no ANSI, draws nothing, and has no demo. Gutters, split panes and coloring are the consumer's job, and the engine supplies the numbers and the kinds those views need.

Tasks

Diff two files on disk

Sides take a raw string or a list<string>. For real files, cast the output of file_get_contents() to a string. The string channel keeps a missing final newline visible, where a file() list would report it as terminated. Pass relative paths as labels, because an absolute path renders as a//path.

$diff = Diff::compute(
    (string) file_get_contents($oldPath),
    (string) file_get_contents($newPath),
    DiffOptions::new()->withNoNewlineAnnotation(),
);
echo $diff->unified('old/file.txt', 'new/file.txt');

Render the rows side by side

SideBySideFormat::rows() pairs one diff's changed runs into [left?, right?] rows for a split viewer. fromUnified() produces the same rows from rendered patch text. Leftover removals and additions stand alone, with one half null.

use SugarCraft\Diff\Writer\SideBySideFormat;

foreach (SideBySideFormat::rows($diff) as $row) {
    $left  = $row->left?->text;    // old column, numbered $row->left?->oldNumber
    $right = $row->right?->text;   // new column, numbered $row->right?->newNumber
    // $row->isPaired() separates replacements and context from leftovers.
}

Number the rows of a patch for a gutter

UnifiedScan::lines() walks any rendered unified diff, honors each hunk's declared counts, and classifies every row with a ScanRowKind. The runnable example examples/unified-scan.php shows the output. A patch from git, GNU diff or this library works the same way.

Keep untrusted content safe

Row text is exactly what the sides held, and the engine never strips control bytes from content. A surface that paints diffs of untrusted files must sanitize or escape those bytes for its own channel. The writer protects only the path labels: a label containing a control byte, " or \ is C-quoted in the style of git's core.quotePath, so every header stays on one physical line. Scanning and pairing never re-emit input, so a multi-line element scans as one verbatim row.

Styling and markers

The engine never colors anything. Color should never carry a change alone, so every row arrives with two non-color channels. The first is a LineKind with its column-0 marker: a space, - or +. The second is, for scanned patches, a ScanRowKind that separates hunk headers, annotations and out-of-hunk prose from content. A viewer that tints rows should keep the sign column as well, because a red-versus-green difference alone fails WCAG 1.4.1. The candy-code-web DiffView renders a visible sign column from the row kind, beside its background tint: + for additions and − (U+2212, not an ASCII hyphen) for deletions.

Examples

Each example runs from a checkout after composer install.

  • examples/quickstart.php prints one change as a diff -u patch and as side-by-side rows.
  • examples/unified-scan.php numbers the rows of a built-in patch, the way a gutter does, and lists the file headers.
  • examples/file-diff.php OLD NEW diffs two files on disk. It exits 0 when they match, 1 when they differ, and 2 on a usage or read error.

Testing

composer install
vendor/bin/phpunit

Two suites compare the output against GNU diff and patch. They skip, and do not fail, when /usr/bin/diff or patch is missing. The tie-placement suite holds the honest contract: equal edit counts, and byte-exact application through patch.

Troubleshooting and FAQ

A change that only touches the final newline shows no hunk

With withNoNewlineAnnotation() off, which is the default, "a\n" against "a" produces no hunks. The behavior is intentional and kept byte for byte. Turn the option on to see the change, and read beforeHasFinalNewline and afterHasFinalNewline to surface it yourself.

Every row count is one higher than the file

A list<string> side keeps its final element even when that element is empty, so explode("\n", "a\nb\n") gives three elements where the string channel counts two. Read the file with file($path, FILE_IGNORE_NEW_LINES), or drop the trailing empty element before you pass the array in.

The same edit lands on a different line than GNU diff

On repeated content, the LCS may place an edit on another occurrence than GNU's Myers algorithm does. Both scripts are minimal and both apply cleanly. Do not pin hunk bodies to /usr/bin/diff output for repeated content. Check that the patch applies, not that it matches byte for byte.

The patch is degraded

$diff->degraded is true when a middle section exceeded maxLcsCells, and that section became one replace block. Raise the budget with withMaxLcsCells() if the output is too coarse. Large edits spread far apart in a big file can exceed the default.

Labels read as a//path

The writer prepends a/ and b/ by plain concatenation, so an absolute path gets a double slash. Pass root-relative paths. A path that already begins with a/ doubles the prefix.

Renames, mode changes and combined diffs show no content

Git's extended headers (similarity index, rename from, old mode) are not modeled. The scanner reports them as OutsideHunk rows and never as file headers. Combined diffs from git diff --cc use a different @@@ grammar, so isHunkHeader() rejects them. Diff against one parent, or pass the two texts to Diff::compute().

Architecture

The pipeline runs in four stages. First, Diff::compute() trims the common prefix and suffix and runs the LCS over the middle, within the cell budget. Second, the result is packed into one operation byte per row. Third, hunks are grouped with their context windows, and only their rows are materialized. Fourth, the writers render the hunks as text, and the scanner reads any patch back into numbered rows. Both directions share one header predicate, UnifiedScan::isHunkHeader(), so a consumer can gate boundaries without a second regex.
