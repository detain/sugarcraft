A ratatui-style constraint layout solver behind a one-method LayoutSolver interface: GreedySolver (deterministic greedy solver, extracted from sugar-style, which now delegates back through its Layout\Solver bridge) implements every constraint type, and the deprecated CassowarySolver shim delegates to it. Plus DockLayout, a center-plus-side-stacks pane geometry. Consumers: sugar-panels (compat mode), candy-code (the Dock\* surface), candy-sql (dashboard page); sugar-forms requires the package but its withConstraints() knob is dormant, and sugar-widgets does not consume it.

Install

composer require sugarcraft/sugar-constraints

Requires PHP 8.3 or newer. The package has no runtime dependencies.

Quickstart

A classic two-pane sidebar: a fixed-width rail and a content pane that takes whatever width is left. The runnable walk ships as examples/sidebar.php, which runs this split at widths 100 and 10, then a four-pane mix.

use SugarCraft\Constraints\Constraint\Constraint;
use SugarCraft\Constraints\{Direction, GreedySolver, Region};

$solver = GreedySolver::new();

$rects = $solver->solve(Region::fromSize(100, 20), Direction::Horizontal, [
    Constraint::length(24),   // 24: sidebar, 24 cells
    Constraint::fill(1),      // 76: content, the cells left
]);

Constraint tour

One 100-cell row with every constraint type. This block is a tour, not a script: no file under examples/ runs it, and the widths in its comments are what the solver returns for it.

$region = Region::fromSize(100, 20);

$rects = $solver->solve($region, Direction::Horizontal, [
    Constraint::length(20),       // 20: exactly 20 cells
    Constraint::min(10),          // 10: a floor; the Fills below take the slack
    Constraint::percentage(25),   // 25: 25% of 100
    Constraint::ratio(1, 10),     // 10: 1/10 of 100
    Constraint::fill(1),          // 12: a third of the 35 cells left (+1 rounding cell, first Fill)
    Constraint::fill(2),          // 23: two thirds of them
]);

// Max is a greedy ceiling: it grows into free space up to its cap.
$capped = $solver->solve($region, Direction::Horizontal, [
    Constraint::length(20),       // 20
    Constraint::max(15),          // 15: clamped at its ceiling
    Constraint::fill(1),          // 65: everything Max did not take
]);

solve() returns one positioned Region per constraint, in list order. The x and y offsets are absolute cell coordinates: the input region's origin is already included, so a region at x=5 returns its first box at x=5. Paint each box at its returned x and y without adding the origin again.

How it works

Each solve is a pure function of the region, the direction and the constraint list. The solver keeps no state between calls, so re-solving on every WindowSizeMsg is the intended pattern. The package places boxes in whole terminal cells and never measures text; sizing a string with CJK, emoji or combining marks is the caller's job, and sugar-core's Width::of() answers it.

The walk runs in this order. Percentage and Ratio resolve to absolute sizes, and Length plus those sizes form a fixed reservation. Min floors and Max ceilings are entered. Whatever slack remains goes to the Fill weights and to Max, which is weighted by its cap and then clamped to it. A Min takes slack directly only when the set has neither Fill nor Max; on its own it absorbs the whole span. A Max clamp hands its excess back, and a Min takes that first, ahead of Fill. Demand above supply shrinks regions proportionally. A well-constrained set then tiles the span exactly, so its widths sum to the region's size.

Rounding is lossless for well-constrained sets. Slack residue rides the first Fill, or the first Max when no Fill is present. Min-only slack rides the first Min. With neither Fill nor Max in the set, a Percentage or Ratio shortfall of at most N−1 cells is reclaimed earliest-first; with a Fill or Max, that shortfall rides the first Fill or Max along with the rest of the slack. Over-subscription truncates silently by design, because a terminal resized below its fixed panes is a normal state, not an error.

// Length(10) and Max(5) in a 100-cell span: the Max clamp hands back the rest.
$rects = GreedySolver::new()->solve(Region::fromSize(100, 20), Direction::Horizontal, [
    Constraint::length(10),
    Constraint::max(5),
]);
// widths: 95, 5

Five carve-outs keep the sum law from holding. Under-constrained fixed-only sets keep their gap, so [percentage(30)] at 100 yields one 30-cell region. Compat mode and withoutOverflowTruncation() run off-grid on overflow. A zero-weight Fill set keeps its slack. A Max-only set keeps the shortfall of its caps, so [max(40), max(40)] at 100 yields 40 and 40; adding any Length, Percentage, Ratio, Fill or Min absorbs it. Extreme-magnitude inputs past int64 ride float arithmetic. The README names all five, and the tests pin the first two.

Choosing a layout strategy

  • One content flow that sizes itself, such as paragraphs or form fields: reach for sugar-flexbox.
  • Several panes split and re-resolved on every resize: this solver.
  • An IDE-style center with vertical side stacks: the Dock\* surface, described below.

Tasks

Check whether a set fits before you paint

$demand = GreedySolver::new()->demandOf(Region::fromSize(100, 20), Direction::Horizontal, [
    Constraint::length(60),
    Constraint::length(60),
]);
// 120: above the 100-cell span, so the set cannot be satisfied whole

demandOf() sums fixed sizes exactly, resolves Percentage and Ratio under the instance's rounding policy, sums Min floors, ceilings Max caps, and counts Fill as 0. Use it when collapse must be visible. Clipping on the host side with withoutOverflowTruncation() is the other option.

Keep the default policy, or opt into compat parity

New code should use GreedySolver::new(). GreedySolver::compat() reproduces the sugar-panels distribute() splits: round-split, remainder to the last region, and non-truncating overflow. Use it only to match an existing sugar-panels golden frame.

Solve a Dock frame

use SugarCraft\Constraints\Dock\{DockLayout, Side};
use SugarCraft\Constraints\Region;

$dock = DockLayout::new('chat')
    ->withSlotAdded(Side::Left, 'files')
    ->withSlotAdded(Side::Left, 'git')
    ->withSlotAdded(Side::Right, 'term')
    ->withStackWeight(Side::Left, 0, 2, 1);      // files takes twice the rows of git

$geometry = $dock->resolve(Region::fromSize(100, 30));
$chat = $geometry->regionFor('chat');           // null when the pane is undocked or dropped
foreach ($geometry->dividerColumns() as $divider) {
    // the host paints each divider column
}

Solvers

GreedySolverDeterministic greedy solver, extracted from sugar-style. No dependencies, and no strength or priority vocabulary. Stateless, so one instance can be shared. Every constraint type is implemented here, and sugar-style routes its own splits back through it.
CassowarySolver (deprecated)The original Big-M simplex prototype never converged, so solve() raises E_USER_DEPRECATED on every call and delegates wholly to GreedySolver. Results are identical. It is kept only so existing call-sites keep working.
DockLayoutA center pane plus left and right weighted slot stacks. Stack heights are split in exact integer arithmetic, so no float decides a boundary row. resolve() never throws; below the floors it drops a side instead.

Constraint types

LengthFixed cell count. One exception: when a Max clamps in a set with neither Min nor Fill, the reclaim ladder can inflate a Length, and a Percentage or Ratio alike.
MinSoft floor of n cells. It grows when the set has neither Fill nor Max, or when a Max clamp hands it cells back ahead of Fill. It clamps proportionally when demand exceeds the span.
MaxGreedy ceiling. It takes slack up to n cells, and its clamp pass can hand cells back to the rest of the set.
FillProportional remainder. Its weight sets the share among Fill constraints. fill(0) is accepted and weightless.
PercentageAn integer from 0 to 100 inclusive, as a share of the solved-axis span. Values outside that range throw. Same reclaim exception as Length: a Max clamp in a set with neither Min nor Fill can inflate it.
Rationumerator/denominator of the span, reserved like a fixed size. It is not an aspect ratio: solve() works on one axis. Same reclaim exception as Length: a Max clamp in a set with neither Min nor Fill can inflate it.

Configuration

GreedySolver takes six named constructor arguments. The zero-argument new() keeps these defaults.

OptionTypeDefaultEffect
roundSplitboolfalseUse round() instead of floor() for Percentage and Ratio sizes. withRoundSplit() sets it.
remainderToLastboolfalseRounding remainder goes to the last region instead of the first. withRemainderToLast() sets it.
truncateOverflowbooltrueWhen fixed demand exceeds the span, shrink regions proportionally. false keeps full base sizes, off-grid. withoutOverflowTruncation() and withOverflowTruncation() set it.
minShareint0Cells reserved per unplaced region before the Fill split. 0 leaves the floor off. Negative values throw.
reserveGapint0Cells added per placed region while the min-share floor is engaged, for inter-region spacing. Negative values throw.
reserveLeadint0Cells reserved before the first region while the min-share floor is engaged, as a leading margin. Negative values throw.

The dock defaults come from DockLayout::new(). The center pane id is 'center' unless you pass another. Each side starts at a 1/3 column share, with a 24-column center floor and a 20-column side floor, and the divider is one column. withMinimums() changes the floors, and withColumnShare() changes the shares.

Troubleshooting

  • solve() throws "Constraints must be a list". The array is keyed or sparse. Pass a sequential list, for example by calling array_values() on it.
  • A static call through the interface name is a fatal error. LayoutSolver declares only the instance method solve(), so a static factory such as greedy() called on the interface name fails with Error: Call to undefined method, followed by the interface and method name. Call a concrete class such as GreedySolver::greedy() or GreedySolver::new().
  • Sizes sum to less than the span. One of the carve-outs applies. For example, [percentage(30)] at 100 yields 30, and [max(40), max(40)] at 100 yields 40 and 40. Add a fill(1) to absorb the rest, or check the set with demandOf().
  • Sizes sum to more than the span. The set was solved with compat mode or withoutOverflowTruncation(). [length(60), length(60)] at 100 yields 60 and 60 under those settings, and 50 and 50 under the default policy.
  • E_USER_DEPRECATED on every solve. The call uses CassowarySolver, which delegates to GreedySolver. Switch to GreedySolver::new().
  • A dock side disappears on a small frame. The frame is below the floors, so resolve() drops that side. Resize the frame, or lower the floors with withMinimums().
  • percentage(150) throws. Percentage takes an integer from 0 to 100. Use ratio() for other fractions.

Upstream mapping

The layout model follows ratatui's constraint system. Badros, Borning and Stuckey's Cassowary paper is the historical source of the deprecated shim, but this port implements neither the simplex nor the strength and priority vocabulary. The port mapping is in docs/MATCHUPS.md, where the SugarConstraints row carries its port status.

Use it for

  • Extracted from sugar-style: sugar-style's Layout\Solver bridge now delegates back through this package.
  • Live pane splits: sugar-panels (compat mode), candy-code's Dock\* surface, and the candy-sql dashboard. sugar-forms requires it, but its constraint knob is dormant, and sugar-widgets does not consume it.
  • Swap solver without breaking call-sites: LayoutSolver (solve() alone; construction lives on the concrete classes) is the only public contract.
