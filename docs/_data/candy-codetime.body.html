Tracks edit-time per project / language to a local append-only JSONL file — or to an optional embedded SQLite backend via --backend=sqlite (no cloud, no database server either way) — and renders a SugarCharts-driven dashboard. Editor integrations can record heartbeats with the push CLI subcommand; the dashboard reads whichever backend you picked.

Install

composer require sugarcraft/candy-codetime

A signed single-file build ships with every release: download candy-codetime.phar with its .sha256 (and minisig) sidecars, verify the digest, and run php candy-codetime.phar on stock PHP — the app never rewrites its own archive and there is no self-update channel, so an upgrade is a new download. Inside an archive --version prints the release build stamp (the frozen vendor/ would otherwise report the build root's dev guess), and SOURCE_DATE_EPOCH keeps rebuilds of a tag byte-stable.

Quickstart

# Editor plugin / cron / git hook pushes a heartbeat:
vendor/bin/candy-codetime push sugarcraft php src/App.php 60

# Open the dashboard:
vendor/bin/candy-codetime

# Override the data dir:
CANDY_CODETIME_DIR=/var/data/codetime vendor/bin/candy-codetime

Formerly shipped as sugar-tick: two separate compat mechanisms remain. Any SUGARTICK_* env export is imported under the CANDY_CODETIME_* name on every launch (new name wins, each import prints a deprecation notice on stderr). The one-time data-directory move from ~/.local/share/sugar-tick runs on first launch only, and only when CANDY_CODETIME_DIR is unset — an explicit directory outranks the migration.

What's in the box

Heartbeat schema{time, project, language, file, duration, tags} — JSONL, one beat per line; tags is never set by the CLI; a plugin-written tag is honored on read and export.
Per-day filesStorage is one YYYY-MM-DD.jsonl per day — append-only, easy to ship to cold storage.
Top projects + languagesTwo ranking panes side-by-side from 62 columns up (they stack below that), sorted by total time descending.
Daily timelineSugarCharts Sparkline driven by one bucket per day, shown in minutes.
Window navigation← / → shift the 7-day window one day per press; r reloads.
Milestonesmilestone add|list markers — sqlite-only, and the dashboard never shows them.
Pure foldingStats::compute is total-input deterministic — every dashboard test runs against fixed beats.
