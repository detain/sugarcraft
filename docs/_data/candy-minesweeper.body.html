CandyMinesweeper is Minesweeper for the terminal, built on the SugarCraft stack. It has a customisable board, an iterative flood-fill, win and loss detection, vim-style movement, mouse support, a mid-game save and resume, opt-in statistics and a 16-locale interface. It is a PHP 8.3+ port of the design of maxpaulus43/go-sweep, a Go game in the Charm ecosystem. The game logic lives in a pure Board class, so every reveal can be tested and driven without a terminal.

Install

composer global require sugarcraft/candy-minesweeper
candy-minesweeper                                # default 10x10 board, 12 mines

Requires PHP 8.3 or newer with ext-mbstring and ext-intl. The Composer path enforces both through sugar-core. The standalone phar installs nothing through Composer, so the binary checks the two extensions at boot and exits with status 1 and a named message if either is missing. On Debian or Ubuntu the packages are php8.3-mbstring and php8.3-intl.

A project-local install works through vendor/bin/candy-minesweeper. From a clone of the monorepo, run composer install inside candy-minesweeper/ and then ./bin/candy-minesweeper.

wget https://github.com/detain/sugarcraft/releases/download/candy-minesweeper/latest/candy-minesweeper.phar
sha256sum -c candy-minesweeper.phar.sha256    # verify the digest
php candy-minesweeper.phar --version

The phar channels are frozen at present. The published latest artifact predates the current sibling pins, and new publish builds are blocked fleet-wide. Until that clears, the Composer paths are the only fresh channel.

Quickstart

Start a game on a chosen board, or use the picker to pick a preset from inside the game.

candy-minesweeper --medium                # 16x16 with 40 mines
candy-minesweeper 16 10                   # 16 columns by 10 rows, 20 mines by default
candy-minesweeper 9 9 10                  # 9 wide, 9 tall, 10 mines
candy-minesweeper --pick                  # open the board picker first

The game draws the board in a rounded frame, with a status line and a help footer below it. Move the cursor with the arrow keys or hjkl, reveal with Space, and flag with f.

The game logic also runs without a terminal. examples/headless.php reveals one cell on a fixed-seed 8x5 board, prints the grid as text and then reveals every safe cell. Its output on every run is:

after revealing (0,0):
.1######
.2######
.2######
12######
########
won: no

after revealing every safe cell:
.111.1#1
.2#2.111
.2#3211.
123#2#1.
1#21211.
won: yes

In the text grid, # is a hidden cell, F is a flag, . is a revealed empty cell, a digit is the count of neighbouring mines, and * is a revealed mine. The six # left at the end are the six mines.

Concepts

The board is a grid of immutable Cell values. Each cell records whether it holds a mine, whether it is revealed, whether it carries a flag or a question mark, and how many of its eight neighbours hide mines. Board is the only place that changes that state. Every transition returns a new board: reveal(), cycleMarker() and chord().

Numbers are the clue. A revealed cell shows how many of its eight neighbours hide mines. The in-game help footer teaches that rule on its first line.

The first reveal is always safe. Mines are placed after the first click, so the clicked cell and its 3x3 neighbourhood start mine-free. At edges and corners the zone is smaller, with 6 or 4 guaranteed-safe cells. A board too dense for the full zone falls back to keeping only the clicked cell clear. The custom-board limits prevent that from happening in a normal game.

Flood-fill. Revealing a zero cell reveals its neighbours, and so on across the connected empty region. The fill is iterative and stack-based, so a large open board cannot overflow the call stack.

Winning. You win by revealing every cell that is not a mine. Flags are notes. The win check counts revealed safe cells only, so a board can be won with no flags at all. Board::isWon() compares a counter with width x height - mines, so the check is constant-time on any board size.

Markers. f cycles a cell through flag, question mark and clear. A question mark is a free memo that never counts toward the mine total and never takes part in a chord. Flagging is refused once the flags equal the mine count, and un-flagging stays free.

Chords. When a revealed number has exactly that many flagged neighbours, c, a middle-click or a double left-click reveals the remaining neighbours. The flags must match exactly. If any flag is wrong, the chord detonates on it. A revealed zero is never chordable.

The clock. The timer starts at the first successful reveal or chord. It is wall-clock time and has no pause, so an idle spell inflates a game in progress. Saves restore the elapsed time but never record a best time.

Tasks and how-to

Pick a difficulty

Four presets exist. Pass one as a flag, or pick it from the in-game picker with n and the keys 1 to 4.

PresetFlagBoardMines
Difficulty::Easy--easy9 x 910
Difficulty::Standard--standard (the default)10 x 1012
Difficulty::Medium--medium16 x 1640
Difficulty::Expert--expert30 x 1699

Play a custom board

Pass a width, a height and a mine count. Width is columns and height is rows. Each side must be 2 to 50, and the mine count must leave a safe 3x3 area for the first click, so 1 <= mines <= width x height - 9. Boards of fewer than 10 cells are refused. If you give only the width and height, the mine count defaults to one eighth of the cells, rounded down, with a minimum of 1.

candy-minesweeper 30 16 99                # the Expert shape, by hand
candy-minesweeper 20 20                   # 20x20 with 50 mines by default

Save and resume a game

Press S to write the live game to a single save slot, and L to load it. Loading works after a win or a loss too, so you can replay the exact board. Saving is refused once the board is finished, which leaves the slot unchanged.

The slot is $XDG_CONFIG_HOME/candy-minesweeper/savegame.json when XDG_CONFIG_HOME is set to an absolute path (a relative value is ignored), and ~/.config/candy-minesweeper/savegame.json otherwise. It is written with mode 0600 through an atomic write. The slot records the full mine layout as well as your progress. Treat the file as private if you sync dotfiles.

Keep statistics across sessions

Statistics are opt-in. Set CANDY_MINESWEEPER_STATS to a file path and each finished game is tallied there per preset: games, wins and best time. Only boards whose shape matches a preset are tallied, and a save restored with L never records a best time.

export CANDY_MINESWEEPER_STATS="$HOME/.local/state/candy-minesweeper/stats.json"
candy-minesweeper --standard

Start a game from code

Build a Game with Game::start(), Game::withDifficulty() or Game::withCustom(), and pass a seeded generator to make the layout repeatable. examples/play.php shows the full runtime wiring.

use SugarCraft\Core\Program;
use SugarCraft\Minesweeper\Difficulty;
use SugarCraft\Minesweeper\Game;

// one of the three constructors, passed to the runtime
$game = Game::withDifficulty(Difficulty::Medium);      // a preset
$game = Game::withCustom(12, 10, 14);                  // a custom shape
$game = Game::start(width: 12, height: 10, mines: 14); // the blank board the binary uses

(new Program($game))->run();

Read the board without a terminal

Use Board directly. The cells come back as rows, and reveal() takes a generator closure for the first click. The examples/headless.php script is a complete worked version of this.

use SugarCraft\Minesweeper\Board;

$board = Board::blank(8, 5, 6);
$board = $board->reveal(0, 0, $rand);          // $rand: Closure(int): int
if ($board->isWon()) {
    // every safe cell is revealed
}
$cell = $board->cell(0, 0);                    // Cell|null, read-only

Configuration

The binary takes its board from the command line and its environment from the shell. The options accepted by the binary are below. Every block of the README accepts the same options.

OptionEffect
--easy, --standard, --medium, --expertStart a preset. Only one preset flag is allowed.
[width] [height] [mines]A custom board. Cannot be combined with a preset flag.
-p, --pickOpen the board picker as the first frame. Cannot be combined with a preset or with dimensions.
-v, --versionPrint the version and exit.
-h, --helpPrint the usage text and exit.

Any other option exits with status 1 and prints the usage text to stderr. Nothing is silently ignored.

CANDY_MINES_STATSThe pre-rename variable. Still read, with a deprecation warning.

NO_COLOR, CLICOLOR=0, TERM=dumbDrop to plain text. The board switches to its narrow glyph set.
FORCE_COLOR, CLICOLOR_FORCEAssert colour to a host that misdetects as dumb.
COLORFGBGA background report ending in ;7 selects the darkened light-console palette.
LC_ALL, LC_MESSAGES, LANGChoose the interface locale. The game falls back to English.

↑ ↓ ← → or h j k lMove the cursor.

Ctrl and Alt letters are inert, so an editor habit cannot restart or save the game by accident. Some control combinations arrive as plain bytes and act as Enter or Escape. Ctrl+J and Ctrl+M reveal like Space, and Ctrl+[ quits like Esc.

Theming and colour

The board uses a number palette in which each adjacent count has its own hue. The count is also drawn as the digit itself, so the board reads correctly without colour. Flags are a bold gold F, hidden cells are a width-safe colon, and the cursor is reverse video.

Colour follows the terminal. Setting NO_COLOR, CLICOLOR=0 or TERM=dumb drops the output to plain text. The renderer then uses an ASCII glyph set: an x for a wrong flag and a + border. On a light console, a background report ending in ;7 in COLORFGBG selects darkened versions of every ink, each of which clears 4.5:1 contrast against white. Terminals that declare neither keep the dark palette.

The always-on help legend uses a dim lavender that sits below WCAG AA for body text against the dark background. NO_COLOR paints every line in the terminal's own ink, which is the highest-contrast option.

  • examples/play.php: the interactive game wired by hand, with the same locale, colour and mouse setup as the binary. Run it in a terminal with php examples/play.php. With stdin at /dev/null it draws one frame and exits with status 0.

Testing

composer install
vendor/bin/phpunit

The suite covers the board rules, the game flow, the saves, the statistics and the views. Snapshot tests in tests/GoldenRenderTest.php pin the first-click safe area, the cascade reveal and the win overlay against golden files under tests/fixtures/, using sugar-testing. LocaleParityTest fails when any of the 16 locale files drifts from the English key set. FooterWidthGuardTest keeps the help footer within 80 columns in every locale.

Troubleshooting and FAQ

  • The binary exits with candy-minesweeper requires ext-mbstring. The phar cannot install extensions through Composer, so it checks them at boot. Install php8.3-mbstring and php8.3-intl, then check with php -m.
  • The footer wraps on a wide-glyph terminal. Terminals set to double-width ambiguous characters, such as --ambigwidth=2, widen the footer separator, the arrow hints and the rounded border. Set the terminal's ambiguous-width option to narrow.
  • The board is cut off in a small terminal. The board renders in full with no scrolling viewport, and there is no resize re-fit. Expert needs a terminal at least 80 by 24, and boards near 50 by 50 need a larger terminal.
  • The save refuses to load. The message save refused (unreadable or tampered) means the file failed validation. The reader re-checks every field and refuses foreign versions, so a hand-edited slot leaves the game untouched.
  • Best times look wrong. The clock is wall-clock time with no pause, so an idle spell inflates a game in progress. A best time is a minimum, so one dishonestly slow first entry stands until a faster run beats it.
  • Two instances lose statistics. Writes are atomic, but two processes sharing one stats file resolve as last-writer-wins. Give each parallel session its own CANDY_MINESWEEPER_STATS path.
  • Screen readers cannot read the board. The board is conveyed only through the visual frame, and there is no text-dump mode. Keyboard play works, and the digits, F and cursor reverse video carry the meaning without colour.

Architecture

The pure state lives in Board, Cell and Difficulty. The runtime is one Model, Game, which owns the cursor, the key routing, the flow and the timer. Renderer is a pure function from a Game to a string, built on sugar-cellbuffer and sugar-mouse. Persistence sits in Stats and DifficultyStats, which use sugar-core's atomic JSON file.

FileRole
CellA value object: mine, revealed, flagged, question mark and the adjacent count.
BoardThe grid and every transition. Win detection is O(1) through a revealed counter. Serialises to versioned JSON.
GameThe TEA model: cursor, key routing, game flow and the timer.
DifficultyThe four presets, with dimension and mine counts.
Stats and DifficultyStatsImmutable tallies per preset, and their atomic JSON persistence.
RendererThe pure view function and the click-to-cell mapping.
Ui\CustomDifficultyValidated custom dimensions, with an error that names the violated bound.
Lang and TickMsgThe translation facade and the 1 Hz clock message.

The board uses an immutable list of lists of Cell. Mines are placed after the first click, and the save format is the same versioned JSON that the in-game slot uses.

Versioning and changelog

The version is reported by --version, and a phar build reads it from the archive metadata. The package was published as sugarcraft/candy-mines until the 2026-10 rename. The namespace moved from SugarCraft\Mines\ to SugarCraft\Minesweeper\. The old CANDY_MINES_STATS variable is still read, with a deprecation warning, and nothing under the old name receives updates.
