candy-kv is a personal key/value store. Each named database is one SQLite file, a key@db suffix routes a key to a database, keys can carry a TTL, values can be binary, and whole databases import and export as JSON or YAML. It ships as a library (Store) and as a bare CLI (candy-kv). The design follows charmbracelet/skate, a Go key/value tool. candy-kv is a native PHP project, not a line-by-line port, and it stores data in SQLite where skate uses BadgerDB.

Install

composer require sugarcraft/candy-kv   # the candy-kv binary lands in vendor/bin/

Requires PHP 8.3 or newer with the sqlite3 and mbstring extensions. A standalone phar is published with the releases. A monorepo checkout runs straight from the tree with php bin/candy-kv after composer install.

Quickstart

use SugarCraft\Kv\Store;

$store = new Store();   // SQLite files under $XDG_CONFIG_HOME/skate, else ~/.config/skate

$store->set('user:1', 'Alice');
$store->set('user:2', 'Bob');
echo $store->get('user:1');             // 'Alice'
echo $store->get('missing', 'n/a');     // the fallback: 'n/a'

// A key@db suffix routes to a named database. "\@" spells a literal at-sign.
$store->set('token@passwords', 'ghp_xxxx');
$store->setWithTtl('session', 'abc', 60);   // expires after 60 seconds

foreach ($store->list('user:*') as $entry) {  // character-wise glob, case-sensitive; yields Entry
    echo "{$entry->key} => {$entry->rawValue()}\n";
}
$store->listDatabases();                 // ['default', 'passwords']
$store->pruneExpired();                  // reclaims expired rows in the default database

Constructing a Store touches nothing on disk. Neither the data directory nor any database file is created until the first write, and a read never creates a file.

The CLI in one screen

candy-kv set color blue              # a value with a NUL byte or invalid UTF-8 is stored as binary
candy-kv get color                   # prints the exact stored bytes, with no added newline
candy-kv list 'user-*'               # key<TAB>value rows; a binary value shows a <binary N bytes> placeholder
candy-kv delete 'tmp-*' --dry-run    # reports how many entries would go, writes nothing
candy-kv prune                       # removes expired residue from the default database
candy-kv export json > backup.json
candy-kv import json backup.json     # atomic within one database; a file spanning databases needs --no-atomic

Exit codes: 0 on success, 1 for a miss, no match or a runtime failure, and 2 for usage errors. Unknown flags and commands are refused before anything is written. candy-kv --help prints the full flag list.

Concepts

A store is a directory of SQLite files, one per database, named <dir>/<dbname>.db. Unsuffixed keys land in default.db. Store is the facade: it routes each key to a Database through Store::splitKey(), which reads the key@db suffix, and the Database does the row work. Database files are created with mode 0600, and the data directory is 0700.

An Entry is one stored row: the key, its value, the binary flag, the created and modified times, and an optional expiry. An expired row is invisible to readers at once and stays on disk until pruneExpired() or prune reclaims it. Database::raw() is the one reader that still sees an expired row.

A binary value is stored base64-encoded with the binary flag. Entry::rawValue() returns the decoded bytes. The CLI picks binary mode for you when a value contains a NUL byte or invalid UTF-8, and --text refuses such a value outright.

Listing and fuzzy search

Store::list() takes a glob pattern, a database name, a reverse flag and a mode of all, keys or values. Any other mode throws, so a typo cannot quietly yield the wrong shape. Store::fuzzyFilter() ranks the keys of a database against a query with a Smith-Waterman local-alignment matcher, which finds usr1 inside user:1.

Tasks

Keep a backup of one database and restore it

candy-kv export json passwords > passwords.json
candy-kv import json passwords.json --if-exists=skip   # keep what is already there

Export writes the database as a JSON or YAML document, and import reads it back into a database of the same name. --if-exists picks the clobber policy: replace (the default), skip to keep a live row, or fail to refuse and name the key. Import runs in one transaction by default, and an overwriting import reports how much it replaced.

Store a file as a binary value

$store->setFile('logo', '/srv/assets/logo.png');   // binary, read from disk
$store->saveTo('logo', '/tmp/logo-copy.png');     // written back out, mode 0600

Both calls work on binary entries. setFile() returns the stored Entry, and saveTo() returns a bool.

Expire a key and sweep it later

candy-kv set session abc --ttl 300   # expires after five minutes
candy-kv prune --all                # sweep expired rows from every listed database

--ttl must be a positive whole number of seconds, from 1 to 999999999. --ttl 0 is a usage error, not "expire now" and not "forever". Leave --ttl off for an entry that never expires.

Run several transactions on one database

use SugarCraft\Kv\{Database, Store};

$store = new Store();
$store->transaction('work', function (Database $db): void {
    // every write in this closure commits together, or none of them does
});

Store::transaction() creates the target database on demand, because a transaction may write. A transaction aimed at settings throws InvalidArgumentException, and so does a single write to a key routed there.

Import a YAML document across several databases

candy-kv import yaml secrets.yml --no-atomic --max-bytes=0

A file that spans databases cannot run as one transaction, so --no-atomic is needed. --max-bytes=0 lifts the default 256 MiB ceiling on the document, and an oversized document is otherwise refused before its bytes are read.

Configuration and data directory

candy-kv reads two environment variables, and neither one is required. The data directory is $XDG_CONFIG_HOME/skate when that is set, otherwise ~/.config/skate. The directory keeps the pre-rename skate name on disk, so installs from before the rename keep working.

SettingTypeDefaultEffect
XDG_CONFIG_HOMEabsolute pathunsetBase directory. The store lives in <base>/skate. A relative value is refused.
HOMEabsolute pathsystem valueUsed when XDG_CONFIG_HOME is unset. The store lives in <home>/.config/skate. A relative value is refused.

If neither variable is set, candy-kv falls back to the home directory in the passwd database. If even that is unavailable, it throws rather than writing into the install tree. Database names are limited to letters, digits, _ and -. The name settings is reserved: listDatabases() never shows it, and every write aimed at it is refused.

Upstream skate keeps its own data in a BadgerDB layout that this store cannot read. Move data across with export there and import here. JSON and YAML are the only bridge, and the two stores never share a directory.

Output discipline

get prints the exact stored bytes, with no newline added and nothing scrubbed, so $(candy-kv get k) round-trips honestly. get --sanitize collapses a value to one line, strips the C0 control bytes (ESC included) and DEL, and removes the C1 range, for terminal printing. Values reach the terminal through Store::sanitizeForTty().

Key naming, @db and escapes

A key is any string, with one syntax on top. A trailing @name routes the key to the database name, and a key without a suffix goes to the default database. \@ spells a literal at-sign in a key, and \* spells a literal star in a glob. Glob patterns support * and ?, and they are case-sensitive.

candy-kv set 'mail@work' hunter2          # stored in the work database, key "mail"
candy-kv set 'a\@b' 1                    # the key is the literal "a@b" in the default database
candy-kv list 'user-?'                   # one character after "user-"

Examples

The examples/ directory holds five runnable programs. Each one uses a temporary data directory, so none of them touches the real store:

  • examples/basic.php covers set(), get(), delete() and list(), the fallback value, and entry() for metadata.
  • examples/binary.php stores raw bytes with set(binary: true) and reads them back through rawValue().
  • examples/glob.php lists keys with * and ? glob patterns.
  • examples/multidb.php uses the key@dbname suffix to keep two databases side by side.
  • examples/reverse-order.php lists the same keys forward and in reverse order.
php examples/basic.php
php examples/multidb.php

Testing

The suite lives in tests/ and runs under PHPUnit 10. Run it from the package root, with stdin redirected so a stray read cannot hang the run:

vendor/bin/phpunit < /dev/null

The tests cover the store contract (StorageContractTest, StoreTest), the database and its TTL migration (DatabaseTest, DatabaseTtlMigrationTest), the import and export commands (ImportCommandTest, ImportExportTest), the YAML dialect (YamlDialectTest), and the CLI's argument contract (CliArgParserTest, CliContractTest).

Troubleshooting

set waits for input

candy-kv set key with no value reads standard input, silently, with no prompt. Pass the value on the command line, or pipe it in: printf 'value' | candy-kv set key.

An import refuses a top-level JSON array or YAML sequence

The document's top level is a JSON array or a YAML sequence. candy-kv refuses it with Expected a JSON object mapping keys to values, got a list. (JSON) or Expected a YAML mapping of keys to values, got a sequence. (YAML), rather than importing the indices as keys. Wrap the entries in an object that maps each key to its value.

An import refuses a null, boolean, array or object value

Those values cannot round-trip as stored text, so the whole import is refused before anything is written. Convert the value to a string in the source document.

A write to key@settings throws InvalidArgumentException

settings is reserved, so a listing-driven backup never misses a half-written values database. Write to a different database name. Reads of a planted key@settings still work.

A relative XDG_CONFIG_HOME or HOME is refused

A relative path would move the store with the working directory, so candy-kv refuses it. Set the variable to an absolute path.

A value with a NUL byte refuses under --text

Every reader truncates at the first NUL, so --text refuses the value with exit 2. Store it with --binary, or drop the --text flag and let the CLI choose binary mode.

Architecture

Store routes, Database stores

Store owns the data directory and the routing. It resolves a key to its database and rejects reserved names. The rows and the SQL all sit in Database, so a transaction or a prune runs against one file at a time.

Import is a pipeline with one commit point

An importer parses its format (JsonImporter, YamlImporter), and FlatDocumentNormaliser validates every row before anything is written. ImportCommit then applies the replace, skip or fail policy. A value that cannot round-trip as stored text refuses the whole import before a single row is written.

Output is sanitized at the edge

A value bound for a terminal goes through Store::sanitizeForTty(), so a stored value that holds escape sequences cannot move the cursor or restyle the screen.

Changelog and versioning

candy-kv --version reports the version stamped into a phar build. A source checkout reports dev-master rather than an invented semver, so an unreleased tree never claims a release number.
