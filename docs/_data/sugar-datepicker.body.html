SugarDatepicker is a month-grid date picker for terminal UIs. It offers single-date and range selection, min and max bounds, keyboard and mouse seams, and localized day and month names in 17 locales. It is a port of the interaction model of EthanEFung/bubble-datepicker (Go), and it renders to an ANSI string. Use DatePicker for a pure value you drive yourself, or Model to run it as a sugar-core TEA model.

Install

composer require sugarcraft/sugar-datepicker:@dev

The package has no tagged release yet, so it ships only dev-master, and the @dev constraint is required until the first version tag lands. It needs PHP ^8.3 and ext-mbstring, and it pulls in sugarcraft/sugar-core and sugarcraft/sugar-cellbuffer. The package was renamed in 2026-10 from sugarcraft/sugar-calendar, and the old name is frozen at its last release, so depend on the new name only.

Quickstart

use SugarCraft\DatePicker\DatePicker;

// The picker opens on the seed date's month, with the cursor on the seed.
// Every step returns a new picker, so rebind each result.
$picker = DatePicker::new(new \DateTimeImmutable('2026-01-15'))
    ->handleKey(DatePicker::KEY_DOWN)  // one row down: Thursday the 22nd
    ->selectDate();                     // select the date under the cursor

echo $picker->selectedDate()->format('Y-m-d'); // 2026-01-22
echo $picker->view();                           // the month grid

// Range mode: the first Enter sets the start, the second sets the end.
$range = DatePicker::new(new \DateTimeImmutable('2026-01-15'))
    ->withRangeMode(true)
    ->handleKey(DatePicker::KEY_DOWN)->handleKey(DatePicker::KEY_ENTER)
    ->handleKey(DatePicker::KEY_RIGHT)->handleKey(DatePicker::KEY_RIGHT)
    ->handleKey(DatePicker::KEY_ENTER);
[$range->rangeStart()->format('j'), $range->rangeEnd()->format('j')]; // ['22', '24']

Drive the same picker as a TEA model when your host runs a sugar-core program loop. The Model maps each KeyMsg itself, and it records transitions to an optional event store:

use SugarCraft\Core\KeyType;
use SugarCraft\Core\Msg\KeyMsg;
use SugarCraft\DatePicker\Model;

$model = Model::new(new \DateTimeImmutable('2026-05-15'));
[$model, $cmd] = $model->update(new KeyMsg(KeyType::Right));
[$model, $cmd] = $model->update(new KeyMsg(KeyType::Enter)); // selects the date
echo $model->view();

Concepts

DatePicker is an immutable value. It holds a viewed month, a cursor on one grid cell, an optional single selection or range, min and max bounds, a today anchor, and the render state (width, week numbers and styles). Each method returns a new picker, and nothing mutates in place. The grid is always six rows of seven days, Sunday first, with blank lead-in and trailing cells. The cursor can rest on a blank cell, but Enter is refused there.

A selection is either refused or accepted, and nothing partial is kept. Enter on a blank cell, or on a day outside the bounds, returns the picker unchanged. The same refusal surfaces as a selection_refused event when the key arrives through Model. Navigation never wraps and never throws. Stepping past a bound, or past the calendar floor at January 0001, is a no-op.

The Model is the only channel that records events. DatePicker::handleKey() and the imperative methods record nothing, by design. A host that drives the picker directly either wraps it in a Model or compares the picker states itself.

Tasks

Limit selection to a date window

Set both bounds. Setting a bound pulls the viewed month into the window and re-clamps the cursor. An out-of-window selection is refused, and an existing selection that falls outside is dimmed, never cleared. examples/constraints.php walks through clamped navigation and refused Enter presses.

use SugarCraft\DatePicker\DatePicker;

$picker = DatePicker::new(new \DateTimeImmutable('2026-05-15'))
    ->withMinDate(new \DateTimeImmutable('2026-05-10'))
    ->withMaxDate(new \DateTimeImmutable('2026-07-20'));

$picker->inBounds(new \DateTimeImmutable('2026-04-01')); // false
$picker = $picker->withoutMinDate(); // lift one bound again

Restore a saved range

withRange() presets both endpoints, and each must lie inside the current bounds. It does not enable range mode, so compose the two calls. Pass null to clear the endpoints and keep the mode.

$picker = DatePicker::new(new \DateTimeImmutable('2026-05-15'))
    ->withRange(new \DateTimeImmutable('2026-05-04'), new \DateTimeImmutable('2026-05-08'))
    ->withRangeMode(true);

$cleared = $picker->withRange(null); // clears both endpoints, keeps range mode

Pin the reference "today"

By default the today marker follows the wall clock, and it is re-read on every render. withToday() pins a reference day, which keeps renders deterministic in tests. withoutToday() hides the marker, and withClockToday() resumes wall-clock following. goToToday() still navigates to the real current day while the marker is hidden.

use SugarCraft\DatePicker\DatePicker;

$picker = DatePicker::new(new \DateTimeImmutable('2026-05-15'))
    ->withToday(new \DateTimeImmutable('2026-05-15'));
$hidden = $picker->withoutToday();
$hidden->todayHidden(); // true

Size the grid for a host layout

The width is clamped into a band, never rejected. Ask renderWidth() for the exact width that view() will produce, and reserve nine rows for every render.

use SugarCraft\DatePicker\DatePicker;

$picker = DatePicker::new(new \DateTimeImmutable('2026-05-15'));
$picker->renderWidth(30, true); // 34: a 30-wide grid plus the 4-cell week column
$picker->renderWidth(64);       // 63: clamped to MAX_TOTAL_WIDTH
echo $picker->view(30, true);

Resolve a mouse click to a date

hitTest() maps a character coordinate in the rendered view to the date under it, or null for chrome, blank cells and padding. It never throws. It reads the week-column state the picker was configured with, so a host must use the same flag it renders with.

use SugarCraft\DatePicker\DatePicker;

$picker = DatePicker::new(new \DateTimeImmutable('2026-05-15'));
$date = $picker->hitTest(0, 0); // the header row is chrome, so null

Record transitions for analytics or undo

Pass an EventStore to Model::new(), and drain it with release() after each update. Every value change is recorded as one of eight PickerEvent kinds. release() returns the rows oldest first, each shaped array{type, payload, time}, where time is whole epoch seconds. The payload keys for each kind are:

  • cursor_moved: {index, date}, with date null on a blank cell.
  • range_started: {date}.
  • date_selected: {date} in single mode, or {date, rangeStart, rangeEnd} when a range completes.
  • date_cleared: an empty payload.
  • range_restarted: {from, to}, where to may equal from.
  • range_cleared: {from}.
  • selection_refused: {date, reason}, where reason is out_of_bounds or empty_cell, and date is null on a blank cell.
  • month_changed: {year, month}.

examples/interactive.php prints the drained transcript.

Keys and input

The picker has a fixed key table. Rebinding is a host job: match the keys you want in your own input reducer, then call the public methods. Every action in the table is also a public method.

Year jumps are programmatic only, through goToPreviousYear() and goToNextYear(). Through Model, the action keys and the letter bindings are reserved to the host under any chord. Ctrl, Alt or Shift held means the key is ignored, so a Shift+Enter newline in a chat host is never hijacked. The six navigation keys act with or without a chord.

Theming and styling

Seven setters take bare SGR parameter strings such as 1;36, up to 32 characters. The accepted set is attributes 1 to 7 and 9, foregrounds 30 to 37 and 90 to 97, and backgrounds 40 to 47 and 100 to 107. Anything else is refused and the offending code is named, which includes escape sequences, the extended-color introducers 38 and 48, and the reset codes. Blink codes 5 and 6 are accepted but discouraged.

The picker does not check the terminal. It does not read NO_COLOR, consult a color profile, or detect a dumb terminal, and it does not fall back to basic colors. Basic foregrounds 30 to 37 and 90 to 97, and backgrounds 40 to 47 and 100 to 107, are mapped through the RGB table of sugar-core's ANSI16 palette and emitted as truecolor (38;2 and 48;2). Attribute-only codes 1, 2, 4, 7 and 9 pass through unchanged. Those choices belong to the host. A colorless build can point every setter at attribute-only codes, for example withHeaderStyle('1'), withDayNameStyle('2'), withTodayStyle('1;4'), withSelectedStyle('3'), withSelectedTodayStyle('1;3'), withCursorStyle('7') and withRangeStyle('9').

Out-of-bounds days always get a faint composition on top of whichever style applies, and no setter changes that. The reverse-video cursor and the faint attribute are the cues that survive a colorless display. The default 90 day-name style has the lowest contrast, so 37 or 97 are the suggested alternates on dark themes.

Troubleshooting and FAQ

Enter does nothing on a day

The day is either a blank lead-in or trailing cell, or a dimmed day outside the bounds. Enter is refused in both cases, and the picker comes back unchanged. Through Model, the refusal is recorded as a selection_refused event whose reason is empty_cell or out_of_bounds.

withMinDate() or withMaxDate() throws

The date is outside 0001-01-01..9999-12-31, or the new bound crosses the existing one. A zero date, such as a MySQL empty-row value, is refused for that reason. Check the value before you pass it in.

Model::new() throws when given a time and a picker

Pass either a seed time or a configured picker. Passing both throws, because the time would be silently discarded. Put the seed on the picker with DatePicker::new() when you need both.

The grid is narrower or wider than requested

The requested width is clamped into the band and never rejected. A request below the natural floor grows to 21, or 25 with the week column. A request above 63 shrinks. Ask renderWidth() for the width that view() will produce.

The grid shows mojibake on a latin1 terminal

The separator is the box-drawing character U+2500, and the grid assumes UTF-8 output. Set the terminal and the PHP output to UTF-8.

Ctrl chords quit the host on a paste

Pasted NUL and corrupted bytes arrive as invented Ctrl chords with an empty rune. The model ignores them. A host that maps any Ctrl chord to quit does not, so bind quit to a named key or an explicit, labeled chord.

The today marker is missing

A picker hides the marker after withoutToday() until withClockToday() or a fresh withToday() restores it. A pinned reference day never follows the wall clock, so a session that runs past midnight keeps showing the pinned day.

Events are missing after a direct handleKey() call

handleKey() and the imperative methods record nothing. Only Model emits events. Drive the picker through a Model, or compare the states yourself.

Architecture

The month grid is laid out by DatePicker into a sugar-cellbuffer buffer that is nine rows high and 21 to 63 cells wide (25 to 63 with the week column), and Buffer::toAnsi() serializes it. Cell widths come from the sugar-core width oracle, so the rendered width agrees with renderWidth(). Model wraps the picker as a sugar-core Model. Its update() maps key messages onto the picker, and it records each transition through the EventStoreInterface. Navigation holds the static grid-index conversion, and DateRange is the immutable endpoint value.
