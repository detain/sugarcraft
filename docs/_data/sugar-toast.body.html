Non-blocking floating notifications at 9 screen positions. Error, Warning, Info, Success types. Auto-dismiss, an Escape-dismiss preference flag for hosts, and stacked multi-toast support. Severity never rides color alone: each type carries a distinct symbol, withAccessibleText() adds the plain-text word, and the REDUCE_MOTION/NO_COLOR environment gates drop blink and color bytes while those text channels keep rendering. It is a port of the alert behavior of DaltonSW/bubbleup, and it is a renderer: the host owns the keys, the clock and the event loop.

Install

composer require sugarcraft/sugar-toast

No tagged releases ship yet — Packagist serves the dev-master branch only, so require it as sugarcraft/sugar-toast:dev-master; on a default-stable project a bare sugarcraft/sugar-toast request does not resolve.

The manifest requires PHP ^8.3. It pulls in sugarcraft/sugar-core for the sanitizer, the i18n registry and the timer commands, and sugarcraft/sugar-cellbuffer for the cell grid that composites the boxes over the background.

Quickstart

use SugarCraft\Toast\{Position, Toast, ToastType};

$toast = Toast::new(50)  // max width 50
    ->withPosition(Position::TopRight)
    ->withDuration(10.0);  // seconds

$toast = $toast->alert(ToastType::Success, 'File saved!');
$toast = $toast->alert(ToastType::Error, 'Connection failed');

$bg = str_repeat("background content\n", 20);
echo $toast->view($bg);

The call returns the background with both boxes composited in the top-right corner of the default 80 by 24 viewport. Each alert inherits the 10 second duration from withDuration(), so both boxes leave the frame on their own. The full runnable program is examples/basic.php.

Concepts

A Toast is an immutable value that holds a queue of Alert objects, a position, a symbol set and a set of limits. Every with*() setter and every alert door returns a new Toast, so the host rebinds the result each time. Nothing is mutated behind the host's back, and a frame drawn from an older value stays valid.

Each alert carries an absolute expiry. A null expiry means inherit: the queueing doors arm the timer set by withDuration() when one is set, and no timer when it is not. Persistence is a separate, explicit sentinel (withCancelledExpiry() or cancelAlert()), so a persistent alert never auto-dismisses. Expired alerts leave the queue on the next write, or when the host calls pruneExpired().

view() stacks the live alerts at the chosen position and composites them over the background through the cell grid. The result is a frame string the host paints. Stacking, overflow and the fold row are described under the Architecture section.

Tasks

Auto-dismiss on a timer instead of polling

Ask the toast when its next expiry is due, and schedule one timer for that moment. secondsUntilNextExpiry() returns null when nothing expires, so no timer is armed for an idle queue. Re-arm from inside update(), because the tick is one-shot.

use SugarCraft\Core\Cmd;
use SugarCraft\Core\Msg;
use SugarCraft\Toast\Toast;

// Host-defined message: sugar-toast ships no message class of its own.
final class RepaintMsg implements Msg {}

function armPrune(Toast $toast): ?\Closure
{
    $delay = $toast->secondsUntilNextExpiry();
    return $delay === null
        ? null
        : Cmd::tick($delay, static fn (): Msg => new RepaintMsg());
}

Keep an error on screen until the user acts

With no withDuration() set, an alert() with no expiry never leaves the queue. Use that for errors the user must see, and clear them with dismiss() once the user has acted. dismiss() files every queued alert into the history log, and clear() drops them without a record.

use SugarCraft\Toast\{Toast, ToastType};

$toast = Toast::new(60)
    ->alert(ToastType::Error, 'Disk is full. Free space before the next save.');

// Later, after the user has freed space:
$toast = $toast->dismiss();

Show progress for a long operation

progressToast() draws a bar under the message. Re-calling it with the same $id advances the one box instead of appending another, so a loop can report progress without filling the stack. The progress value is clamped to 0.0 through 1.0.

use SugarCraft\Toast\{Toast, ToastType};

$toast = Toast::new(50);
foreach ([0.25, 0.5, 0.75, 1.0] as $done) {
    $toast = $toast->progressToast(ToastType::Info, 'Uploading backup', $done, id: 'upload');
}

Attach a button that runs a callback

Pass Action objects to any alert door. The label renders as [Label], and its frame cells are reported by actionRects(). Route a mouse click or a hotkey through actionAt() to find the action under a cell, then call its callback.

use SugarCraft\Toast\{Action, Toast, ToastType};

$retry = static function (): void {
    // Re-send the failed request here.
};

$background = str_repeat("background content\n", 20);
$toast = Toast::new(50)
    ->error('Save failed', actions: [new Action('Retry', $retry)]);

// Paint the frame first: actionAt() reads the geometry of the last render.
$toast->view($background, 80, 24);

// On a click at a frame cell, $col and $row come from the host's mouse event.
$hit = $toast->actionAt(col: 4, row: 2);
if ($hit !== null) {
    ($hit->callback)();
}

Register a custom alert type

An AlertTypeDefinition gives a new key its own header prefix and icon color, and a base severity that the renderer falls back to. Register it on an AlertTypeRegistry, and pass that registry to withTypeRegistry(). String types resolve against the registry first and then against the built-ins.

use SugarCraft\Toast\{AlertTypeDefinition, AlertTypeRegistry, Toast, ToastType};

$registry = AlertTypeRegistry::new()
    ->with(AlertTypeDefinition::new('deploy', '▲', base: ToastType::Success, label: 'Deploy'));

$toast = Toast::new(50)
    ->withTypeRegistry($registry)
    ->alert('deploy', 'Release 2.4 is live');

Every option is a fluent setter on Toast. The defaults below are the values a fresh Toast::new() carries.

Environment variables are read at render time and never probe a TTY. REDUCE_MOTION or PREFERS_REDUCED_MOTION drop blink. NO_COLOR or CLICOLOR=0 drop every color byte. CLICOLOR_FORCE wins over both. A literal NO_COLOR=0 counts as unset, and CLICOLOR must read exactly 0 to suppress color.

Keys and input

The renderer binds no keys. The host reads the keyboard and the mouse and calls the door that matches. allowEscToClose() reports the Escape preference, and the host calls dismiss() when Escape arrives and the flag is on. For buttons, actionRects() lists every painted [Label] cell, so a host can bind Alt plus a number or a focus ring to them. A click goes through actionAt($col, $row), and expandAt() handles the [+N more] fold row.

Theming and styling

Three layers set the look. The SymbolSet chooses glyphs and borders. ToastType::color() gives the default icon color for each severity. Per-alert withBackgroundColor(), withForegroundColor() and withBorderColor() override the fill, the message text and the box glyphs. A null override is unstyled, not the type color, so the type color reaches only the icon. Custom types supply their own prefix and icon color through AlertTypeDefinition. The environment gates above can strip all color at render time without changing the glyphs.

Troubleshooting and FAQ

Alerts never disappear

With no withDuration() set, the timer is never armed, so an inheriting alert stays until the host calls dismiss(), clear() or removeAlert(). Set a duration on the toast, or pass an explicit $expiresAt or $ttlSeconds to the door, when the alert should leave on its own.

Escape does nothing

The renderer reads no input. allowEscToClose() only reports a preference, and the host must read Escape and call dismiss() itself. Check that the flag is on for the frame, and that the key handler reaches the toast's dismiss() call.

Colors are missing from the output

NO_COLOR or CLICOLOR=0 in the environment drops every color byte, and CLICOLOR_FORCE overrides both. Unset those variables, or set CLICOLOR_FORCE=1 for a pipe that should keep color. Severity stays visible through the glyph and the [E], [W], [I] and [S] prefixes.

view() throws InvalidArgumentException

Both viewport dimensions must lie between 1 and Toast::MAX_VIEWPORT_DIMENSION (4 096), and their product must fit Toast::MAX_VIEWPORT_CELLS (1 000 000). The check runs before any allocation, so a bad size fails fast. Pass the terminal's real size, or clamp it before calling view().

Boxes move when an older alert expires

Expiry reflows the stack, so the boxes below an expired one move up. This is expected. To keep a box fixed, make it persistent with cancelAlert(), or cap the stack with withMaxConcurrent() so reflow stays small.

A message from a remote service changes the colors of the box

Raw ESC, OSC and BEL bytes never reach the output, because alert text is composited through the cell grid. Inline SGR is honored as styling, though, so a remote message can recolor its own box. Run attacker-authored text through Sanitize::untrusted() before it is queued. The trust-boundary section of the README sets out the full contract.

Upstream mapping

The port follows the alert model of DaltonSW/bubbleup. SugarCraft is developed as a native PHP project, so the mapping is a port of behavior, not of Go code.

Alert definition (key, color, prefix)AlertTypeDefinition, validated at construction and registered through a value, not a global.
RegisterNewAlertTypeAlertTypeRegistry::with() and Toast::withTypeRegistry(), immutable, with custom keys resolved registry-first.
Alert positionsPosition enum, nine positions with the placement maths on the enum.
Alert typesToastType enum: Error, Warning, Info and Success.

Architecture

A Toast is immutable. Its queue holds Alert values, and each door returns a new Toast with the change applied. view() stacks the live alerts at the chosen position, paints them into a cell grid over the background, and serializes the result. The frame and the hit rectangles are memoized on the last render, so actionRects() and actionAt() read the frame the host just painted. Calls that name a different frame throw instead of answering for the wrong one. Overflow applies when the queue would exceed maxConcurrent, and deep stacks fold into a +N hidden row rather than covering each other. The cell grid keeps raw control payloads out of the output, and inline SGR is styling the renderer honors, so untrusted text should be sanitized before it is queued.

Changelog and versioning

The library is pre-1.0, so consume dev-master. The deprecated withoutExpiry() forwarder is kept working until 2.x, and the canonical door is withCancelledExpiry(). Behavior changes that alter a rendered frame are pinned by the golden fixtures.
