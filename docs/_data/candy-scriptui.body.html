13 presentation subcommands — choose, confirm, file, filter, format, input, join, log, pager, spin, style, table, write — plus completion and version utilities. Drop into a shell script and instantly get a Charm-quality interactive UX.

Install

composer require sugarcraft/candy-scriptui

Or grab the rolling latest phar — rebuilt and published for every commit that touches this app (verify against the published .phar.sha256 sidecar before making it executable):

curl -fsSLO https://github.com/detain/sugarcraft/releases/download/candy-scriptui/latest/candy-scriptui.phar
curl -fsSLO https://github.com/detain/sugarcraft/releases/download/candy-scriptui/latest/candy-scriptui.phar.sha256
sha256sum -c candy-scriptui.phar.sha256 && chmod +x candy-scriptui.phar

Quickstart

# Apply styling.
candy-scriptui style --foreground "#ff5f87" --bold "Hello, candy!"

# Pick one item.
choice=$(candy-scriptui choose Pizza Burger Salad)

# Read a single line.
name=$(candy-scriptui input --placeholder "Your name?")

# Confirm a destructive action.
file=old-build.log
candy-scriptui confirm "Really delete $file?" && rm "$file"

# Show a spinner while running a command.
candy-scriptui spin --title "Building..." -- make build

# Filter a list (substring by default; --fuzzy for fuzzy matching).
git branch | candy-scriptui filter

Concepts

The binary is one entry point with one subcommand per job. Each subcommand reads its input from argv or stdin, prints its result to stdout, and reports the outcome through its exit code, so the parts compose in a shell pipeline. style, format, table and join print and exit. The interactive commands draw their frame on the terminal, and when stdout is redirected the frame goes to STDERR, so the selection on stdout stays clean. Keys always come from the terminal, never from a pipe. The exit codes are the contract: 0 on success, 1 when the user aborts with Esc (except in pager), 130 on Ctrl+C, 124 on a --timeout deadline, and 128 plus the signal number on an OS signal.

Keys and input

Every interactive command is keyboard-driven — the README carries the full key map (arrows and Enter navigate; j/k and g/G move and jump in lists, the vim style applies except in filter where they are typed into the query; Esc aborts with exit 1 except in pager, where it finishes like q; Ctrl+C aborts with 130). There is no mouse. Color follows one contract everywhere: --no-ansi is final, --ansi outranks every environment rule, and FORCE_COLOR, CLICOLOR_FORCE, NO_COLOR, CLICOLOR, and TERM=dumb resolve in that order — the README's Environment section carries the full ladder.

Auto-discovery

candy-scriptui uses PHP attributes to auto-discover commands at runtime. Mark any class extending Symfony\Component\Console\Command\Command with #[Command] (add class-level #[Flag] attributes to declare options — additive, never required) and Application::scan() registers it once the class is loaded:

namespace My\Commands;

use SugarCraft\ScriptUi\Attribute\{Command, Flag};
use Symfony\Component\Console\Command\Command as SymfonyCommand;
use Symfony\Component\Console\Input\InputInterface;
use Symfony\Component\Console\Output\OutputInterface;

#[Command(name: 'mycmd', description: 'Does something useful.', descriptionSection: 'Longer help text.')]
#[Flag(name: 'format', short: 'f', description: 'Output format.', default: 'json')]
final class MyCommand extends SymfonyCommand
{
    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        $output->writeln('format=' . $input->getOption('format'));
        return self::SUCCESS;
    }
}
use SugarCraft\ScriptUi\Application;

// scan() registers the #[Command] classes that are already loaded under the
// namespace, so load them first.
class_exists(\My\Commands\MyCommand::class);

$app = new Application();
$app->scan('My\Commands');
$app->run();                 // mycmd --format yaml  →  format=yaml

Tasks

Branch on an abort. A cancelled choose exits 1, so the script can tell a pick from a cancel.

if ! choice=$(candy-scriptui choose Pizza Burger Salad); then
  echo "nothing selected" >&2
  exit 1
fi

Bound a pipeline with a timeout. --timeout aborts after N seconds with exit 124, so an unattended run cannot wait forever.

git branch | candy-scriptui filter --fuzzy --timeout 30

Run a build under a spinner and keep its exit code. spin forwards the child's own exit code.

candy-scriptui spin --title "Building..." -- make build
echo "make exited $?"

Render a CSV report as a bordered table. --has-header treats the first row as the header.

candy-scriptui table --has-header < report.csv

Output channels & environment

Data (chosen value, rendered table, completion script) goes to STDOUT raw and byte-exact; diagnostics go to STDERR; the interactive frame is painted to the controlling tty (or STDERR when that is the terminal), never into the capture stream. Because STDOUT is raw, quote every capture and never eval it when the input is third-party.

Recent additions: cursor mode has a default; pager gains --hard-wrap and --fade; confirm gains --pointer; format gains --code, --foreground, and --background, and its refusals are localized like every other command's; the color tier is derived from TERM; CANDY_SCRIPTUI_NO_DECORATION strips decoration; an intake read that times out exits 124; a read-only allow-listed GUM_<COMMAND>_<OPTION> mirror eases migration from gum (the README carries the disclosed table and the warning that names are not command-scoped); and the whole help surface (descriptions, option text, Aliases/Examples labels) is localized through the catalogs.

candy-scriptui also reads CANDY_SCRIPTUI_* env fallbacks through a fail-closed allow-list of eighteen presentation option names — CANDY_SCRIPTUI_<OPTION> in uppercase arms that option when no explicit CLI flag is given, and names outside the list are ignored. Every option that answers for the user, grants capability, or redirects data is excluded by construction — allow-env, default, file, out, value, selected, type, shell, password — so a hostile environment can never retarget a sink or weaken a fail-closed flag. The roster is pinned in EnvVarFallbackTest. That exclusion is the lesson of the old universal option↔env mapping, where CANDY_SCRIPTUI_ALLOW_ENV='*' could arm format --type template to exfiltrate the whole environment and CANDY_SCRIPTUI_DEFAULT=yes silently answered confirm; both names now sit outside the allow-list and are ignored with no notice.

Theming and styling

style applies ANSI attributes to its arguments or to stdin, and takes --foreground, --background and --bold. format accepts the same color flags, and also --code. The color tier is derived from TERM, so the palette follows the depth the terminal advertises. CANDY_SCRIPTUI_NO_DECORATION strips the decoration when a script needs plain output. The color contract above applies to every command.

Examples

  • examples/cli.php builds an Application in-process, adds one custom status command, and runs the argv through it. php examples/cli.php status prints OK and exits 0. php examples/cli.php stat exits 1 with the typo suggestion Did you mean "status"?.
  • examples/setup-script.sh is an interactive shell script. It chooses a shell flavor, confirms it, and branches on the confirm exit code. It uses a candy-scriptui on the PATH when one is present, and otherwise this checkout's bin/. Run it from a terminal.
php examples/cli.php status
./examples/setup-script.sh

Troubleshooting and FAQ

An interactive command exits 1 with a notice on STDERR

It has no usable controlling terminal. choose, confirm, filter, input, write, file and pager refuse up front rather than paint a fake session. Run them from a terminal, or give them input and output that a terminal can reach.

The captured output contains the interactive frame

It should not. When stdout is redirected, painting goes to STDERR, and only the answer goes to stdout. Quote every capture, and never eval the output of a third-party script.

A script cannot tell a timeout from the child's own exit code

spin forwards the child's exit code verbatim, the same as gum. A child that exits 2, 124, 130 or 143 looks the same as a timeout or an interrupt. Gate on the child's success (0) rather than on a specific non-zero code.

A discovered command is not found

Application::scan() registers only the classes that are already loaded. Call class_exists() on each class first, as the auto-discovery example does.

An environment fallback has no effect

The fallback applies only to allow-listed options, and only when no CLI flag is given for that option. Check the name against the eighteen-option list, and check that the flag is absent from the command line.

Upstream mapping

candy-scriptui follows the command set and the exit-code conventions of gum. SugarCraft is developed as a native PHP project, so the mapping is a port of behavior, not of Go code.

Architecture

Application is the Symfony Console shell. It adds scan(), add() and the version ladder. Each subcommand is one class in Command/. The interactive commands build a model from Model/, which holds the state of one screen, and they hand it to Runtime/InteractiveRuntime. That class is the single launch point for every interactive run. It keeps keys on the terminal and sends the frame to STDERR when stdout is redirected. Process/RealProcess runs the child for spin. Discovery/CommandScanner finds the #[Command] classes, and Style/StyleBuilder builds the styles. Help/ and Completion/ hold the help and completion generators, and Lang is the i18n facade.

Changelog and versioning

The version comes from the phar metadata first, then from the nearest composer.json with a version, and finally from a dev fallback. The rolling phar is rebuilt for every commit that touches the app, so pin a sha256 sidecar if a script must stay on one build. The README's compatibility section covers the gum invocations.
