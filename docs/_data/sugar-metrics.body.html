sugar-metrics is a telemetry library. It offers six instrument kinds (counters, gauges, histograms, up-down counters, and asynchronous counters and gauges that read a callback at collection time), a Registry facade that forwards every emit to a pluggable backend, per-metric cardinality limits, and a drop-in middleware that records SSH session telemetry for sugar-ssh-server. It ships five backends: in-memory, newline-delimited JSON, StatsD/DogStatsD over UDP, a Prometheus textfile-collector file, and a multi-backend fan-out. The registry and the Prometheus and StatsD sinks mirror the charmbracelet/promwish design, and the instrument kinds follow the OpenTelemetry metrics API.

Install

composer require sugarcraft/sugar-metrics

Requires PHP 8.3 or newer. The manifest names no native extensions itself. ext-intl and ext-mbstring arrive through sugarcraft/sugar-core. The SSH middleware also pulls sugarcraft/sugar-ssh-server, which brings ext-ffi through sugar-pty. The Registry, the instruments and every backend never load that stack, so a consumer that skips SessionMetrics autoloads none of its code. Check the extensions before you wire metrics into a minimal container.

Sibling packages track dev-master, so the plain command above needs dev stability allowed. Pin with composer require sugarcraft/sugar-metrics:@dev, or set minimum-stability to dev with prefer-stable set to true.

Quickstart

use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\StatsdBackend;

$reg = Registry::new(StatsdBackend::new('127.0.0.1', 8125));

$reg->counter('http.requests', 1, ['route' => '/api/foo', 'status' => '200']);
$reg->gauge('queue.depth', 42);

$stop = $reg->time('http.duration', ['route' => '/api/foo']);
// ... do the work being timed ...
$elapsed = $stop();          // records one histogram sample and returns the seconds

// Pre-tag every emit made through the child registry:
$req = $reg->withTags(['request_id' => $rid, 'user' => $userId]);
$req->counter('events');

Nothing leaves the process until a backend writes it. The StatsD backend sends one UDP datagram per emit, and a failing sink does not stop the caller by default, because failSilently is on.

Start with an in-memory registry

For tests and boot probes, Registry::inMemory() accumulates everything in process, and Registry::to($target) streams newline-delimited JSON to a path, a resource, or php://stderr when the target is null:

use SugarCraft\Metrics\Registry;

$reg   = Registry::inMemory();
$audit = Registry::to('/var/log/app/metrics.jsonl');

Concepts

Primitives

PrimitiveBehaviour
CounterMonotonic value that accumulates, such as connect counts or errors. Negative samples are refused.
GaugeInstantaneous value that replaces the last one on each set, such as queue depth or resident memory.
HistogramDistribution of samples, such as latency or payload size. Negative samples are refused.
UpDownCounterSynchronous counter that accepts positive and negative increments, such as active connections.
AsyncCounterCounter backed by a callback. observe() reads the callback and emits the current external total.
AsyncGaugeGauge backed by a callback. observe() emits one instantaneous external reading.

Nothing is sampled on a timer. Async instruments run their callback only when you call observe(), and the library arms no timers of its own.

Tags are labels

A tag is a key and value attached to an emit. The Prometheus text format calls the same thing a label, and PrometheusFileBackend translates between the two. Every distinct tag combination is a separate time series, so a tag that carries a user id or a request id multiplies the series count. Hash or bucket such values before you tag with them.

Instruments hold their tags

The factory methods return instrument objects for repeated use. Tags passed to a factory ride on every call the instrument makes, and per-call tags merge over them, with the per-call value winning on a conflict. The $help string is metadata that the instrument carries. Prometheus # HELP lines come from Descriptor registration, not from factory calls.

Flushing is explicit

Stream and socket backends write as they record. The Prometheus textfile backend rewrites its file only inside flush(). Call flush() from your own schedule, for example once per scrape interval or at session close. The destructor flushes as well, but it swallows any error it hits, so do not depend on it for delivery.

Tasks

Count active connections with an up-down counter

use SugarCraft\Metrics\Registry;

$reg   = Registry::inMemory();
$conns = $reg->newUpDownCounter('server.active_connections', 'Active server connections', ['host' => $host]);

$conns->add(1);     // connection opened
// ... later, when the connection closes ...
$conns->add(-1);    // connection closed

Observe an external total with an async counter

use SugarCraft\Metrics\Registry;

$reg = Registry::inMemory();
$gc  = $reg->newAsyncCounter('jvm.gc.count', 'JVM garbage collection count', fn() => $jvm->gcCount());
$pool = $reg->newAsyncGauge('db.pool.size', 'Open database connections', fn() => $pdo->poolSize());

$gc->observe();                          // runs the callback now and emits the reading
$pool->observe(['shard' => 'eu']);    // static and per-call tags merge on this sample

Time a block and keep the sample

The stop function returns the elapsed seconds, so the same measurement can feed a log line as well as the histogram. The timer uses the monotonic clock, so a system clock step cannot produce a negative duration:

use SugarCraft\Metrics\Registry;

$reg  = Registry::inMemory();
$stop = $reg->time('report.render', ['format' => 'pdf']);
// ... render the report ...
$seconds = $stop();          // one histogram sample is recorded here
echo sprintf("rendered in %.3fs\n", $seconds);

Fan out to StatsD and a JSON audit trail

use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\{JsonStreamBackend, MultiBackend, StatsdBackend};

$reg = Registry::new(MultiBackend::new(
    StatsdBackend::new(),
    JsonStreamBackend::new('./metrics.jsonl'),
));

With the plain constructor, the fan-out stops at the first child that fails, and that failure propagates unchanged. MultiBackend::withContinueOnError() gives every child its turn and rethrows the collected failures together, as a MultiBackendException.

Publish a Prometheus textfile for node_exporter

use SugarCraft\Metrics\{Descriptor, Registry};
use SugarCraft\Metrics\Backend\PrometheusFileBackend;

$reg = Registry::new(PrometheusFileBackend::new('/var/lib/app/metrics.prom'));

// Declared families show their # TYPE and # HELP lines before the first sample.
$reg->register(Descriptor::new(
    name: 'http_request_duration_seconds',
    help: 'HTTP request duration in seconds',
    type: 'histogram',
    labelKeys: ['route', 'status'],
));

$reg->histogram('http_request_duration_seconds', 0.042, ['route' => '/api/foo', 'status' => '200']);
$reg->flush();            // the file is rewritten here, atomically

Point node_exporter at the directory with --collector.textfile.directory. Each flush stages a uniquely named temporary file and renames it over the target, so a scrape never reads a half-written file.

Instrument SSH sessions

use SugarCraft\Metrics\Middleware\SessionMetrics;
use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\PrometheusFileBackend;
use SugarCraft\SshServer\Server;

$reg = Registry::new(PrometheusFileBackend::new('/var/lib/ssh/metrics.prom'));

Server::new()
    ->use(SessionMetrics::new($reg))
    ->serve();

Per session the middleware emits ssh.session.connect (a counter), ssh.session.duration (a histogram) and ssh.session.error (a counter, when the session ends on an exception). Each carries user and term tags, and the error counter also carries exception. The middleware only emits, so pre-register those names with register() if you want their metadata in the textfile before the first session. Pass an extraTags closure to SessionMetrics::new() to add tags such as a client subnet or build version.

Configuration

Cardinality limits

Each metric name may track up to cardinalityLimit label combinations, 10 000 by default. When the limit is exceeded, the oldest combination is evicted. Eviction drops it from the tracker, and it reclaims the series from the backend when that backend stores series. StatsdBackend and JsonStreamBackend have already sent their lines, so for them eviction bounds the tracker only. The limit applies per metric name, and the set of metric names is not bounded at all. Treat untrusted strings as label values and never as metric names.

use SugarCraft\Metrics\Registry;

$reg = Registry::new($backend, [], 500);      // a 500-combination budget per metric
echo $reg->cardinality('http.requests');     // combinations tracked right now

BackendOptionDefaultEffect

Histogram buckets

The Prometheus backend emits 14 cumulative buckets: 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0, 25.0, 50.0 and 100.0, plus +Inf. The first eleven are the classic client_golang boundaries, and 25, 50 and 100 extend them. Each histogram also emits _count and _sum. The constant is PrometheusFileBackend::DEFAULT_BUCKETS.

Examples

Both examples live in examples/, and both need composer install first.

examples/showcase.php

The flagship example records session counters, gauges and latency samples through an in-memory registry, then prints the totals. It is the example the demo GIF is recorded from.

php examples/showcase.php
=== Counters ===
  ssh.sessions.opened{app=demo}                 2
  ssh.sessions.opened{app=docs}                 1

=== Gauges ===
  ssh.sessions.active{app=demo}                 2
  ssh.sessions.active{app=docs}                 1

=== Histograms ===
  ssh.session.duration_s{app=demo}              count=5  sum=0.100000  avg=0.020000
  demo.work_s                                   count=1  sum=0.007563  avg=0.007563

The demo.work_s line is a measured duration, so its sum changes from run to run. The other figures are fixed inputs.

examples/ssh-server-with-metrics.php

Wires SessionMetrics into a sugar-ssh-server stack. It fans the telemetry out to a Prometheus textfile and an in-memory backend through MultiBackend. The textfile path comes from SSH_METRICS_TEXTFILE when that is set. The example serves the terminal it runs in as one session through the server's in-process transport. It greets the user, writes JSON session events to stderr, and prints the session totals when the session ends. It is not a long-running listener. For that, see sugar-ssh-server.

SSH_METRICS_TEXTFILE=/tmp/ssh.prom php examples/ssh-server-with-metrics.php

Testing

cd sugar-metrics && composer install && vendor/bin/phpunit

The suite lives in tests/. It has one test file per backend under tests/Backend/, tests for each instrument, the registry's cardinality and descriptor rules, and InstrumentSymmetryTest, which checks that the holdable instruments apply the same tag and guard rules. tests/Examples/ExampleSmokeTest.php lints both examples and runs showcase.php to completion. LangLocalesParityTest keeps the 16 locale catalogues in step.

Troubleshooting

Descriptor::new() refuses a dotted metric name

Descriptor::new() and register() check the name raw against the Prometheus exposition charset, so http.request.duration is refused there. Emit dotted names as you like: the Prometheus writer folds dots to underscores on the way out. Register the underscore spelling, such as http_request_duration, so the # TYPE line matches the name that reaches the file.

The Prometheus file never changes

The file is rewritten only inside flush(), and the library arms no timers. Call flush() from your own loop, for example once per scrape interval or at each session close. The destructor flushes too, but it hides its errors.

flush() throws a RuntimeException about a name collision

The Prometheus writer refuses to publish a file when two distinct raw names fold to one metric name, when one name is used for two kinds, or when a histogram's derived _count or _sum clashes with another series. The message names the conflict. Rename one of the metrics, and do not rely on the fold to merge them.

Series counts keep climbing

Usually a tag carries an unbounded value such as a user id, request id or a full URL path. Every distinct value is a new series, and cardinality() shows the count per metric. Bucket the value, or drop the tag. Lower the limit only after the source is fixed, because the limit only evicts the oldest series.

StatsD metrics never arrive

With failSilently on, a send that fails is ignored, so nothing is logged. Pass failSilently: false while you debug, and check that the host and port match your agent. Non-DogStatsD agents do not read the tag segment, so pass dogstatsd: false for them.

A MultiBackend child failure stops the others

That is the default. The plain constructor stops at the first failing child, so later children never see the emit. Build with MultiBackend::withContinueOnError() to give every child its turn, and read the failures with errors() on the MultiBackendException.

Architecture

The registry is a facade over a backend

The Registry validates and bounds each emit, tracks cardinality, and forwards the emit to one Backend. Backends decide how state is stored or sent. The Backend interface has ten methods. Emit methods may throw on structurally invalid input, and a cross-kind name collision is refused loudly. A custom backend implements the same ten methods and returns void.

Untrusted values

Names and tag values from the network are attacker-influenced. The SSH middleware normalises the user and term tags to [A-Za-z0-9._:@/-], collapses everything else to _, and clamps each value to 64 bytes. The same clamp applies to every value an extraTags closure returns. Each backend also sweeps its own wire format. StatsD flattens the characters that would forge a field or a line, the Prometheus writer folds names and labels, and the JSON backend encodes values as JSON strings. Treat untrusted text as a label value, never as a metric name.

Exposition integrity

The Prometheus writer refuses to publish a file it cannot defend. It throws, rather than merging two series that fold to one name, and it repairs malformed UTF-8 to U+FFFD. Each publish is fsynced before it is renamed into place, so a crash leaves either the old file or the new one.

Localization

Every exception message goes through SugarCraft\Metrics\Lang, which sits on the shared SugarCraft\Core\I18n machinery. The library never sets the locale itself. Pin it in the host with \SugarCraft\Core\I18n\T::setLocale('de'). The 16 shipped locales are ar, cs, de, en, es, fr, it, ja, ko, nl, pl, pt, pt-br, ru, tr and zh-cn.

Changelog and versioning

The README has a Breaking changes section that lists every change to public behaviour, with the reason for each. Two entries matter most to upgraders. MultiBackendException::getErrors() became errors(), following the bare-accessor convention. The SSH middleware renamed its metrics from wish.session.* to ssh.session.* after the 2026-10 rename. Any other breaking change follows the same pattern: the README entry names the old call and its replacement.
