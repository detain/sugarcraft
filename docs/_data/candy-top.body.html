Originally inspired by btop (v1.4.7 plus a set of adopted upstream pull requests) and built on the SugarCraft stack, candy-top is a full-screen terminal system monitor in pure PHP. cpu, memory + disks, network, process and containers boxes drawn with braille / block / sextant graphs, gradient meters and themes in the btop tradition, fed by Linux /proc + /sys or FreeBSD sysctl collectors and driven by the CandyCore Model/Cmd runtime. It reads btop's config format, so a btop.conf works unchanged.

Install

composer require sugarcraft/candy-top

Run

vendor/bin/candy-top                      # the live host
vendor/bin/candy-top --config ~/top.conf  # another config file (also the save target)
vendor/bin/candy-top --fake               # deterministic demo data, never the real host
vendor/bin/candy-top --help               # options + the full key list

What's in the box

cpu boxUpper/lower dual-sample graphs (any /proc/stat field), per-core grid with mini graphs and temperatures, load / uptime, frequency (aggregate and per-core, value or graph), battery badge with watts, GPU sub-graphs for the GPUs without a box of their own.
mem + disksUsed / available / cached / free as graphs or meters, a single focused metric (mem_selected), swap + zswap, ZFS ARC, per-mount meters with read/write/busy readouts and a big-graph io mode.
net boxDownload/upload graphs with hysteresis auto-scale and sync, interface cycling, totals zeroing, interface IP in the title.
proc boxSortable list (cpu lazy/direct, memory, io, …), tree view with collapse, live substring / regex filter, detailed view with cwd and IO, signals, renice, follow, pause, IO/R + IO/W columns, per-process Gpu% / GMem columns with a mini GPU graph, gpu / gpu memory sorts and a GPU-only filter (g).
gpu boxesUp to six GPU / NPU boxes toggled with 5–0, laid out side by side (gpu_box_columns) at Full, Compact or Minimal detail, each retargetable with its ← gpuN → title arrows. NVIDIA via nvidia-smi, AMD and Intel GPUs plus Intel / AMD NPUs via sysfs.
Containers + VMsProcesses tagged [engine:name] from their cgroup — docker, podman, k8s, lxc, nspawn — and KVM/QEMU guests by name; one key hides them all. The containers box (x) lists each container's processes, memory and cpu from cgroup v2 with docker names from the socket; [ / ] pick one and the proc box shows only its processes.
btop's menusMain menu, a tabbed options menu with grouped headings and live preview, paged help, signal chooser, renice and warning boxes — over a dimmed backdrop.
Presets + layoutp / P cycle layout presets (with btop #1476's proc width field); Shift/Alt/Ctrl+Shift arrows resize the proc box; boxes toggle with 1–4, the containers box with x, gpu boxes with 5–0.
Themes + TTY modeThe 42 btop themes are bundled, and you can add your own .theme files. TTY mode (16 colours, stepped gradients, tty glyphs) is used on a real console or with force_tty.
Config that persistsbtop-format config.conf, atomic save on exit (also on SIGTERM / SIGHUP), ctrl+r hot reload, every key documented and drift-tested.
MouseEvery border button, list rows, tree markers, a draggable scrollbar, the wheel, and menu tabs and entries all respond to the mouse.

Adopted upstream btop PRs

zswap (#1739), per-core frequency (#1785), interface IPs (#1573), command basename (#1859), per-process IO columns and sorts (#1823), container tags, filter and the containers box (#1873), block2 sextant graphs (#1783), focused mem graph (#1747), disks_order (#1700), cwd in the detail view (#1546), tree branch sorting, option headings and tree-state persistence in an XDG state file (#1791), proc box width and presets W field (#1476), digit option tabs (#1411), reload repaint (#1849), the mellow theme (#1683), WSL nvidia-smi discovery (#1869), GPU boxes with slots and target arrows (#1730), the GPU box grid and detail levels (#1881), Intel and AMD NPUs (#985, #1839), AMD sysfs and multi-Intel GPUs (#1854, #1888), per-process GPU columns, sorts and filter (#1552), and the FreeBSD memory and battery fixes (#1851, #1728, #1830, #1787). The README lists the key, config key and theme tables, which are generated from the source. It also covers data sources, permissions, and every deviation from btop.
