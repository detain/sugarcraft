Image-to-cell renderer for the terminal. PNG, JPEG, GIF (still and animated), APNG, WebP and BMP decoded via ext-gd and rendered via the best available protocol: Sixel, Kitty graphics, iTerm2 inline images, the chafa CLI — or one of the Unicode text tiers: half-block, quarter-block, an ASCII character ramp, or chafa's coverage-class symbol engine.

Install

composer require sugarcraft/sugar-image

Quickstart

use SugarCraft\Image\Mosaic;
use SugarCraft\Image\ImageSource;

$mosaic = Mosaic::halfBlock();
$image  = ImageSource::fromFile('cat.png');
$ansi   = $mosaic->render($image, width: 40, height: 20);
echo $ansi;

API

use SugarCraft\Image\Renderer\QuarterBlockRenderer;

// Probe terminal once, pick best protocol
$mosaic = Mosaic::probe();

// Force a specific backend
$mosaic = Mosaic::sixel();
$mosaic = Mosaic::kitty();
$mosaic = Mosaic::iterm2();
$mosaic = Mosaic::halfBlock();
$mosaic = Mosaic::quarterBlock();
$mosaic = Mosaic::ascii();        // character ramp (Mono/Ansi16/Ansi256/TrueColor)
$mosaic = Mosaic::symbols();      // chafa symbol engine, default 676-glyph corpus
$mosaic = Mosaic::chafa('--colors=256');  // external chafa CLI (opt-in)

// Render — returns ANSI bytes
$ansi = $mosaic->render($image, width: 40, height: 20);

// Builder for fine-grained control; withResize() sets the default cell box
// render() uses when called without a width
$mosaic = Mosaic::builder()
    ->withRenderer(new QuarterBlockRenderer())
    ->withResize(width: 40, height: 20)
    ->build();
$ansi = $mosaic->render($image);          // 40×20 cells
$ansi = $mosaic->render($image, 60);      // explicit width wins; height from aspect

What's in the box

Sixel rendererxterm, foot, mlterm, wezterm, contour support; mlterm and foot are recognised from TERM alone.
Kitty graphics protocolkitty, ghostty, wezterm support.
iTerm2 inline imagesOSC 1337 support for iTerm2, wezterm, mintty.
Unicode half-blockUniversal fallback using ▀ + 24-bit fg/bg.
Unicode quarter-blockHigher fidelity using ░▒▓█ 2×2 sub-pixel rendering.
ext-gd integrationPNG, JPEG, static GIF via GD (imagecreatefrompng, imagecreatefromjpeg, imagecreatefromgif). ImageSource::fromString() also accepts anything imagecreatefromstring() decodes (WebP, BMP, …) with its real MIME in format; the Kitty/iTerm2 renderers re-encode any payload that is not PNG by signature. Animated GIF and APNG load via ImageSource::fromAnimatedFile(). Pixel allocations are bounded before GD is asked for them.
Protocol detectionMosaic::probe() checks environment variables and DA1 capability query. Cached per-process.
Kitty virtual-image placementStore once with KittyOptions::transmit(id)->withUseVirtual(true) (a=T,U=1 payload plus a trailing control-only a=p placement), then reference it at many offsets with KittyOptions::place(id, x:, y:) — a one-shot control-only a=p frame that never carries payload again.
Kitty zlib compressionCompress the PNG payload with zlib before base64-encoding via KittyOptions::withCompression(1) — emitted as f=100,o=z (compression rides the spec's o key). Useful for large images on slow links.
Half-block transparencyTransparent pixels (alpha=127) emit no SGR codes — terminal default background shows through. Enables overlay compositing on existing terminal content.
Sixel 256-color fallbackPass maxColors (1–256) to SixelRenderer constructor to limit palette size for terminals with limited truecolor support.
Symbol-map engine (chafa parity)Unicode braille/sextant/octant/block glyph cells chosen by Hamming-distance candidate search — pure inline SGR, so it always works. Mosaic::symbols(canvas:, workFactor:, symbols:) selects the colour canvas, candidate budget, and chafa's --symbols= tag grammar over the 1,251-glyph effective corpus (1,260 parsed, nine AMBIGUOUS-tagged misc-narrow glyphs BAD-vetoed even by all); the default 676-glyph corpus is byte-frozen. A double-width wide-glyph engine carries the opt-in kana tier.
ASCII character rampMosaic::ascii() maps one luminance sample per cell onto a character ramp; AsciiColorMode::Ansi16 | Ansi256 | TrueColor carries pixel colours on the characters themselves.
chafa CLI tierChafaRenderer shells out to the chafa command with option passthrough — output is bounded and the child is reaped on a TERM→KILL ladder. Binary discovery is gated (InfocmpBinary precedent): a fixed absolute roster or the explicit SUGAR_IMAGE_CHAFA override, never an implicit PATH search. Opt-in only; the pure-PHP tiers above never shell out.
Remote imagesImageSource::fromUrl() / fromUrlAsync() (ReactPHP) with a security floor: scheme allowlist re-checked every redirect hop, and any host resolving to a private/loopback/link-local/reserved address (including cloud metadata) is refused.
Render cachesDiskCache stores finished bytes keyed by URL + size + protocol(+ mode detail) for cross-process redraws; AdaptiveImage is the in-session LRU; ImageLayer reserves marker blocks so images ride inside a text frame without wrecking layout.
tmux passthrough automationtmux panes swallow DCS/APC/OSC graphics unless allow-passthrough is on; TmuxPassthrough flips it pane-scoped for the render and restores (or unsets) it on retire — fail-soft, never a throw, opt-out via Detect::setAutoPassthrough(false).
Decode budgetsDecoding untrusted input is capped: 64 MiB read budget, a 50-megapixel per-decode ceiling, a 400,000-cell aggregate budget for animated GIFs, and a bounded RIFF walk for WebP — every cap pinned by tests.
Animation supportAnimation (immutable frame sequence) + AnimationDriver (Model with tick-based frame timing). Use KittyRenderer::renderFrame() for stable per-frame ids that support targeted redraws.
