The wire contract for the candy-code.v1 serve protocol, in one small package. Clients that talk to a running candy-code serve read the same discovery record, token file and WebSocket URL through it, so the rule lives in one place. It only reads: writing the token, creating the state directory and running the server stay with the host. First-party: original work, with no upstream Go port.

Install

composer require sugarcraft/sugar-serve-protocol

Requires PHP 8.3 or newer. The package has no runtime dependency beyond PHP. sugarcraft/sugar-mcp-client is a dev-only requirement, used by the test suite to pin the JSON-RPC envelope.

Quickstart

use SugarCraft\ServeProtocol\Auth\TokenFile;
use SugarCraft\ServeProtocol\Discovery\StateDirReader;
use SugarCraft\ServeProtocol\Url\WebsocketUrl;

$dir = StateDirReader::existing('/home/me/.local/state/candy-code');
$token = $dir === null ? null : TokenFile::read($dir);
$url = WebsocketUrl::from('http://127.0.0.1:7420'); // "ws://127.0.0.1:7420/ws"

A runnable version lives in examples/read-state.php (see Examples). The URL rule prints the following for a set of addresses:

Concepts

The package is the read side of the serve protocol's state. A client looks for the server's state directory, reads the discovery record that names the running process, reads the bearer token, and turns the address the server printed into the WebSocket URL it dials. Most reads return null when there is nothing usable, and an unreadable discovery record answers null just like an absent one. The state directory check throws when the directory is present but not private, and the token read throws when the token file is present but cannot be read, so a caller can tell an absent server from a refused state directory or token.

The package also holds the wire constants: the subprotocol name, the frame cap and the approval expiry. These values are the contract. The host reads them from Protocol (through ServerConfig, the dispatcher and PendingAsk), so changing a value here changes the wire the server speaks.

The laws

Read side onlyDiscovery, token and URL helpers read and normalise. A missing file answers null; an unreadable state directory or token file throws, so a token is never silently replaced. An unreadable discovery record answers null.
Private stateA state directory that is a symbolic link, a file, the wrong owner or a mode other than 0700 is refused, not followed.
Bounded parsingDiscovery records are decoded to a bounded depth and returned raw, so field-level checks stay with the host.
Pinned, not sharedThe package ships no JSON-RPC codec. Its tests pin the envelope against the codec of sugar-mcp-client, a dev-only requirement. The running candy-code serve speaks its own candy-code.v1 codec (candy-code/src/Protocol/JsonRpc.php), so a fix made in one does not reach the other. Install sugarcraft/sugar-mcp-client yourself to use its JsonRpc class from your own code.

Tasks

Get the URL of a running server. LiveRecord::url() reads server.json and answers the record's URL only when the process it names is still the same process. A stale record answers null.

use SugarCraft\ServeProtocol\Discovery\LiveRecord;

$url = LiveRecord::url($stateDir); // null when no live server is recorded

Read the bearer token. TokenFile::read() returns the 64-character lowercase hex token. A null return means there is no usable token, so the host may mint a new one. An exception means the file exists and could not be read, so the caller must stop rather than replace it.

use SugarCraft\ServeProtocol\Auth\TokenFile;

try {
    $token = TokenFile::read($stateDir);
} catch (\RuntimeException $e) {
    // Unreadable: report it and stop. Do not write a new token over it.
    fwrite(STDERR, $e->getMessage() . PHP_EOL);
    exit(1);
}

Normalise an address the user typed. WebsocketUrl::from() accepts http(s):// and ws(s):// addresses and returns the /ws URL. Anything else returns null, and so does a malformed IPv6 host. The candy-code host's Attach::websocketUrl delegates here, so both refuse the same inputs.

use SugarCraft\ServeProtocol\Url\WebsocketUrl;

$url = WebsocketUrl::from('https://[2001:db8::1]:7420'); // "wss://[2001:db8::1]:7420/ws"
$none = WebsocketUrl::from('ftp://example.test');        // null

Check that a state directory is private before using it. StateDirReader::existing() returns the trimmed path of an existing private directory and null when nothing exists there. It throws when the path exists but is a symbolic link, a file, owned by another user, or not mode 0700.

use SugarCraft\ServeProtocol\Discovery\StateDirReader;

$dir = StateDirReader::existing($stateDir); // throws on an unsafe directory

Read a discovery record without trusting its fields. DiscoveryRecordReader::read() returns the validated raw array. Field checks such as the pid and the URL belong to the caller, or to LiveRecord for the running-server case.

use SugarCraft\ServeProtocol\Discovery\DiscoveryRecordReader;
use SugarCraft\ServeProtocol\Discovery\LiveRecord;

$record = DiscoveryRecordReader::read($stateDir . '/' . LiveRecord::FILE); // ?array

Configuration

The package takes no options. Its fixed values are the wire constants in Protocol, the request path WebsocketUrl::WS_PATH (/ws), the directory mode PrivateDirCheck::MODE (0700), the JSON depth limit DiscoveryRecordReader::MAX_DEPTH (8), and the file names TokenFile::FILE (token) and LiveRecord::FILE (server.json). The state directory is passed in by the caller, so where it lives is the host's choice.

Use it for

  • Attaching to a running server — the attach command (candy-code/src/Cli/Attach.php) and the remote session push (candy-code/src/Session/Import/RemoteSessionPush.php), which both normalise addresses through WebsocketUrl.
  • Discovery tooling — anything that needs the server's URL or token without starting it.

Examples

Both examples run from the library root after composer install, and neither needs a running server.

  • examples/read-state.php builds a private state directory in the system temp area, writes a discovery record naming its own process and a token file, reads both back through the package, and removes them. It shows the state directory check, the token read, the live URL and the absent-directory answer.
  • examples/websocket-url.php prints the dial URL for a set of addresses, and marks as refused the malformed inputs the package rejects on purpose.

Testing

cd sugar-serve-protocol
composer install
vendor/bin/phpunit

The suite covers each reader and the URL rule. It builds its state trees in temporary directories through tests/Support/TempTree.php. JsonRpcCodecWiringTest needs sugarcraft/sugar-mcp-client, which composer install installs as a dev dependency.

Troubleshooting

  • StateDirReader::existing() throws "server state directory … is mode 0755, not 0700". The reader refuses a directory whose mode is not 0700 and does not change it. Run chmod 700 on the directory, as the message says.
  • StateDirReader::existing() throws "is owned by uid N, not by this user". The directory belongs to another account. Run the client as the owning user, or point it at that user's own state directory.
  • TokenFile::read() throws "exists … but cannot be read; refusing to replace it". The token file is present but the current user cannot read it. Fix its permissions. The package never rewrites the token, so a replacement is the host's decision to make.
  • TokenFile::read() returns null for a token file that exists. After trimming whitespace, the content must be exactly 64 lowercase hex characters. Uppercase hex, a short value and a symbolic link all read as no usable token. Have the host write a fresh token.
  • WebsocketUrl::from('http://::1') returns null. A bare IPv6 host cannot be split from its port. Bracket the host: http://[::1]:7420.
  • LiveRecord::url() returns null while the server appears to run. The record must hold a positive integer pid and a non-empty url. If procStartTime is present and differs from the process's start time, the pid was reused and the record is stale. Restart the server so it writes a new record.

Upstream

There is no Charmbracelet upstream for this package. The serve protocol is specific to SugarCraft's candy-code agent, so there is no port to map class by class. The host-side code that shares this contract lives in candy-code/src/Server/ and candy-code/src/Cli/Attach.php. Those files delegate here: Cli/Attach.php normalises addresses with WebsocketUrl, Server/StateDir.php and Server/DiscoveryFile.php use the readers, Server/Auth/TokenStore.php uses TokenFile, and Server/ServerConfig.php takes its constants from Protocol.

Changelog and versioning

Protocol::MAJOR (1) is the wire version a client negotiates, and the subprotocol string candy-code.v1 carries it. This tree keeps no separate changelog for the package; its history is the git log of sugar-serve-protocol/.
