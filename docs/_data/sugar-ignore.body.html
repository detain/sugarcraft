The gitignore engine a repository-walking tool needs, so every app answers "is this path ignored?" the same way. It never touches the filesystem: the caller injects each ignore file's contents as a path-to-text map, so a TUI, a git server and a tree browser can share one engine. A cloned repository supplies both the patterns and the paths, so patterns are treated as hostile input. The semantics follow git's gitignore(5). There is no Charmbracelet upstream; this library is first-party.

Install

composer require sugarcraft/sugar-ignore

Requires PHP 8.3 or newer. The package has no runtime dependencies beyond PHP.

Quickstart

use SugarCraft\Ignore\IgnoreRules;

$rules = IgnoreRules::fromPaths([
    '.gitignore'        => file_get_contents('.gitignore'),
    'pkg/.gitignore'    => "!keep.log\n",
    '.git/info/exclude' => "scratch.txt\n",
]);

$rules->ignores('app/debug.log', false);  // ".gitignore: *.log" (the deciding rule) or null
$rules->isIgnored('pkg/keep.log', false); // false
$rules->ignores('build', true);           // directory-only rules need $isDir

Paths are root-relative. The map keys name the ignore files, and each file applies only beneath its own directory.

Concepts

The caller owns all IO. IgnoreRules::fromPaths() takes a map of ignore-file path to contents, and the engine never reads a file itself. Each file is scoped to its own directory, a deeper file overrides a shallower one, and .git/info/exclude ranks below every .gitignore, as it does in git.

Ancestors decide first. ignores() tests every ancestor directory before the path itself, shallowest first, and the first ignored ancestor wins outright. Nothing under an ignored directory can be re-included, and a nested ignore file inside an ignored directory never applies.

The answer is the rule. ignores() returns the deciding <file>: <pattern> string, which is what a UI shows when it explains why a file is hidden. isIgnored() is the boolean form of the same question.

Every call passes $isDir. A pattern with a trailing slash matches only directories, and a path string alone cannot say whether it names one.

Tasks

Use it for

  • Agent file tools: candy-code's Glob, Grep and Ls skip the same paths a git checkout would, through candy-code's Tools\IgnoreRules wrapper.

Add one ignore file after construction

withFile() returns a new instance that carries one more file, or replaces an existing one. The receiver is unchanged.

$rules = IgnoreRules::fromPaths(['.gitignore' => "*.log\n"]);
$rules = $rules->withFile('pkg/.gitignore', "*.tmp\n");   // a new instance

Explain why a path is hidden

if (($why = $rules->ignores($path, $isDir)) !== null) {
    $status = "hidden by {$why}";   // e.g. "hidden by .gitignore: *.log"
}

Pass absolute paths with a root

Give fromPaths() a root and absolute paths under it are stripped to root-relative. An absolute path outside the root has no jurisdiction, so it answers "not ignored".

$rules = IgnoreRules::fromPaths(['.gitignore' => "*.log\n"], '/srv/repo');

$rules->ignores('/srv/repo/app/debug.log', false); // ".gitignore: *.log"
$rules->ignores('/etc/passwd', false);             // null

The engine has no environment variables and no config file. Its only knobs are the root argument and two public constants.

Semantics

The engine supports # comments and \#, blank lines, trailing whitespace unless escaped, ! negation (the later rule wins), trailing / for directory-only rules, leading or inner / for anchoring, bare patterns that match at any depth, * ? [...] and [!...], the **/, /** and a/**/b forms, backslash escapes, nested ignore files, and git's rule that nothing under an ignored directory can be re-included.

It deliberately does not support global excludes, git config, case folding, or the index. A tracked file still counts as ignored when a pattern matches it. Matching is case-sensitive.

Hostile patterns

A cloned repository supplies both the ignore file and the paths, so a pattern is hostile input. Simple shapes such as *.log, **/foo and foo/** run on PCRE. Anything that could backtrack runs on a lazily built automaton (Automaton) that never backtracks.

A rule whose cost still exceeds the budget is undecidable. It fails closed: a hide rule hides, and a negation does not re-include. Each such rule is recorded on undecidableRules() instead of being logged, because stderr under a TUI is nowhere a user reads.

Troubleshooting and FAQ

A pattern I wrote does not match

A leading or inner slash anchors the rule to its ignore file's directory, so /secret.env matches only at the root. A bare name such as *.log matches at any depth. A trailing slash matches only directories, so pass $isDir = true for the directory itself.

A file stays hidden after a ! negation

Git cannot re-include a file while a parent directory is excluded, and the engine follows that rule. Negate the directory itself, not the file beneath it.

undecidableRules() is not empty

A pattern exceeded the matching budget, so it resolved toward hiding. Shorten or split the rule. The list names the ignore file and the pattern.

foreach ($rules->undecidableRules() as [$file, $pattern]) {
    error_log("undecidable in {$file}: {$pattern}");   // log it outside the TUI
}

An absolute path is never ignored

Pass the same root to fromPaths(), or give paths relative to it. With a root set, an absolute path outside that root has no jurisdiction and answers "not ignored". With no root, the leading slash is trimmed and the rest is matched, so /abs/app/x.log is matched as abs/app/x.log.

Architecture

Four classes make up the engine. IgnoreRules is the public facade: it scopes each file, ranks the rule files, and caches verdicts per directory. Its public fields are readonly, and every with*() method returns a new instance. Pattern parses one ignore line into tokens and a PCRE regex, and carries the directory-only and negation flags. Automaton matches a pattern's tokens with a lazily built, backtrack-free automaton. Token names the token kinds: literal, single character, character class, star, globstar and directory separator.
