CandyMail builds and sends email. An immutable Email value carries the addresses, subject, plain and HTML bodies, attachments and headers. A Transport delivers it over SMTP, the Resend HTTP API or the Mailgun HTTP API, and Mailer checks the envelope before the transport dials. The package also ships a command-line sender and a compose TUI. It mirrors the send path of charmbracelet/pop, which sends through go-mail; the message model follows go-mail's NewEmail() shape, and the rest is native PHP.

Install

composer require sugarcraft/candy-mail

Requires PHP 8.3 or newer. The Resend and Mailgun API transports need the curl extension, and STARTTLS or implicit-TLS SMTP needs openssl. Plain SMTP works without either. The composer install puts the candy-mail binary in vendor/bin/. A standalone phar is also published; the README's Install section covers both.

Sibling sugarcraft/* requirements track dev-master, so the plain command above only resolves when dev stability is allowed. Pin the package with composer require sugarcraft/candy-mail:@dev, or set minimum-stability to dev with prefer-stable set to true in your consuming manifest. The pin covers the whole sibling closure, so allowing dev for candy-mail alone is not enough. The global install takes the same form: composer global require sugarcraft/candy-mail:@dev.

Quickstart

use SugarCraft\Mail\{Email, ResendTransport, SmtpTransport};

// Immutable: every with*() returns a new Email. The constructor takes named
// arguments too, so a partial build stays readable.
$email = Email::new('noreply@example.com', 'user@example.com', 'Deployment complete', 'Your app was deployed successfully.')
    ->withHtmlBody('<p>Your app was deployed <strong>successfully</strong>.</p>')
    ->withCc('ops@example.com')
    ->withAttachment('build.zip', '/tmp/build.zip');   // display name, then the file on disk

// Credentials come from the environment, never from committed source.
$transport = new SmtpTransport(
    host:     'smtp.example.com',
    port:     587,
    username: (string) getenv('CANDY_MAIL_SMTP_USERNAME'),
    password: (string) getenv('CANDY_MAIL_SMTP_PASSWORD'),
);
$transport->send($email);

// Or over the Resend HTTP API, with the key taken from RESEND_API_KEY
(new ResendTransport())->send($email);

The SMTP transport requires TLS by default, so credentials never travel over a plaintext channel. The candy-mail CLI reads the same CANDY_MAIL_SMTP_* names listed under Configuration.

To see the message without sending anything, build the MIME text offline. No transport or network is involved:

$mime = (new SmtpTransport('smtp.example.com'))->buildMimeMessage($email);
echo $mime;   // headers, the multipart/alternative body and the base64 attachment part

Concepts

An Email is a value. It holds the sender and recipient lists, the subject, the plain and HTML bodies, the attachments and any extra headers. Each with*() returns a new instance, and Email::new() is the one-pair shortcut. The constructor refuses, rather than cleans, any header value that holds a carriage return, line feed or other control byte, so a header cannot forge a second header.

A Transport is the delivery contract. It has a send(Email, ?CancellationToken) method and a name() for logging. Three implementations ship: SmtpTransport, ResendTransport and MailgunTransport. Writing your own means implementing the interface.

Mailer wraps one transport. Before it dials, it refuses an email with no recipient in to, cc or bcc, and an email with no sender. The candy-mail CLI reports a missing transport configuration as MissingTransportConfig, a RuntimeException, and its offline --render fallback catches exactly that type, so a broken configuration stays a loud error. The library does not raise that type: a ResendTransport built with a blank key throws InvalidArgumentException when it sends.

Attachments are read when they are built, not when the message is sent. Attachment::fromPath() reads the file eagerly, so an unreadable path throws at withAttachment() time. A single attachment is capped at Attachment::MAX_BYTES (25 MiB), and the whole message at Email::MAX_TOTAL_BYTES (64 MiB).

Tasks

Send over SMTP with TLS and an explicit CA bundle

$smtp = (new SmtpTransport(
    host: 'smtp.example.com',
    port: 587,
    username: (string) getenv('CANDY_MAIL_SMTP_USERNAME'),
    password: (string) getenv('CANDY_MAIL_SMTP_PASSWORD'),
))->withCaFile('/etc/ssl/certs/corp-ca.pem');

$smtp->send($email);

STARTTLS is the default on port 587, and implicit TLS is selected automatically on port 465. withRequireTls(false) allows a plaintext fallback. Use it only when you accept that the credentials may cross the network unencrypted.

Send through the Resend or Mailgun API

use SugarCraft\Mail\{MailgunTransport, Mailer, ResendTransport};

$resend  = new ResendTransport();                              // reads RESEND_API_KEY when the argument is empty
$mailgun = new MailgunTransport(domain: 'mg.example.com', region: MailgunTransport::REGION_EU);

(new Mailer($resend))->send($email);

A transport constructed with an empty key falls back to the environment. A key that contains whitespace or a control character is refused at construction, before any request is made. One gap remains: a single trailing line feed passes that check, so trim a key read from a file before you pass it. The API transports never send without a key.

Embed an inline image and reference it by content ID

$html = $email
    ->withInlineAttachment('/srv/assets/logo.png', 'logo')   // the cid is the handle
    ->withHtmlBody('<img src="cid:logo" alt="logo"> <p>Deployed.</p>');
$smtp->send($html);   // $smtp from the first recipe; ResendTransport refuses inline parts

The inline part is sent with its content ID, and the HTML body refers to it as cid:logo. Attachment::inline() builds the same value object if you need it outside an Email.

Inline CID needs the SMTP or the Mailgun transport. ResendTransport refuses an inline attachment with an error keyed resend.cid_unsupported, because the Resend API payload has no Content-ID field, so a Resend key never sends this recipe. Send the message with SmtpTransport or MailgunTransport.

Attach bytes that never touch the disk

use SugarCraft\Mail\{Attachment, Email};

$report = Attachment::fromContent($csv, 'report.csv', 'text/csv');
$email  = new Email(
    from:        ['ops@example.com'],
    to:          ['you@example.com'],
    subject:     'Weekly report',
    attachments: [$report],
);

withAttachment() is for files on disk and refuses a missing path. Attachment::fromContent() takes the bytes and a MIME type, and defaults to application/octet-stream when none is given. The constructor's attachments argument accepts the value objects directly.

Send from the command line

printf 'Build 42 is live.\n' | candy-mail --from ops@example.com --to you@example.com --subject "Deploy"
candy-mail --from ops@example.com --to you@example.com --attach build.zip --render < message.txt   # offline preview, nothing sent

The body is read from stdin. --to, --cc, --bcc and --attach repeat. --render prints the composed MIME message and sends nothing, so it needs no transport configured.

Configuration

The library reads no configuration files. Transports take their settings as constructor arguments, and the CLI maps environment variables onto them. Flags beat the environment, and the environment beats the defaults.

The transport is chosen by a ladder, not a merge. A non-blank Resend key wins outright, then the Mailgun key, then SMTP. When more than one transport is configured, --transport=smtp, --transport=resend or --transport=mailgun forces the choice, because the sending domain sets SPF and DKIM alignment.

Keys in the compose TUI

candy-mail tui opens the compose screen, a ComposeModel that runs on the sugar-core Model loop. A bare invocation on a terminal opens it too. Fields are from, to, cc, bcc, replyto, subject, body, html and attach.

KeyAction
Tab, Shift+TabMove to the next or previous field
EnterIn the body or the HTML field, insert a newline. Elsewhere, move to the next field.
Up, DownIn the body or the HTML field, move between lines. Elsewhere, and on the first or last line of those fields, move to the previous or next field.
Left, Right, Home, EndMove the cursor within the field
Backspace, Delete, Ctrl+UDelete before the cursor, after it, or clear the field

Esc on the edit screen, Ctrl+C, Ctrl+QQuit. With unsaved edits the first press asks for confirmation.

Examples

The examples/ directory holds six runnable programs. Five of them print an offline MIME preview unless they find the credentials they need, so none of them sends mail by accident. showcase.php prints a field summary instead of a MIME message.

  • examples/showcase.php builds Email values and prints their fields. It needs no SMTP or Resend access.
  • examples/basic.php sends through the Resend API when RESEND_API_KEY is set. Without a key it prints the composed MIME message.
  • examples/html-email.php adds CC and BCC recipients, an HTML body and an inline CID image, then prints an offline MIME preview. With RESEND_API_KEY set it tries the Resend API instead, which refuses the inline image with the error keyed resend.cid_unsupported, so the run exits 1. Inline CID needs SMTP or Mailgun.
  • examples/attachments.php attaches two files from disk with withAttachment() and prints the offline MIME preview.
  • examples/smtp.php sends over SMTP when CANDY_MAIL_SMTP_HOST is set. Without it, the example prints the offline preview.
  • examples/pipeline.php reads the message body from stdin, takes an optional recipient and subject from the command line, and sends through Resend when RESEND_API_KEY is set. Otherwise it prints the preview. It needs a piped body: with stdin empty or closed it prints a usage line and exits 1.
php examples/showcase.php
php examples/html-email.php           # offline MIME preview; RESEND_API_KEY routes it to Resend, which refuses the inline image

Testing

The suite lives in tests/ and runs under PHPUnit 10. Run it from the package root, with stdin redirected so a stray read cannot hang the run:

vendor/bin/phpunit < /dev/null

The SMTP tests cover the MIME structure, and TlsChannelTest forks a minimal TLS-terminating fake SMTP server to exercise the TLS channel. The Resend and Mailgun tests check the request payload. The compose TUI has its own tests under tests/Tui/.

Troubleshooting

Building an attachment throws a RuntimeException

The path does not exist or is not readable, and withAttachment() reads the file when it is called. Check the path before building the email, or pass the bytes with Attachment::fromContent() instead.

Mailer throws InvalidArgumentException before sending

The email has no recipient in to, cc or bcc, or it has no sender. Add a recipient with withTo() and a sender with withFrom(). The transports never see an envelope that Mailer refuses.

An API key is refused at construction

The key contains a carriage return, whitespace inside the value, or another control character. A trailing carriage return, as left by a Windows-style line ending in RESEND_API_KEY, is a common cause. The check exists because the key is written verbatim into an Authorization header, so a carriage return would forge a second header. A single trailing line feed is the one exception: it passes the check, so trim the value in the environment or after reading it from a file.

Resend refuses a message with only cc or bcc recipients

The Resend API needs at least one to recipient. SMTP accepts a cc or bcc-only send, so the same email can succeed over SMTP and fail over Resend.

The CLI sent through a different provider than expected

A configured Resend key wins over SMTP, and a Mailgun key wins over SMTP when no Resend key is set. Pass --transport=smtp to force SMTP, or --transport=resend and --transport=mailgun to refuse without their credentials.

Architecture

Values in, transports out

The message is built as values, validated, and then handed to a transport. Sending is the only network step. A message can be built, inspected and rendered without one, and buildMimeMessage() exposes the exact bytes a send would produce. Attachments are the one I/O at build time, because they read their files when attached.

Validate before dialing

Mailer refuses an envelope with no recipient or no sender, and a canceled token stops a send before it starts. The SMTP transport validates its own host, port, timeout and EHLO name in the constructor, so a bad value fails where the caller still owns it.

The compose screen is a Model

ComposeModel keeps one TextBuffer per field. Each key returns a new model, and the send is a Cmd that reports back through SendResultMsg, so the view never performs I/O.
