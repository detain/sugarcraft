candy-flappy is a terminal flap game. The bird's vertical motion is a SugarSpring Projectile (gravity plus an upward velocity kick on each flap), pipes slide left one cell per tick, and collision is tested per cell. The game state is a pure value: Game is a SugarCraft Model, so every key, tick and resize returns a new Game, and Renderer paints one frame from it. The design is a native PHP take on flapioca; the Go original ticks at 5 Hz, and this port runs the same one-column-per-tick rule at 30 ticks per second.

Install

Requires PHP 8.3 or newer with the intl and mbstring extensions. The package is pre-1.0 and publishes a dev branch only, so Composer needs the explicit @dev constraint:

composer require sugarcraft/candy-flappy:@dev   # the game binary lands in vendor/bin/candy-flappy

A standalone .phar is published with the GitHub releases and runs with php candy-flappy.phar. A monorepo checkout needs only composer install inside candy-flappy/.

Quickstart

# From a checkout: install the lib's own dependencies, then run the checked-in bin
cd candy-flappy && composer install && ./bin/candy-flappy

# From a Composer install: the vendored console bin
vendor/bin/candy-flappy

candy-flappy --version   # prints the version line and exits 0
candy-flappy --help      # prints the usage and exits 0

The game needs a terminal at least 62 columns by 21 rows, with stdout attached to a real TTY. A smaller window shows a notice screen instead of the board, and a piped stdout is refused with exit 1 before the game starts.

use SugarCraft\Core\Program;
use SugarCraft\Core\ProgramOptions;
use SugarCraft\Flappy\Game;

$final = (new Program(Game::start(), new ProgramOptions(useAltScreen: true)))->run();   // the final model: the Game

Program::run() returns the final model, typed as Model. A q or Esc quit settles a qualifying score inside update(), so that score is on the board before the call comes back. Ctrl+C does the same when the terminal delivers it as a key, as it does under kitty keyboard reporting. On a legacy terminal, Ctrl+C raises SIGINT instead. A signal death (SIGINT, SIGTERM, SIGHUP) skips update(), so a score from a run that ends that way is banked only if you also call settleOnExit() on the returned Game. When the program can receive a signal, check that the result is a Game and call settleOnExit() on it after run() returns, as bin/candy-flappy does. The call is idempotent. Read the best score from the Game with $final->highScore().

Concepts

The board opens on a ready card. The bird hovers and the world stays frozen until the first flap, so a launch never drops the player into the floor. The first flap starts the run and the 30 Hz tick subscription from Game::subscriptions() begins to deliver TickMsg values.

Each tick advances the bird, scrolls every pipe one column, spawns a pipe every Game::PIPE_EVERY ticks, and checks for a crash. A crash happens on the floor (the bird's row reaches Game::HEIGHT), on the ceiling (the row goes above 0), or in a pipe (the bird's cell lies outside the open gap). All three end the run the same way. Score rises by one for every pipe that has just slid past the bird's column, so surviving is scored, not flapping.

The pipe gap is the only progressive difficulty. PipeGenerator::gapHeightForScore() starts at 6 cells, shrinks by 1 every 5 points, and floors at 3. The gap's center row comes from the injected PRNG, so a gap never touches the floor or ceiling rows.

Physics constants

The bird's motion uses three constants on Bird, tuned for an 18-row playfield at 30 ticks per second:

ConstantValueRole
Bird::FLAP_KICK-10.0Upward velocity in cells per second, applied by flap()
Bird::GRAVITY18.0Constant downward acceleration in cells per second squared
Bird::TICKS_PER_SEC30Simulation rate, baked into the projectile's time step

Fall speed is clamped to Projectile::TERMINAL_GRAVITY on every tick. The clamp never engages in ordinary play, because the fastest reachable fall peaks at about 25.4 cells per second while the bird is still inside the 18-row world, and at about 26 on the tick that reaches the floor. Both sit under one row per tick, so the bird cannot tunnel through a gap unchecked.

Tasks

Run the game headless and read the frame

use SugarCraft\Flappy\Game;
use SugarCraft\Flappy\Renderer;

$game  = Game::start();
$after = $game->tickN(30);         // advance 30 ticks, one second of physics, with no terminal
echo Renderer::render($after);     // the full ANSI frame, as a string

Game::tickN($n) applies $n physics ticks in sequence. It is the deterministic helper the suite uses, and it needs no terminal.

Pin the pipe layout with an injected PRNG

use SugarCraft\Flappy\Game;

// The closure receives the inclusive upper bound and returns an int in 0..$max.
$pinned = Game::start(rand: static fn (int $max): int => intdiv($max, 2));

Every pipe gap is drawn through the closure, so the same seed gives the same board. Game::start() takes the closure as its first argument and a config directory as its second.

Read and merge the leaderboard

$game = Game::start();
$game->highScores();              // the kept top-ten list, lowest first (ascending)
$game->highScore();               // the best score, 0 when the board is empty; read this, not highScores()[0]
$merged = $game->withHighScore(42);   // a new Game with 42 merged in; nothing is written to disk

withHighScore() only changes the in-memory board. The write happens through the Cmd the game returns on a finish, so a test or a script can check a score without touching the score file.

Reset the leaderboard

rm ~/.config/.candy-flappy/scores.json      # or $XDG_CONFIG_HOME/.candy-flappy/scores.json

The next launch starts with an empty board. The lock sidecar next to the file stays in place on purpose; the lock is the anchor for concurrent writers, and removing it while another instance waits would race that instance.

Run the bundled example from a checkout

php examples/play.php --version
FORCE_COLOR=1 php examples/play.php   # draws into a pipe on purpose; use a real terminal for play

The example mirrors the binary: it answers --version and --help, refuses unknown arguments with exit 2, and refuses a non-TTY stdout with exit 1 unless FORCE_COLOR or CLICOLOR_FORCE is set.

Configuration

Almost nothing is configurable, on purpose. The physics, tick rate, gap bands and key bindings are compiled in, because the leaderboard and the difficulty curve form one game, and knobs would let a session claim scores the defaults could not produce. What the environment controls is where the leaderboard lives and how color is drawn.

SettingTypeDefaultEffect
XDG_CONFIG_HOMEabsolute pathunsetConfig base for the score file. Falls back to HOME/.config. With neither set the game refuses to launch rather than guess.
HOMEabsolute pathsystem valueUsed only when XDG_CONFIG_HOME is unset.
NO_COLORany non-empty valueunsetForces the ASCII posture.
CLICOLOR_FORCE, FORCE_COLORany non-empty value except 0 or falseunsetForces color on where detection would withhold it, and lets the bin draw into a pipe on purpose.
TERMterminal namesystem valuedumb gets the plain refusal screen.

The leaderboard lives at <config base>/.candy-flappy/scores.json. The directory is mode 0700 and the file is mode 0600. A write goes through sugar-core's AtomicJsonFile (flock plus temp-and-rename), never a bare truncating write.

PipeGenerator::GAP_DEFAULT, GAP_MIN6, 3Gap height at score 0, and the floor it shrinks to

Game::MAX_SCORE_FILE_BYTES65536Larger score files are quarantined, not read
Game::SCORE_CEILING100000Scores at or above this are refused on read and write, so 99999 is the highest score the board keeps

Keys and input

InputAction
Space, Enter, ↑, w (either case)Flap. The first flap also starts the run.
Mouse click or touch tapFlap. The first click also starts the run.
rRestart after a crash or mid-flight. A qualifying mid-flight score is settled first, and the run lands on the ready card.
q, Esc, Ctrl+CQuit. A qualifying mid-flight score is saved before the process exits.

Other Ctrl chords do nothing. On terminals without kitty-protocol reporting, Ctrl+M and Ctrl+J arrive as Enter and flap, and Ctrl+[ is byte-identical to Esc and quits.

Color and styling

Color follows sugar-core's ColorProfile::detect(). The game reads the profile the terminal reports through ColorProfileMsg. A NoTty profile gets the refusal screen and quits, and NO_COLOR selects the ASCII tier, which draws the same layout with plain glyphs. The game has no theme file, and the glyphs and colors are fixed by Renderer.

Testing

The suite lives in tests/ and runs under PHPUnit 10. Run it from the package root with stdin redirected, so a stray read cannot hang the run:

cd candy-flappy && composer install && vendor/bin/phpunit < /dev/null

The tests drive the physics with tickN() and an injected PRNG, check the rendered frame with golden snapshots (GoldenRenderTest), and cover the binary's flags and preflight (BinFlagsTest, BinNoTtyPreflightTest). LocaleParityTest keeps every lang/ catalog in step with the default.

Troubleshooting

"needs an interactive terminal on stdout" and exit 1

Stdout is a pipe or a file. Run the game in a terminal window. To draw into a pipe on purpose, set FORCE_COLOR=1, which is the same escape hatch the bin honors.

A notice screen instead of the board

The viewport is smaller than 62 columns by 21 rows. Resize the window. The world stands still while the notice shows, and Game::subscriptions() returns null, so no ticks are spent.

The game refuses to launch

Neither XDG_CONFIG_HOME nor HOME is set, so there is no config base to write the leaderboard into. Export one, for example export XDG_CONFIG_HOME=$HOME/.config. The game refuses rather than guess a location.

The leaderboard is empty, or a file named scores.json.corrupt-<timestamp> appears

A corrupt, unreadable or oversized save was set aside, and play started with an empty board so a bad file cannot block launch. Inspect the quarantined file if you need the old scores. Entries that are not whole positive scores below SCORE_CEILING are dropped on read.

A score was not saved

A save that fails mid-run gives up silently. A failed end-of-run save prints one warning line to stderr. A score is written only when it earns a slot on the board, so a run that does not beat the lowest entry on a full board leaves the file alone.

Upstream mapping

Upstream (Go or library)candy-flappy (PHP)
kbrgl/flapioca, the game loop and the bird and pipe rulesGame, Bird, Pipe, PipeGenerator
flapioca's draw passRenderer::render(), a one-pass canvas fill
Projectile motion (not in flapioca)SugarSpring Projectile, used by Bird

The tick rate differs from upstream on purpose. Flapioca slides at 5 cells per second; candy-flappy runs the same rule at 30 ticks per second, and the difficulty curve is tuned against that faster clock.

Architecture

Pure state, one frame per update

Game never mutates. Carry-through transitions (flaps, ticks, resizes, blur, settling) build a new instance through mutate(), so their field list lives in one place. start() and the two restart arms reset the board and call the constructor directly, so a new field must also be listed in those constructor calls; the restart arms pass the live viewport explicitly, so a restart cannot drop it. view() is a pure function of the state, so a test can compare two frames without a terminal.

Subscriptions drive the clock

The tick cadence is a subscription with a stable id, not a loop inside the Model. Program reconciles the subscription each cycle, which keeps exactly one tick chain alive across restarts and cancels it when the game stands down, so a dead bird or a frozen ready card burns no timer.

Persistence runs as a command

The leaderboard write is a Cmd that update() returns, so the synchronous reducer never touches the disk. The bin and the example also call settleOnExit() at the process boundary as a safety net for signal deaths.
