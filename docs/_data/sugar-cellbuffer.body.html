Immutable Buffer (2-D cell grid) and Cell (rune, style, link, width) value objects forming the shared data model for terminal rendering across the SugarCraft ecosystem. Wide-char (CJK/emoji) cells declare width=2; the writing API enforces the width-0 continuation pair for you.

Install

composer require sugarcraft/sugar-cellbuffer

Quickstart

withCellAt(5, 1, Cell::new('H'));

// Blit a seeded 2x2 sub-buffer at origin — seeding matters: blitting an
// all-blank sub-buffer over blank cells is a visible no-op.
$sub = Buffer::new(2, 2);
$sub = $sub->withCellAt(0, 0, Cell::new('A'))->withCellAt(1, 0, Cell::new('B'));
$sub = $sub->withCellAt(0, 1, Cell::new('C'))->withCellAt(1, 1, Cell::new('D'));
$buf = $buf->withRegion(Region::new(Position::new(0, 0), 2, 2), $sub);

// Read a cell back.
$cell = $buf->cellAt(5, 1);
echo $cell->rune(); // 'H'

// Access dimensions.
echo $buf->width();  // 20
echo $buf->height(); // 3

What's in the box

BufferImmutable 2-D cell grid: the fluent with*() family plus fill(), copy() and applyDiff() (not named with*, equally immutable — every mutation returns a new instance). Bounds-checked cellAt() throws OutOfRangeException.
CellReadonly value object: rune (string), style (?Style), link (?Hyperlink), width (int). Cell::continuation() for wide-char neighbour cells. No with*() — rebuild via new.
Position2-D coordinate (col, row) with bare accessors. Negative coordinates may be used for relative offsets.
RegionRectangular sub-region defined by Position origin + width/height. contains() helper for hit-testing; zero-area regions no-op in fill()/withRegion().
StylePer-cell pen: foreground/background as RGB 0xRRGGBB or palette-slot identity (0-255), underline color, and an attribute bitmask. The with*() builders keep slot and RGB mutually exclusive per channel; the public fromSgr() parses SGR parameter strings back into styles. The rich styling API (border, padding, transforms) lives in sugar-style.
HyperlinkOSC 8 anchor — url and optional id grouping field, validated at construction and again on unserialization (C0/DEL, lone raw 8-bit C1 bytes and their UTF-8 C2 xx spellings, plus semicolons-in-id refused; valid multibyte IRI payloads pass).
Wide char handlingwidth=2 cells (CJK, many emoji) carry a width-0 continuation partner at col+1; larger widths are single run-length spans that carry no continuation cells. The writing API enforces the pair law automatically; Buffer::fromGrid() is the escape hatch that skips it — it validates the dimensions and requires a flat list of exactly width×height cells, but takes the cells as given, so pair maintenance is the caller's duty.

Use it for

  • Shared cell-grid foundation — consumed by sugar-overlay, sugar-toast, sugar-panels, sugar-table, sugar-forms, sugar-style, sugar-charts, sugar-image, sugar-dashboard, sugar-testing, sugar-video, sugar-datepicker, sugar-flexbox, candy-minesweeper and candy-tetris. Some renderers keep independent engines by design (sugar-core's line-diff Renderer, sugar-vterm's mutable grid) and candy-code does not consume this library; the package's role is the shared data model and its byte encoders.
  • Per-cell dirty tracking — Buffer::diff() emits move / style / set-cell / repeat-run / erase-run / hyperlink ops for only the changed cells, and applyDiff() is its round-trip inverse.
  • Terminal rendering — the data model behind styled-grid output: toAnsi() full repaints and diff-encoded delta frames, hyperlinks surviving intact.

Security & trust boundaries

  • Cell runes ride the wire verbatim. toAnsi() and the diff encoder never strip control characters from cell contents — callers rendering untrusted text must sanitize first (sugar-core Sanitize::untrusted()). text() does not respect styles either: invisible-styled runes still come out, so invisibility is not a redaction boundary.
  • Hyperlink fields are hard-gated. url and id refuse C0 controls, DEL and the C1 escape introducers — lone raw 0x80-0x9F bytes that do not continue a well-formed UTF-8 sequence, and their UTF-8 C2 xx spellings — and ids refuse semicolons, at construction and again on unserialization, so no escape introducer can be forged into the OSC 8 frame. Well-formed multibyte payloads (arrows, emoji, Cyrillic: an IRI) pass even though their continuation bytes sit in the C1 window.
  • Buffer::fromString() is test-support, not an emulator. Only SGR sequences are interpreted; every other CSI frame deposits its parameter text into cells as literal runes. Do not feed it untrusted input expecting a parse.
