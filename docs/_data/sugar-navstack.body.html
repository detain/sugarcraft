sugar-navstack is the navigation state behind a breadcrumb trail: a stack of titled items, a renderer that elides the oldest crumbs to fit a width, and click zones that map a terminal cell back to a stack position. It renders nothing by itself beyond plain text and accessible HTML, so a host decides how the trail looks. It mirrors KevM/bubbleo (Go) in shape; the code is native PHP.

Install

composer require sugarcraft/sugar-navstack

Packagist serves this package from dev-master only, with no tagged release yet. Require it with a root minimum-stability: "dev" and prefer-stable: true, the SugarCraft-wide convention, or pin "sugarcraft/sugar-navstack": "dev-master". Requires PHP 8.3 or newer and ext-mbstring. Click zones depend on sugarcraft/sugar-mouse, which Composer installs with it.

Quickstart

push('Home', '/')
    ->push('Settings', '/settings')
    ->push('Display', '/settings/display');

echo $nav->view();            // Home › Settings › Display
echo $nav->view(' / ');       // Home / Settings / Display

$top = $nav->pop();           // NavigationItem: title 'Display', data '/settings/display'
echo $nav->depth();           // 2

The payload argument is opaque to the library. It travels with the item and comes back on pop(), current() and items(), so a host can store a route, a screen object or an id there.

Concepts

The model has three layers. NavStack owns the ordered items and a generation counter that changes on every mutation. Breadcrumb turns a stack into a painted row, elides the oldest crumbs when a width cap applies, and optionally records a click zone for each visible crumb. Shell pairs a stack with a breadcrumb through immutable operations, for hosts that prefer value semantics.

Titles are untrusted by default. Every title passes through the same display sweep before it reaches output: terminal escapes, control bytes and the library's own zone sentinels are removed, and a title that is empty after that sweep is refused. Payloads are never rendered, so they are safe to carry arbitrary data.

NavStack is the navigation-state model, not a UI. The README records zero in-repo consumers today. sugar-dashboard's navigation components are the intended kind of host, rendering this kind of state.

Tasks

Track a menu path and go back

$nav = NavStack::new()->push('Home', 'home');
$nav->push('Settings', 'settings');
$nav->push('Display', 'display');

$back = $nav->canPop() ? $nav->pop() : null;   // removes Display
$nav->popToRoot();                              // back to Home only
echo $nav->view();                              // Home

pop() returns null only on an empty stack. canPop() is true only when a pop leaves a non-empty stack, so it is false at depth 1 even though pop() still returns the root and empties the stack. To pop whatever is on top, check isEmpty() instead.

Render an accessible HTML trail with links

use SugarCraft\NavStack\{NavStack, Url};

$stack = NavStack::new()->push('Home')->push('My Settings');

echo $stack->viewHtml(
    href: static fn ($item, int $i): ?string => Url::deriveTo($stack, $i),
    label: 'Breadcrumb',
    allowSchemes: ['/', 'https'],
);

viewHtml() emits nav[aria-label] around an ol, with aria-current="page" on the last crumb. Each ancestor becomes an anchor when the callback returns a string, and stays plain text when it returns null. $allowSchemes gates the URLs the callback returns, and rejected ones render as plain text. The '/' entry admits scheme-less paths such as Url::deriveTo() output, so leave it out and every relative link renders as plain text. The first crumb of the example therefore becomes an anchor to /Home.

Make crumbs clickable with mouse zones

use SugarCraft\Mouse\{Scan, Scanner};
use SugarCraft\NavStack\Breadcrumb;

$bc = Breadcrumb::new()->withScanner(Scanner::new())->setMaxWidth(40);

$rendered = $bc->render($stack);
$bc->scan($rendered, viewportWidth: 80, row: 1);   // scan the untouched output
echo Scan::strip($rendered), "\n";                 // strip before painting

// On a click at ($col, 1):
$item = $bc->hitItem($stack, $col, 1);
if ($item !== null) {
    $stack->popTo(array_search($item, $stack->items(), true));
}

The order matters. Scan the output from render() untouched, then strip it for display, or the zone sentinels appear as garbage cells. Zone ids carry the stack index, so a click still resolves after elision has hidden the oldest crumbs. Re-scan after every render. A click on the … marker returns null from hitItem(), and elisionSpan() reports where the marker sits if the host wants to treat it as an expansion gesture.

Keep a deep trail readable in a narrow bar

$bc = Breadcrumb::new()
    ->setMaxWidth(24)
    ->setTruncator('[more] ')
    ->setItemRenderer(static fn ($item, int $i, bool $focused = false): ?string
        => $focused ? '[' . $item->title . ']' : null);   // null keeps the default

$bc->setFocusedIndex($selected);
echo $bc->render($stack);

setMaxWidth() elides the oldest crumbs first. setTruncator() replaces the default …, which helps screen readers. A custom item renderer returns null for crumbs it does not style, and its strings are emitted raw, so do not put untrusted text in them. setFocusedIndex() is intent only. Read focusedIndex() afterwards to see whether the selected crumb survived the width math.

Track a directory trail

use SugarCraft\NavStack\Shell;

$shell = Shell::new();
$shell = $shell->withDirectory('/home/user/projects/sugarcraft/src');
echo $shell->renderBreadcrumb();

Shell never watches the filesystem. The host detects a directory change and calls withDirectory(). pushDirectory() still works as a deprecated forwarder. Every with*() returns a new Shell. All of them except withBreadcrumb() give the derived shell its own copy of the breadcrumb renderer. withBreadcrumb() keeps the instance you pass, so later changes to that renderer show through.

Configuration

sugar-navstack has no config file or environment variables. Its behavior is set by the constants and the renderer setters below.

OptionTypeDefaultEffect
NavStack::SEPARATORstring' › 'Separator used by view() and the breadcrumb default
NavStack::TRUNCATORstring'… 'Elision marker used by the breadcrumb default
NavStack::MAX_STACK_DEPTHint10000Refuses push() past this depth
NavigationItem::MAX_TITLE_BYTESint65536Refuses titles longer than this in raw bytes
Breadcrumb::setMaxWidth()int0Width cap in cells. 0 means no cap

Filtering and payload walking refuse payloads nested deeper than 64 levels. Guards throw \InvalidArgumentException rather than truncating silently.

Keys and keybindings

sugar-navstack handles no keys. A host maps its own keys to pop(), popTo() and popToRoot(). A keyboard user reaches the same jumps as a mouse user: select a visible index from visibleIndices() and call popTo() on it. An index past the top of the stack is a no-op in popTo(), but a negative index throws \InvalidArgumentException.

Theme and styling

The library emits no ANSI and no motion. The default output is plain text, so styling belongs to the host. Wrap the item renderer's return value with your own Style to color the current crumb, and keep the separator and truncator plain so they stay legible in monochrome terminals.

The glyphs › and … assume a UTF-8 terminal. Under LANG=C or TERM=dumb, switch to ASCII with setSeparator(' > ')->setTruncator('... ').

Examples

  • examples/basic.php drives a stack through push(), depth(), current(), parent() and items(). It then renders the trail with the default separator, a custom separator and a width-20 cap that elides the oldest crumb. Run it with php examples/basic.php.
  • examples/navigation.php walks a push, pop and back flow, shows the filtered view, adds a Shell directory trail, and demonstrates the focus callback. Run it with php examples/navigation.php.
  • examples/mouse.php is the click-zone reference. It renders a four-deep stack in a width-24 bar, prints the cell range of each crumb, dispatches synthetic clicks to popTo() indices, and checks that the elision marker is not navigation. Run it with php examples/mouse.php.

The examples read vendor/autoload.php, so run them from the library root after composer install.

Troubleshooting

A click lands on the wrong crumb after the bar narrows

Hit-testing must use the same stack that was rendered. Zone ids are positions in the rendered stack, so after filtered() they are positions in the filtered stack. Pass that exact stack to hitItem(), and re-scan after every render.

Stray control characters appear in the terminal

The painted row still carries zone sentinels. Strip the output with Scan::strip() before writing it, and keep the unstripped string only for scan().

push() throws for a title that looks valid

A title that is empty after trimming and sanitizing is refused. Sanitizing removes escapes and control bytes, so a title made only of those is refused too. A title over 65536 raw bytes is refused by NavigationItem. Trim and cap titles before pushing them, or call NavStack::safeTitle() to see what the sweep produces.

The separator throws

view() and Breadcrumb::setSeparator() refuse separators that contain CR or LF, and view() refuses terminal escapes. Use a single-line separator.

The focused crumb does not render as focused

setFocusedIndex() is intent. An index beyond the stack, a negative index, or a crumb elided off the left edge reads back as null. Check focusedIndex() after render(), and compare visibleIndices() to confirm the crumb survived the width cap.

Architecture

Every mutation on NavStack bumps the generation counter, so a breadcrumb hit recorded against an older stack is refused. Breadcrumb::scan() records zones against the stack indices it rendered. Those zones persist until the next scan(), so a click resolves against the render the user actually saw.

Titles pass through TitleSanitizer::sanitize() before they reach output. Escape handles the separator inside the crumb stream, so a title that contains the separator text survives a round trip only when it is escaped. Payloads are never rendered.
