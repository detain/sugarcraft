A tiny, dependency-free focus ring for full-window terminal UIs: an ordered set of focusable regions with a single focused member and wrap-around Tab/Shift-Tab traversal. It is the "which panel has focus" state for a TUI layout — register each focusable region (sidebar, content grid, filter bar…), map Tab to next() and Shift-Tab to previous(), and give the region current() returns an accent border when you render. The ring carries no rendering or key decoding of its own, so it composes with any sugar-core model without pulling in dependencies. Original SugarCraft component.

Install

composer require sugarcraft/sugar-focus

Quickstart

use SugarCraft\Focus\FocusRing;

$ring = FocusRing::of('sidebar', 'grid', 'filter'); // 'sidebar' is focused

$ring = $ring->next();        // → 'grid'
$ring = $ring->next();        // → 'filter'
$ring = $ring->next();        // → 'sidebar' (wraps)
$ring = $ring->previous();    // → 'filter' (wraps the other way)
$ring = $ring->focus('grid'); // jump straight to a region

$ring->current();             // 'grid'
$ring->isFocused('grid');     // true

Wire it into a sugar-core model's update(), then let each region style itself in view():

use SugarCraft\Core\KeyType;
use SugarCraft\Core\Msg\KeyMsg;

// …in update():
if ($msg instanceof KeyMsg && $msg->type === KeyType::Tab
    && !$msg->ctrl && !$msg->alt) {
    $ring = $msg->shift ? $this->ring->previous() : $this->ring->next();
    return [$this->withRing($ring), null];
}

// …and in view():
$style = $ring->isFocused('sidebar') && $ring->isEnabled('sidebar')
    ? $accentBorder : $plainBorder;

On the wire, Shift+Tab arrives as Tab with shift: true — sugar-core's InputReader decodes ESC [ Z (CSI-Z, the literal "Backtab" sequence) into that shape. The ring leg is gated on !$msg->ctrl && !$msg->alt, so Ctrl+Tab and Ctrl+Shift+Tab stay free for other bindings — but only on terminals that report modifiers (kitty keyboard negotiation or an xterm modifyOtherKeys-style decoder); on legacy/basic terminals Ctrl+Tab is byte-identical to bare Tab and moves the ring like a plain Tab would. The isEnabled() conjunct in the paint matters: focus can legally park on a disabled region, so isFocused() alone can accent a dimmed panel.

Behaviour

Exactly one focused regionA non-empty ring always has exactly one focused region; an empty ring focuses nothing (current() is null, index() is -1).
register() appendsAdds to the traversal order and focuses the region only when the ring was empty; re-registering an existing id is a no-op.
unregister() lands enabledKeeps focus on the same region where possible; removing the focused region lands focus on the nearest enabled survivor at or after the vacated slot — the slot is first clamped to the new end, so removing the focused tail lands on the new tail rather than wrapping to the head, and the wrap reaches the earliest enabled survivor only when every survivor ahead is disabled. With nothing enabled left, focus parks on the clamped slot itself; emptying the ring clears focus.
Wrap-around traversalnext() / previous() wrap past the ends and are no-ops with fewer than two enabled regions — with one exception: focus parked on a disabled region beats the no-op and moves to the nearest enabled survivor in that direction.
reorder() in one stepReplaces the traversal order: ids are deduped (first wins), focus stays on the current region if it survives — otherwise it lands on the first enabled survivor, index 0 only when every survivor is disabled. New ids are added and missing ids dropped; reordering an already-empty ring is a no-op.
Disabled regionsdisable() keeps a region registered but makes traversal skip it; enable() puts it back. Disabling the focused region does not move focus — the next next() / previous() carries it to the nearest enabled region in that direction, even a sole enabled survivor. focus() refuses a disabled id (no-op) so it cannot teleport past that wall — snapshots restore focuses the id before re-applying its flag. A region dropped while disabled comes back enabled.
Iterable, countable, serialisableImplements IteratorAggregate, Countable and JsonSerializable: foreach walks every registered id, count($ring) counts them, json_encode($ring) gives {"ids":[…],"focused":…,"index":n,"disabled":[…]}, and FocusRing::restore() rebuilds the ring — preferring the focused id over the positional leg, an unknown focused id landing on the first region, clamping stale indices on legacy positional-only snapshots, and dropping unknown disabled entries.
Pure queriesnextOf() / previousOf() answer where traversal would land from an id without moving focus; focusFirst() / focusLast() jump to the first / last enabled region; enabledIndex() is the focused region's ordinal among enabled ids (null while parked or empty).
Modals and focus trapsNo layer concept: a dialog is just another region and the trap is the disabled set — register it, disable the background, and on close re-enable the background before dropping the dialog and restoring the saved region. The README carries the full recipe and its edges.
ImmutableEvery mutator returns a new FocusRing and leaves the receiver untouched, so it slots into the immutable Model–Update–View pattern. No-op calls return the same instance, so $new === $old cheaply detects "nothing changed".
Dependency-freeNo rendering or key decoding of its own — the owning model wires keys to it and reads isFocused() when drawing. Composes with any sugar-core model.

Use it for

  • Full-window TUI layouts — track which panel (sidebar, content grid, filter bar) currently owns keyboard focus.
  • Tab / Shift-Tab traversal — wrap-around movement across an ordered set of regions, decoupled from key decoding.
  • Accent-border styling — read isFocused() together with isEnabled() in view() to highlight the focused region.
  • Immutable models — drop the ring into your Model state; every mutator returns a fresh instance.
