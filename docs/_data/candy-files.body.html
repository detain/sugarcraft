candy-files is a dual-pane terminal file manager in the Midnight Commander lineage: two directory panes side by side, Tab to swap focus, multi-select, copy, move, rename, delete with a confirm gate, undo, tabs, and fuzzy search by name. It runs on the SugarCraft stack and is inspired by superfile; it is native PHP, not a port of superfile. Its filesystem layer is injected, so every transition is unit-testable without a temporary directory.

Install

composer require sugarcraft/candy-files:@dev

Requires PHP 8.3 or newer with ext-intl and ext-mbstring. Both are required transitively by sugar-core, whose cell-width math runs through ICU, so composer install is the step that refuses on a bare php-cli machine.

While the release channel is dev-only the inline :@dev is required. Packagist carries only dev-master, and a fresh project's default minimum-stability: stable refuses the bare command. Archive browsing is optional: ext-zip, ext-zlib and ext-bz2 are suggested and only needed for .zip, .tar.gz and .tar.bz2 archives.

Quickstart

Run it from a Composer install, from a source checkout, or from the rolling phar. The positional arguments are the left and right start directories; both default to the current directory and $HOME.

# Composer consumer: the package bin from composer.json "bin"
vendor/bin/candy-files [LEFT_DIR] [RIGHT_DIR]

# Source checkout of this repository
composer install
./bin/candy-files [LEFT_DIR] [RIGHT_DIR]

# Rolling phar from the candy-files/latest GitHub release
php candy-files.phar [LEFT_DIR] [RIGHT_DIR]

A missing or unreadable start directory refuses before the interface opens, with left/right directory does not exist: <dir> and exit status 1. The interface needs a terminal. Frame, status line and prompts are windowed to the live terminal size, so they stay on screen at any size.

Command-line flags

Flags are answered before the positional directory scan. --version and --help never open the terminal interface, and a directory literally named --version prints the version too, because flags are matched anywhere in argv.

Concepts

The screen is two panes, each with its own working directory, cursor, selection, sort order and hidden-file flag. Tabs hold a pair of panes, so one tab can keep two directory pairs open. Tab moves the focus between the panes of the current tab; every file operation acts on the focused pane's selection, or on the cursor entry when nothing is selected, and targets the other pane for copy and move.

Mutations do not run straight away. c, m, d and p arm a confirm gate: the next key answers it, and only y (or the affirmative word your locale's prompt teaches) commits. Any other key cancels. Copy runs on the event loop as a tick-sliced job, so a large tree does not freeze the frame; move and rename are synchronous renames on the same filesystem.

Delete is recoverable only while the process lives. d moves files into a per-process trash directory under the system temporary directory, created with mode 0700 and removed on exit. A delete that would cross a device is announced as PERMANENT before you confirm, because a cross-device move cannot be undone by renaming back.

The undo stack keeps the last 50 delete, move and rename operations. u undoes, Ctrl+y redoes. Copy is not undoable; the status line says so.

Modes

Exactly one mode owns the keyboard at a time: browse (the default), the confirm gate, text entry (R rename, N make directory, Ctrl+O typed path, * pattern select), search (/), and the help overlay (?). In text entry every printable key is a letter, so y is typed rather than answered; in search every printable key extends the query, and ↑/↓ move the result cursor.

Tasks

Copy a selection to the other pane

  1. Move to the first file and press Space, which selects it and advances. Repeat for the rest, or press Ctrl+a to select every listed entry, v to invert the selection, or * and type a glob such as *.log.
  2. Press c to arm the copy gate. The prompt names the count and the destination pane.
  3. Press y to commit. Existing files are replaced and directories merge; the status line announces the replacement.

Delete with undo

Press d, then y, to move the selection to the session trash. Press u while the process is still running to bring it back. Quitting with q empties the trash, so a delete made in one session cannot be undone in the next.

Search the active pane by name

Press / and type. Matching is a fuzzy filter over the names in the active pane, NFC-normalized so a composed query finds a decomposed macOS name. Enter opens a directory result or lands the cursor on a file result. Ctrl+R inside search starts a bounded recursive walk of the whole tree; its hits show their path relative to the pane, and the status reads search partial when a cap fires.

Change the shell's directory when you quit

--print-cd prints the directory of the active pane on exit to stdout and draws the interface on /dev/tty, so a shell function can change directory afterwards. Add this to ~/.bashrc or ~/.zshrc:

candy-files-cd() {
    local dir
    dir=$(candy-files --print-cd "$@") || return $?
    if [[ -n "$dir" && -d "$dir" ]]; then
        builtin cd "$dir"
    fi
}

With tabs open the handshake reports the active pane of the tab that was on screen at exit. A ^C abort exits non-zero, and the wrapper returns that status, so the shell stays where it was.

Browse and extract an archive

Press Enter on a .zip, .tar, .tar.gz, .tgz, .tar.bz2 or .tbz2 file to browse it as a read-only directory. Press x inside the archive to extract the entry under the cursor, or the whole view, to the other pane through the copy gate. Zip-slip names, links and devices are dropped, and scans stop at 256 MiB and extraction at 512 MiB, so a decompression bomb cannot fill the disk.

Open an entry in an editor or a pager

Enter on a regular file launches the editor from VISUAL, then EDITOR, then vi (notepad on Windows), then nano. l pages a file through $PAGER, then less, then more, and falls back to the built-in read-only viewer when none is on PATH. o hands the entry to the platform opener (xdg-open, open or cmd start) as an argument list, never as a shell string.

The public surface is four classes plus the value objects they exchange. Manager is the SugarCraft Model: update() returns the next model and an optional command, and view() renders the frame. Everything else is a pure helper the model calls.

Constructing Manager

Prefer the builder to the 32-parameter constructor, which is kept only for backward compatibility. The state the machine itself produces, such as recursive search results, the in-flight copy count, and the help overlay, takes safe defaults and is not exposed on the builder.

use SugarCraft\Files\ConfirmState;
use SugarCraft\Files\FsLister;
use SugarCraft\Files\Manager;

$manager = Manager::builder()
    ->withLeft($leftPane)
    ->withRight($rightPane)
    ->withActiveIdx(0)
    ->withStatus('')
    ->withConfirm(ConfirmState::None)
    ->withLister(FsLister::lister())
    ->withSearchQuery(null)
    ->withSearchResults([])
    ->withSearchCursor(0)
    ->withTabs([])
    ->withTabIndex(0)
    ->withUndoStack([])
    ->withRedoStack([])
    ->withPendingOpDest(null)
    ->withPendingOpType(null)
    ->withInputBuffer(null)
    ->withTermCols(0)
    ->withTermRows(0)
    ->build();

Mouse input uses SGR cell-motion reporting. The wheel scrolls the pane under the pointer, a click activates the pane and parks the cursor, Ctrl+click toggles a mark, a double-click opens, and a click on a tab label switches tabs. Modal frames swallow the pointer, so a click cannot answer a prompt.

Configuration

candy-files has no configuration file. Its behavior comes from the command line, the environment, and the start directories. Bookmarks are state, not configuration, and live in the data directory.

Theme, styling and glyph tiers

The interface is monochrome by construction. The renderer emits no color or font styling, so emphasis rides on text and shape: the ▸ cursor, the ✓ selection mark, the thick border, the localized focus label, and the ↑ N more and ↓ N more fold hints. A NO_COLOR, high-contrast or inverted terminal palette shows the full interface.

The chrome glyphs (▸ ✓ ─ ↑ ↓ ·) are East Asian Width "Ambiguous": some terminals draw them one cell wide and some two. candy-files draws them one cell wide unless it detects a surface that doubles them: a zh, ja or ko locale, a legacy CJK codepage (CP932, GBK, EUC-JP, BIG5), or the Linux console. Those surfaces get the ASCII tier (> v - ^ v | and plain +--+ borders). Set CANDY_FILES_GLYPHS=ascii or unicode to choose the tier yourself. File names are data and are never rewritten by the tier.

The layout follows the live terminal size. Each pane box is (cols - 2) / 2 cells wide, and every status and search line is clipped to the width, so nothing wraps.

Examples

Both examples run without a terminal and without touching the real filesystem: they build the panes from an in-memory tree and print the frame.

  • examples/browse.php starts a manager over two in-memory directories and prints the frame it renders. Run it with php examples/browse.php.
  • examples/select-and-copy.php feeds the key sequence j, Space, Space, c to update(), selecting two entries and arming the copy gate. Nothing is copied. Run it with php examples/select-and-copy.php.

The interactive program is bin/candy-files. It needs a real terminal and is not run from an example.

Testing

Run the suite from the package root after composer install:

vendor/bin/phpunit

The suite pins CANDY_FILES_GLYPHS to unicode in tests/bootstrap.php, so the goldens describe the unicode chrome tier. An export of CANDY_FILES_GLYPHS in your shell wins over that pin. Most tests drive Manager::update() with scripted KeyMsg values over an in-memory lister, so they need no temporary directories. Tests that drive the real program through a pseudo-terminal use sugarcraft/sugar-pty, a dev dependency, via tests/Support/PtyRun.php.

Troubleshooting

It refuses to start with "directory does not exist"

A start directory is missing or unreadable. Pass existing directories, or omit the positional arguments to start in the current directory and $HOME. The check runs before the interface opens, so the exit status is 1 and no frame is drawn.

Ctrl+Tab does nothing

Most terminals do not report a modified Tab key. Use 1 to 9 to pick a tab, or Ctrl+PgUp and Ctrl+PgDn. tmux and browser terminals may intercept the Page keys, in which case use the digit keys.

The box borders or arrows are misaligned

Your terminal draws the ambiguous-width glyphs at two cells. Run with CANDY_FILES_GLYPHS=ascii to switch to the ASCII tier, or set your terminal's ambiguous-width option to one cell.

w and W copy nothing to the clipboard

The clipboard uses the OSC 52 escape sequence, which some terminals ignore. candy-files refuses it under TERM=dumb and TERM=linux and says so in the status line. Use a terminal with OSC 52 support, or copy the path shown in the I info overlay.

An archive will not open

The status names the missing PHP extension. A .zip needs ext-zip; a .tar.gz or .tgz needs ext-zlib; a .tar.bz2 or .tbz2 needs ext-bz2. Install the extension and restart candy-files.

A deleted file is gone after I quit

Deleted files go to a per-process trash that is removed on exit, so a delete survives only while the process lives. Press u before you quit. A delete across devices is permanent, and the confirm prompt says PERMANENT before you commit.

l opens the built-in viewer, not less

No pager was found. Set PAGER, or install less on PATH. The built-in viewer shows only the first 256 KiB of a file, and l refuses a binary file or one over 32 MiB with a status message.

Enter opens the wrong editor

The editor chain checks VISUAL first, then EDITOR, then vi (notepad on Windows), then nano. Set VISUAL or EDITOR to the editor you want.

Search says "search partial"

The recursive walk hit one of its caps: depth 8, 20 000 names, or four screens of hits. Narrow the query, or search a deeper directory directly.

Upstream and inspiration

candy-files has no Charmbracelet counterpart, so it has no upstream mapping table. It is original SugarCraft work, inspired by superfile (Go) and by the dual-pane layout of Midnight Commander. Its terminal layer runs on sugar-core and sugar-style, and its name search runs on sugar-fuzzy.

Architecture

The transition layer is pure. Filesystem reads enter through an injected lister, a Closure(string $path): list<Entry>, so every transition runs in memory. Production uses FsLister, and copy runs as a tick-sliced job through AsyncOps. Each model is immutable, and with*() methods return new instances.

ClassRole
ManagerThe SugarCraft Model. Orchestrates two panes, handles every key, and runs the confirm gate.
PaneOne pane: working directory, entries, cursor, selection set, sort, and the hidden-file flag.
Entry, SortThe value object for one directory entry, and the sort modes with their comparators.
ConfirmStateThe mode that owns the keyboard for a pending prompt: delete, copy, move, rename, mkdir, path or pattern.
FsListerThe default lister, built on scandir and lstat. memo() adds the directory-mtime cache.
RendererA pure view function: tab bar, two pane boxes side by side, the search overlay, and the status line.
AsyncOpsThe deferred copy engine. It is the only home of recursive copy, depth-capped at 256, and runs on the event loop.
UndoActionAn immutable undo record: delete records for restores, or old-to-new path maps for rename, move and copy.
LangThe i18n wrapper over the catalogs under lang/.
Support\Archive, Support\ArchiveExtractor, Support\TarReaderArchive detection and the read-only index, loop-sliced extraction with a bomb meter, and a forward-only tar reader.
Support\Bookmarks, Support\Home, Support\GlyphSet, Support\VersionThe bookmark store, the home-directory cascade, the glyph tier, and the --version stamp.

Changelog and versioning

candy-files ships no separate changelog file, and the GitHub releases are the release history. The rolling phar is published under the candy-files/latest release tag, with .sha256 and .sig sidecars and a .phar.commit build stamp. Stable cuts ride the candy-files/v* tags. --version prints the stamp that the running phar carries.
