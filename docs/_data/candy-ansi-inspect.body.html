candy-ansi-inspect decodes terminal escape sequences into labeled lines. Pipe styled output through it, or name a saved capture, and each SGR, CSI, OSC, DCS, APC and SS3 sequence becomes one line that says what it does, next to the raw bytes it was sent as. It is a PHP port of charmbracelet/sequin, reimplemented for PHP 8.3 with the sequin core behavior and a narrower flag surface. The tool and the library share one parser, so the CLI report and Inspector::report() produce the same text.

Install

composer require sugarcraft/candy-ansi-inspect   # binary lands in vendor/bin/candy-ansi-inspect

Requires PHP 8.3 or newer. From a project root the examples below type the bare command, so either prefix it with vendor/bin/ or put vendor/bin on your PATH. composer global require installs it the same way.

A self-contained phar is the other option. The build seals the app with its published vendor/ into one file, and refuses a linked-mode vendor or a dirty tree:

php -d phar.readonly=0 tools/build-phar.php --out=dist/candy-ansi-inspect.phar

A downloaded archive, even one renamed to drop the suffix, boots through its own frozen autoload and answers --version with the stamp it was built under. A source checkout reports dev-master rather than an invented semver.

Quickstart

$ printf '\e[31mhello\e[0m world\n' | candy-ansi-inspect
ESC[31m  SGR foreground red
hello
ESC[0m  SGR reset
 world
LF  C0 LF (line feed)

$ printf '\e]0;new title\e\\' | candy-ansi-inspect
ESC]0;new titleBEL  set window title to "new title"

$ printf '\e[?2026h' | candy-ansi-inspect
ESC[?2026h  enable synchronized output

The display column prints named tokens (BEL, LF, ESC) wherever a raw control byte was sent. A captured sequence therefore cannot beep, retitle your window or move the cursor while you read the report, and the transcript diffs cleanly against od output.

Concepts

The tool is a parser with a label table. Input is split into segments. A TextSegment holds visible text between escapes, and a SequenceSegment holds one escape sequence, its raw bytes and its decoded label. Each segment records the byte offset where it started in the source stream, so a report can point at the exact position of a sequence in a multi-megabyte capture.

Anything the decoder does not recognize falls back to a generic CSI/OSC/... descriptor. No sequence that reaches the segmenter is dropped without a report. Bytes can still disappear upstream, inside the parser's state table. The byte-fidelity contract below lists exactly where that happens.

Reports are live and byte-stable

A pipe is reported as it arrives. Stdin is read chunk by chunk, and each segment's line is written as soon as its sequence completes, so tail -f log | candy-ansi-inspect emits per sequence instead of waiting for the writer to close. The live report and the file report produce the same bytes.

Exec mode runs a program

Exec mode starts a command on a fresh pseudo-terminal and reports every sequence it prints the instant it completes, then exits with the child's status. Everything after -- belongs to the command, including its own flags. The PTY work is done by sugar-pty.

Tasks

Inspect a saved capture

printf '\e[31merror: disk full\e[0m\n' > capture.ansi
candy-ansi-inspect capture.ansi
candy-ansi-inspect --show-offsets capture.ansi   # prefix each line with its byte position as @hex

A saved capture works exactly like a pipe: the file argument produces the same report. --show-offsets adds the position column. Offsets count from zero across the whole source, and a normal segment's offset plus its reported bytes lands exactly on the next segment's offset.

Get the report as JSON

candy-ansi-inspect --json capture.ansi | jq '.[] | select(.type == "sequence") | .description'

--json prints a JSON array with one object per segment. Each object carries type (text or sequence), the raw content bytes, the human description and the byteOffset. JSON is never live. A partial array is not parseable, so --json on a pipe collects every segment and prints the array when the source ends. The flag works before or after the file operand.

Run a program and label what it prints

candy-ansi-inspect -- ls --color=always
candy-ansi-inspect -- git -c color.ui=always status

The child runs on a PTY, so it sees a terminal and writes the sequences a real session would. The tool's exit status is the child's.

Label sequences from PHP

use SugarCraft\AnsiInspect\Inspector;

echo Inspector::report("\e[1;31mboom\e[0m");   // the three report lines, as the CLI prints them

For a chunked source such as a log file or a live process, use StreamingInspector. See the Examples section for a worked chunk split.

Read a hostile capture safely

The report never replays a control byte. Control bytes are printed as named tokens, so a capture that contains a title change or a clipboard write shows only its label and cannot move your cursor or retitle your window.

Locale

Messages the tool prints itself, such as usage and refusals, are translated. The locale is read from LC_ALL, then LC_MESSAGES, then LANG, and the first usable value wins. fr_FR.UTF-8 resolves to fr, and an unknown locale falls back to English. The labels inside a report are always English, so report bytes never depend on the caller's locale. Seventeen locale catalogs ship in lang/.

Keys and input

The tool has no keyboard handling and no key bindings. Its input is bytes: a file operand, a pipe on stdin, or the output of a command after --. Pass exactly one source. Naming two files is refused with usage, rather than reporting the first and silently dropping the other.

A path that carries a scheme such as php:// or data:// is refused as a stream wrapper. Pipe those bytes on stdin instead. Process substitution (<(cmd)), FIFOs and other special files are not readable regular files either, so pipe them as well.

Theming

There is no theme. The report is intentionally uncolored: an ANSI-colored inspector would have to escape its own output, and the point of this tool is a byte-trustworthy transcript. Vocabulary lives in the labels themselves. The sequin option that reads SEQUIN_THEME has no counterpart here.

Examples

The examples/ directory holds one shell script and three PHP programs. The PHP examples load the Composer autoloader, so run them from a checkout after composer install.

  • examples/inspect.sh is a guided tour of common sequences through the CLI: SGR colors, DEC private modes, OSC clipboard writes and OSC 8 hyperlinks. It is the program behind the demo GIF below.
  • examples/inspect-string.php labels a byte string with Inspector::parse(), printing each segment's kind, offset and description, and then the full Inspector::report() text.
  • examples/streaming-chunks.php feeds StreamingInspector three chunks, one of which ends inside ESC[31m. The held half sequence arrives only with the chunk that completes it, and finish() reports the dangling ESC[ as truncated.
  • examples/json-report.php prints Inspector::reportAsJson() and reads it back with json_decode() to show the fields a script would use.
./examples/inspect.sh
php examples/inspect-string.php
php examples/streaming-chunks.php
php examples/json-report.php

Testing

The suite runs under PHPUnit 10. Run it once from the package root, with stdin redirected so a test that reads stdin cannot hang:

cd candy-ansi-inspect && composer install && vendor/bin/phpunit < /dev/null

The suite pins the behavior in several ways. ReadmeTranscriptGoldenTest checks that the transcripts in this README still come out byte for byte. ByteFidelityTest and ByteOffsetTest check the byte-fidelity contract. C1ClassificationSweepTest pins the C1 control roster byte for byte. StreamingInspectorTest covers chunk boundaries, and CliTest and ExecRunnerTest cover the command line and exec mode. LangParityTest checks that the locale catalogs match. PerfGuardTest keeps the report's cost growing no faster than its input, so a large capture cannot turn into a stall.

Troubleshooting

Exit 1 with "cannot read"

The operand is not a readable regular file. A directory, a FIFO, a process substitution and a stream wrapper all refuse the same way. For a wrapper such as data:// the message adds a hint line. Pipe the bytes on stdin instead: cmd | candy-ansi-inspect.

Exit 1 with a usage message and nothing to read

With no operand and a terminal on stdin, there is no source. Name a file or pipe something in. A pipe is always a source, even an empty one, and an empty source prints an empty report and exits 0.

A sequence is missing from the report

Most such cases are documented byte-fidelity deviations, pinned by named tests. A cancel byte (CAN or SUB) inside a string such as an OSC is consumed as the terminator, so it appears nowhere in the report. An invalid UTF-8 byte in the middle of text is dropped with its position. An OSC closed by ESC \ is re-emitted with a BEL terminator, because terminals accept that spelling everywhere. The full list is in the byte-fidelity section below.

Output appears late under --json

That is by design. A partial JSON array cannot be parsed, so --json collects every segment and prints the array when the source ends. For a live feed, drop --json and read the line-mode report, which prints each sequence as it completes.

Exec mode exits 1 and says no pseudo-terminal is available

Exec mode needs a PTY. When one cannot be opened, the run exits with ExecRunner::EXIT_UNAVAILABLE (1) and names the reason on stderr. Use a pipe or a file in that environment.

Offsets look wrong after a multi-byte character

Offsets are positions in the input bytes, not in characters. A text segment's offset is the byte where its first character starts. Use byteOffset() with raw() when you need exact positions, and not the length of a decoded string.

Byte-fidelity contract

Reported bytes are the bytes that were sent, in four respects. Parameters keep the separator the sender used, so ESC[4;3m is never reported as ESC[4:3m. A dispatched CSI replays its own bytes verbatim, including stacked private markers and the 8-bit 0x9B spelling. A string's ESC \ terminator is reported once, inside the sequence it closed. A truncated sequence still arrives, as a truncated … segment carrying its raw bytes.

Every known deviation is pinned by a named test rather than hidden. Anything else that loses a byte is a bug. The deviations are these:

  • An OSC closed by ESC \ is re-emitted with a BEL terminator.
  • A DCS prelude rebuilt through the parser fields is lossy. Its final byte is dropped and an intermediate byte comes back ahead of the parameters. A BEL-terminated DCS replays verbatim.
  • A sequence is capped at 32 parameters, and a parameter value accumulates only up to 65535, both inside the parser. A dispatched CSI still replays its bytes as sent.
  • A string payload stops at 64 KiB, so a longer OSC arrives cut at that length with its terminator attached.
  • Some C0 bytes are ignored inside an OSC payload and never reach the buffer.
  • An illegal parameter byte, or a CAN or SUB inside a control sequence, cancels the sequence in flight. The cancelled bytes appear only when a later byte observes them.
  • A truncated UTF-8 rune at end of stream is dropped. Invalid UTF-8 bytes in the middle of text are dropped with their position.
  • An 8-bit string introducer such as 0x9D (OSC) is re-emitted in its 7-bit spelling with a normalized terminator.
  • A CAN or SUB inside a string payload terminates it. The payload so far is reported as a truncated segment, and the cancel byte is consumed.

Upstream mapping

Upstream (Go, charmbracelet/sequin)candy-ansi-inspect (PHP)

The byte position column, which sequin prints by default--show-offsets, opt-in
Running a child command for its output (-cmd)-- cmd [args…] exec mode

Divergences, by design. -- cmd replaces sequin's -cmd. The offset column is opt-in. There is no --raw inline-highlight mode, because the report's first column always shows the sent bytes tokenized, and there is nothing to switch off. There is no theming and no --list, since the cheat sheet is the README's decode section. There is no listen mode, because accepting network connections on a tool that renders untrusted byte streams is a security-review-sized feature the fleet has no precedent for.

Architecture

One parser, three front doors

Inspector::parse() and StreamingInspector both drive the same AnsiHandler, which implements the Handler interface of the sugar-ansi-parser state machine. The handler collects segments as the parser dispatches them. The file, pipe and exec doors all reach it through one of those two entry points, so they produce the same labels.

Sanitized labels

Labels are built from the decoded fields. The raw bytes are kept only in the segment's raw(), and the report displays them through SequenceSegment::printable(), which tokenizes control bytes. A payload therefore cannot forge a report line or replay a control at the terminal.

Changelog and versioning

The version a build reports comes from its packaging. A tagged phar reports its build stamp through --version. A downloaded archive reports the stamp it was built under.
