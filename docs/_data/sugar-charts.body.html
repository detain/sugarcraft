Sparkline, Bar, Line, Heatmap, Scatter, TimeSeries, Streamline, Waveline, OHLC, plus inline image rendering via Sixel / Kitty / iTerm2 protocols. Picture::detect() is multiplexer-first — it declines under tmux/Zellij (where image escapes are swallowed) unless CHARTS_PICTURE_PASSTHROUGH=1, then routes iTerm2/WezTerm/kitty/Foot/mlterm/Windows Terminal on TERM / TERM_PROGRAM; everything else is explicitly configured. It is modeled on NimbleMarkets/ntcharts, the Go terminal-chart library, and ports its behavior rather than its code.

Install

composer require sugarcraft/sugar-charts

No tagged releases ship yet — Packagist serves the dev-master branch only, so name it explicitly; on a default-stable project a bare sugarcraft/sugar-charts request does not resolve.

Quickstart

// The snippets assume a composer project with this package installed and require 'vendor/autoload.php'; in scope.

use SugarCraft\Charts\Sparkline\Sparkline;
use SugarCraft\Charts\BarChart\BarChart;
use SugarCraft\Charts\LineChart\LineChart;

echo Sparkline::new([1, 3, 2, 8, 5, 4, 7, 6], 8)->view() . PHP_EOL;
// " ▂▁█▅▃▇▆" (scaled to the window's minimum and maximum; the minimum maps to the blank leading cell)

echo BarChart::new(
    [['cpu', 0.7], ['mem', 0.4], ['disk', 0.9]], 20, 5
)->view() . PHP_EOL;

echo LineChart::new([1, 4, 2, 8, 6, 3, 7], 30, 6)->view();

Concepts

A chart holds its data, width and height, and view() returns the rendered text without writing to the terminal. The grid renderers (LineChart, Heatmap, Scatter, OHLCChart and Waveline) draw onto a Canvas of cells, each holding a rune and a Style, and the canvas is flattened to text on view(). Sparkline builds on sugar-cellbuffer, and Picture emits raw protocol bytes rather than cells. Colors come from the theme and the resolver closures, and the environment color ladder applies to every text renderer.

Per-point and per-bar colors

btop tints every graph point and meter by its value through the theme gradient. LineChart::withSeriesColorFn(fn(string $dataset, int $x, float $value): ?Color) colors each sample's dot, fill run and outgoing connector ($dataset is LineChart::PRIMARY_SERIES for the unnamed series; $x is the index in the full series; null keeps the series color). BarChart::withBarColor(fn(Bar $bar, int $i): ?Color) colors each bar's body and eighth-block cap. Passing null restores byte-identical default output. A non-Color return from an untyped resolver throws UnexpectedValueException at render time. A resolver declared with the ?Color return type, as in the signatures above, makes PHP throw TypeError at the return before that check runs, so catch both when the resolver's return type is not under your control.

use SugarCraft\Charts\BarChart\{Bar, BarChart};
use SugarCraft\Charts\LineChart\LineChart;
use SugarCraft\Core\Util\Color;

$heat = static fn (float $v): Color => match (true) {
    $v >= 7 => Color::hex('#ff5555'),
    $v >= 4 => Color::hex('#f1fa8c'),
    default => Color::hex('#50fa7b'),
};

echo LineChart::new([1, 4, 2, 8, 6, 3, 7], 30, 6)
    ->withSeriesColorFn(
        static fn (string $dataset, int $x, float $v): ?Color =>
            $dataset === LineChart::PRIMARY_SERIES ? $heat($v) : null,
    )
    ->view() . PHP_EOL;

echo BarChart::new([['cpu', 0.7], ['mem', 0.4], ['disk', 0.9]], 20, 5)
    ->withFractionalHeights()
    ->withBarColor(static fn (Bar $bar, int $i): ?Color => $heat($bar->value * 10))
    ->view() . PHP_EOL;

Accessibility & readability. Charts encode magnitude through color and glyph position — the channel that fails first in monochrome, for color-vision-deficient readers, and on high-contrast hosts. The environment ladder (CLICOLOR_FORCE/FORCE_COLOR beat NO_COLOR, which beats CLICOLOR=0) is honored by every text renderer's view(): under NO_COLOR legends, bar bodies, heatmap fills and themed rules all come back SGR-free (image payloads are exempt — the escapes are the image). Structural channels carry the same meaning without color: withDataLabels() prints bar values as text; cell-mode LineChart labels series with six plain-ASCII point runes; withRune()/withBodyRunes() swap glyphs — but Sparkline's block shades and BarChart's █ have no glyph setter today, and Unicode track glyphs assume the fleet's one-cell Ambiguous canon. Braille output is a dot-grid density mode, not screen-reader braille: assistive technology should read the data (cells(), source arrays, CSV), not the picture. For low vision, Theme::ansi() keeps the 16-color tier and withMonoRamp(true) gives the heatmap a background-safe density ramp. For reduced motion, skip animation sweeps and render the final frame at progress 1.0. Full guidance: README — Accessibility note.

Untrusted labels. Every string the library can echo is sanitized through SugarCraft\Charts\Support\UntrustedText: static labels are swept at their setters, and formatter closures (withXLabelFormatter(), withYLabelFormatter(), BarChart's withDataLabelFormatter()) are swept at the resolve and render sites, so hostile data cannot bypass the boundary. The Canvas and Graph layers that compose the frame are trusted internals and stay unguarded by design. Full story: README — Untrusted labels.

Keys and input

The charts take no keystrokes, and LineChart has no mouse hit-testing yet. Apart from the color ladder under Theming, the one input read from the environment is Picture::detect(). It routes on TERM and TERM_PROGRAM, and it declines under tmux and Zellij unless CHARTS_PICTURE_PASSTHROUGH=1 is set. It is a best-effort sniff of the environment, not a terminal query.

Theming and styling

A chart takes its palette from withTheme(), which reads a sugar-style Theme. Theme::ansi() keeps the 16-color tier, which suits low-vision setups. Per-point and per-bar colors come from resolver closures, withSeriesColorFn() and withBarColor(). A resolver that returns null keeps the default color. The environment ladder applies to every text renderer: CLICOLOR_FORCE and FORCE_COLOR beat NO_COLOR, which beats CLICOLOR=0. Under NO_COLOR, the output comes back free of SGR. Image payloads are the exception, because the escapes are the image.

Troubleshooting and FAQ

Picture prints a plain-text placeholder instead of an image

No protocol was detected. Under tmux or Zellij, detect() declines because those multiplexers swallow image escapes. Set CHARTS_PICTURE_PASSTHROUGH=1 if the outer terminal really renders them, or pin the protocol with withProtocol().

Chart colors disappear

Check NO_COLOR and CLICOLOR=0. Both drop the SGR from every text renderer. Set CLICOLOR_FORCE=1 to keep color, since the force variables outrank both.

A color resolver throws an exception

withBarColor() and withSeriesColorFn() must return a Color or null. Any other return value throws: an untyped resolver raises UnexpectedValueException, and a resolver typed ?Color raises TypeError at the return. Return null to keep the default color.

The sparkline's first cell is blank

That is the design. The series minimum maps to the blank leading cell, and the maximum maps to the tallest glyph, so the window is scaled to the data's range.

Labels from user data look wrong

Every label the library echoes is sanitized through SugarCraft\Charts\Support\UntrustedText. Formatter closures are swept at render time too, so hostile data cannot put control sequences into the frame. See the untrusted-labels section above.

Upstream mapping

The design antecedent is NimbleMarkets/ntcharts. SugarCraft is developed as a native PHP project, so the mapping is a port of behavior, not of Go code. The Graph primitives keep the ntcharts method names as compatibility aliases.

Architecture

Each renderer draws into a shared canvas, a fixed grid of runes and sugar-style cells. The Graph primitives and the BrailleGrid write into that grid, and the renderer's view() serializes it. Sparkline builds on sugar-cellbuffer. Picture is the exception: it emits raw protocol bytes instead of cells. Labels pass through UntrustedText at every setter and render site, and the canvas itself is trusted internal state.

Changelog and versioning

The library is pre-1.0, so consume dev-master. The README's status table tracks what is shipped and what is pending. The known gaps are the LineChart mouse hit-testing, the OHLC volume pane, multi-bar grouped datasets in BarChart, and per-point rune sets for Scatter.
