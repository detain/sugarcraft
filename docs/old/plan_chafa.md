## §0 HOW TO RUN (orchestrator contract — binding on every agent brief)

1. **Investigate first, then derive lanes.** For each proposed fix spawn an investigation agent that answers "which files will this touch" and reports in **lane format**: `improvement-id | files-touched list | risks`. Wave 0 exists exactly for this (re-derived live anchors — survey line numbers may drift). Concurrency lanes = fixes with **DISJOINT file sets**. Two fixes touching the SAME file (even different hunks) share a wave only if assigned to **ONE agent** (grouped lane) or **serialized across waves**. Every wave ends with a careful merge/verification pass (WELD) before it is considered landed.
2. **CONCURRENCY CAP: exactly 10 simultaneous agents.** Never exceed; keep near-filled while lanes are live. (2026-10-21 OWNER RULATION: the standing cap 5 won over this row's 10 for the remediation program — fix-audit waves of 5 ran accordingly; historical W0-W11 waves ran to the 10 on this row.)
3. **Worktrees, but commits land DIRECTLY ON MASTER.** Lane setup: `git -C /home/sites/sugarcraft worktree add /home/sites/chafa-lane-<id> -b lane/<id> master`. Agent implements + commits inside its worktree (its commit *is* on master's tip lineage once welded). **No branches kept, no PRs, ever.** Weld agent absorbs every lane commit into master (cherry-pick / patch-id) and prunes worktree+branch **only after absorption is proven** via `git cherry master lane/<id>` / `git patch-id` equality (a `+` after conflict-resolution is a false positive — verify content equivalence before deleting).
4. **Commit law.** Author+committer `Joe Huss <detain@interserver.net>` assembled via split shell vars so no email literal reaches the redactor:
   `A='detain'; B='interserver.net'; MAIL="${A}@${B}"; GIT_AUTHOR_NAME='Joe Huss' GIT_AUTHOR_EMAIL="$MAIL" GIT_COMMITTER_NAME='Joe Huss' GIT_COMMITTER_EMAIL="$MAIL" git commit --author="Joe Huss <$MAIL>" -m "..."`
   Verify `%ae` and `%ce` on **separate** greps (`git log -1 --format='%ae' | grep -c detain` and same for `%ce` — a joined format is ambiguous). **NO Co-Authored-By trailers.** Plain `-m` messages. **One improvement (or the cohesive pair named in its step id) per commit.**
5. **Push law.** After each wave weld: `git ls-remote origin master` + `git fetch` FIRST (origin can move mid-wave — sibling pushes exist), then push master only when a clean fast-forward. If not clean: merge remote into local preserving both intents (manual conflict resolution, re-run the touched-libs targeted windows), then push. **Never force-push.** Report push state (SHA before/after, FF or merge) in the weld report.
6. **Tests.** Targeted tests per fix AS YOU GO: `cd <lib> && vendor/bin/phpunit --filter <Pattern>` (sugar-* libs run standalone from their own dir; candy-* apps likewise). New/updated tests ship **in the same commit as the fix**. Avoid the FULL suite until the end. The final wave (W8) runs the full serial suite of EVERY touched lib + repo tools (`php tools/check-path-repos.php --no-lib-path-repos`, `php tools/check-child-lifetimes.php`) + regenerates everything tracking figures: per-lib goldens via each lib's update-env idiom (probe P0 discovers the exact env var per lib — sugar-image / sugar-charts / sugar-animation have GoldenRender-style tests), and `candy-code/tests/Config/Support/suite-figure.json` + `scripts/parallel-tests-durations.tsv` **only if candy-code test counts change** (plan assumption: S1.7/S6.2 flip *existing* candy-code assertions only — zero new candy-code test files; if any lane adds one, the weld MUST re-pin figures that wave).
7. **REVIEW LOOP.** After a wave's fixes land, spawn read-only reviewer agent(s) per lane with the diff + that step's DoD checklist. Reviewer returns findings with severity (critical/major/minor). Spawn fixer agents for anything found. Loop with a **FRESH reviewer** until zero critical AND zero major. Minors: fix-if-trivial, else record in `prompt_kit/findings/chafa/` (create dir) or the wave ledger.
8. **BLANK RESPONSE LAW.** An agent returning blank/mid-fragment (common on this model) gets resumed with the single word `continue` on the **SAME session**, up to 10 consecutive times, before any restart or prompt change. No disk-verify between the first 10 resumes.
9. **COMPRESSION LAW.** Context compression only on material already used (e.g., after writing a report file, never right before). Agents near the end of their task must NOT bother with compression — just finish and respond.
10. **Every agent brief is self-contained** (agents do not see this chat): pass absolute file paths, finding-ids, the survey line-ranges to read, chafa evidence lines, DoD, and the relevant §0 laws inline (author law, test command, hotspot ownership).
11. **Docs are pinned.** Any README/docs/*.md or docblock roster change must keep that lib's drift guards green (candy-code ReadmeRosterDrift/EnvRosterDrift/KeyBindingDrift/DocFigureProseDrift family; per-lib guards discovered by probes). **Never hand-edit generated files** (`docs/lib/*`, `ansi/README.md` — regenerate via `tools/gen-docs.php` / `tools/gen-ansi-readme.php` if a tile/row must change).
12. **Façade law.** Behavior lands in the canonical lib only; a façade lib (e.g. sugar-widgets) gets at most an alias-resolution smoke test — never a duplicated suite.
13. **Child-lifetime law.** Any `pcntl_fork`/`proc_open`/child-process change requires `php tools/check-child-lifetimes.php` exit-0, with the new `ACCOUNTED` roster row added **in the same commit**. **NO new `pcntl_fork` call sites anywhere in this campaign** — if process parallelism is introduced (D-02b, E-05(2), D-07 reaping patterns), use `React\ChildProcess\Process` (see S7.4 and F-15/D-07 analysis in survey :635-669, :504-530).
14. **Evidence discipline.** Disk is truth: orchestrator verifies every "landed/committed/green" claim with `git log`/`git status`/test-run output before recording it. Zero-golden default: any golden digest move must be disclosed + justified in the commit message body's first line after the subject. A lane must not leave working-tree dirt outside its own paths.
15. **Scratch.** Lane scratch = own worktree + `/tmp/opencode/chafa-study/w<N>/<lane>/`. Reports there too (`REPORT.md`), never committed.
