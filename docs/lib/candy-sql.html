Composer-installable multi-driver SQL TUI: connect to SQLite, MySQL, or PostgreSQL, browse tables, peek at row data, run ad-hoc queries, and explore a full MySQL-Workbench-style admin dashboard — all on the SugarCraft stack. SQLite-first; MySQL and PostgreSQL drivers plus a Performance Dashboard, Server Status, Variables, Connections, Reports, and Performance Schema Setup ship on dev-master (rolling prerelease tag candy-sql/latest). The interaction model follows lazysql, a Go SQL terminal client; candy-sql is a native PHP project.

Install

composer require sugarcraft/candy-sql:@dev

Requires PHP 8.3 or newer, with ext-pdo_sqlite and ext-sqlite3, which the manifest requires. A MySQL target needs ext-pdo_mysql, and a PostgreSQL target needs ext-pdo_pgsql. Both are suggested rather than required, because a plain install may not need them. ext-pcntl is suggested as well: it arms the query timeout, and without it the timeout falls back to the driver's network timeout.

The :@dev suffix is needed while the release channel is dev-only. The sugar-* siblings track dev-master, and react/mysql is pinned to 0.7.x-dev, so a stable-only project cannot resolve the bare command.

Quickstart

# SQLite via bare path (inferred as Flavor::Sqlite)
vendor/bin/candy-sql app.sqlite

# Any DSN — SQLite, MySQL, PostgreSQL (flags are equals-form only)
vendor/bin/candy-sql --dsn=mysql://user:pass@localhost:3306/dbname

# No database at hand: seed an in-memory SQLite and browse it
php examples/play.php
// Or wire it up programmatically:
use SugarCraft\Core\Program;
use SugarCraft\Core\ProgramOptions;
use SugarCraft\Sql\App;
use SugarCraft\Sql\Db\ConnectionFactory;
use SugarCraft\Sql\Db\Flavor;

// fromDsn() only parses the DSN into a ConnectionConfig; fromConfig() connects.
$db = ConnectionFactory::fromConfig(ConnectionFactory::fromDsn('mysql://user:pass@localhost:3306/dbname'));
(new Program(App::start($db, Flavor::MySQL), new ProgramOptions(useAltScreen: true)))->run();

A SQLite path must name an existing file. The launcher refuses a missing file rather than creating an empty database that would lose every write at exit. The :memory: form is the exception, and it gives a throwaway database.

Concepts

The app is a single model with four panes: Tables, Rows, Query and Admin. Tab cycles through them. The Tables pane lists tables and views. The Rows pane shows the first 100 rows of the selected table, and a table preview there is editable. The Query pane is an SQL editor. The Admin pane holds the server dashboards, and it is available only on MySQL and PostgreSQL. On SQLite the Admin pane answers through an empty-context fallback.

Every driver speaks one interface, DatabaseInterface, and the rest of the app works against that interface. The flavor, an enum of Flavor values, selects the schema queries, the explain output and the admin providers. Driver-specific behavior sits behind strategy objects such as SchemaBrowser, ExplainView and AdminProviderInterface.

Errors stay on the screen. A failed query writes its error to the status line and does not end the session. A connection lost mid-session is detected by its error code (2002, 2003 or 2013), and the session can reconnect. Strings from the server pass through CellValue::sanitize before they reach the terminal.

Tasks

Connect to a MySQL server with a password from the environment

Pass the password through CANDY_SQL_PASS rather than argv, so it stays out of /proc/<pid>/cmdline:

CANDY_SQL_PASS=secret vendor/bin/candy-sql --driver=mysql --user=root --db=mydb

Save a connection and dial it by name

Named connections live in $XDG_CONFIG_HOME/candy-sql/connections.json, or $HOME/.config/candy-sql/connections.json when XDG_CONFIG_HOME is unset. An entry names an environment variable with pass-env, and the password is read when the connection is dialed. Dial the entry with --connect=prod, or run with no arguments in a terminal to choose one from a picker. See Configuration for the fields.

Edit a cell in a table preview

  1. In the Tables pane, select a table and press Enter to load it into the Rows pane.
  2. Move the cell cursor with ←/→ or h/l, and press e. Type the new value. Ctrl+N stores NULL.
  3. Press Enter to show the UPDATE statement, and press Enter again to commit it. Nothing is written before the second Enter.

Row insert with o and row delete with D follow the same confirm-then-write flow. The Troubleshooting section lists the refusals.

Run a query and keep it as a favorite

Type SQL in the Query pane. Enter inserts a newline, and Ctrl+R, Ctrl+E or Ctrl+Enter runs the statement. Ctrl+F saves the text to the favorites list for the session. A statement with ? or :name placeholders opens a prompt for each parameter before it runs. An empty value binds NULL.

Export a table to CSV, or import a file

With rows on screen, press x in the Tables or Rows pane to open the export line, or press Ctrl+S from any pane to open the same line. Press i in the Tables or Rows pane to open the import line. In either line Enter submits and Esc closes it.

Read the recorded status history

Press H in the Tables, Rows or Admin pane to read the recorded status history. Its counter trend is folded into the Rows pane. Recording is on by default in the launcher. Pass --no-history to turn it off, or --history=PATH to choose the file. See Status-snapshot history.

Drive it from a script

The launcher is an interactive program. With stdout not a terminal it dials the connection and then refuses with exit status 2. To drive it from a script, run it under a pseudo-terminal, for example script -qec 'candy-sql app.sqlite' /dev/null. To render results from library code, use ResultTable::renderPlain(), which produces an escape-free grid.

Connection details come from a DSN, from individual flags, or from a saved connection. Each one is a route into the same ConnectionFactory.

Allowed fields are driver, host, port, user, db, ssl-mode and pass-env. An unknown field, an unsupported driver, a non-numeric port or a malformed name is refused by name, with one line and exit status 2. Passwords are never stored on disk.

Status-snapshot history

The launcher records the admin poll snapshots to SQLite by default. The file is $HOME/.candy-sql/history.db, or the path given to --history. It is created with mode 0600 inside a 0700 directory. A snapshot is a timestamped map of server status variables, and SQL statement text is never persisted.

Recording applies to MySQL and PostgreSQL only. A SQLite session has no status feed, so the history file stays empty for it. Retention is bounded by two caps, the newest 10 000 rows and the last 72 hours, and whichever discards more wins. The sweep runs at open and after every insert.

Theming and styling

candy-sql ships no theme file. Its colors come from the terminal profile that sugar-core detects, so NO_COLOR, TERM=dumb and COLORTERM decide what you see. The focus marker is a bold ▶ on the pane's frame title. That glyph survives NO_COLOR, where a hue change would vanish, and the status-line legends and the error: word stay readable without color.

The result grid uses a reverse-video cursor on styling terminals. JSON cells pretty-print with a two-space indent, and long rows scroll horizontally. The renderer does not offer a high-contrast mode or a reduced-motion toggle. The [p] key freezes the dashboard gauges at their last values until it is pressed again. The 1-second admin fetch keeps running while paused, so the cached server status still refreshes.

Troubleshooting

The launcher says "no such SQLite file"

The path names a file that does not exist. candy-sql does not create SQLite files, so an empty file cannot appear and lose writes at exit. Point it at an existing file, or create the file first, for example with sqlite3 fresh.sqlite < dump.sql. :memory: is exempt.

A MySQL or PostgreSQL connection fails because its PDO driver is missing

The matching PDO driver is not installed. Install ext-pdo_mysql for mysql:// DSNs and --driver=mysql, or ext-pdo_pgsql for pgsql:// DSNs and --driver=pgsql. Without pdo_mysql, a MySQL DSN stops with candy-sql: Undefined constant PDO::MYSQL_ATTR_SSL_CA and exit status 2. Without pdo_pgsql, a PostgreSQL DSN stops with PDO's could not find driver and exit status 2.

The launcher prints USAGE, or refuses a piped stdout, and exits 2

With no DSN, no flags and no saved connection, the launcher prints USAGE. Give a DSN, use --connect=NAME, or run the command in a terminal. A piped or redirected stdout is refused with this launcher drives an interactive terminal and refuses to stream ANSI onto a pipe (exit 2), even when a path is given, for example candy-sql app.sqlite | cat. Use a pseudo-terminal when scripting.

A warning says "history recording DISABLED"

The history file is corrupt or cannot be written. The session runs without history and says so on stderr. Relocate the file with --history=PATH, or turn recording off with --no-history.

A query timeout does not fire

The SIGALRM timeout needs ext-pcntl, which Windows and slim Docker php-cli images often lack. Without it the timeout falls back to the driver's network timeout. Install the extension, or run on a host that has it.

A saved connection is refused because of a pass field

A pass field in connections.json is a hard refusal, because passwords are never stored on disk. Move the password to an environment variable, and name that variable with pass-env.

Editing a cell is refused

Edits address rows by their full primary key. A table with no primary key, a NULL or binary key value, a binary or large cell, a query-result view, or a --read-only session all refuse with a named reason. A write that touches a different row count than promised is rolled back.

y copies nothing to the clipboard

The clipboard uses OSC 52. A terminal that reports TERM=dumb, TERM=linux or nothing never receives the sequence. Use a terminal that supports OSC 52.

Upstream mapping

lazysql is the design antecedent. Its Tables, Rows and Query layout, and its change-cell, new-row and delete-row flow, are the model for the editable Rows pane. The admin dashboard is modeled on MySQL Workbench. candy-sql is native PHP, and it is not a line-by-line port, so there is no class-for-class table. The README's Editing table data section names the lazysql flow it follows.

Architecture

The layers run from the terminal down to the server:

  • Model. App holds the panes, the query state and the admin pages. It returns a new model for each message.
  • Database. DatabaseInterface and its PDO adapters, SqliteDatabase, MysqlDatabase and PostgresDatabase. ConnectionFactory parses a DSN, and Flavor names the server type.
  • Strategies. SchemaBrowser and ExplainView pick the driver-specific SQL for schema introspection and plan output.
  • Edits. DmlBuilder builds statements from the full primary key, and DmlRunner wraps each write in a transaction that rolls back unless the promised row count changed.
  • Admin. AdminProviderInterface gives one port for admin data, with a MySQL and a PostgreSQL adapter. The pages sit on top of it.
  • History. HistoryRecorder writes snapshots through SqliteHistoryStore.

Known limitations

The gaps are pre-1.0, and most sit on the asynchronous ReactPHP query path.

  • No connection pooling. One async connection per flavor, DSN and user is cached and reused. Concurrent admin queries are serialized onto that connection.
  • No transactions on async connections. ReactMysqlConnection and ReactPostgresConnection run single statements. A BEGIN and COMMIT that spans several queries is not coordinated on that path.
