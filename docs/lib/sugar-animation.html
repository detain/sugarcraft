SugarAnimation is an ANSI/GIF animation toolkit for PHP 8.3+. It decodes a .gif from disk with ext-gd, area-averages each frame onto a fixed cell grid, and paints it with 24-bit ANSI color. It also parses and replays truecolor .ansi art files frame by frame, which needs no GD at all. The GIF path is inspired by the Go project gifterm; the library itself is native PHP. The ready-made viewer CLI ships separately as candy-gifview.

Install

composer require sugarcraft/sugar-animation

Requires PHP 8.3 or newer. ext-gd is needed only for the GIF path (Decoder). AnsiArt, ArtLibrary, ArtLoop and Player run without it. Without GD, Decoder::decode(), Decoder::decodeFile() and Decoder::decodeBytes() throw a RuntimeException that names the missing extension. Decoder::readFile() and Decoder::loopCount() do not use GD and keep working.

Quickstart

// Decode a GIF from disk and play it in the alternate screen.
// "cat.gif" is any .gif on disk.
use SugarCraft\Core\Program;
use SugarCraft\Core\ProgramOptions;
use SugarCraft\Animation\Decoder;
use SugarCraft\Animation\Player;

$frames = Decoder::decode('cat.gif', cellsW: 80, cellsH: 30);
(new Program(new Player($frames),
             new ProgramOptions(useAltScreen: true)))->run();
// .ansi art: parse once, then print one frame as SGR text.
use SugarCraft\Animation\AnsiArt;

$art = AnsiArt::fromFile('logo-neon-tc-72x9.ansi');
echo $art->sgrText(0), PHP_EOL; // animated files: pick a frame index
# The viewer CLI is a separate app package:
#   composer require sugarcraft/candy-gifview
#   candy-gifview my-animation.gif           # solid blocks (default)
#   candy-gifview my-animation.gif density   # luminance ramp

To see the whole pipeline without any file of your own, run examples/play.php (see Examples below).

Concepts

The library has two halves that share a cell model. The GIF half turns bytes into Frame values. A Frame is a grid of RGB cells (null marks a transparent cell), a centisecond delay, a disposal method and a transparency flag. Decoder walks the GIF stream, hands each image to GD, and area-averages the source pixels under each cell with CellSampler. The grid size is fixed at decode time, so the art is stretched to exactly cellsW by cellsH cells and is never re-fit to the terminal.

The playback half is a TEA model. Player implements the sugar-core Model contract. It advances on TickMsg values scheduled with Cmd::tick(), so no fiber busy-waits. Renderer turns one frame into an ANSI string with one of two presets: solid paints full cells with a 24-bit background, and density maps each cell's luminance to a glyph from a ramp with a 24-bit foreground.

The .ansi half is separate. AnsiArt parses a byte stream of SGR runs and glyphs into cell-grid frames, ArtLibrary indexes a corpus of pre-authored files, and ArtLoop converts elapsed seconds into a frame index for banners and logos.

Tasks

Decode a GIF to a fixed grid. Call Decoder::decode($path, $cellsW, $cellsH) for a plain list<Frame>. Use Decoder::decodeFile() when you also need the loop count and the stop reason in one value.

Start paused and step by hand. Pass paused: true to the Player constructor. Then use the arrow keys to move one frame at a time.

Bound a run. Chain playOnce(), withLoops(3) or withMaxSeconds(10.0) on the Player. Each returns a new instance.

Pin the frame rate. Call withFixedFps(12.0) to advance on a uniform wall-clock cadence instead of the per-frame GIF delays.

Choose the viewport-fit renderer. Pass Renderer::withAdaptiveSize() to the Player constructor. It reads the terminal size from STDOUT with PosixBackend::queryWinsize(1) and clips the art to the viewport. It throws a RuntimeException when STDOUT is not a terminal, so guard the call in piped output or CI and fall back to Renderer::new(). Pass Renderer::withAdaptiveSize(reservedRows: 2) to leave rows free for your own chrome.

Pick a logo variant by terminal depth. Build an ArtLibrary with ArtLibrary::fromDir($dir), then call pick($slug, $depthTag). The requested depth is tried first. If the slug has no variant at that depth, the adjacent depths are tried in a fixed order: a tc request falls back to 256 then 16, a 256 request to tc then 16, and a 16 request to 256 then tc.

What's in the box

ext-gd decodeWalks the GIF byte stream for image-descriptor offsets, hands each frame to GD, and area-averages it onto the cell grid.
Area-average downsamplingEach cell averages the fully opaque source pixels that cover it. The palette path skips pixels that match the transparent index.
ASCII luminance rampThe density preset maps each cell's luminance (0.299r + 0.587g + 0.114b) to a ramp glyph and carries the color as a 24-bit foreground, so the shape still reads where color is stripped.
Local color tablesEach frame uses its own Local Color Table when the Image Descriptor carries one, and falls back to the Global Color Table otherwise.
Transparency and disposalThe Graphic Control Extension supplies the transparent index and disposal method (none, restore to background, restore previous), tracked per frame in Frame.
Two presetssolid paints full cells with a 24-bit background and a space glyph. density uses the ramp ' .:-=+*#%@' with a 24-bit foreground.
Viewport-fit renderingRenderer::withAdaptiveSize() reads the terminal size from STDOUT through PosixBackend::queryWinsize(1) (TIOCGWINSZ) and clips the art. It throws when STDOUT is not a terminal. A resize clips the art; it never re-scales it.
.ansi art playbackTruecolor .ansi streams parse into cell-grid frames with AnsiArt. ArtLibrary selects a variant for the detected depth, and ArtLoop cycles frames by elapsed time.
Bounded playbackplayOnce(), withLoops(n) and withMaxSeconds(s) cap a run. withFixedFps() pins the cadence.
Decode capsOne decode holds at most 256 frames (Decoder::MAX_FRAMES), 2,000,000 source pixels (MAX_TOTAL_PIXELS) and 100,000 output cells per frame (MAX_CELLS). A cap breach throws. The file entry points read at most one byte past Decoder::MAX_INPUT_BYTES (64 MiB), then refuse any file that is larger.

Player final class

E-03: GIF player as a SugarCraft Model driven by an ABSOLUTE schedule. Loads every frame up-front (the decoder caps at 256); frame k is due at anchor + C[k] where C is the prefix sum of the frame periods (modulo one cycle of total length T), and each TickMsg re-arms the loop for the NEXT frame's deadline — max(nextDue - now, MIN_TICK_CS) — never a fresh copy of the CURRENT frame's delay. While the elapsed position resolves to a frame OTHER than the one on screen the table stays absolute from the kickoff origin: an overrun costs lateness, not drift, and the tick skips straight to its landing frame (the ArtLoop philosophy — on that path the displayed frame is a total function of elapsed time). The table DOES rescale at the wrap boundary, however: when the elapsed position lands back inside the window of the frame already on screen — which every stall of at least one full cycle does, as does a pump fired inside the current window — the tick force-advances exactly ONE frame and re-anchors the epoch to wall-clock now, so that frame holds a fresh full period. Post- wrap the cadence (the per-lap sequence of holds) is therefore preserved while the epoch is re-based, bounding the catch-up to one advance per tick. The naive alternative — continuing the absolute table without re- basing — was rejected because the force-advanced frame would survive only the sliver of window left before its table deadline (arbitrarily short partial holds at every stall boundary); the re-anchor is the shipped choice and PlayerScheduleTest pins the resulting index/arm stream against an independent walk. Before E-03 the Player re-armed the current frame's full delay on every tick, so the per-frame period was delay + handling + render time and playback silently stretched under load — the docblock here used to promise rate-stability the schedule did not deliver.

Theme and styling

There is no theme object. Both presets always emit 24-bit truecolor SGR (38;2;… and 48;2;…). The library has no 256-color fallback and no NO_COLOR mode. On a terminal without truecolor the colors degrade, and density stays the more legible preset. The .ansi side has its own fallback: ArtLibrary resolves a slug through the tc, 256 and 16 depth cascade and picks a pre-authored variant. It does not recolor art at runtime.

Examples

examples/play.php builds a three-frame synthetic GIF in the system temp directory. The GIF has a red, green and blue band that slides across a black field. It decodes that GIF and plays it in the alternate screen. The temporary file is removed on shutdown.

php examples/play.php           # interactive player in a terminal
php examples/play.php < /dev/null   # prints: decoded 3 frame(s)

When stdout is not a terminal, the example prints a one-line summary and exits. Run it that way in CI or in a pipe.

Testing

The suite runs with PHPUnit 10 and the golden-render fixtures in tests/fixtures/:

composer install
vendor/bin/phpunit

The decoder tests use a set of hostile GIFs in tests/fixtures/bad/. They cover oversize descriptors, bad LZW data, zero-delay storms and frame floods. GoldenRenderTest compares the density render against tests/fixtures/density-3x3.golden. A changed render has to update that golden file on purpose.

Troubleshooting and FAQ

  • Decode throws a RuntimeException that names ext-gd. Install or enable the gd extension. The .ansi classes never need it.
  • The decode throws a cap error on a large GIF. The caps are Decoder::MAX_FRAMES (256), MAX_TOTAL_PIXELS (2,000,000), MAX_CELLS (100,000 per frame) and MAX_INPUT_BYTES (64 MiB). Shrink the source or lower the cell grid.
  • The art is clipped after a resize. This is by design. The cell grid is fixed at decode time. Decode again at the new size, or use the viewport-fit renderer, which clips rather than re-scales.
  • The status line wraps on a narrow terminal. The overlay is clamped to the renderer's column budget. It shows its full hint from 82 columns up. Use 82 or more columns for best results.
  • Colors look wrong, or the art shows raw escapes. The output is 24-bit truecolor. On a terminal without truecolor, the colors degrade. On TERM=dumb, expect raw escape sequences. Switch to the density preset with d for a shape that still reads without color.
  • The animation does not respect reduced-motion settings. The library does not read REDUCE_MOTION. Start paused with paused: true, slow it down with withFixedFps(), or bound it with playOnce().

Untrusted input

The parser is defensive but it is not a sandbox. Complete OSC sequences and unknown CSI bodies are dropped. Frame and AnsiArt keep only canonical SGR runs, so sgrText() never replays an escape the input carried. C0 control bytes outside an escape sequence stay in the output as glyph data. Echoing $cell->glyph raw, or sgrText(), passes them to the terminal. Bound file ingress with Decoder::MAX_INPUT_BYTES, which the file entry points enforce with a bounded read. At most MAX_INPUT_BYTES + 1 bytes are pulled, and a larger file is refused. fromString() and decodeBytes() take the bytes you hold and refuse input over the same MAX_INPUT_BYTES cap. That check runs once the bytes are already in memory, so bound the input size yourself before you read it.

Localization

Decode and parse errors, and the Player status overlay, go through Lang in the animation namespace. Translations ship for each locale in lang/. The literal key names the overlay advertises (space, d, q) do not change between locales.

Architecture

The GIF path runs Decoder (walk the stream and read each image) into CellSampler (area-average onto the grid) into Frame. The playback path runs Player (a TEA model that schedules TickMsg through Cmd::tick()) and Renderer (frame to SGR string). AnsiArt, ArtLibrary and ArtLoop form a separate path with no GD dependency.
