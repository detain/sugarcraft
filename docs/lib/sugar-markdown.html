sugar-markdown renders CommonMark into ANSI for the terminal: word-wrapped text, OSC 8 hyperlinks, syntax-highlighted code, and nine built-in themes plus JSON themes in both this library's flat schema and glamour's styles.json schema. It mirrors charmbracelet/glamour (Go) and is built on league/commonmark and sugar-style.

Install

composer require sugarcraft/sugar-markdown

Requires PHP 8.3 or newer. The sibling sugarcraft/* packages track dev-master, so mirror the monorepo's minimum-stability: dev with prefer-stable: true in your own root manifest. The HTML converter needs ext-dom, which is a suggestion rather than a requirement. Without it, HtmlToMarkdown::convert() returns null.

Quickstart

render($markdown), "\n";

// A flat JSON theme takes one or more style slots, and the rest keep their defaults.
$theme = Theme::fromJsonString('{"heading1":{"bold":true}}');
echo (new Renderer($theme))->render("# Styled\n"), "\n";

A renderer with no theme uses Theme::ansi(). That is a deliberate divergence from glamour, which defaults to its dark style. Use new Renderer(Theme::dark()) for the one-line parity path.

Concepts

A Renderer holds the options and the theme. It parses a document with the CommonMark parser, walks the blocks, and writes ANSI bytes. The option setters are immutable: each with*() returns a new renderer. A renderer is not reentrant, so use one per thread of work and reuse it across renders. Renderer::cached() hands back a shared instance for a theme and width, which suits a render loop.

A Theme is a set of styles for each block and inline element, plus a few scalar decorations such as heading prefixes and the image text. Every decoded string is swept for control bytes, so a theme file cannot inject a raw escape sequence. A theme file is code that the terminal runs, so load only files the operator pinned.

Streaming is the second mode. stream() yields rendered sections as the Markdown arrives, and for any split of the same input the joined output equals render() byte for byte. Writer is the push-side version for a sink you control.

Tasks

Render a file to the terminal

$renderer = (new Renderer(Theme::tokyoNight()))->withWordWrap(100);
echo $renderer->render(file_get_contents('README.md')), "\n";

Word wrap is off unless you call withWordWrap(), so rendered lines follow the source. Wrapping counts terminal cells, not bytes, and it honors SGR and grapheme clusters.

Pipe Markdown through a stock theme from stdin

cat README.md | php examples/stdin-stdout.php --theme=dracula

The example reads at most 1 MiB, and an unknown theme name prints a warning to stderr and falls back to ansi. A longer input is refused with exit code 2.

Take the theme from the environment

$renderer = new Renderer(Theme::fromEnvironment(Theme::dark()));

Theme::fromEnvironment() reads GLAMOUR_STYLE, and NO_COLOR wins over every other input. GLAMOUR_STYLE=auto trusts isatty only, so pin notty or ascii for a pipeline behind a PTY that should carry no color.

Stream a document as it arrives

use SugarCraft\Markdown\Renderer;

$renderer = new Renderer(Theme::dark());
foreach ($renderer->stream($chunks) as $section) {
    echo $section;
}

Each yielded section is a complete block-level unit. Link reference definitions carry across sections, and a section that refers to a definition not yet seen is held back until that definition arrives. A document that uses post-processing themes, or withPreservedNewLines(true), buffers and emits once. defersStreaming() reports which regime applies.

Fold sections under chosen headings

$renderer = (new Renderer(Theme::dark()))->withFolds([Renderer::headingId('Usage')]);

A folded heading keeps its line and a fold marker, and hides the blocks after it up to the next heading of any level. Heading IDs come from the rendered text, so Renderer::headingId() must see the same text the renderer does.

Convert fetched HTML to Markdown

use SugarCraft\Markdown\Html\HtmlToMarkdown;

$markdown = HtmlToMarkdown::convert($html, 'https://example.com/docs/', 'UTF-8');
if ($markdown === null) {
    // Fall back to the raw body. See the troubleshooting entry below.
}

Scripts, styles, navigation and other non-content subtrees are dropped whole. The result is then rendered by Renderer like any other Markdown.

Hard limits apply regardless of options. Block nesting is capped at Renderer::MAX_NESTED_BLOCK_DEPTH (32): past the ceiling content still renders, but decoration stops. Keys and input

sugar-markdown handles no keys. It is a renderer, and a TUI host such as candy-mdview owns its own key bindings for scrolling and navigation.

Theme and styling

The nine presets are ansi, plain, notty, ascii, dark, light, dracula, tokyo-night and pink. notty is an alias of plain. The catalog adds solarized, monokai and github from the bundled themes/ directory.

Two schemas load through Theme::fromJsonString(). The flat schema is this library's own, and it lists style slots such as {"heading1":{"bold":true}}. A payload with a top-level document object follows glamour's styles.json schema and routes through StyleGuide, which reads the document block, the element blocks and the chroma tokens.

StyleGuide::theme() projects what the Theme can hold. It keeps the paragraph block_prefix and block_suffix, and drops the affixes on other non-document elements such as headings and block quotes. It also drops per-heading-level prefixes and chroma families beyond the four slots it has. Dropped keys stay readable through element() and chroma(), so a richer theme can use them later. Glamour's inline and block images style the alt text only, because the library does not embed images.

Custom theme example: start from a stock theme and swap individual style slots with Theme::with(), as examples/custom-theme.php does.

Examples

  • examples/render.php renders a sample document with a handful of stock themes. With GLAMOUR_STYLE or NO_COLOR set, it adds a section for Theme::fromEnvironment(). Run it with php examples/render.php.
  • examples/themes.php renders the same document under each colorful stock theme. Run it with php examples/themes.php.
  • examples/custom-theme.php starts from a stock theme and swaps individual slots with Theme::with(). Run it with php examples/custom-theme.php.
  • examples/stdin-stdout.php renders Markdown read from stdin, with an optional --theme= flag. Run it with cat README.md | php examples/stdin-stdout.php.

The examples read vendor/autoload.php, so run them from the library root after composer install.

Troubleshooting

Colors are missing in a pipeline

GLAMOUR_STYLE=auto trusts isatty and nothing else. A pipeline behind a PTY can still receive full SGR. Set GLAMOUR_STYLE=notty or ascii explicitly for those pipelines. NO_COLOR always wins over GLAMOUR_STYLE.

A long word overflows the wrap width

Wrapping counts terminal cells. A whitespace-free run longer than four times the wrap width is hard-broken before the wrapper sees it, so a long token is split rather than overflowing. Check that withWordWrap() was called, because word wrap is off by default.

A link is not clickable in my terminal

The OSC 8 envelope is on by default and wraps the visible text, and the visible text is followed by (url) in both modes. A terminal without OSC 8 support shows the text and the URL and nothing is lost. withHyperlinks(false) removes only the envelope, so the (url) suffix stays. A refused scheme never opens an OSC 8 target.

A theme throws on load

Lenient keys and strict values. An unknown key is ignored, but a bad hex color such as #ff5f or an out-of-range ansi:99 throws InvalidArgumentException. A file that is unreadable or over the byte ceiling throws RuntimeException. Read the message, which names the field.

HtmlToMarkdown returns null

The converter returns null for empty input, when ext-dom is absent, for a body over 512 KiB, for a body the parser refuses, and for a body with no renderable text, such as a lone <script>. Fall back to the raw body in that case. The raw bytes include the text that the drop rule removed, so a caller that must never show raw content should not take the fallback.

Architecture

The pipeline is parse, scan, render. SectionScanner splits the input into candidate sections, and SectionStream holds back any section whose link references are not yet defined. The renderer walks the CommonMark blocks with a block stack, and TokenWrap and the ANSI-aware wrapper do the layout. Every decoded string from a theme passes through the sanitizer before it reaches the output.

Renderer-side limits are fixed in code: the block nesting depth, the section size, the highlight size and the theme decoration ceiling. The converter uses its own limit, a 512 KiB parse size checked before parsing. Input is not capped at the library, so a hostile stdin needs an intake guard in the host.
