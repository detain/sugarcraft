SugarFlexbox is a layout toolkit for terminal cell grids. It has a ratio-based FlexBox engine, a sortable and filterable model Table with delta rendering, a scrolling Viewport with sticky rows, and a Scrollbar. Viewport and Scrollbar are thin compositions of the canonical sugar-forms classes. The full keyboard-driven data grid belongs to sugar-table. SugarFlexbox is the lighter layout layer beside it.

Install

composer require sugarcraft/sugar-flexbox

Requires PHP 8.3 or newer. Composer pulls in sugarcraft/sugar-core, sugarcraft/sugar-forms and sugarcraft/sugar-cellbuffer. The layout classes need nothing beyond those. TableRenderer uses the cellbuffer for delta rendering.

Quickstart

use SugarCraft\Flexbox\Flex\{FlexBox, FlexItem};
use SugarCraft\Flexbox\Flex\Align;
use SugarCraft\Flexbox\Table\{Table, Column};

$flex = FlexBox::row(
    FlexItem::new('LEFT')->withRatio(1),
    FlexItem::new('RIGHT')->withRatio(2),
)->withGap(2);

$table = Table::new()
    ->withColumn(Column::new('Name', 20))
    ->withColumn(Column::new('Age', 5)->withAlign(Align::End))
    ->withRow(['Alice', '30'])
    ->withRow(['Bob', '25'])
    ->withSort(0);

echo $flex->render(40, 1), PHP_EOL;
echo $table->render(), PHP_EOL;

The FlexBox shares the 38 cells left after the 2-cell gap between its two items in a 1:2 ratio. The table sorts by its first column and right-aligns the Age column. Both calls return strings, so nothing is written to the terminal until you echo them.

Concepts

Every class is an immutable value. Each with*() method returns a new instance and leaves the receiver unchanged. Plain constructor state is a public readonly property, such as Column->title or FlexItem->ratio. Anything derived or guarded is read through a method, such as Table::cursor() or Viewport::yOffset(). The methods are where the settle-and-refuse logic lives.

FlexBox sizes items on one main axis. A basis reserves a fixed number of cells first. The leftover cells are shared by ratio, and an item with ratio 0 keeps its 1-cell floor. Align places items across the cross axis, where Stretch fills the box. Justify and Wrap handle spacing and line breaks along the main axis.

Table renders text. Cell values and column titles are sanitized as untrusted data. render() returns the full frame. TableRenderer keeps the last frame and emits only the rows that changed, which keeps repaints small. Table never wraps: a grid wider than the terminal stays wide, and you scroll it inside a Viewport.

Viewport is a scrolling window over text. It keeps the first or last rows pinned with sticky headers and footers. Its key and mouse handling come from sugar-forms.

Tasks

Split a row by ratio with a fixed sidebar. Give the sidebar a basis and the content a ratio. The basis is taken first and the ratio shares what remains:

$row = FlexBox::row(
    FlexItem::new($sidebar)->withBasis(20),
    FlexItem::new($content)->withRatio(1),
)->withGap(1);
echo $row->render(100, 24), PHP_EOL;

Sort, then filter, a table. Sort first, then filter. A filter that drops the cursor row moves the cursor to row 0:

$table = Table::new()
    ->withColumn(Column::new('Name', 16))
    ->withColumn(Column::new('Score', 6)->withAlign(Align::End))
    ->withRow(['Mira', '91'])
    ->withRow(['Oren', '78'])
    ->withSort(1, false)           // column 1, descending
    ->withFilter('o');            // case-folded substring match
echo $table->render(), PHP_EOL;

Mark the cursor row without color. A cursor style is an SGR string, and a screen reader does not hear color. Add a glyph prefix as well, and read cursor() when focus moves:

$table = $table
    ->withFilter('')                 // lift the filter from the Task above
    ->withCursorStyle('7')           // SGR parameter 7: reverse video
    ->withCursorMarker('> ')
    ->withCursor(1);
$index = $table->cursor();          // int|null: the settled row index

Redraw only the changes. Use one TableRenderer for the life of the screen. The first frame, and every resized frame, is full. After that only the changed rows are emitted:

use SugarCraft\Flexbox\Table\TableRenderer;

$renderer = TableRenderer::new();
echo $renderer->render($table);     // first frame: full
echo $renderer->render($table);     // unchanged: no bytes (the delta is empty)

Scroll a long document with a sticky header. Pin the first row, then scroll the rest with the keys in the Keys and controls section:

use SugarCraft\Flexbox\Viewport;

$vp = Viewport::fromContent($document, width: 80, height: 20)
    ->withStickyHeader(1)
    ->withSmoothScroll(false)       // reduced motion: each scroll settles in one frame
    ->gotoTop();

What's in the box

FlexBoxRatio-based row and column layout. Align (Start, Center, End, Stretch) drives both axes, and Justify and Wrap add main-axis spacing and wrapping. There is no CSS justify-content equivalent for the cross axis.
TableSort by column (ascending or descending, with authored tiebreakers through Column::sorted()). Filter by a case-folded substring. Cursor navigation is guarded at its door. Each column can carry its own style, and a column can be hidden at width 0. The ruler is themeable. An over-wide grid is reported by computeTotalWidth(), and render() never wraps it.
TableRendererDelta rendering. The first frame and every resized frame are full, and each later frame emits only the rows that changed.
ViewportA scrolling window that composes the canonical sugar-forms Viewport. It supports line, page and half-page moves, mouse wheel, smooth scroll and a scrollbar. Sticky headers and footers pin rows with withStickyHeader() and withStickyFooter(). withLinkedViewport() only marks a partner. Scroll state is not shared.
ScrollbarA vertical or horizontal scrollbar that composes the canonical sugar-forms Scrollbar, with configurable thumb and track characters.
ImmutabilityEvery builder returns a new instance, so a shared table or box can be reused without side effects.

Keys and controls

Only Viewport reads keys. It inherits its bindings from sugar-forms, so the keys below work in any program that passes messages to Viewport::update(). Table and FlexBox have no key handling. Your program moves the cursor with withCursor().

KeyAction
↑ / kScroll up one line.
↓ / jScroll down one line.
← / hScroll left.
→ / lScroll right.
PageUp / bScroll up one page.
PageDown / f / SpaceScroll down one page.
Ctrl+u / Ctrl+dScroll up or down half a page.
Home / gJump to the top.
End / GJump to the bottom.

Mouse-wheel scrolling works when withMouseWheelEnabled(true) is set. The wheel moves withMouseWheelDelta() lines per notch. examples/viewport-keys.php drives the full key set.

Theme and styling

Styles are SGR parameter strings, not theme objects. Pass them to Column::withStyle(), Table::withCursorStyle() and Table::withHeaderStyle(). The ruler characters come from Table::withRulerChars(), and the column separator from Table::withSeparator(). The cursor style paints over a column style. Validated SGR that you pass in is emitted as given. The library does not read NO_COLOR or TERM, so color policy belongs to your host program.

Trust boundary

Table, Column and FlexBox treat everything they render as untrusted data: cell values and column titles pass through Sanitize::untrusted(), and at render time a line feed or a CRLF pair collapses to a single space, a tab becomes a single space, and a lone carriage return is DELETED (not replaced) — so no escape sequence can ride in through content. One asymmetry to know about: the FlexBox measures an item's raw content before the sweep, and only the tab skews the budget (it measures four cells and prints one space — over-allocation, never a truncation); every other swept byte measures zero cells on both sides. Style strings are gated to legal SGR parameter text (codes 0..255 separated by single ;, colon sub-parameters normalized at the door) or empty for no style; anything else throws InvalidArgumentException naming the refused property. Viewport and Scrollbar are trusted-input by design — the Viewport renders your setContent() / fromContent() lines as given and the Scrollbar emits your runes verbatim — so sanitize user input before feeding them.

Accessibility

Focus is never carried by color alone. The cursor row's default cue is its style; withCursorMarker() prepends a glyph inside the first column's width without moving frame dimensions. A screen reader announces neither color nor shape — pair the visual cue by reading cursor()/currentRow() on every change. Sort state is a glyph (▲/▼), not a color; a filtered-to-nothing table can say so with withEmptyText() over totalRowCount()/filterText().

Reduced motion has a real switch (withSmoothScroll(false)), keyboard is the primary path (every scroll verb answers update() with a KeyMsg; see examples/viewport-keys.php), and color policy stays the host's: the library never reads NO_COLOR/TERM — validated SGR you pass in is passed through deliberately.

Troubleshooting and FAQ

  • A wide table is cut off, or it spills past the terminal. Table::render() never wraps. Check computeTotalWidth(), then put the table in a Viewport and scroll it with the keys above.
  • The cursor disappears after a filter. A filter that removes the cursor row moves the selection to row 0. An empty view returns cursor() === null. Read cursor() after each change rather than caching the index.
  • The cursor is visible on screen but a screen reader says nothing. Color and reverse video are not spoken. Add withCursorMarker() and announce cursor() on every move.
  • An item with a fixed basis is squeezed in a narrow box. A basis is clamped to the container size at render time, so an oversized basis shrinks rather than overflowing. Give the flexible items a ratio, or widen the box.
  • Each frame prints the whole table. Call render() through one TableRenderer instance. A new renderer, or reset(), starts over with a full frame.
  • An exception names a surplus value or a bad column. withRow() throws when a row has more values than there are columns.

Architecture

Layout is pure. FlexBox::render() and Table::render() take their inputs and return strings, with no terminal writes. TableRenderer is the only class that keeps state between frames, and it holds one previous frame. Viewport is a value that wraps the sugar-forms Viewport and returns a new instance from each update().

Changelog and versioning

The package has no separate changelog file. The version history is in the commit log of sugar-flexbox/. The README records the deprecations, which retire in 2.0.0. The main ones are Column::make() (use Column::new()), Table::addColumn() and addRow() (use withColumn() and withRow()), FlexItem::withWidth() (use withBasis()), and Viewport::withContent() and withScrollbar(). The 2026-10-24 accessor cleanup moved dimension reads to width() and height() and sizing to withSize().
