FlexBox layout engine for terminal grids — ratio-based item sizing, gap, align. Plus a simple table with sort, filter, cursor nav, and column styling. Viewport and Scrollbar compose the canonical sugar-forms classes.

Install

composer require sugarcraft/sugar-flexbox

Quickstart

use SugarCraft\Flexbox\Flex\{FlexBox, FlexItem};
use SugarCraft\Flexbox\Flex\Align;
use SugarCraft\Flexbox\Table\{Table, Column};

$flex = FlexBox::row(
    FlexItem::new('LEFT')->withRatio(1),
    FlexItem::new('RIGHT')->withRatio(2),
)->withGap(2);

$table = Table::new()
    ->withColumn(Column::new('Name', 20))
    ->withColumn(Column::new('Age', 5)->withAlign(Align::End))
    ->withRow(['Alice', '30'])
    ->withRow(['Bob', '25'])
    ->withSort(0);

echo $flex->render(40, 1), PHP_EOL;
echo $table->render(), PHP_EOL;

What's in the box

FlexBoxRatio-based row / column layout. Align: Start, Center, End, Stretch (one value drives both axes — box height plus text placement in row mode, rendered width plus placement in column mode; no CSS justify-content counterpart).
TableSort by column (asc/desc toggle, with authored secondary tiebreakers via Column::sorted()), filter by case-folded text, cursor navigation guarded at its door, per-column style, hidden (width-0) columns, themeable ruler, and an over-wide disclosure: computeTotalWidth() is the whole grid's width and render() never wraps — compose in a Viewport to scroll it.
ViewportScrollable viewport composes the canonical sugar-forms Viewport. Keyboard nav (line/page/half-page), mouse wheel, smooth scroll, scrollbar. Sticky headers and footers via withStickyHeader()/withStickyFooter(); a document that fits renders the plain streaming face. withLinkedViewport() is a decorative partner marker only (scroll state never propagates).
ScrollbarScrollbar composes the canonical sugar-forms Scrollbar. Vertical/horizontal, configurable thumb/track chars.
ImmutabilityAll builders return new instances.

Trust boundary

Table, Column and FlexBox treat everything they render as untrusted data: cell values and column titles pass through Sanitize::untrusted(), and at render time a line feed or a CRLF pair collapses to a single space, a tab becomes a single space, and a lone carriage return is DELETED (not replaced) — so no escape sequence can ride in through content. One asymmetry to know about: the FlexBox measures an item's raw content before the sweep, and only the tab skews the budget (it measures four cells and prints one space — over-allocation, never a truncation); every other swept byte measures zero cells on both sides. Style strings are gated to legal SGR parameter text (codes 0..255 separated by single ;, colon sub-parameters normalized at the door) or empty for no style; anything else throws InvalidArgumentException naming the refused property. Viewport and Scrollbar are trusted-input by design — the Viewport renders your setContent() / fromContent() lines as given and the Scrollbar emits your runes verbatim — so sanitize user input before feeding them.

Accessibility

Focus is never carried by colour alone. The cursor row's default cue is its style; withCursorMarker() prepends a glyph inside the first column's width without moving frame dimensions. A screen reader announces neither colour nor shape — pair the visual cue by reading cursor()/currentRow() on every change. Sort state is a glyph (▲/▼), not a colour; a filtered-to-nothing table can say so with withEmptyText() over totalRowCount()/filterText().

Reduced motion has a real switch (withSmoothScroll(false)), keyboard is the primary path (every scroll verb answers update() with a KeyMsg; see examples/viewport-keys.php), and colour policy stays the host's: the library never reads NO_COLOR/TERM — validated SGR you pass in is passed through deliberately.
