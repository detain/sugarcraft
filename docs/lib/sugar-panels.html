H/V panels with flex/natural sizing, borders, nesting, and stateful delta rendering

Compose terminal layouts with horizontal and vertical panels. Attach borders, hint minimum and maximum sizes, let flex children fill the rest, and nest arbitrarily deep.

Install

composer require sugarcraft/sugar-panels

Quickstart

use SugarCraft\Panels\SugarPanels;

$panels = SugarPanels::new();

$layout = $panels->vertical(
    $panels->horizontal(
        $panels->leaf("Left panel"),
        $panels->leaf("Right panel"),
    )->withBorder(false)->withGrow(),
    $panels->leaf("Bottom bar")->withBorder(false),
)->withBorder(false);

echo $panels->render($layout, 60, 7);

Every node is bordered by default — a plain nested layout paints a doubled frame at each level. Containers are usually scaffolding, so turn their frames off with withBorder(false) (or wrap a subtree in noBorder(), which suppresses every frame and every divider below it), and give the viewport enough rows to hold what you asked for. That prints (protocol and styling stripped):

╭────────────────────────────╮╭────────────────────────────╮
│Left panel                  ││Right panel                 │
│                            ││                            │
│                            ││                            │
│                            ││                            │
╰────────────────────────────╯╰────────────────────────────╯
Bottom bar

The horizontal row carries withGrow(), so it flexes to six of the seven rows while Bottom bar — the fixed child — claims its measured natural single row at the bottom. Every row the renderer emits is padded to the viewport width, Bottom bar's included.

Concepts

A layout is a tree of Node values. A leaf holds text. A horizontal or vertical node splits its region among its children, and noBorder() wraps a subtree to drop every frame and divider inside it. SugarPanels::render() paints the tree into a viewport of a given width and height and returns one ANSI string.

Nodes are immutable. Every with*() call returns a new node, so a chain whose result is discarded has no effect. Sizing comes from hints. withMinWidth(), withMaxWidth() and their height twins bound a node's footprint, and withFlex() or withGrow() lets a child fill the space its fixed siblings leave over. Flex sizing is delegated to the greedy solver in sugar-constraints, running in its parity mode.

Every node draws a border by default. That is right for leaf panels and wrong for scaffolding, which is why the Quickstart turns container frames off. The renderer keeps the previous frame's cell grid, so a second render() at the same size emits only the cells that changed.

Tasks

  • Fixed header and status bar around a growing body. Give the header and bar no flex weight, so they claim their natural size, and give the body withGrow(). Put the three in a vertical() node.
  • Remove frames from a container. Call withBorder(false) on the container, or wrap the subtree in noBorder() to suppress every frame and divider below it. Adjacent panels then render touching.
  • Title a panel. Call withTitle() on the leaf or container. The title is sanitized with Sanitize::paintedTitle(), so line feeds are flattened and it paints on one row.
  • Redraw efficiently. Keep one SugarPanels instance and call render() each frame at the same size. Call resetPreviousFrame() after anything else has written to the terminal, so the next render repaints in full without erasing.
  • Show untrusted text. Sanitize it before it reaches leaf() or withTitle(). Trusted text can carry escape sequences into the grid, as the Trust boundary section of the README explains.

Where it fits

There are no in-repo consumers yet — sugar-panels ships as the ecosystem's pane composer for your application. When a sibling does a similar-looking job: the raw CSS flexbox computation (solve, don't paint) is sugar-flexbox; modal foregrounds over existing content with dimming and zone hit-testing are sugar-overlay; tabular data grids with a row cursor are sugar-table. Nested horizontal/vertical panes with borders, titles and flex weights, painted as plain ANSI strings — that is sugar-panels.

Keys and input

sugar-panels reads no input and binds no keys. It is an output composer: the host decides what the viewport shows and calls render() when it changes. The inputs that matter are the viewport numbers. Negative sizes, sides above MAX_VIEWPORT_DIMENSION and areas above MAX_VIEWPORT_CELLS throw. A zero width or height is valid, paints nothing and leaves no diff state behind, so a collapsed pane cannot poison the next size.

Theme and styling

Styling goes through sugar-style. withStyle() applies color and attributes to a node's content, and withBorderStyle() picks a border character set. The examples/borders.php demo reads Border::catalog() at runtime, so every preset sugar-style ships appears in it. Styled text stays trusted input, so escape sequences in content pass through unchanged, and a clipped or unbalanced span is reset so its color stays inside its box.

Testing

Run the suite from the lib root:

composer install && vendor/bin/phpunit

The suites cover framing and separators, flex layout, the solver delegation, the frame protocol, ANSI placement, the sanitize boundary, max-width and margin rules, and the edge cases of tiny viewports. Test your own layouts by rendering to a fixed width and height and comparing against the expected string.

Troubleshooting and FAQ

  • Every level of a nested layout draws its own frame. Every node is bordered by default. Use withBorder(false) on containers, or wrap the subtree in noBorder().
  • render() throws InvalidArgumentException. The viewport is outside the documented ranges: a negative side, a side above 4096, or an area above 1000000 cells. Clamp the host's winsize before calling render.
  • Old text stays on screen after a resize. A full frame that follows a resize erases the screen first. resetPreviousFrame() forces a full repaint without an erase, so call it only when the screen is already clear.
  • A with*() call seems to do nothing. Nodes are immutable, so the result must be kept. Write $node = $node->withGrow();.
  • Content is cut off or wrapped unexpectedly. Lines wider than the interior word-wrap at cell boundaries. Height overflow is dropped without a trace, because continuations consume the row budget and lines past the interior height are not painted. Give the node more rows, or let it flex.
  • A grown child is smaller than its min hint. A grown child gets only its weighted share, so its min is not applied, and totalWidth() over-claims for grown children. Fixed children honor the min through their base size.

Upstream mapping

The lib is inspired by treilik/bubbleboxer (Go), a library of nested boxes with weighted sizes and borders. The mapping is by concept. It is not a class-for-class port.

Bordered boxesNode::withBorder(), Node::withBorderStyle()
Titled boxesNode::withTitle()

Architecture

Three classes do the work. SugarPanels is the renderer. It walks the tree, asks the constraint solver for each split, paints cells into a buffer, and diffs the buffer against the previous frame. Node is the immutable tree value, and its with*() setters return new nodes. Sanitize normalizes text before it reaches the grid: painted() repairs UTF-8, collapses carriage returns and tabs, and removes unpaintable control characters, and paintedTitle() also flattens line feeds. Both are idempotent, so a host can pre-sanitize and round-trip content unchanged. Cell storage and the delta encoder come from sugar-cellbuffer. Borders and styles come from sugar-style.

Changelog and versioning

The package ships no CHANGELOG file. The commit history of sugar-panels/ in the monorepo is the record of changes. Pin a version in your own manifest. The monorepo publishes all libraries together.
