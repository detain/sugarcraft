Build TUIs anyone can ssh user@host to run. Leans on the host's OpenSSH daemon (ForceCommand) rather than re-implementing the SSH wire protocol. sshd handles auth, ciphers, host keys, audit logs; blocking brute-forcers stays fail2ban's separate job.

Install

composer require sugarcraft/sugar-ssh-server

Quickstart — in-process bash

// /opt/wish/server.php — invoked by sshd ForceCommand
require '/opt/wish/vendor/autoload.php';

use SugarCraft\SshServer\Server;
use SugarCraft\SshServer\Middleware\{Logger, Auth, Spawn};
use SugarCraft\SshServer\Session;

exit(Server::new()
    ->use(Logger::toFile('/var/log/wish.jsonl'))
    ->use(new Auth(users: ['wishuser']))
    ->use(new Spawn(fn (Session $s) => [
        'cmd' => ['/bin/bash', '-l'],
        'env' => [
            'TERM' => $s->term, 'USER' => $s->user, 'HOME' => "/home/{$s->user}",
            'PATH' => '/usr/local/bin:/usr/bin:/bin',
        ],
    ]))
    ->serve());

Quickstart — host-sshd legacy

use App\MyApp;
use SugarCraft\SshServer\Transport\HostSshdTransport;
use SugarCraft\SshServer\Middleware\BubbleTea;

exit(Server::new()
    ->withTransport(new HostSshdTransport())
    ->use(Logger::toFile('/var/log/wish.jsonl'))
    ->use(new Auth(users: ['wishuser']))
    ->use(new BubbleTea(fn($session) => new MyApp($session)))
    ->serve());

The wishuser in both Auth allowlists is what the sshd Match block makes true: under ForceCommand the entry script runs as the target account, so $s->user is that account on every connection, and an allowlist of human names refuses 100% of logins with exit Server::EXIT_DENIED. Per-user separation needs per-user Match blocks or authorized_keys command= entries, each running its own entry script.

Concepts

The server runs a middleware pipeline inside the process that sshd spawns under ForceCommand. It opens no listener of its own. What the supervisor PHP process does internally is pluggable via the Transport abstraction, and there are two transports:

  • InProcessTransport (default). Allocates a sugar-pty master/slave pair, spawns the user's cmd as a subprocess with full controlling-terminal semantics (Ctrl+C → SIGINT, SIGWINCH-driven resize, job control), pumps bytes between the supervisor's STDIN/STDOUT and the sugar-pty master. Terminal middleware: Spawn.
  • HostSshdTransport (legacy, opt-in). Pre-PTY-upgrade architecture: middleware run inline in the supervisor; the terminal middleware (BubbleTea) mounts a SugarCraft Program directly on the supervisor's STDIN/STDOUT. Pin via Server::withTransport(new HostSshdTransport()). Use this for inline-STDIN-reading middleware or zero-subprocess Program mounts.

What's in the box

InProcessTransport (default)sugar-pty supervisor — allocates a PTY, spawns child with controllingTerminal:true, pumps bytes, forwards SIGWINCH. Lets you mount any cmd / shell / editor.
HostSshdTransport (legacy)Pre-PTY-upgrade behavior. Middleware run inline against sshd's PTY directly. Zero subprocess overhead.
Spawn middleware (InProcess only)Terminal — produces cmd[] from Session via factory. Drives runChild() on the active transport.
BubbleTea middleware (HostSshd only)Terminal — mounts a SugarCraft Program inline reading STDIN/STDOUT. Transport-aware: throws clearly under InProcess.
Logger / Auth / RateLimitTransport-agnostic. Same composition surface under either mode.
Custom middlewareAnything implementing Middleware::handle(Context $ctx, Session $session, callable $next): void.

Configuration

Each option is set on Server or on the middleware that owns it. The defaults are the values the classes ship with.

  • Server::withTransport(Transport): Transport, default InProcessTransport. Selects the transport the middleware stack runs under.
  • Server::withKeepalive(int $intervalSeconds): int. Keepalive is opt-in and off unless withKeepalive() is called; Server::$keepalive stays null until then. 60 is the argument default, not a shipped default. Once armed, it sends a NUL byte to the child's stdin when the pump loop has been idle for this many seconds. This is not an SSH-level keepalive.
  • Logger sink: string, resource or null, default $SSH_SERVER_LOG when set, else stderr. Where the one-line JSON session records go. Files the logger creates are 0600.
  • new RateLimit($statePath, $burst, $ratePerSec, ..., $failClosed): int, float, bool, default 5, 0.5, false. Per-IP token bucket. With $failClosed left false, a connection is let through when the state file cannot be read.
  • Auth::__construct(array $users, array $keyFingerprints, ...): list, default empty lists. The allowlists. With both empty, every session is admitted.
  • Server::EXIT_DENIED: int, default 129. The exit status a refused session returns to the SSH client.

Examples

Each file in examples/ runs from the library root as php examples/<name>.php. Several need an sshd ForceCommand setup to log in through, and showcase.php runs without one.

  • hello-server.php: The smallest end-to-end server: a session banner, used as a deployment smoke test.
  • spawn-bash.php: The default in-process supervisor. It spawns a login bash in a sugar-pty for each connecting user.
  • spawn-program.php: A SugarCraft Program mounted inside a sugar-pty subprocess.
  • run-program.php: The wrapper program that spawn-program.php runs as the PTY child.
  • showcase.php: Drives the middleware pipeline against a synthesised session in one process, with Logger, RateLimit and a custom middleware.

Troubleshooting

The client gets exit status 129 and the child never starts

A refusal gate such as Auth or RateLimit marks the session refused, so the process exits Server::EXIT_DENIED (129) and no child is spawned. There is no disconnect packet or error body. A throttle writes its rate-limit notice to the stream it was given, and that is the first place to look.

The client gets exit status 0 and nothing ran

A stack that runs out of middleware without spawning a child answers 0, meaning there was nothing to run, not a refusal. Add a terminal middleware such as Spawn or BubbleTea to the stack. A child that ran reports its own code, which wins over both values.

->use() registers nothing

Server is immutable. use() returns a new server with the middleware appended, and the receiver stays as it was. A bare $server->use($m); with the return value discarded therefore does nothing. Write $server = $server->use($m);, or chain the calls as the examples do.

Every login is admitted

new Auth() with no users, keyFingerprints or userKeys admits every session, and KeyboardInteractive without a validator accepts any answer. RateLimit with the default failClosed: false lets the connection through when its state file cannot be read. Pass an allow-list, or use Auth::allowingUsers([...]), which throws a LogicException on an empty list, and pass failClosed: true to RateLimit.

Composer refuses to install on a host without ext-ffi

The sugar-pty dependency requires ext-ffi in its own manifest, so composer require fails on a host without it, even though this package only suggests it. Install the extension. Adding --ignore-platform-reqs=ext-ffi lets the install finish, but then only the legacy HostSshdTransport can run, because the default transport needs FFI to allocate the PTY.

runChild() throws PtyException

The default InProcessTransport throws PtyException when ext-pcntl is missing or the host cannot allocate a PTY. Install ext-pcntl. In a restricted container, grant the device /dev/ptmx and a devpts mount at /dev/pts, or keep the connection behind sshd and use HostSshdTransport, which needs none of these.

Output is cut off partway through

runChild() sets the PTY master and STDIN to non-blocking and leaves STDOUT blocking on purpose. A non-blocking STDOUT drops every byte past the pipe buffer with no error. Keep STDOUT blocking when you call runChild(), and do not add a stream_set_blocking($stdout, false) line.

One abusive client locks out a whole bastion

The ip: bucket in RateLimit keys on the direct TCP peer, so a bastion, a load balancer or a ProxyJump hop collapses many operators into one bucket. Enable the username bucket ($userBurst), or move throttling to the fronting layer. Keep the state file and its lock on a local filesystem, because flock on NFS can be silently absent.

Upstream mapping

The server is inspired by charmbracelet/wish, which is also cited in the docblocks. Other classes mirror Go concepts directly.

  • Context: Go context.Context: Done() and Deadline() semantics
  • Promise handling in the transports: charmbracelet/wish PromiseDispatch.awaitPromise
  • HostSshdTransport: sugar-ssh-server's own pre-PTY-upgrade architecture, kept for existing deployments. It has no upstream counterpart.

Changelog and versioning

The package has no separate changelog file and no release tag in the monorepo, so its history is the commit log of sugar-ssh-server/, mirrored on GitHub. One change to know about when you upgrade: Server is immutable. Before audit sugar-ssh-server-008, use() changed the server in place. It now returns a new server, so a bare $server->use($m); no longer registers anything.
