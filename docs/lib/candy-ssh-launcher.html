Launch candy-ssh-launcher, pick a host, and press Enter. The launcher replaces its own process with ssh connecting to that host, so the prompts, the keys and the exit code are all ssh's. It is a PHP port of the selection flow in charmbracelet/wishlist: your machines live in one YAML or JSON list, you type to narrow it, and Enter connects. The picker is a one-shot local widget, not a server-backed store.

Install

composer require sugarcraft/candy-ssh-launcher:@dev

Until the first candy-ssh-launcher/v* tag is cut, the package publishes only its dev branch, so a bare composer require finds nothing under Composer's default minimum-stability. The :@dev suffix names that branch explicitly. The binary lands at vendor/bin/candy-ssh-launcher, and tools/build-phar.php builds a single-file .phar.

Requires PHP 8.3 or newer with ext-pcntl (the launcher hands off with pcntl_exec), a Unix host (raw-mode terminals, pcntl and ~ expansion have no Windows story) and a UTF-8 terminal, because the picker draws ▸, ─ and ….

Quickstart

Endpoints form a flat top-level YAML list. This is examples/sample-wishlist.yml:

# Sample wishlist directory. Copy to ~/.config/wishlist.yml and edit.

- name: production
  host: prod.example.com
  port: 2222
  user: deploy
  # A leading ~ on an identity path is expanded by the launcher ($HOME,
  # passwd fallback). An absolute path is the portable spelling — it does
  # not depend on who expands it.
  identity_file: ~/.ssh/prod-deploy
  description: Live customer-facing app servers

- name: staging
  host: stage.example.com
  user: deploy
  description: Pre-prod mirror — safe to break

- name: dev
  host: dev.example.com
  user: dev

- name: jumpbox
  host: bastion.example.com
  options:
    - ServerAliveInterval=30
    - ServerAliveCountMax=3

Run the picker in a terminal. With no --config, the launcher looks for wishlist.yml in the current directory, then in ~/.config:

vendor/bin/candy-ssh-launcher --config examples/sample-wishlist.yml

Without a terminal, --list prints one row per endpoint (name, host:port, user or -), tab-separated, and exits 0:

production	prod.example.com:2222	deploy
staging	stage.example.com:22	deploy
dev	dev.example.com:22	dev
jumpbox	bastion.example.com:22	-

Concepts

The config file is trusted input, exactly like ~/.ssh/config. The launcher does not sandbox a wishlist. It turns each row into an argument list and gives that list to ssh, so the rows decide what runs. The security section below explains which rows deserve a second look.

An endpoint becomes an argv list. Endpoint::toSshArgv() emits ssh, then -p when the port is not 22, one - flag per letter in flags, one -i per identity file in order, -J for a jump host, one -o per option, then --, the destination and an optional remote command. A value that starts with a dash is refused by name before it reaches argv, so a config cannot smuggle a second option in through a host or identity field.

The picker is a one-shot widget. Picker::pick() draws one frame, reads keys until Enter or Esc, and returns one Endpoint or null. It needs a real terminal on both stdin and stdout, so a piped run is refused with exit 2. Pasted text is typed into the filter and never connects, even when the paste ends in a newline.

Dispatch replaces the process. Launcher::dispatch() calls pcntl_exec with the vetted binary, which performs no $PATH search. A successful call never returns, so signals and the exit status belong to ssh. A failed exec throws, and the CLI reports it as exit 3.

Tasks

Connect from the picker

Type to narrow the list (the match is fuzzy and scored by sugar-fuzzy), move with the arrow keys, and press Enter. The header shows the shown-of-total count while a filter is live, and a (no matches …) line appears when the filter removes every row.

Connect by name, without the picker

A bare positional argument names an endpoint. An exact, unique match dispatches straight away and never touches the terminal, so it works in scripts, because ssh gets the terminal and no picker is drawn. An ambiguous name opens the picker already filtered to the matches. An unknown name opens the full picker rather than failing on a typo.

vendor/bin/candy-ssh-launcher --config examples/sample-wishlist.yml staging

Import your OpenSSH config

--from-ssh-config reads endpoints from an OpenSSH config instead of a wishlist. Host patterns become endpoint names, and HostName (or the pattern, when no HostName is given) becomes the host. Without --config it reads ~/.ssh/config, which is auto-discovered and therefore passes the same ownership gate. The source file is named on stderr so an imported list is never mistaken for your wishlist.

vendor/bin/candy-ssh-launcher --from-ssh-config
vendor/bin/candy-ssh-launcher --from-ssh-config --config ~/lab/ssh_config

Jump through a bastion with keys and flags

Set proxyJump for -J, list identityFiles (each becomes its own -i, in order), add options for -o, and use flags for the letter-only switches such as t (-t) or N (-N).

- name: db-prod
  host: db.internal.example.com
  user: dba
  proxyJump: bastion.example.com
  identityFiles:
    - ~/.ssh/prod-deploy
    - ~/.ssh/prod-dba
  options:
    - ServerAliveInterval=30
  flags:
    - t
  remoteCommand: psql

Use a different transport for one host

A row may set command (the alias transport is accepted) to name a different binary for that endpoint, such as a mosh-style client. The binary passes the same exists-and-executable check as --ssh, and it is not searched on $PATH. Fields the custom transport cannot carry (identityFiles, proxyJump, options and remoteCommand) are dropped, and the launcher prints one stderr line naming each dropped field before it runs.

Script the list

--list is the machine-readable view and never launches anything, so it stays safe in a pipe. Each row is name, host:port and user (or -). Tabs and line breaks inside a value are folded to spaces so one endpoint is always one row, and a duplicated name gets a #n suffix with its 1-based config index. A config with zero endpoints prints nothing and exits 0 under --list.

vendor/bin/candy-ssh-launcher --list | awk -F'\t' '$3 == "deploy" { print $1 }'

Picker class

Tiny terminal picker — renders marker-prefixed display lines (selectedMarker() over displayLine()) of Endpoints. The user moves with ↑/↓, Home/End and PgUp/PgDn (j/k are query letters on every row — the invert model, -060), narrows with type-to-search, and picks with Enter. Returns the selected Endpoint, or null on Esc or the cancel byte (0x03 — what a closed stdin maps to as well). On a real terminal Ctrl-C raises SIGINT, which the picker traps to restore the terminal before exiting 130.

Keys

The picker reads these keys in its raw-mode loop. Letters always type into the filter, so j and k do not move the selection.

Configuration

The launcher has a small command line, a handful of environment variables and one per-endpoint schema.

OptionEffect

--ssh <path>The ssh binary. Must be an existing executable path. A bare name such as ssh is refused, because nothing searches $PATH.

-h, --helpPrint usage, the keys and the exit codes, then exit 0.

Where the wishlist comes from

Without --config, the first file that exists wins at each tier, and the tiers are searched in this order:

  1. The current directory: wishlist.yml, then wishlist.yaml, then wishlist.json. A notice on stderr names the project-local file.
  2. The user directory: the same three names under $XDG_CONFIG_HOME when it is set and non-empty, otherwise under ~/.config.

Auto-discovered files face a trust gate. A file owned by another user (root excepted) or writable by its group or by others is refused by name. Keep the file owned by you and at mode 0600 or 0644.

Ssh binary resolution

--ssh wins. Otherwise SSH_LAUNCHER_SSH is used when set. Otherwise the first existing executable of /usr/bin/ssh, /run/current-system/sw/bin/ssh and /opt/homebrew/bin/ssh is used, and /usr/bin/ssh is the final fallback. The gate then checks that the chosen path is an executable file, and it refuses honestly when it is not.

A key outside this list, and outside the aliases, is named on stderr and ignored, so a typo never changes the connection silently. The loader refuses files larger than 4 MiB, refuses a list field with more than 1000 items, strips a leading UTF-8 byte-order mark, and refuses UTF-16 by name.

Security

Whatever a wishlist declares, the launcher passes to ssh. Most options are safe, but a few weaken the trust that ssh gives a connection, and ProxyCommand and LocalCommand run commands at connect time. Before it execs, the launcher prints one stderr line for each option that degrades host-key trust or logging, naming the option and what it costs:

  • StrictHostKeyChecking set to no, never or accept-new
  • LogLevel set to quiet, error or fatal
  • UserKnownHostsFile, GlobalKnownHostsFile, IdentityAgent and CertificateFile, whatever their value

Keep wishlists and ~/.ssh/config owned by you, and do not accept endpoint files from other people. The fleet-wide rules are in the trust boundary document.

Theme and styling

The picker has no theme option. Its palette is fixed: a bold cyan ▸ marker on the selected row, a cyan filter line, and dim gray descriptions. NO_COLOR and CLICOLOR=0 remove every color escape, and the marker and the layout stay, so the selection is still visible without color. --list prints plain text in every case.

Examples

examples/endpoint-argv.php loads the sample wishlist and prints the ssh argv each endpoint would produce. It executes nothing and exits 0.

php examples/endpoint-argv.php
production
  ssh -p 2222 -i /home/you/.ssh/prod-deploy -- deploy@prod.example.com
staging
  ssh -- deploy@stage.example.com
dev
  ssh -- dev@dev.example.com
jumpbox
  ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -- bastion.example.com

The -i path is the first endpoint's identity file expanded against your $HOME, so that line differs between machines.

examples/unsafe-options.php parses an inline wishlist and lists the options that the launcher would flag before connecting. It exits 0.

php examples/unsafe-options.php
lab: StrictHostKeyChecking=no
legacy: UserKnownHostsFile=/dev/null, LogLevel=quiet

examples/sample-wishlist.yml is the config used in the quickstart.

Testing

cd candy-ssh-launcher && composer install && vendor/bin/phpunit

The suite covers the config loader (ConfigTest, ConfigHardeningTest, ConfigEncodingTest), the argv builder (EndpointArgvSafetyTest, EndpointIdentityFilesTest), the OpenSSH importer (SshConfigParserTest), the picker (PickerTest, PickerInputIntegrityTest), the exec handoff through the executor seam (LauncherTest, ExecHandoffTest), the CLI (BinCliTest), the translation catalogs (LocaleParityTest) and a pseudo-terminal signal test (PtySignalIntegrationTest).

Troubleshooting and FAQ

The picker needs an interactive terminal

The launcher exits 2 and prints the picker needs an interactive terminal when stdin or stdout is not a TTY. Use --list to read the endpoints, or name an endpoint, which dispatches without a terminal when the name is unique.

A config is refused as owned by another user or writable

An auto-discovered file that another user owns, or that its group or the world can write, exits 1 and is named in the message. Run chmod 600 on it, or pass the file explicitly with --config, which skips the gate because naming a path is consent.

It says the file looks like an OpenSSH config

A file with a line that begins with Host is ssh config syntax, not a wishlist. The launcher refuses it and points at --from-ssh-config. A top-level mapping keyed by endpoint name, the shape charmbracelet/wishlist uses, is also refused, because the schema is a flat list. The README names the failure.

The ssh binary is not found or not executable

Pass --ssh /absolute/path/to/ssh, or set SSH_LAUNCHER_SSH. A bare name such as ssh is never resolved through $PATH, because pcntl_exec receives exactly the path the gate vetted.

The picker exits 130 before drawing

A terminal narrower than 12 columns is refused as too small. The picker then returns the same result as a cancel, so the launcher prints the cancel line and exits 130. Widen the terminal and run it again.

Exit 3 at launch

Exit 3 means the endpoint was refused at dispatch (a field that starts with a dash, or an empty field), or the exec itself failed. The message names the binary and, when PHP reports one, the reason. A custom command that is not an executable file is refused the same way.

A duplicate name warning

Names identify endpoints, so two rows with the same name cannot be told apart in the picker. Both still load, and --list suffixes each with its config index (name#2). Rename one of them.

Upstream mapping

The port follows the selection flow of charmbracelet/wishlist: a list, a fuzzy filter, and a connect step. The table maps each part of that flow to the SugarCraft class that carries it. The deliberate differences from upstream are listed in the README.

Flow stepClassNotes
Filterable list of hostsPickerOne-shot raw-mode loop with no event loop. Matching uses sugar-fuzzy's Smith–Waterman scorer.

Import from OpenSSH configSshConfigParser, Config::importFromSshConfig()Host patterns become names. The parser reads HostName, User, Port, IdentityFile and ProxyJump, and expands %h, %r and %u.

Architecture

Nine classes carry the program. Config reads a file and turns each row into an Endpoint, a readonly value object whose with*() methods return new instances. SshConfigParser reads the OpenSSH import, and Support\CommentStrip removes trailing comments from both formats. IdentityPath expands ~. Picker renders the rows and reads keys. Launcher builds the final argv and performs the exec through a callable seam, which is how tests observe the handoff without replacing the process. Support\Version reports the version, and Lang wraps the shared SugarCraft\Core\I18n\T catalog for the sshlauncher keys. The bin script ties them together: argument parsing, the trust gate, resolution of the ssh binary and the exit codes.

Changelog and versioning

Releases are tagged candy-ssh-launcher/v*, and a tagged phar stamps its tag into --version. A checkout reports the compiled-in version. The commit history on GitHub is the change record.
