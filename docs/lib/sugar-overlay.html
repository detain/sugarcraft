🎭 SugarOverlay

Terminal overlay compositor

inspired by rmhubbert/bubbletea-overlay overlaycompositingui

Composite overlay views (modals, tooltips, toasts) on top of a base TUI frame. Render your models first, then let the compositor handle positioning, backdrop dimming, z-ordering, animated transitions and click-outside hit-testing.

Install

composer require sugarcraft/sugar-overlay

Quickstart

use SugarCraft\Overlay\{Position, Veil, VeilStack};

$baseView  = "underlying text\nmore underlying\ntext underneath";
$modalView = "[modal]";
$tooltip   = "Click to dismiss";

$veil = Veil::new()->withBackdrop(40);   // 40% dim — 60% brightness remains

// Composite a foreground string centered over a background string
echo $veil->composite($modalView, $baseView, Position::CENTER, Position::CENTER);

// Layer several overlays by z-index
$stack = VeilStack::new()
    ->add(Veil::new()->withContent($modalView)->withZIndex(1))
    ->add(Veil::new()->withContent($tooltip)->withZIndex(2)
        ->withPosition(Position::TOP, Position::RIGHT));
echo $stack->compositeAll($baseView);

What's in the box

PositioningNine anchors — Top, Right, Bottom, Left, Center and the four corners — plus X/Y offsets in cells (columns/rows).
Backdrop dimmingTruecolor opacity blend (0–100): every non-empty background line is wrapped in a computed dim pen during assembly (the blend does not compound across stacked veils — the first dim to touch a cell governs — and the pen assumes a light default foreground: on a terminal that renders dark text, the gray pen brightens that text instead of dimming it).
Animated transitionswithAnimation() + animate(…, $progress): SLIDE enters from the anchored edge, SCALE reveals lines from the center outward, and FADE brightens the overlay in from black through a truecolor gray pen (terminals cannot alpha-blend), returning the original bytes at full opacity. Progress is clamped to 0–1 and the scrim ramps with the animation; withReducedMotion() makes any progress emit the settled frame in one shot for hosts reading the platform preference (sugar-colorprofile's Probe::reducedMotion()).
VeilStackOrdered collection of veils rendered by ascending z-index; maxZIndex() / minZIndex() return null for an empty stack, since 0 is a real z-index.
Click-outside dismisswithClickOutsideDismiss() + scan() / isClickOutside() via sugar-mouse zones. The scanned zones travel with the veil across later with*() calls, so a click is judged against the frame that was on screen.
Buffer diffingcomposite() diffs against the previous frame and emits only changed cells. An empty background returns the overlay itself as the frame, and extended color operands saturate before any arithmetic runs: 38;2;r;g;b components and 38;5;n palette indices clamp to 0–255 each, so a hostile 38;5;300 cannot push the grayscale-ramp formula (38;5;232-255 is the grey ramp, not the 6×6×6 colour cube) past the 0xRRGGBB range the cell model stores.
Border chromewithBorder() wraps veil content in a terminal border; when a border is configured the chrome applies to every composited frame — withAutoSize() is a deprecated no-op retained for source compatibility.
Untrusted contentwithUntrustedContent() sweeps payloads at set time: control characters, forged U+E000/U+E001 zone sentinels and live OSC-8 links are neutralised (CRLF/CR folded to LF, TAB to its measured four cells), while sugar-image's U+E002 marker band passes through untouched. Backgrounds are as attacker-reachable as foregrounds — both paths are documented trust boundaries. Raw withContent() and composite() payloads pass through verbatim — sweep hostile frames yourself with sugar-core Sanitize::untrustedForMarkedFrames() before mark(): the sweep strips every U+E000/U+E001 sentinel, legitimate zone markers included, so order matters — sweep, then mark, then render.

Accessibility

  • The keyboard half is yours, the geometry is not hidden — sugar-overlay ships no key handling by design: bind Esc/Enter to the same dismiss action isClickOutside() answers and keep focus movement inside sugar-focus / sugar-navstack. The clone returned by scan() publishes every zone's rect (zoneRects() / lastZoneRect($id)) in the same 1-based cell space hit() uses, so a focus ring and a click agree on one geometry by construction.
  • Announce with text, not chrome — when an overlay opens, the title line you emit is the screen-reader cue; a withBorder() frame only adds box-glyph noise for terminal readers and is a sighted-user affordance — users who want the box gone have Border::hidden() and Border::ascii() from sugar-style.
  • NO_COLOR is the host's choice — the renderer deliberately does not consult it, because the dim pen is color; a host that honours it emits the backdrop pre-striped and runs with withBackdrop(0) and no animation.
  • Reduced motion — withReducedMotion() makes animate() paint the settled frame in one shot (no dim sweep, no travel; the scrim ramps with the animation otherwise). The fleet-standard read is sugar-colorprofile's Probe::reducedMotion(), but it sees only environment variables — offer an in-app setting as well.
