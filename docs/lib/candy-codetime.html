candy-codetime is a privacy-first coding-time tracker. It records only the heartbeats you give it, one activity sample per call, such as I was working on this file, in this language, for this many seconds. It stores them locally as one append-only JSONL file per day, or in an optional embedded SQLite database, and it draws a seven-day dashboard with SugarCharts. Nothing watches the editor, nothing leaves the machine, and there is no daemon and no database server. The design antecedent is TakaTime, a Go tool whose always-on daemon was replaced here by an explicit push.

Install

composer global require sugarcraft/candy-codetime
# the global bin dir varies by composer version and platform; ask composer:
BIN="$(composer global config bin-dir --absolute)"
export PATH="$BIN:$PATH"   # keep this line in your shell profile

Requires PHP 8.3 or newer. The SQLite backend and the milestone command also need the sqlite3 extension, and the dashboard needs a terminal. A project-local install works the same way through vendor/bin/candy-codetime.

Every candy-codetime/v* release also ships a single-file build, candy-codetime.phar, with a .sha256 digest and minisig sidecars. Verify the digest, then run php candy-codetime.phar on stock PHP. The app never rewrites its own archive and has no self-update channel, so an upgrade is a new download. Inside an archive, --version prints the release build stamp.

sha256sum -c candy-codetime.phar.sha256   # integrity before first run
php candy-codetime.phar --version

Quickstart

Record two beats, check for untracked time, and read the digest. The first line is a real run against an empty data directory. The date in the summary is the day you run it.

candy-codetime push sugarcraft php src/App.php 60     # one heartbeat: project, language, file, seconds
candy-codetime push myproj php src/Main.php 120
candy-codetime gaps                                  # untracked stretches of 5 minutes or more
candy-codetime summary                               # per-project and per-language digest, last 7 days
recorded 60s of sugarcraft (php)
recorded 120s of myproj (php)
No gaps found.
summary: 2026-11-13 – 2026-11-19
total: 0h 03m
by project:
  myproj  0h 02m
  sugarcraft  0h 01m
by language:
  php  0h 03m

Three replies are worth knowing. gaps: no tracked data for that period means nothing has been recorded yet. No gaps found. means the window is covered. Running candy-codetime dashboard < /dev/null prints the dashboard needs an interactive terminal and exits 1, with the headless commands named as the alternative, so a script cannot hang on a missing terminal.

Open the dashboard in a real terminal with candy-codetime, or candy-codetime dashboard 30 for a 30-day window. Use export csv 30 for a plain-text dump of the same data.

Concepts

A heartbeat is one activity sample with six fields: time, project, language, file, duration in seconds and tags. The CLI never sets tags itself. A heartbeat becomes a beat once it is stored, and the two words are used interchangeably below.

Storage is local and plain. The file backend writes one YYYY-MM-DD.jsonl per day inside the data directory, and the file is append-only, so an editor hook can add a line without coordinating with the dashboard. The SQLite backend stores the same heartbeats in candy-codetime.db, indexed on time, for range queries. Milestones exist only in SQLite. The CLI reads whichever backend you select, and it can auto-select SQLite when the database holds records and the JSONL store does not.

Recording is explicit

candy-codetime does not watch files, windows or keystrokes. It records what it is told, by a hand-typed push, a save hook, a cron entry or an editor binding that calls the CLI. No editor plugins ship. The binding is one command line, and the worked example in examples/plugin-heartbeat.example.sh is the recommended starting point.

Reading is pure

Stats::compute() folds a list of beats over a date window into totals per project and per language, plus one bucket per day. It takes no I/O and uses no clock, so the same beats always give the same answer. The dashboard, the exporters and the gaps report all read through the same HeartbeatReader contract.

Tasks

Wire a save hook

# vim: one heartbeat per save, using the worked example script
autocmd BufWritePost * silent! !sh /path/to/examples/plugin-heartbeat.example.sh "$EXPANDEF"

# or feed a batch of JSON lines through the stdin door, which applies ignore rules, clamps and the lock
printf '%s\n' '{"time": 1795100000, "project": "myproj", "language": "php", "file": "src/Main.php", "duration": 300, "tags": []}' | candy-codetime push --

The script prefers push --, so the ignore door, the duration clamps and the advisory lock all apply. It falls back to a raw append under flock whenever push -- exits nonzero, which includes a binary missing from PATH and a refusal such as an oversized ignore file. The raw append skips the ignore door, the duration clamps and the lock, so a file the ignore rules would skip is recorded by the fallback. Set CODETIME_HOOK_DURATION to change the seconds credited per save, which defaults to 60.

Backfill a past beat

candy-codetime push --time=1795000000 myproj php src/Main.php 900   # one beat at a past instant
candy-codetime push --time=1795000000 myproj php src/Main.php 900 review,work   # with tags

--time takes a Unix timestamp and files a single beat at that instant. A malformed value is refused rather than coerced. A raw JSON line written by hand has no default time, so a line without time is a corrupt record and is dropped on read. Use push -- or --time to backfill, because both stamp the real instant.

Skip files with an ignore file

printf '%s\n' 'secret.log' 'vendor/*' > .sugartrackignore
candy-codetime push src/Main.php 120      # tracked
candy-codetime push vendor/lib/a.php 60   # skipped: reported, never stored

The .sugartrackignore file in the current directory, or else in the tracked file's own directory, holds one glob per line. A bare pattern matches a file name at any depth, a full path matches exactly, and a path pattern matches below any matching directory. The sibling .sugartrackallow file re-enables a path that an ignore file would skip. Both files are capped at 1 MiB. Ignore files often live inside a checked-out repository, so a bare * pattern, which would silently zero a project, is reported on stderr with the file's path.

Find untracked time

candy-codetime gaps 14                    # untracked stretches of 300 seconds or more, last 14 days
candy-codetime gaps --min=1800 2026-11-01 2026-11-19   # only gaps of 30 minutes or more, in a dated window

Report\GapsReport reads the sorted beats and reports each stretch between them that is at least the threshold. The default threshold is 300 seconds. It is a question of whether your tracking is honest, not a judgement about the work.

Export for a spreadsheet, a JSON pipeline or a calendar

candy-codetime export csv 30 --project=myproj > week.csv
candy-codetime export json 2026-10 2026-10 > october.json
candy-codetime export ics 7 --tag=review > review.ics

Output goes to stdout, so redirect it to save it. --project and --tag filter the rows on either backend. The ics format writes one VEVENT per heartbeat, with UTC stamps whose difference is the beat's duration. Every exported path is verbatim, so do not send an export somewhere shared without thinking about what the file paths reveal.

Move to SQLite and keep milestones

candy-codetime --backend=sqlite push myproj php src/Main.php 120
candy-codetime milestone add "v1.0 shipped" "first stable tag"
candy-codetime milestone list
CANDY_CODETIME_BACKEND=sqlite candy-codetime dashboard 30

The SQLite backend tunes the database on open with WAL journaling, a five-second busy timeout and synchronous=NORMAL. A milestone always writes to SQLite, even when --backend is not given, and the SQLite dashboard marks milestone days with * under the weekday row. The file backend never shows milestones.

Remove a project, safely

candy-codetime backup                                   # archive day files older than 30 days first
candy-codetime forget --project=old-experiment          # dry run: counts matches, changes nothing
candy-codetime forget --project=old-experiment --apply  # removes them from both stores

forget is a dry run unless --apply is given. Lines that fail to parse are never removed. Run backup first, because the archive is the undo path, and plain backup does not copy a live SQLite database. Use backup --sqlite for that, which writes a consistent snapshot with VACUUM INTO.

Set a daily goal

CANDY_CODETIME_GOAL=6h candy-codetime dashboard

The goal shows as today 2h01 / 1h00 in the header, and every day that reaches it is drawn as a shaded block in the activity band. It is presentation only, so it records nothing and gates nothing.

Configuration

Options are accepted before or after the command. Environment variables are read on every invocation, and an explicit flag always outranks the environment.

Options

OptionEffect
--backend=file|sqliteStorage for push, export, gaps, summary and dashboard. Both --backend=sqlite and --backend sqlite work. Without the flag, the CLI auto-selects SQLite when the database holds records and the JSONL store does not. The choice is made per invocation and never saved.
--theme=<name>Dashboard palette: default, light, dracula, solarized, gruvbox or high-contrast. A junk name is refused with the list of choices.
--project=<name>, --tag=<label>For export and gaps, keep only the rows that match.
--min=<secs>For gaps, the minimum untracked stretch to report. The default is 300 seconds.
--format=text|mdFor summary. md prints Markdown for a README or a badge.
--time=<unix>For push, files one beat at a past or future instant.
--sqliteFor backup, archives the SQLite database with VACUUM INTO.
--applyFor forget, turns the dry run into a real removal.

Environment

VariableEffect
CANDY_CODETIME_DIRThe data directory. The default is $XDG_DATA_HOME/candy-codetime, falling back to ~/.local/share/candy-codetime. If it is unset and XDG_DATA_HOME and HOME are both unset too, the CLI refuses rather than writing next to the working directory.
CANDY_CODETIME_BACKENDThe default backend, file or sqlite. An explicit --backend outranks it, and a junk value is refused.
CANDY_CODETIME_GOALThe daily goal, as whole seconds or whole hours such as 6h. It is presentation only.
CANDY_CODETIME_THEMEThe palette name, the same as --theme. The flag outranks it.
CODETIME_HOOK_DURATION, CODETIME_HOOK_BINRead by the worked hook script only, for the seconds per save and the binary path.
SUGARTICK_*Legacy names from the tool's earlier life. Each one is imported under its CANDY_CODETIME_* name on every launch, with a deprecation notice on stderr. The new name wins.

Storage details

Each day file line is one JSON object with the keys time, project, language, file, duration and tags. Readers ignore unknown keys. The SQLite schema is versioned with user_version set to 1, and a file stamped with a version this build does not know is refused on open. Nothing is pruned automatically: neither the live database nor the archives are trimmed.

Day files are keyed by the calendar date in PHP's effective timezone. Since PHP 8.3 the TZ variable no longer sets that zone, so set date.timezone in php.ini to choose it.

Keys and keybindings

The dashboard reacts to these keys. Keys cannot be rebound. Letter commands answer unmodified keys only, so Ctrl+q does not quit and Ctrl+r does not reload.

KeyAction
← / hMove the window back one day
→ / lMove the window forward one day
gJump the window end back to today
+ / -Widen or narrow the window through 7, 14, 30 and 90 days
tToggle the lower pane between languages and tags
rReload from disk
q, Esc, Ctrl+CQuit

The dashboard subscribes to no timers and does not animate. It redraws only when a key changes the view, and it does not refresh by itself while it is open.

Theme and colour

The --theme flag and CANDY_CODETIME_THEME pick one of six palettes. default is the shipped palette. light is for a white terminal, where the pastel tones of the default wash out. The palettes apply only where the terminal answers with 256-colour or TrueColor support. The frames are identical everywhere else.

candy-codetime --theme=light dashboard
CANDY_CODETIME_THEME=gruvbox candy-codetime

Colour is decorative only. Bars are drawn by height, every coloured value carries a text label, and the milestone mark is the text *. NO_COLOR=1, CLICOLOR=0 and TERM=dumb all turn the tints off. A light or high-contrast choice never removes a label.

Examples

The examples/ directory holds two PHP programs and one shell script. The PHP programs load the Composer autoloader, so run them from a checkout after composer install.

  • examples/dashboard.php seeds a demo data directory at a fixed path under the system temp directory, which other local users can also reach, with a pretend week of beats and opens the dashboard. It refuses with exit 1 unless both stdin and stdout are terminals. This is the program behind the demo GIF below.
  • examples/headless-report.php seeds two days of beats into a temporary directory, reads them back with Store::loadRange(), folds them with Stats::compute() and prints the totals. It needs no terminal and is the library version of summary.
  • examples/plugin-heartbeat.example.sh is a POSIX shell hook of about 35 lines. It sends one heartbeat per save through push --, falling back to a locked append. It is a worked example, not a shipped plugin.
php examples/headless-report.php < /dev/null
php examples/dashboard.php < /dev/null     # exits 1: stdin is not a terminal

Testing

The suite runs under PHPUnit 10. Run it once from the package root, with stdin redirected:

cd candy-codetime && composer install && vendor/bin/phpunit < /dev/null

The tests cover the CLI, the dashboard, the renderer, the store and its privacy modes, the SQLite backend under tests/Storage/, the exporters under tests/Export/, the gaps report, the ignore rules, the backup archiver and the locale parity check in LangParityTest. PharBuildScriptTest covers the phar build. The fold in Stats is pure, so most dashboard tests run against fixed beats.

Troubleshooting

The dashboard prints an error and exits 1

Stdin or stdout is not a terminal. This is expected in a cron job, a pipe or a CI log. Use the headless commands instead: export csv, export json, summary or gaps, which write plain lines to stdout.

A beat I pushed by hand does not appear

There are three usual causes. A raw line written with >> and no time key is a corrupt record, and it is dropped on read and counted in the day-file warning. A --backend=sqlite dashboard never reads a raw JSONL line, because raw lines land in the file backend only. And a .sugartrackignore match skips the push, which is reported on stdout. Run the push through candy-codetime push to see which case applies.

The sqlite backend is used but my records are in the file store

Auto-selection looks at what each store holds. When the database has records and the JSONL store does not, the CLI picks SQLite. Set --backend=file or CANDY_CODETIME_BACKEND=file to pin the choice. When both stores hold records, the CLI prints a one-line pointer on stderr naming the other store.

A push is refused, or an ignore file is refused

A duration that is negative or not a whole number is refused with exit 1. A duration above one year is clamped rather than refused. An ignore or allow file over 1 MiB, or one that exists but cannot be read, makes push exit 1, because tracking with an unknown opt-out is the failure the file exists to prevent. Shrink the file, or fix its permissions.

A file mode warning, or the run aborts

A directory or file left world-readable is tightened on the next CLI run, whatever the command. If the tightening fails, the run aborts instead of printing over data that is still exposed. Write plugin and cron output under umask 077 so the files are private from the start.

The CLI refuses to start a write

With CANDY_CODETIME_DIR unset and neither XDG_DATA_HOME nor HOME set, the CLI has no safe place to write and refuses. Set CANDY_CODETIME_DIR to an absolute path for that run.

Architecture

The CLI lives in bin/candy-codetime. It parses the global flags, then dispatches each command to the library. The library splits along the data flow: the storage layer reads and writes beats, the fold and the report layers turn beats into numbers, and the view layer draws them. Each layer depends only on the one before it.

FileRole
src/Heartbeat.phpThe value object for one activity sample.
src/Store.phpThe JSONL store. It implements HeartbeatReader, takes the advisory lock and enforces the private modes.
src/Storage/SqliteBackend.php, src/Storage/HeartbeatReader.phpThe indexed SQLite backend, and the read contract that both backends satisfy.
src/Stats.phpThe pure fold into totals and day buckets.
src/Report/GapsReport.phpGap detection over sorted beats.
src/Dashboard.php, src/Renderer.php, src/Theme.phpThe SugarCraft Model, its view and the palettes.
src/Export/*The csv, json and ics exporters.
src/Backup/AutoBackup.phpThe copy-only archiver for day files and the database.
src/Ignore/SugarTrackIgnore.php, src/Support/Detect.phpThe ignore matcher, and the project and language detection used by push.

Writes are append-only, and reads degrade loudly

The file store is append-only at the file level, so a hook can append with >>. Raw appends skip the advisory lock and the privacy checks, which is why plugins should call push. A day file that exists but cannot be opened is named in a stderr warning and counted as an empty day. It is never skipped in silence.

Privacy is a launch invariant

Directories are 0700, and day files, the database and its sidecars are 0600. Stored names are swept of escape sequences and control characters before they are drawn, so a doctored file cannot inject a sequence into the dashboard. Shared foundations: the cooperative cancellation token from sugar-async is checked before each write.

Upstream mapping

UpstreamWhere it shows up here
Rtarun3606k/TakaTime (Go)The design antecedent. The heartbeat model, the project, language and file tracking, the dashboard and the ignore file are ported. The always-on daemon became an explicit push, and MongoDB became JSONL day files plus an optional SQLite backend.
TakaTime's taka-report binaryNot ported. The summary command folds the same data in the CLI, and it has no GitHub Action.
TakaTime's .takatrack allowlistNot ported. The .sugartrackallow file plays that role.
TakaTime's editor fieldNot carried. Upstream heartbeats carry it, and this schema omits it, so a plugin-written value survives the round trip but nothing reads it.

SugarCraft is a native PHP project. This app is not a line-for-line port, and the rename from sugar-tick is covered in the Changelog section.

Changelog and versioning

The version is Support\Version::CURRENT, 0.1.0, and the release tags use the candy-codetime/v prefix. Inside a phar, --version prints the build stamp instead, and SOURCE_DATE_EPOCH keeps rebuilds of a tag byte-stable. The package was published as sugarcraft/sugar-tick until the 2026-10 rename. The namespace moved from SugarCraft\Tick\ to SugarCraft\CodeTime\. The old SUGARTICK_* environment names and the old data directory still work through one-time compatibility paths.
