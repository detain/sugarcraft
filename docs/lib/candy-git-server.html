CandyGitServer

Git server building blocks (status: scaffold)

inspired by charmbracelet/soft-serve gitserversshself-hosted

Status: scaffold. Library building blocks for a self-hostable Git server — config, repo, users, access control, git-daemon, smart-HTTP, SSH-gate and LFS classes, each individually tested. No assembled server ships: the serve command refuses with a non-zero exit and nothing binds a port. See the README "Known gaps" inventory.

Install

composer require sugarcraft/candy-git-server

Quickstart

use SugarCraft\GitServer\{AccessControl, Config, Repo, User};
use SugarCraft\GitServer\Git\GitDaemon;

$config = Config::fromDefaults();        // CANDY_SERVE_* env vars, else defaults
                                         // (Config::load($yamlPath) reads a config file)

// Describe a repository and create it as a bare git repo on disk
$repo = Repo::new('my-project', $config->reposPath() . '/my-project.git')
    ->withDescription('Greeting service')
    ->withPublic(true)
    ->addCollaborator('alice')
    ->init();

// Ask the permission matrix
$acl = AccessControl::getInstance();
$acl->canWrite(User::new('alice'), $repo);   // true  (collaborator)
$acl->canWrite(User::new('bob'), $repo);     // false
$acl->canRead(null, $repo);                  // true  (public repo, anonymous read)

// Library surface (not assembled): a future host would drive the daemon
// like this — the serve() method exists; no shipped entrypoint calls it.
$daemon = new GitDaemon($config);
$daemon->registerRepo($repo);

What's in the box

SSH front end (class)SSHServer authenticates users by public key and dispatches git upload-pack / receive-pack for the single request a host sshd ForceCommand hands it. No SSH wire protocol, no shipped entrypoint.
Git daemon (class)GitDaemon implements a git:// daemon surface — blocking serve() or ReactPHP serveAsync(); its wire framing deviates from spec (see README Known gaps) and nothing constructs it yet.
HTTP smart protocol (class)HttpSmartProtocol\Server routes smart-HTTP clone/fetch/push and LFS requests when a host feeds it; security gaps are inventoried before it may be wired.
Access controlAccessControl answers read / write / admin for a user (or anonymous) against a repo's visibility and collaborators.
LFS supportGit LFS over HTTP through LFSHandler and a pluggable storage backend.
Config fileYAML server configuration via Config::load(), or env + defaults via Config::fromDefaults().
