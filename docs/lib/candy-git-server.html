candy-git-server is a self-hostable Git server in PHP 8.3+. It is a port of parts of charmbracelet/soft-serve. The smart-HTTP transport is live: serve --http runs a listener that real git clone, git fetch and authenticated git push work against, with the Git LFS batch and object routes beside it. The SSH and git-daemon transports exist as classes that a host has to wire up. There is no terminal UI.

Install

composer require sugarcraft/candy-git-server
vendor/bin/candy-git-server help

Requires PHP 8.3 or newer and the system git binary on PATH. Both the read path and the push path run through git upload-pack and git receive-pack --stateless-rpc, and the protocol tests run against git 2.43. Without git, serve --http still starts, but every request answers 500.

ext-sockets is a hard requirement, because the blocking GitDaemon::serve() loop calls socket_create() directly. ext-pcntl is optional, and it enables the graceful SIGINT and SIGTERM exit and the one-process-per-connection HTTP worker. Without it the listener still runs, and a stop signal ends the process with status 130 or 143.

A single-file candy-git-server.phar is built on each push to master. It needs only PHP on the host, and it is started the same way: php candy-git-server.phar serve --http --repo-root /srv/git/repositories.

Quickstart

This run takes a fresh data directory from init to a clone. The output is trimmed from a real run: the data path is shortened to /var/lib/candy-git-server, and the listener is shown on its default port. The password for the first admin is read from stdin, never from argv.

D=/var/lib/candy-git-server

# 1. initialize the data directory and mint the first admin
printf '%s\n' 'correct horse battery staple' |
    candy-git-server init "$D" --admin alice --admin-password-stdin

# 2. add a least-privilege account: non-admin unless --admin is passed
printf '%s\n' 'hunter2hunter2' | candy-git-server user add bob "$D" --password

# 3. create a repository: private by default, --public marks it public
candy-git-server repo create myrepo "$D"
candy-git-server repo collaborator myrepo add bob "$D"

# 4. serve it over smart HTTP
candy-git-server serve --http --repo-root "$D/repositories" --config "$D/config.yaml"

# 5. from another shell, clone and push as a collaborator
git clone http://bob@localhost:23232/myrepo.git
User 'bob' created (admin: false)
Password stored as a hash.
Persisted to /var/lib/candy-git-server/users.json
Repository 'myrepo' created at /var/lib/candy-git-server/repositories/myrepo
Note: start a listener to serve it: candy-git-server serve --http --repo-root /var/lib/candy-git-server/repositories (private until --public; anonymous-read needs git.allow_anonymous_read).
Repo 'myrepo': collaborator 'bob' added (plane now: bob)

candy-git-server: smart-HTTP listener on 127.0.0.1:23232 (2 repos, 1 published; 2 accounts; anonymous-read=off; push is served too — hook declines ride in-band)
access 127.0.0.1 GET /myrepo.git/info/refs 401 23 1.6ms
access 127.0.0.1 GET /myrepo.git/info/refs 200 288 69.0ms
access 127.0.0.1 POST /myrepo.git/git-receive-pack 200 50 72.4ms

The first info/refs request answers 401 because git has no credentials yet. The retry with Basic auth answers 200. Two more facts matter here. Anonymous reads of a public repo still answer 401 unless git.allow_anonymous_read is turned on, which it is not by default. And a plain init or user add run on a directory under the system temp directory prints a warning, because local users can read it there. Set CANDY_GIT_SERVER_DATA_PATH to a real path before a deployment.

Concepts

The package is organized around four nouns. A Repo is an immutable description of a bare Git repository on disk, with its visibility, collaborators, push setting and optional mirror source. A User is an immutable account, with a password hash and any authorized SSH keys. AccessControl answers whether a user, or an anonymous caller, may read, write or administer a repo. A transport is the way bytes reach Git: the smart-HTTP listener, the SSH dispatcher or the git-daemon class.

Every access check runs before any Git child is spawned or any ref byte is written. A request that fails authorization is refused with no repository data sent. Hook declines from a push ride back in-band, in the report-status stream that the Git client expects.

Visibility and access

A repo has one of three visibilities, and the enum Visibility holds them. Visibility::Public is readable without credentials, but only while git.allow_anonymous_read is on. Visibility::CollaboratorOnly admits only collaborators and admins. Visibility::Private admits the same people, and it is the default for a repo created without --public. Authenticated collaborators can push. allowPush widens push to every authenticated user, and it never admits an anonymous caller.

Visibility is a marker on disk, and directory presence alone never publishes a repository. Every path that resolves a repo consults the marker and falls back to private when it is absent.

Accounts persist, and the store is refused when corrupt

Accounts live in <data_path>/users.json. Writes are atomic, through a temporary file and a rename, and the file is mode 0600. A corrupt store refuses to load rather than silently starting with zero accounts. Passwords are stored only as password_hash digests, so cleartext never reaches disk.

Tasks

Create a repo from PHP and check who may write

use SugarCraft\GitServer\{AccessControl, Config, Repo, User};

$config = Config::fromDefaults();   // reads CANDY_GIT_SERVER_DATA_PATH, else defaults
$repo = Repo::new('my-project', $config->reposPath() . '/my-project.git')
    ->withDescription('Greeting service')
    ->withPublic(true)
    ->addCollaborator('alice')
    ->init();                          // creates the bare repository on disk

$acl = AccessControl::instance();
$acl->canWrite(User::new('alice'), $repo);   // true: collaborator
$acl->canWrite(User::new('bob'), $repo);     // false: not a collaborator
$acl->canRead(null, $repo);                  // false: anonymous reads are off

Each with*() call returns a new immutable Repo, so keep the result of the chain. The init() call is the only one that touches the filesystem. examples/repo.php runs this flow end to end without writing to a real data path.

Let anonymous clients read a public repo

; config.yaml
git:
  allow_anonymous_read: true

Anonymous reads need both the repo marked public and the git.allow_anonymous_read lever on. Either one alone refuses. The same lever is consulted by the smart-HTTP router and by the daemon. Leave it off on a host that serves private work.

Mint a proxy token for a trusted front end

candy-git-server user token alice 3600 "$D"   # TTL in seconds, then the data path

The command prints an expiring <expiry-unix>.<hex-hmac> value. It needs http.auth_secret set in config.yaml, and the TTL is capped by http.token_max_ttl. Under http.user_trust_mode: token, the value is sent in the X-CandyGitServer-User-Sig header together with X-CandyGitServer-User. The HMAC is checked against http.auth_secret, and it expires. Under proxy mode a trusted reverse proxy sets the identity header instead, and the proxy must replace any header a client sends.

Mirror an upstream repository on a schedule

use SugarCraft\GitServer\Config;
use SugarCraft\GitServer\Jobs\MirrorPuller;
use SugarCraft\GitServer\Repo;

$mirror = Repo::new('linux', $config->reposPath() . '/linux.git')
    ->withMirrorFrom('https://github.com/torvalds/linux.git');

$puller = new MirrorPuller($config);   // reads jobs.mirror_pull
$puller->registerRepo($mirror);
$puller->runOnce();                  // from cron: pull every due mirror now
// or, in a ReactPHP host: $puller->attach($loop);

Each due mirror is fetched with git fetch --prune and the full +refs/*:refs/* refspec, so refs deleted upstream are removed locally. The schedule accepts @every with a Go-style duration such as 10m or 1h30m, and the aliases @hourly, @daily, @weekly, @monthly and @yearly. Full cron expressions are refused.

Watch the counters on a loopback endpoint

curl -s localhost:23233/stats
{"uptime_seconds":42.1,"connections":7,"pack_uploads":1,"pack_downloads":4,
  "lfs_batch_requests":2,"lfs_object_downloads":2,"lfs_object_uploads":1}

StatsServer runs only on a ReactPHP loop, so a host has to start it. The endpoint is unauthenticated. A hostless stats.listen_addr, such as the default :23233, binds to loopback, and only an explicit non-loopback host makes the counters reachable from the network. Set stats.persist_path to keep counters across restarts, since the default is volatile.

Put TLS in front of the listener

The library never terminates TLS. Setting http.tls_key_path or http.tls_cert_path refuses the config at load. Put a reverse proxy in front, as shown under Deployment, and point http.public_url at the https:// origin, so the LFS batch hrefs never downgrade a client to cleartext.

Changing it changes nothing.

Run

serve --http is the only long-running entry point. It runs in the foreground, and it has no daemon mode. Its flags are listed below.

FlagMeaningDefault
--repo-root DIRThe directory whose subdirectories are served. Required.none
--http-port NThe listen port. --port is a deprecated alias.23232
--http-host HThe listen host.127.0.0.1
--config FThe YAML config, whose directory is the data path.defaults applied
--daemon, --pid-file, --verboseRefused on this path, because the listener always stays in the foreground.n/a

The bare command serve refuses with exit 1 and an honest message, because the SSH and git-daemon transports are not wired. The exit codes are 0 for success and graceful shutdown, and 1 for any refusal. A refusal covers a bad flag, a bind failure, an unknown user or repo, an existing admin, a corrupt store and a bare serve.

candy-git-server serve
candy-git-server: 'serve' refuses to start: the ssh and git listeners are not wired yet, only 'serve --http' runs (see the README, Known gaps)
$ echo $?
1

Admin and account commands

candy-git-server init /var/lib/candy-git-server --admin alice --admin-password-stdin
candy-git-server user add bob /var/lib/candy-git-server --password
candy-git-server user key bob ~/.ssh/id_ed25519.pub
candy-git-server user token alice 3600 /var/lib/candy-git-server
candy-git-server user deactivate bob /var/lib/candy-git-server
candy-git-server repo collaborator myrepo add bob /var/lib/candy-git-server
candy-git-server repo list /var/lib/candy-git-server

init --admin refuses when an admin already exists, unless --force replaces the named account. A --password with no value reads stdin. An account with no password and no key is warned about, because it authenticates nothing. user add without flags creates a non-admin, and --admin raises a global admin that passes every check.

Keys and signals

There are no keybindings, because there is no terminal interface. The signals are the only control surface. serve --http arms SIGINT and SIGTERM when ext-pcntl is loaded, and both stop the listener and exit 0. It has no reload path, and SIGHUP keeps its default disposition, which kills the process. The GitDaemon class routes SIGTERM, SIGINT and SIGHUP into one shutdown handler, so a daemon you host yourself also stops on SIGHUP.

Theming and styling

This package draws nothing. It has no TUI, and no theme. The Clipboard\Osc52 class encodes OSC 52 clipboard sequences, but no code path consumes it, so it does nothing in this release. Output from the CLI is plain text, localized through the same catalogs used for errors.

Examples

The examples/ directory holds two PHP programs. They load the Composer autoloader, so run them from a checkout after composer install. Both are safe to run without a server.

Testing

The suite runs under PHPUnit 10. Run it once from the package root, with stdin redirected:

cd candy-git-server && composer install && vendor/bin/phpunit < /dev/null

The tests are grouped by the transport they cover. tests/HttpSmartProtocol/ covers the clone, fetch, push and LFS routes, the trust modes and the listener's hardening. It includes BinServeLiveE2ETest, which drives the launched bin/candy-git-server over a live socket. tests/Git/ covers the pkt-line codec, the stateless-rpc children and the daemon. tests/SSH/ covers the dispatcher. tests/Jobs/ covers the mirror schedule. UserStoreTwoProcessTest checks the account store across two processes.

Troubleshooting

The repo create command fails with a class not found error

This means the sugar-core in vendor/ is older than the one candy-git-server was written against. Run composer update in the package, or rebuild the monorepo wiring with php scripts/refresh-deps.php --mode=linked when you develop inside the monorepo.

Clone prompts for a password, then refuses, on a public repo

Anonymous reads need two things: the repo's visibility is public, and git.allow_anonymous_read is true. The listener logs the 401 it returns. Set the lever in config.yaml and restart the listener so it loads the new config. An authenticated clone works either way.

A push of a large file answers 413

http.max_pack_bytes caps the request body, and the default is 256 MiB. Raise it in config.yaml and restart. Behind nginx, set client_max_body_size to at least the same value, or nginx refuses the push before the server sees it.

Every identity header is ignored, or every request is refused in proxy mode

off is the default, and it ignores the identity headers entirely. proxy mode trusts a header only from a peer listed in http.trusted_proxies, so an empty list refuses everything. List the proxy's exact address or its CIDR range. Under token mode, a header with an expired or wrong HMAC is refused, so mint a new value with user token.

The server stops on a SIGHUP, or exits with 130 or 143

serve --http has no reload. SIGHUP kills it, so do not write an ExecReload line. Without ext-pcntl, a stop signal is not caught, and the shell reports 130 or 143 instead of 0. Install the extension in the container image, or accept that the exit code is not clean.

The CLI says Repository not found

The name you passed does not match a repository under the data path. Check the spelling and the data path argument. Create the repo first with repo create, or point the command at the data directory where it lives.

Architecture

The CLI is bin/candy-git-server. It parses commands and flags, then calls into the library. The library is organized around the transports, and each transport reuses the same access checks, the same pkt-line codec and the same bounded subprocess runner.

Every subprocess is bounded and reaped

Each served request spawns a git child through BoundedCommand. That runner takes an argv array, never a shell string. It enforces a cap on the output bytes and a deadline, and it reaps the child with TERM and then KILL. A child that outlives its deadline is killed, not waited on.

Workers isolate connections

By default the HTTP listener forks one worker per connection, when ext-pcntl is present and http.worker_per_request is not set to false. Each worker serves its connection to completion and exits, so one stalled request cannot delay the others. With the knob off, or without pcntl, connections are served one at a time, and the CLI says so on stderr at startup.

Upstream mapping

UpstreamWhere it shows up here

SugarCraft is a native PHP project. The classes in src/ carry docblocks that cite the soft-serve source where a behavior was taken from it.

Changelog and versioning

The version is Support\Version::CURRENT, 0.1.0. Inside a phar, the build stamp replaces it. The package was published as sugarcraft/candy-serve until the 2026-10 rename, and its namespace moved from SugarCraft\Serve\ to SugarCraft\GitServer\. The CANDY_SERVE_* environment names still work through LegacyEnv, with a stderr notice. Known gaps are listed in the README, and they are the authority on what is not yet built.

The gaps in short. git:// completes no fetch past the advertisement, no shipped SSH deployment recipe exists, nothing starts the mirror job or the stats endpoint on its own, and there is no TLS termination. Locale coverage is machine-assisted and not reviewed by a native speaker.
