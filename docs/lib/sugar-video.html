Terminal video player. It plays mp4, gif, avi, webm and animated webp on the fly, rendering each frame as ASCII, ANSI 256-color, truecolor half- or quarter-blocks, or through a graphics protocol (sixel, kitty or iTerm2), with WebVTT subtitle overlays. It builds on prior art in terminal video-to-text tools, including tplay (see Upstream mapping), and runs on the SugarCraft TEA runtime.

Install

composer require sugarcraft/sugar-video

Requires PHP 8.3+. GIF and animated WebP play in-process through ext-gd, with no ffmpeg needed. mp4, avi and webm need the ffmpeg and ffprobe binaries on $PATH. Those are a runtime toolchain, not a Composer package. Audio needs ffplay or mpv, and it is optional. Video decode through ffmpeg is refused on Windows, while GIF playback still works there.

Quickstart

php examples/play.php video.mp4           # play a video
php examples/play.php                    # synthetic test pattern (no file needed)
SUGAR_VIDEO_COLS=120 SUGAR_VIDEO_ROWS=40 php examples/play.php   # seed the size; the terminal's own size message overrides it (live resize always wins)
// Programmatic (mode auto-detects terminal capability):
use SugarCraft\Video\Player;
$player = Player::open('clip.mp4', cellsW: 80, cellsH: 24);   // mp4/avi/webm decode through ffmpeg
(new \SugarCraft\Core\Program($player))->run();

Concepts

Playback is a pipeline with four stages. A decoder turns the source into RgbFrame values. A renderer turns each frame into terminal output for the chosen mode. The Player is a TEA model that advances on ticks and returns its view. The Reel is the front door: you open a source, configure it with with*() methods, then call play(), or toPlayer() to get a paused Player you can embed.

The player starts paused. Nothing moves until you press Space, which is the reduced-motion default described under Accessibility. Timing comes from a monotonic clock, so an NTP step or a laptop resume does not fast-forward playback.

Tasks

Play a file with a chosen mode

use SugarCraft\Video\Reel;
use SugarCraft\Video\Render\Mode;

Reel::open('clip.mp4')
    ->withMode(Mode::HalfBlock)
    ->withSize(100, 30)
    ->withFps(24.0)          // null (the default) means auto-detect
    ->play();

Loop playback and attach subtitles

Reel::open('clip.mp4')
    ->withLoop(true)
    ->withSubtitles('clip.vtt')   // WebVTT, or lenient SRT
    ->play();

Play a signed remote stream

Reel::openUrl(
    'https://cdn.example.com/clip.mp4',
    ['Authorization' => 'Bearer ' . $token],   // forwarded to ffmpeg and to the audio companion
    ['cdn.example.com'],                          // host allowlist, the SSRF guard
)->play();

Credentials in the URL are redacted from every log line and error. A bare URL without an allowlist logs a warning and allows any host, so pin the allowlist for anything you do not control.

Embed the player in your own program

use SugarCraft\Video\Reel;

$player = Reel::open('clip.mp4')->withSize(80, 24)->toPlayer();   // paused, first frame ready
// $player is a TEA model: feed it ticks through your own Program loop and render view().

Decode frames without a terminal

The decoders run without any terminal, so they can be tested and used in batch code. examples/decode-frames.php generates a synthetic animation and reports each decoded frame.

use SugarCraft\Video\Decode\GifDecoder;
use SugarCraft\Video\Render\Mode;

$decoder = new GifDecoder();
$decoder->open('animation.gif', 40, 12, 10.0, Mode::HalfBlock);
while (($frame = $decoder->next()) !== null) {
    echo $frame->w, 'x', $frame->h, "\n";   // RgbFrame: packed RGB bytes plus dimensions
}
$decoder->close();

Luminance ramp

The ascii and ansi256 modes map brightness onto a character ramp. withRamp() selects minimal, standard or dense. LumaRamp::compute() derives BT.601 luma from RGB, and LumaRamp::char() maps a 0–255 value to a character.

Reel::open('clip.mp4')->withMode(Mode::Ascii)->withRamp('dense')->play();

Remote sources and security

Remote playback goes through Reel::openUrl(), which applies an SSRF guard through allowedHosts. Request headers are validated by HttpHeaders::parse(), which refuses list-shaped input and control bytes. The same headers reach ffmpeg for the video input and the audio companion, in each player's own dialect. FfmpegCommandBuilder::scrubbedEnv() strips variables that the child processes should not inherit.

use SugarCraft\Video\Source\HttpHeaders;

$headers = HttpHeaders::parse(['X-Session' => 'abc123']);
$ffmpegArg = $headers->toFfmpegHeaderString();   // CLI spelling for ffmpeg
$mpvArg    = $headers->toMpvHeaderFields();     // CLI spelling for mpv

Subtitles and accessibility

Reel::withSubtitles('clip.vtt') parses WebVTT, lenient enough for most SRT files, and paints the active cue as one caption line under the frame in every mode. WebVtt::cueAt(seconds) finds the active caption for a playhead position. The caption line is the one real-text channel in every graphics mode, so it is the text alternative for playback that image protocols draw as pixels.

Playback starts paused, and it never begins without a key press. Nothing moves unless the user asks for it, so there is no ambient motion for a reduced-motion setting to suppress. The README Accessibility section has the detail.

Examples

  • examples/play.php [path|synthetic] [mode] is the full player. It accepts --subs=FILE and --help. It is interactive, so run it by hand.
  • examples/decode-frames.php [frames] decodes a synthetic GIF with the pure-PHP decoder and prints each frame. It needs no terminal, exits 0 on success, and removes its temporary files.
php examples/play.php --help
php examples/decode-frames.php 6

Testing

cd sugar-video && composer install && vendor/bin/phpunit

The suite is split across about 60 files under tests/. ReadmeSnippetsTest keeps the README's code samples in step with the API. Helpers under tests/Concerns hide or stub the ffmpeg and ffprobe binaries for the cases that need them absent or fake, so the decoder and probe paths run without a real toolchain.

Troubleshooting and FAQ

An mp4, avi or webm file does not play

Those formats decode through ffmpeg and ffprobe, and both must be on $PATH. Check with ffmpeg -version and ffprobe -version. Probe::hasFFmpeg() answers the same question from PHP.

A GIF or animated WebP fails to load

These decode in-process and need ext-gd. Check it with php -m. Animated WebP uses a RIFF walk that is pure PHP, plus GD for each frame.

There is no sound

Audio needs ffplay or mpv on $PATH. Without either binary the audio companion cannot start, so playback is silent. A source with no audio track also plays silently.

Video from a file is refused on Windows

FfmpegDecoder::open() refuses ffmpeg video on Windows with a guidance error, because the frame pump depends on stream_select(), which Windows does not support. GIF playback still works there.

A remote URL is refused

The host is not on the allowlist, or it resolves to a private or reserved address. Add the host to withAllowedHosts().

The picture is not what I expected in halfblock mode

Each cell covers two source rows, so a GIF fills the terminal at its full height in halfblock mode. Text modes keep the GIF at its native pixel dimensions. Set withSize() to fit the pane.

Playback starts paused

This is deliberate. Press Space to start. The player never moves on its own.

Architecture

video file (mp4/gif/avi/webm)
        |
        v
  VideoSource.probe           ffprobe JSON for the source
        |
        v
  DecoderFactory.new
        |
   +----+----------------------------+
   |                                 |
  GifDecoder (pure PHP, GD)     FfmpegDecoder (ffmpeg pipe)
   |                                 |
   +----+----------------------------+
        |
        v
  RgbFrame (rgb24, pre-scaled to cell size)
        |
        v
  FrameRenderer / RendererFactory   (Mosaic bridge for sixel, kitty, iterm2)
        |
        v
  Player (TEA model: tick() then view())
        |
        v
  Program (sugar-core: raw mode, alternate screen)
  • Decode: FfmpegDecoder runs ffmpeg for raw RGB frames, pre-scaled to cell dimensions. GifDecoder and AnimatedWebpDecoder decode in-process. Local GIF and animated WebP sources decode in-process.
  • Render: the text modes assemble their SGR cell grid with sugar-cellbuffer. The graphics modes delegate to sugar-image. Color mapping uses sugar-colorprofile.
  • Pace: Sync aligns ticks, with no busy wait. Deltas accumulate on a monotonic base, and one tick charges at most Player::MAX_TICK_DELTA_SEC of content time.
  • Audio: AudioPlayer runs ffplay or mpv as a companion. The player's own monotonic clock stays master, so audio may drift but never drives pacing.

Known limitations

  • Repaint granularity is rows, not cells. The player returns the full frame from view() on every tick. The default renderer re-sends each changed row, so one dirty cell costs a row of output.
  • Audio plays at 1.0× regardless of speed. The [ and ] keys change only the video pacing. A/V diverges at other speeds.
  • Seeks are fast but keyframe-snapped. ffmpeg input seeking lands on the keyframe at or before the target, so the first frame can be a little less exact than output seeking.
  • Sixel frames cost PHP time. The pure-PHP encoder spends more CPU per large frame than a native encoder would. No child process is spawned from the render path.
  • Audio pause and seek are approximate. Pause ends the audio child and resume starts a new one from the banked position. The audio clock is quantized to the last pause boundary.
  • Audio headers reach only two dialects. A per-request nonce, or a cookie that the video side obtained by redirect, will not reach the audio companion.
