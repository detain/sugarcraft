The self-update machinery a phar-shipped SugarCraft app needs, extracted from candy-code so every app follows the same laws. It picks the right release from a shared GitHub release stream, verifies the bytes before the rename, keeps a one-shot .old undo copy, and tells the user at launch when a newer release exists. Everything app-specific (repository, tag prefix, asset names, pinned public key, Composer package, display name) is one ReleaseSource value, and the host parses its own argv and supplies its running version. First-party: there is no upstream Go port.

Install

composer require sugarcraft/sugar-releases

The manifest requires PHP ^8.3. ext-sodium is optional but needed for Ed25519 signature checks: with a key pinned and no sodium, every update is refused (fail-closed). The self-update verb only works in phar mode. A Composer install gets a loud refusal that names the command that fits its install shape.

Quickstart

use SugarCraft\Releases\ReleaseSource;
use SugarCraft\Releases\SelfUpdate;
use SugarCraft\Releases\UpdateCheck;
use SugarCraft\Releases\UpdateOptions;

$source = ReleaseSource::new('acme/tools', 'widget')   // tags widget/v1.2.3, asset widget.phar
    ->withComposerPackage('acme/widget')
    ->withPublicKey($base64Ed25519PublicKey);          // '' = keyless state

// `widget self-update --check`, bare, --rollback, or --channel=latest
$exit = SelfUpdate::new($source)->run(UpdateOptions::new()->withCheck(), $currentVersion);

// At launch: refresh a 24 h cache over the event loop, paint the PREVIOUS check's answer
$check = UpdateCheck::new($source, $stateDir, $currentVersion);
$check->refreshIfStale();
echo $check->cachedNotice() ?? '';

Exit codes: 0 up to date, swapped or rolled back; 1 refusals and failures, and --check finding an update; 2 usage errors, as reported by UpdateOptions::validate().

Concepts

The engine has two halves that never share state. Self-update (SelfUpdate) is a verb the user runs on purpose: it downloads, verifies and swaps, or refuses. The launch notice (UpdateCheck) runs in the background and only ever paints the answer from the previous check, so the notice never blocks the first frame. Both share one ReleaseSource, so a tag prefix or key set once applies to both halves.

Verify before renameThe sha256 sidecar is fetched first and must be a lowercase 64-hex digest that names the phar. The phar streams to a temp file beside the target, is hashed with hash_equals(), and only then is renamed. Every download leg judges HTTP status.
Pinned-key Ed25519With a key pinned, a release without a verifying signature is refused. The signature over the sidecar body is preferred. The legacy raw-bytes asset is accepted behind a deprecation notice. --allow-unsigned never skips the sha256 gate.
Two channelsStable: the newest non-draft, non-prerelease <app>/v* release carrying both assets, ordered numerically. Latest: the rolling <app>/latest release, judged by commit identity against a dev-<sha> build. An undecidable comparison is a refusal, never a guess.
One-shot rollbackThe running phar is copied to .old before the swap. --rollback renames it back, consuming it, with no network. The live file's mode is carried onto both halves.
Windows relaunch danceWindows refuses to rename over a running image, so the verified bytes stage at .new and a detached helper retries the rename every 200 ms for up to 60 s, logging to .swap.log. The helper source is a fixed literal, and paths travel as argv data.
Never blocks, never spamsThe launch notice reads only the previous check's cache, re-validates the cached version at paint time, follows only same-origin release-list links, and degrades every failure to "no notice".

Tasks

Wire self-update into an app

Describe the app once with ReleaseSource::new($repo, $app). The defaults derive the tag prefix <app>/, the phar asset <app>.phar, the sidecar <app>.phar.sha256, and the signature names. Override only what differs, and keep the result immutable: each with*() returns a new source.

Check without installing

widget self-update --check

The check reads the release list and reports the newer version, if any, with exit 1. Nothing is downloaded or swapped.

Follow the rolling channel

widget self-update --channel=latest

The latest channel only answers for a dev build that embeds its commit as dev-<sha>. A release build (v1.2.3) cannot be compared against a commit, so the swap is refused with a cannot-compare message.

Undo the last upgrade

widget self-update --rollback

The rollback renames <phar>.old back over the live phar and consumes it. It needs no network, and a second rollback has nothing to restore.

Show the launch notice without blocking

Call refreshIfStale() once the event loop runs. It returns as soon as the request is handed to the loop, and the result lands in <stateDir>/update-check.json. Then paint cachedNotice(). The first launch after an install paints nothing, because there is no previous check yet.

Options

Verb flags come from UpdateOptions. Mutual exclusion is enforced: --check cannot combine with --rollback or --allow-unsigned.

Verb flags and launch settings
OptionTypeDefaultEffect
--checkflagoffReport whether a newer release exists, with exit 1 when one does. Nothing is swapped.
--rollbackflagoffRestore <phar>.old over the live phar. No network.
--allow-unsignedflagoffSkip the Ed25519 leg when a key is pinned, with a notice printed. It never skips the sha256 gate.
--channelstable or lateststable, or latest for a dev buildStable picks the newest tagged release. Latest follows the rolling release and needs a dev build. Without the flag, a dev-<sha> build defaults to latest.
ReleaseSource::withPublicKey()base64 Ed25519 key''Empty means keyless. A key that is set makes every release need a verifying signature.
ReleaseSource::withTagPrefix()string<app>/Lets one repository host several apps' release streams.
<APP>_NO_UPDATE_CHECKenvironment variableunsetOpt-out for the launch notice. The name is the uppercased app name, and UpdateCheck::withOptOutEnv() overrides it.

Fixed limits, pinned by the suite: the release list is walked through Link: rel="next" for at most 5 pages. The launch check reruns after 86 400 s. The cache file is written at mode 0600. Connect time is capped at 5 s, a read at 60 s, and a stall below 1 KiB/s for 60 s is aborted.

Output and styling

The engine paints no color and no layout. Report lines go to STDERR, or to the stream set with withErrorStream(). Messages come from the selfupdate.* keys in lang/en.php. Pass withTranslator() to map those keys onto the host's own catalog; the placeholders {app} and {package} are filled in before the translator sees the text.

Examples

Each example runs offline. None of them touches the network or the phar.

  • examples/select-release.php feeds a decoded GitHub release list to ReleaseSelector. It shows the stable pick, which skips drafts, prereleases and entries without a sidecar, and the latest-channel decision for a dev build.
  • examples/verify-signature.php generates a throwaway Ed25519 keypair. It then shows a genuine sidecar passing Signature::verifyDetached() and a tampered sidecar, a wrong key and malformed input all being refused. It needs ext-sodium.
  • examples/version-ordering.php covers Version::compare(), the dev-<sha> helpers, and ReleaseSelector::parseSidecar() and sidecarName().
php examples/select-release.php
php examples/verify-signature.php
php examples/version-ordering.php

Testing

composer install
vendor/bin/phpunit

The suite mounts a fake release server as a Guzzle handler, so it opens no sockets, and it swaps in stub archives. A few pins spawn real child PHP processes: a memory-limit raise, a 48 MB sidecar-signed swap inside a 32 MB child, and the Windows helper. The Ed25519 positive legs skip when ext-sodium is absent.

Troubleshooting and FAQ

Self-update refuses with a Composer message

The verb runs only from a phar. A Composer install reads the refusal from SelfUpdate::composerRefusal() and exits 1. Upgrade through Composer, using the command the message names.

Every update is refused, even one that looks right

A pinned key needs ext-sodium. Without it, Signature::verifyDetached() answers false for every release, which is the fail-closed design. Install the extension to verify releases.

A dev build reports "cannot compare"

The latest channel needs the commit baked into the build as dev-<sha>, and the sha must be a prefix of the release's target commit. A build with no embedded sha, or a release that names a branch instead of a commit, gets a refusal. That is intended: the engine never guesses that a dev build is behind.

No update notice appears at launch

The notice paints only the previous check's cache, so a fresh install shows nothing until a second launch. The notice is also silent when the opt-out variable is set, or when the process is not running from a phar.

--allow-unsigned still refuses a release

That flag only relaxes the signature leg. The sha256 gate still runs. A release whose sidecar is missing, malformed or does not match the downloaded bytes is refused in every mode.

A Windows upgrade stays pending

The helper retries the rename for up to 60 s after the parent process exits. Read <phar>.swap.log for its attempts. The verified bytes wait at <phar>.new until the swap succeeds.

Upstream mapping

There is no Charmbracelet counterpart. The library is first-party and was extracted from candy-code. The table below maps each class to the candy-code code it replaced.

SugarCraft classOriginResponsibility
SelfUpdatecandy-code's self-update codeDownload, verify, swap, rollback
UpdateCheckcandy-code's launch-time update checkBackground refresh and the cached notice
WindowsSwapcandy-code's Windows relaunch helperDetached rename-retry after the parent exits
ReleaseSelector, Version, SignatureShared helpers that the classes above callSelection, ordering and Ed25519 checks with no I/O

Architecture

Pure logic sits at the bottom. Version, Signature, ReleaseSelector and UpdateOptions do no I/O, so the examples and most of the suite run without a network. The middle layer is SelfUpdate, which owns the Guzzle client, the temp-file dance and the swap. UpdateCheck is the asynchronous half, which runs over the shared ReactPHP loop and writes the cache. WindowsSwap is the only code that spawns a detached process. Every network and process seam is injectable, so the host controls the process containment.

Changelog and versioning

The library is pre-1.0 and has no tagged releases yet, so consume dev-master. Each app ships its own phar versions, and the self-update verb moves between those tags. Check the release notes on the source repository.
