CandyGit is a terminal Git client on the SugarCraft stack: a three-pane TUI for staging, branching, log, diff, stash, worktrees, cherry-pick, merge and rebase. It mirrors the workflow of lazygit in native PHP rather than as a line-by-line port. Every verb shells out to your own git, so your hooks, GPG signing and credentials apply exactly as they do at the command line. Its u and Ctrl+r keys undo and redo the last mutations through a 100-entry history.

Install

composer require sugarcraft/candy-git:@dev

Requires PHP 8.3 or newer and git 2.23 or newer. The :@dev suffix is needed while the project's minimum-stability is stable: Packagist carries only the rolling dev-master branch until a stable tag is cut, so the bare requirement stops with does not match your minimum-stability.

CandyGit runs as a full-screen program. It needs an interactive terminal, and a piped stdout is refused rather than filled with escape sequences. It needs a checked-out work tree, since a bare repository has no status pane to show. At launch it checks git --version and refuses an older binary, or a missing one, with one sentence and exit status 1.

Quickstart

Run it from any git working tree:

cd path/to/your/repo
vendor/bin/candy-git

To embed the app in your own program, build the driver and the program yourself:

use SugarCraft\Core\Program;
use SugarCraft\Core\ProgramOptions;
use SugarCraft\Git\App;
use SugarCraft\Git\Git;

$git = new Git(getcwd());
(new Program(App::start($git), new ProgramOptions(useAltScreen: true)))->run();

The screen has three panes. Status is on the left, with the work-tree rows and the branch summary. Branches and log are stacked on the right. Tab cycles focus between the three, and each pane has its own verbs. The bottom line lists the keys for the focused pane.

Concepts

The application is one immutable model. Every key returns a fresh App that owns the three lists, their cursors, the focused pane and the open overlays. The renderer is a pure function of that model, so a frame can be reproduced from a fixture. Only the Git driver and the Process runner touch the outside world.

Git calls are synchronous. Each one is a bounded subprocess with a 30-second default timeout, and it runs on the UI thread. That is deliberate for version 1: a slow remote can pause the screen while a fetch, pull or push runs. Moving git work to the event loop is the planned version 2 direction.

Every verb has one of three behaviors. It runs straight away, runs after a second press (d, f, p, P, D), or opens a prompt. History records each verb with its inverse. Where no safe inverse exists, undo refuses with a notice rather than pretending to undo.

Trust boundary

Opening a repository executes its configuration unless told otherwise, and git has several config keys that name executables. CandyGit runs every git call through a fixed argument prelude, -c core.quotepath=off -c core.fsmonitor=false, plus --no-ext-diff on diffs. That disarms the repository-controlled execution channels it can neutralize without breaking legitimate tooling. Merge drivers are enumerated on the merged config scope and each one is overridden with false before any merge-capable command. A driver shape that cannot be re-expressed makes the merge refuse outright.

Filter drivers (clean, smudge, process) are detected and announced on stderr rather than silently disarmed, because git-lfs-class tooling depends on them. Set CANDY_GIT_STRICT_FILTERS=1 to turn that announcement into a refusal. Git and other child processes start through Process::run(), which pins the environment, including GIT_TERMINAL_PROMPT=0. The one other proc_open caller is the Windows process-tree teardown in Platform, which spawns taskkill and the MSYS group-kill script under a bounded drain without that pinned environment.

A hostile clone can still reach a trusted global git-lfs driver through its .gitattributes. Operate only on repositories you trust. The full disclosure is in the README's Trust boundary section.

Tasks

Stage part of a file and commit

  1. Focus the status pane and press Enter on the file. The diff viewer shows its hunks, and the title carries a worktree or staged chip for the side you are viewing.
  2. Press [ and ] to move between hunks, and Space to stage the current one. The viewer stays open and lands on the next hunk. On the staged side, Space unstages instead, and it asks you to press twice. Each hunk goes into the index through git apply --cached.
  3. Press c, type the message, and press Enter. Tab inserts a newline; Esc cancels.

c commits only what is staged. Unstaged edits stay in the work tree.

Amend the last commit

Press A. The collector opens with the last message. Edit it and press Enter to rewrite HEAD, or submit it unchanged to keep the message. Undo refuses an amend, because the old commit cannot be restored from the history lane.

Undo the last operation

u reverses the most recent history entry. Undoing a commit moves the branch boundary back and re-arms the collector with your typed message, so no text is lost. Undoing a stage-all restores the exact prior selection, unless a file was partially staged, in which case undo refuses. Ctrl+r redoes, and a new operation clears the redo side.

Stash work in progress

Press S to open the stash overlay. Press u inside it to include untracked files. Apply keeps the entry and leaves the overlay open. Pop and drop ask once more before they run. A drop is undoable from the main view.

Work across worktrees

Press w on the branches pane to open the worktree manager. It lists worktrees, adds one, and removes one. A new worktree always gets a created branch: type a name with -b, or let git name the branch from the path's basename. CandyGit never creates a detached worktree.

Cherry-pick or merge a ref

Press V to cherry-pick. In a log view the cursor's commit fills in as the default ref. Press M to merge a typed branch or ref into the current branch. If a rebase, cherry-pick or conflicted merge stops, press r to continue, abort, or, on a rebase, skip.

Create a branch at a commit

Move the cursor to the commit in the log pane and press n. The collector reads new branch from <sha>:, and the branch starts at that commit.

Configuration

CandyGit has no configuration file. Its behavior comes from the command line, the environment, and the repository's own git configuration.

Inside a text buffer every printable key is typed, so q is just a letter. Ctrl+W and Ctrl+U delete a word or the line, and a bracketed paste inserts the whole sanitized blob with its line structure. Remote-tracking branches appear with divergence badges such as [↑2 ↓1], or [!] when the upstream has vanished. Those are read-only for D.

Theme, styling and accessibility

Every state the interface needs you to know is carried by text, not by color alone. Status rows show git's porcelain XY codes, and diff lines keep their leading + and -. The rebase todo spells its actions as words: pick, reword, edit, squash, drop. The ahead-and-behind summary is git's own header. The panes stay readable under NO_COLOR, under TERM=dumb, or with an ASCII-only palette.

The focused pane shows two signals: the accent border and a ▸ text marker before its title. The selected row uses reverse video on styling terminals. Because TERM=dumb emits no escape sequences, the frame also carries a plain-text cursor: line that names the selected file, branch, commit or overlay entry.

The palette is not tuned for WCAG conformance. Its hint strip lands near 3.4:1 against the dark background of the demos, and the unfocused border near 2.1:1. Actual ratios depend on your terminal palette.

Internationalization

User-facing strings use SugarCraft\Git\Lang::t(). The catalog is lang/en.php, and the other locales are under lang/, 16 files in all. The keys carry a git. prefix inside the file, and you pass the file key verbatim: Lang::t('git.timeout'). The facade adds the library namespace on lookup, so the shared registry sees git.git.timeout. Lang::t('timeout') does not resolve. It returns the prefixed key git.timeout rather than a message, so always call through SugarCraft\Git\Lang.

To localize, copy lang/en.php to lang/<code>.php and translate the values. The cli.not_a_repo refusal fires when git rev-parse --absolute-git-dir fails in the working directory. Linked worktrees, where .git is a file, are accepted.

Examples

Both examples are hermetic. They render a fixture-backed driver, so they need no repository. Each one is interactive. In a terminal it runs until you quit it. When stdin reaches end of file, it renders one frame and exits 0.

  • examples/play.php is the pane tour, with status, branches and log. Run it in a terminal with php examples/play.php, and press q to quit. Non-interactively, printf 'q' | php examples/play.php renders one frame and exits 0. With stdin at /dev/null it also renders one frame and exits 0, so it never blocks a script or CI job. It keeps running only while stdin is an open pipe or terminal, so write a key to an open stream to drive it.
  • examples/stage.php is the staging demo, where s stages and unstages rows that visibly change. Run it with php examples/stage.php. Piping sq into it exits 0, and so does stdin at /dev/null.

The VHS tapes drive these examples, not the live binary, so the recorded output does not depend on the state of a repository. tests/ExamplesSmokeTest.php compiles each example against the live driver interface and boots the app, so a driver change that breaks an example fails the suite.

Testing

Run the suite from the package root after composer install:

vendor/bin/phpunit

Most tests drive the model with a fixture-backed GitDriver, so they need no repository. The *IntegrationTest files create real repositories in a temporary directory and run the real git. Those need git 2.23 or newer on PATH. The ExamplesSmokeTest keeps both examples booting.

Troubleshooting

candy-git: cannot find composer autoload.php

You are running from a clone that has no vendor/ directory. Run composer install inside candy-git/. The directory is gitignored, so a fresh clone never has it.

It refuses to start: git is too old or missing

CandyGit needs git 2.23 or newer, because it uses git restore for unstage and discard. The refusal is one sentence with exit status 1. Upgrade git, or make sure the git on PATH is the one you expect.

It refuses: not a git repository

Run it inside a checked-out work tree. Bare repositories are refused because they have no status to show. Linked worktrees work.

It refuses to run with output piped

The interface is a full-screen program, so stdout must be a terminal. Run it directly in a terminal, not through a pipe or a capturing wrapper.

Undo refuses an operation

That is by design. Undo refuses where the inverse would lie: discard, untracked-file delete, amend, merge, revert, reset --hard, a checkout with no origin to return to, and a branch delete whose prior SHA was never recorded. Undo also refuses a stage-all when a file was partly staged. The status line says why.

A deleted untracked file is gone

d on an untracked file deletes it from disk, and undo does not restore it. The press-twice guard is the only confirmation. Stage or move files you want to keep before you press d.

Push refuses on a detached HEAD

There is no branch to push. Check out a branch with Space on the branches pane, or create one with n, then push with P.

A filter driver prints a notice on stderr

The repository configures a clean, smudge or process filter, such as git-lfs. CandyGit announces it rather than disabling it, because those tools need their filters to work. Set CANDY_GIT_STRICT_FILTERS=1 to refuse such repositories instead.

git: command timed out after 30s

A git call ran past its 30-second budget, usually a slow remote or a fetch waiting on credentials. Git calls run on the UI thread, so the screen pauses until the call returns or times out. Check the network or the remote, then retry. The timed-out child is stopped with TERM, then KILL.

Upstream mapping

lazygit is the design antecedent. CandyGit mirrors its three-pane workflow and its single-key verbs, and it is native PHP rather than a port, so there is no class-for-class table. Each verb maps to a git subcommand, which is why the git documentation is the reference for behavior. The table in the API reference lists the classes that carry it.

Architecture

The model is pure. Every key returns a fresh App, and the git work happens in the driver. The main classes are below.

ClassRole
AppThe TEA model. Owns the lists, cursors, focus and overlays. Each key returns a fresh instance.
Git, GitDriverThe concrete shell-out driver, and the interface every operation goes through. Tests inject a fixture-backed driver.
ProcessThe main proc_open site. It runs a bounded drain loop, pins the child environment, isolates stdin from the terminal, and tears down with TERM, a grace period, then KILL. Platform::runBounded() is the other caller (Windows teardown only) and does not pin the environment.
PlatformThe OS seam: the null device, PATH lookup, and process-tree kill on Windows. Both branches are unit-tested on any host.
HistoryEntry, HistoryManagerOne undoable operation with its inverse or a refusal marker, and the bounded undo and redo stacks.
DiffViewer, DiffHighlighterThe immutable diff overlay state with hunk navigation, and the per-line highlight spans.
StashManager, StashEntryThe immutable stash list and its entries.
CherryPick, Worktrees, WorktreeEntryThe cherry-pick collector, and the worktree list with its add and remove modes.
InteractiveRebase, RebaseCommit, RebaseActionThe rebase todo preview, its entries, and the action enum: Pick, Reword, Edit, Squash, Drop.
RendererA pure view function. It draws the three bordered panes and the focus marker.
LangThe git-namespaced translation facade over the shared registry.
Support\Version, Support\GitRequirementThe version and build-stamp reader, and the git version floor.

Changelog and versioning

CandyGit was published as sugarcraft/sugar-stash until a rename in 2026-10, when the namespace changed from SugarCraft\Stash\ to SugarCraft\Git\. The Composer channel tracks dev-master. The GitHub release channel has two tags. candy-git/latest is the rolling prerelease phar, and candy-git/v* tags are stable cuts. Until a stable tag is cut, the prerelease phar is the only release artifact. Each release ships candy-git.phar.sha256 and candy-git.phar.commit, which names the tested commit the bytes were built at.
