🧰 CandyScriptui

Composer-installable CLI of TUI primitives

inspired by charmbracelet/gum cli shell-script one-shot

13 presentation subcommands — choose, confirm, file, filter, format, input, join, log, pager, spin, style, table, write — plus completion. Drop into a shell script and instantly get a Charm-quality interactive UX.

Install

composer require sugarcraft/candy-scriptui

Or grab the rolling dev phar — rebuilt and published for every commit that touches this app (verify against the published .phar.sha256 sidecar before making it executable):

curl -fsSLO https://github.com/detain/sugarcraft/releases/download/candy-scriptui/dev/candy-scriptui.phar
curl -fsSLO https://github.com/detain/sugarcraft/releases/download/candy-scriptui/dev/candy-scriptui.phar.sha256
sha256sum -c candy-scriptui.phar.sha256 && chmod +x candy-scriptui.phar

Quickstart

# Apply styling.
candy-scriptui style --foreground "#ff5f87" --bold "Hello, candy!"

# Pick one item.
choice=$(candy-scriptui choose Pizza Burger Salad)

# Read a single line.
name=$(candy-scriptui input --placeholder "Your name?")

# Confirm a destructive action.
candy-scriptui confirm "Really delete $file?" && rm "$file"

# Show a spinner while running a command.
candy-scriptui spin --title "Building..." -- make build

# Filter a list (substring by default; --fuzzy for fuzzy matching).
git branch | candy-scriptui filter

Keyboard & colour

Every interactive command is keyboard-driven — the README carries the full key map (arrows · j/k · g/G · Space/Tab · Ctrl+C aborts, pager q/Esc finishes). Colour follows one contract everywhere: --no-ansi is final, then --ansi force-arms TrueColor, then FORCE_COLOR, CLICOLOR_FORCE, NO_COLOR, CLICOLOR, and TERM=dumb decide the rest.

Auto-discovery

CandyScriptui uses PHP attributes to auto-discover commands at runtime. Mark any class extending Symfony\Component\Console\Command\Command with #[Command] (add class-level #[Flag] attributes to declare options — additive, never required) and Application::scan() registers it once the class is loaded:

namespace My\Commands;

use SugarCraft\ScriptUi\Attribute\{Command, Flag};
use Symfony\Component\Console\Command\Command as SymfonyCommand;
use Symfony\Component\Console\Input\InputInterface;
use Symfony\Component\Console\Output\OutputInterface;

#[Command(name: 'mycmd', description: 'Does something useful.', descriptionSection: 'Longer help text.')]
#[Flag(name: 'format', short: 'f', description: 'Output format.', default: 'json')]
final class MyCommand extends SymfonyCommand
{
    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        $output->writeln('format=' . $input->getOption('format'));
        return self::SUCCESS;
    }
}
use SugarCraft\ScriptUi\Application;

// scan() registers the #[Command] classes that are already loaded under the
// namespace, so load them first.
class_exists(\My\Commands\MyCommand::class);

$app = new Application();
$app->scan('My\Commands');
$app->run();                 // mycmd --format yaml  →  format=yaml

CandyScriptui also reads CANDY_SCRIPTUI_* env fallbacks through a fail-closed allow-list of eighteen presentation option names — CANDY_SCRIPTUI_<OPTION> in uppercase arms that option when no explicit CLI flag is given. Names outside the list are ignored, and every option that answers for the user, grants capability, or redirects data — allow-env, default, file, out, value, selected, type, shell, password (the fail-closed roster pinned in EnvVarFallbackTest) — is excluded by construction, so a hostile environment can never retarget a sink or weaken a fail-closed flag. That exclusion is the lesson of the old universal option↔env mapping, where CANDY_SCRIPTUI_ALLOW_ENV='*' could arm format --type template to exfiltrate the whole environment and CANDY_SCRIPTUI_DEFAULT=yes silently answered confirm; both names now sit outside the allow-list and are ignored with no notice.
