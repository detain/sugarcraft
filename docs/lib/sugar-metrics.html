SugarMetrics is a telemetry library for PHP 8.3+ services and terminal apps. It provides counters, gauges, histograms, up-down counters and two callback-driven async instruments, collected by a Registry and sent to one of five backends: in-memory, JSON stream, StatsD, a Prometheus textfile, or a fan-out over several of them. A drop-in middleware records per-session telemetry for sugarcraft/sugar-ssh-server. The instrument model follows the OpenTelemetry metrics API, and the SSH middleware follows charmbracelet/promwish.

Install

composer require sugarcraft/sugar-metrics

Requires PHP 8.3 or newer. The package depends on sugarcraft/sugar-ssh-server, which is needed only by the optional SessionMetrics middleware, and that dependency brings in the ext-ffi requirement. The sibling packages track dev-master, so a project on the default stable minimum stability must set "minimum-stability": "dev" and "prefer-stable": true. Check the platform requirements before wiring metrics into a minimal container image.

Quickstart

use SugarCraft\Metrics\Registry;

$reg = Registry::inMemory();   // accumulates in memory; good for tests and boot probes

$reg->counter('http.requests', 1, ['route' => '/api/foo', 'status' => '200']);
$reg->gauge('queue.depth', 42);

$stop = $reg->time('http.duration', ['route' => '/api/foo']);
// ... do the work ...
$stop();                       // records the elapsed seconds as a histogram sample

The same work through instrument objects, which keep their name next to the code that emits them. The help text is published only when the family is also registered with a Descriptor, as described under Troubleshooting:

$requests = $reg->newCounter('http_requests', 'Requests served');
$requests->inc(1.0, ['route' => '/api/foo']);

Concepts and how it works

PrimitiveBehavior
CounterMonotonic total, such as connects or errors. Negative samples are refused.
GaugeInstantaneous value that replaces the previous one on each set, such as queue depth.
HistogramDistribution of samples, such as latency. Negative samples are refused. The Prometheus backend emits 14 cumulative le buckets plus +Inf.
UpDownCounterSynchronous counter that accepts positive and negative increments, such as active connections.
AsyncCounterCounter read through a callback. Call observe() to emit the current external reading.
AsyncGaugeGauge read through a callback, such as memory use or pool size.

A Registry is the application-facing facade. It forwards each emit to one Backend, and the backend decides how to store or forward the data. A tag is a key/value pair attached to one emit. The Prometheus text format calls the same thing a label, and PrometheusFileBackend translates between the two.

Each unique tag combination is a separate time series. The registry caps the combinations per metric name and evicts the oldest one when the cap is reached. It also asks the backend to release that series, and only storing backends can do that.

Tasks and recipes

Expose a Prometheus textfile

use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\PrometheusFileBackend;

$reg = Registry::new(PrometheusFileBackend::new('/var/lib/app/metrics.prom'));
$reg->counter('jobs_done', 1, ['queue' => 'bake']);
$reg->flush();                      // writes the textfile atomically, fsync before rename

Stream newline-delimited JSON

use SugarCraft\Metrics\Registry;

$audit = Registry::to('/var/log/app/metrics.json');   // a path, a resource, or php://stderr when null
$audit->gauge('queue.depth', 42);

Fan out to two backends

use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\InMemoryBackend;
use SugarCraft\Metrics\Backend\MultiBackend;
use SugarCraft\Metrics\Backend\StatsdBackend;

$memory = new InMemoryBackend();
$reg    = Registry::new(MultiBackend::new($memory, StatsdBackend::new('127.0.0.1', 8125)));
$reg->counter('http.requests', 1);
echo $memory->counterValue('http.requests');   // prints 1 (PHP echoes the float 1.0 without a decimal point)

Bound label cardinality

use SugarCraft\Metrics\Registry;

$reg = Registry::new($backend, [], 500);   // 500 label combinations per metric name
$reg->cardinality('http.requests');         // current count for this name
$reg->remove('http.requests', ['route' => '/logout']);   // drop one series and its backend data

Tag every emit from one request

$req = $reg->withTags(['request_id' => $rid, 'user' => $userId]);
$req->counter('events');

Values from callers you do not trust should be hashed or bucketed before tagging. The backends sweep wire-framing characters, but every distinct value still creates a new series.

Record SSH session telemetry

use SugarCraft\SshServer\Context;
use SugarCraft\SshServer\Middleware;
use SugarCraft\SshServer\Server;
use SugarCraft\SshServer\Session;
use SugarCraft\Metrics\Registry;
use SugarCraft\Metrics\Backend\PrometheusFileBackend;
use SugarCraft\Metrics\Middleware\SessionMetrics;

// The library arms no timers and the textfile is written only on flush() or at
// exit, so a long-lived server must flush after each session itself.
final class FlushMetrics implements Middleware
{
    public function __construct(private readonly Registry $registry)
    {
    }

    public function handle(Context $ctx, Session $session, callable $next): void
    {
        // finally: a session that throws is the one whose error sample must reach the textfile.
        $completed = false;
        try {
            $next($ctx, $session);
            $completed = true;
        } finally {
            try {
                $this->registry->flush();
            } catch (\Throwable $flushError) {
                // A flush failure must not replace the session's own exception;
                // on a clean session there is none to protect, so it surfaces.
                if ($completed) {
                    throw $flushError;
                }
            }
        }
    }
}

$reg = Registry::new(PrometheusFileBackend::new('/var/lib/ssh/metrics.prom'));

// FlushMetrics is registered first so it wraps SessionMetrics and flushes after
// SessionMetrics has recorded the session's duration and error samples.
Server::new()
    ->use(new FlushMetrics($reg))
    ->use(SessionMetrics::new($reg))
    ->serve();

Long-lived servers must call flush() themselves: the metrics library never does it on a timer, so without a flush per session the textfile shows no ssh_session_* series until the process exits. The shipped examples/ssh-server-with-metrics.php follows the same pattern.

Util final class

Shared utility functions for the metrics library.

MethodSummary
static tagKey(array $tags): stringSort tags by key and build a stable, collision-free k=v|k2=v2 string. Every key and value is backslash-escaped first (\ → \\, | → \|, = → \=), so a separator that appears inside a tag payload cannot impersonate the pair delimiter: without it, ['x' => 'a|y=b'] and ['x' => 'a', 'y' => 'b'] would serialize identically and collapse two distinct series into one cardinality slot.
static nameToken(string $name): stringThe storage-key NAME segment gets the identical escape a tag token gets (see self::escapeTagToken()). In-memory accumulation accepts arbitrary raw names — there is no sanitize-name gate on that path — so without this the name 'x|y=1' would land in exactly the bucket 'x' + tags ['y' => '1'] folds into (finding 013). One escaper for every segment makes the separator unforgeable from both sides, and the map stays readable: a clean name escapes to itself, so the storage key of every well-behaved series is unchanged.

Troubleshooting and FAQ

RuntimeException: a metric name is registered twice with different metadata

Registry::register() accepts a re-registration only when the type, help text and label keys all match. Any difference throws a RuntimeException. Give the metric one Descriptor and reuse it.

InvalidArgumentException for a descriptor name containing a dot

A Descriptor name must match [a-zA-Z_:][a-zA-Z0-9_:]*, so http.requests is refused. The emit path can keep the dotted name, but on the Prometheus wire it becomes http_requests. Register the underscore form with a descriptor, as in $reg->register(Descriptor::new('http_requests', 'Requests served', 'counter')), to publish # TYPE and # HELP lines before the first emit. The instrument returned by newCounter() keeps its help text but does not register it, so newCounter('http_requests', 'Requests served') alone never publishes the # HELP line.

RuntimeException on a negative counter or histogram sample

Counters and histograms are monotonic in the sense that they refuse negative samples. Use upDownCounter() for a value that rises and falls, such as active connections, or a gauge for an instantaneous reading.

RuntimeException about two series that fold to the same Prometheus name

Prometheus names cannot contain most punctuation, so PrometheusFileBackend folds names and label keys. When two distinct raw names fold to the same key, it throws rather than merging them. Rename one of the metrics so the folded names differ.

The textfile shows no samples for a family

The file shows a family only after its first sample, unless it was registered with a Descriptor. Register the descriptor on the registry to publish the # TYPE and # HELP lines before the first sample arrives.

Memory keeps growing on StatsD or JSON output

Eviction releases series from storing backends such as InMemoryBackend and PrometheusFileBackend. StatsdBackend and JsonStreamBackend have already sent what they emitted, so their remove() is a no-op. Against those backends the cardinality limit bounds only the registry's own tracker.

Changelog and versioning

The package ships no separate changelog file. It is published from the monorepo with the other sugarcraft/* packages on dev-master. Breaking changes are recorded in the README under Breaking changes. For example, the multi-backend exception's error accessor is now the bare errors() method, following the bare-accessor convention; code that still calls the earlier get-prefixed accessor must switch.
