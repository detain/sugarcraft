💣 CandyMinesweeper

Minesweeper on the SugarCraft stack

inspired by maxpaulus43/go-sweep game minesweeper sugarcraft injectable-rng

Customisable board (width / height / mine count), iterative zero-flood-fill, win / lose detection. Pure-state Board class so every reveal is unit-testable without touching the runtime.

Install

composer require sugarcraft/candy-minesweeper
./vendor/bin/candy-minesweeper       # play straight from the dependency

# or run the shipped binary from a clone:
composer install
./bin/candy-minesweeper

# or grab the rolling development phar (rebuilt on every push to master):
wget https://github.com/detain/sugarcraft/releases/download/candy-minesweeper/dev/candy-minesweeper.phar
php candy-minesweeper.phar

Quickstart

./bin/candy-minesweeper                    # 10×10, 12 mines (defaults)
./bin/candy-minesweeper 16 16 40           # positional args: width height mines
// Programmatic:
use SugarCraft\Core\MouseMode;
use SugarCraft\Core\Program;
use SugarCraft\Core\ProgramOptions;
use SugarCraft\Minesweeper\Game;

(new Program(Game::start(width: 16, height: 16, mines: 40),
             new ProgramOptions(useAltScreen: true,
                                mouseMode: MouseMode::CellMotion)))->run();

What's in the box

First-click safetyMines aren't placed until the first reveal, with the clicked cell's 3×3 neighbourhood excluded (6 or 4 cells at edges) — every game gets a non-trivial flood-fill on click 1. On densely customised boards that cannot spare a full 3×3 the exclusion falls back to the clicked cell alone, so the first click is still never a mine and every requested mine is placed.
Iterative flood fillZero-adjacency cells reveal their neighbours transitively, exactly like classic Minesweeper.
Vim-style movementhjkl alongside arrows; cursor clamps at board edges.
Flag togglef flags / unflags the cursor cell; flagged cells can't be revealed by accident.
Chord clickc or middle-click on a satisfied number reveals all unflagged neighbours — mirrors classic left+right chord behaviour.
Sub-second timerThe clock reads microtime(true) internally, but every observable path — the status line and the persisted best times — is whole seconds; frozen on win/lose.
Best-time persistenceOpt-in via CANDY_MINESWEEPER_STATS=/path/stats.json (off by default): DifficultyStats then persists games/wins/best time per difficulty to JSON atomically via sugar-core AtomicJsonFile (flock sidecar, temp + rename) so crashes never corrupt the record.
Win + lose detectionisWon = every non-mine revealed; exploded = at least one mine was clicked. O(1) via revealedCount — no grid scan on each move.
Restart keyr reseeds with a fresh layout, preserving the chosen board size.
Save / resume mid-gamePress S to write the live board to the single save slot — $XDG_CONFIG_HOME/candy-minesweeper/savegame.json when set, ~/.config/candy-minesweeper/savegame.json otherwise (mode 0600) — and L to restore it. The slot carries the full live mine layout: it is the answer key to the game in progress, so keep the file private if you sync dotfiles. Backed by Board::serialize() versioned JSON; unserialize() re-validates every shape and recomputes the counts, so tampered payloads are refused rather than half-parsed.
Localised interfaceStatus line, win/lose banners and the help footer route through Lang::t; LC_ALL/LC_MESSAGES/LANG pick the locale from 16 shipped files.
Custom difficultyUi\CustomDifficulty validates rows (2–50), cols (2–50), mines (1 to rows×cols−9) with i18n-aware error messages.
Terminal graceful downgradeSetting NO_COLOR, CLICOLOR=0, or TERM=dumb strips the foreground/background colours through the fleet colour authority; the game stays fully playable without them.
