sugar-log is a leveled, structured logger for terminal programs. It has five levels (Debug, Info, Warn, Error, Fatal), key/value context on every call, three formatters (human text, JSON and logfmt), and child loggers that carry persistent fields. It also ships a static facade in the style of charmbracelet/log, a PSR-3 bridge, per-level hooks, a Go-style log.Logger call adapter and a panic handler that restores the terminal before it prints its report. Color follows the environment and falls back to plain bytes whenever the destination is not a terminal.

Install

composer require sugarcraft/sugar-log

Requires PHP 8.3 or newer. The package requires its sugarcraft/ siblings at dev-master, so a project on the default stable minimum stability cannot resolve them. Set "minimum-stability": "dev" and "prefer-stable": true in the consuming root manifest, or pin released sugarcraft/* tags once they are cut. The monorepo publishes all of its libraries together, so sibling versions always line up.

Quickstart

use SugarCraft\Log\{Level, Logger};

$log = Logger::new(level: Level::Debug);   // the default threshold is Info; Debug opts in
$log->debug('preheat cycle', ['stage' => 1]);
$log->info('Starting oven', ['degree' => 375]);
$log->warn('Almost ready', ['batch' => 2]);
$log->error('Temperature too low', ['err' => 'underheated']);

$baker = $log->with(['service' => 'bakery']);   // every line from $baker carries service=bakery
$baker->info('Batch complete');

What the default output looks like

The default formatter is TextFormatter, and the default stream is STDOUT. This is the first part of php examples/demo.php on a terminal with color off:

2026/11/19 18:17:11 INF 🍪 Starting the oven degree=375 mode=convection
2026/11/19 18:17:11 WRN 🍪 Door left open seconds=3
2026/11/19 18:17:11 ERR 🍪 Temperature sensor disconnected sensor=temp_01

Concepts

Levels are integers

Level is an int-backed enum with the values Debug = -4, Info = 0, Warn = 4, Error = 8 and Fatal = 12. The deltas match charmbracelet/log. They are deliberately not RFC 5424 severities, so compare them through ->value. A record is written when its level is at or above the logger's minimum level, which defaults to Info. print() and printf() skip that filter, but the record still carries its label. Level::fromPsrString() maps a PSR-3 severity string onto the ladder and returns null for an unknown string.

Fatal writes, then throws

Calling fatal() writes the record and then throws FatalLoggedException, which extends RuntimeException. Go's log.Fatal exits the process at this point, but a PHP library should not, so the exit becomes a catchable throw. A host that wants to stop can let the exception reach the top level. Nothing is exited for it.

Context and child loggers

Each call takes an array of context fields. with(array $fields) returns a child logger that carries those fields on every line it writes, and the parent is not changed. Context keys that collide with the record's own envelope, such as level, msg or time, are renamed with a ctx_ prefix, so a decoder always reads the real level and message.

Formatted helpers

Every level has a sprintf-style twin: debugf(), infof(), warnf(), errorf(), fatalf() and printf(). The second argument is mixed on purpose. An array there is context, and any other value is the first sprintf argument. The level-bound helpers check enabled() before they format, so a dropped record costs no formatting work.

Output goes to STDOUT by default

Every level is written to STDOUT by default. charmbracelet/log writes to stderr, and this port deliberately differs so that pipes and files get every level on one stream. Split the severe records out with an error stream, described in Configuration. Under a web SAPI, the standard streams resolve lazily to php://stdout and php://stderr, and a stream that cannot be opened goes silent instead of failing the request.

Tasks

Emit structured JSON for a log shipper

use SugarCraft\Log\Formatter\JsonFormatter;
use SugarCraft\Log\Logger;

$log = Logger::new(formatter: new JsonFormatter());
$log->info('Bake complete', ['batch' => 3, 'cookies' => 24]);
{"level":"INFO","msg":"Bake complete","time":"2026-11-03T07:15:04+00:00","batch":3,"cookies":24}

LogfmtFormatter works the same way and writes key=value pairs. Both accept an optional $timeFormat, which defaults to DateTimeInterface::ATOM, because machine parsers expect that shape. Change it only on purpose.

Send errors to a second stream

use SugarCraft\Log\{Level, Logger};

$err = fopen('php://stderr', 'w');
$log = Logger::new(errorStream: $err, errorStreamAt: Level::Warn);   // Warn and above go to STDERR
$one = $log->withErrorStream(null);                                 // back to a single stream

Log to a file

use SugarCraft\Log\Logger;

$log = Logger::new(stream: '/var/log/bakery/app.log');   // opened in append mode on assignment

A path that cannot be opened throws an InvalidArgumentException that names it. The file is created with mode 0666 masked by your umask, so a typical umask leaves it world-readable. Set umask 0077 first, or chmod the file afterwards, for a 0600 log. Files are buffered, so call flush() before a hard exit.

Use the static facade

use SugarCraft\Log\{Level, Log};

Log::info('baking started', ['temp' => 375]);
Log::warn('timer almost up');
Log::default()->setMinLevel(Level::Debug);   // the shared logger starts at Info
Log::debug('oven state', ['door' => 'closed']);

Log is a process-shared facade over one lazily created default Logger. Log::setLogger() swaps it for another, and Log::reset() returns to the default.

Bridge to PSR-3 code

use SugarCraft\Log\{Logger, PsrBridge};

$psr = new PsrBridge(new Logger());
$psr->warning('Something is off', ['detail' => 'temperature rising']);
$psr->log('error', 'Operation failed', ['code' => 500]);  // any PSR-3 level string

The bridge implements Psr\Log\LoggerInterface, so PSR-3 libraries can log through it. Its level mapping is in the API reference below.

React to warnings with a hook

use SugarCraft\Log\{Level, Logger, PsrBridge};
use SugarCraft\Log\Hook\HookRegistry;

$hooks = new HookRegistry();
$id = $hooks->onLevel(Level::Warn, function (Level $level, string $psrLevel, string $message, array $context): void {
    // React to the completed write: count it, alert, or ship it. Do not mutate the log.
});

$psr = new PsrBridge(new Logger(), $hooks);
$psr->warning('Something is off');   // the hook runs after the record is written
$hooks->remove($id);

Hooks run only through PsrBridge or an explicit HookRegistry::fire(). A plain Logger call never fires them. A hook that throws is contained, so it cannot cancel the walk or lose the log line.

Order the parts of a text line

use SugarCraft\Log\{Logger, PartsOrder};
use SugarCraft\Log\Formatter\TextFormatter;

$log = Logger::new(formatter: new TextFormatter(partsOrder: PartsOrder::syslog()));
$order = new PartsOrder([PartsOrder::PART_MESSAGE, PartsOrder::PART_LEVEL, PartsOrder::PART_FIELDS]);

PartsOrder applies only to TextFormatter. A JSON object has no member order, and a logfmt record is fixed-shape, so both ignore it. The constructor refuses unknown or duplicated parts and names the offenders, so a typo such as msg cannot silently delete the message from every line.

Install a panic handler

use SugarCraft\Log\{Log, PanicFormatter};

Log::installPanicHandler();                               // default formatter, styled only on a color terminal
Log::installPanicHandler(PanicFormatter::plain(true, ['/etc/secrets']));   // or force plain text with redaction

The handler catches uncaught exceptions and fatal PHP errors, restores the terminal from alternate-screen mode, and prints a report with the error class, message and backtrace. Log::removePanicHandler() undoes the install and restores whatever handling existed before it. Pass the formatter itself, not extra options: a call that passes both a formatter and showLocals or redactPaths throws, rather than dropping them.

Environment variables

VariableRead atEffect
CLICOLOR_FORCE=1construction and every writeForces color on. The value must be exactly 1. It outranks NO_COLOR at construction
NO_COLORconstruction and panic-handler installTurns color off for a logger built afterwards. It is not re-read per write
FORCE_COLORconstructionHonoured by the construction-time probe. The per-write gate ignores it

Color decisions happen in two layers. The construction-time probe reads the environment once, so changing a variable later does not re-probe an existing logger. The per-write gate looks only at CLICOLOR_FORCE and whether the stream is a terminal, so files and pipes always receive plain bytes.

Styling

Styles apply only when the destination can render them. Override the level colours through Logger::styles(), or build a Styles and install it with setStyles(). A logger built without styles owns a private snapshot, so changing its styles does not touch other loggers.

Per-level and per-field colours

use SugarCraft\Core\Util\Color;
use SugarCraft\Log\{Level, Logger, Styles};
use SugarCraft\Style\Style;

$styles = new Styles();
$styles->levels[Level::Error->value] = Style::new()->foreground(Color::parse('red'))->bold();
$styles->keys['time']    = Style::new()->foreground(Color::parse('cyan'));
$styles->keys['message'] = Style::new()->italic();
$styles->keys['value']   = Style::new()->foreground(Color::parse('green'));   // splits key=value into two segments
$styles->values['batch'] = Style::new()->foreground(Color::parse('magenta')); // one field's value

Logger::new()->setStyles($styles);

Part roles that have no style fall back to the matching property, such as $timestamp or $message, or to the level colour map. A style on keys['level'] wins over the level map.

High-contrast terminals

The shipped palette is re-tuned for legibility and differs from charmbracelet/log. Debug, the caller tag and the generic keys use bright black, which is only about 2.5 to 3 to 1 against a dark background. Labels always carry text, so colour is never the only signal. Where contrast matters, override the roles:

use SugarCraft\Core\Util\Color;
use SugarCraft\Log\{Level, Logger, Styles};
use SugarCraft\Style\Style;

$styles = Styles::snapshot();
$styles->levels[Level::Debug->value] = Style::new()->foreground(Color::parse('white'));
$styles->levels[Level::Info->value]  = Style::new()->foreground(Color::parse('cyan'))->bold();
$styles->keys['key']                    = Style::new()->foreground(Color::parse('white'));
$styles->caller                         = Style::new()->foreground(Color::parse('white'))->bold();

Logger::new()->setStyles($styles);

The panic report has its own colours. PanicFormatter::pretty() paints its backtrace in bright black, and no Styles override reaches it. For a high-contrast report, pass PanicFormatter::plain() to installPanicHandler().

Level label alignment

Set padLevelText to true to right-pad every level label to five characters, so the columns line up. Styles::padLevelText('INF') returns "INF ", and 'DEBUG' is returned unchanged.

Examples

The examples live in examples/ and need composer install first. None of them takes arguments.

examples/demo.php

Exercises every level, the structured fields, the child loggers, the three formatters and the stdlog adapter. It exits with status 0. The end of its output is the stdlog adapter's fatal record, which is caught and printed as (fatal contract: ...).

php examples/demo.php

examples/panic-handler.php

Installs the panic handler and then raises a user error on purpose, so you can see the panic report. The process exits with status 255, which is the expected result of the demo.

php examples/panic-handler.php

examples/panic-restore.php

Shows Tty::restoreLast() from sugar-core. It saves the terminal state, does some work, and then restores the state. Run it in a terminal to see the terminal restored.

php examples/panic-restore.php

cd sugar-log && composer install && vendor/bin/phpunit

Troubleshooting

Debug lines never appear

The default minimum level is Info. Start the logger with Logger::new(level: Level::Debug), or call setMinLevel(Level::Debug) on a shared logger. print() skips the filter entirely, so it is the way to force a line out.

Colour codes appear in a log file

The per-write gate keeps colour out of files and pipes, unless CLICOLOR_FORCE=1 is set. A standalone new TextFormatter(useColors: true) emits SGR by contract, because the gate lives in the logger and not in the formatter. Write through a Logger when the destination might not be a terminal.

Setting NO_COLOR after the logger was built has no effect

The construction-time probe reads the environment once. Set NO_COLOR before you construct the logger, or build a new logger after you set it.

Hooks never fire

Hooks run only through PsrBridge or an explicit HookRegistry::fire(). Call the bridge's PSR-3 methods, not the Logger methods directly.

The process stops after fatal()

That is intended. fatal() throws FatalLoggedException, a RuntimeException, after it writes the record. Catch it where you want the program to stop, or let it reach the top-level handler. The PSR-3 bridge swallows it, so a critical() call does not stop the program.

A line is missing from the output

If a write fails, the logger retries it once after a flush. If the retry also fails, it prints a sanitised [sugar-log] log write failed: notice to STDERR, with a copy of the dropped record. Nothing else is reported. For file streams, call flush() before a hard exit such as exit() under a framework fatal, or before a signal kills the process, so no buffered record is lost.

Architecture

Record integrity

Untrusted data cannot forge or reshape a record. Text reaching the text and logfmt formatters passes through Sanitize::untrusted(), which strips ESC-based sequences. The JSON formatter sweeps control bytes from the message, prefix, caller and every context key and value, and it replaces invalid UTF-8 rather than failing the encode. Logfmt escapes backslashes, quotes and line breaks, and quotes any value that contains whitespace, = or ". Reference cycles stop at a depth cap. A throwing __toString() is contained, and a failed JSON encode drops only the offending field and flags it with _encode_error.

Streams and write failures

A stream may be a resource or an append-mode path. A stream that is neither is refused with an InvalidArgumentException. A record that cannot be written never throws into the caller. It is retried once, and the loss is announced on STDERR as a sanitised notice. Routing is decided for each record, so a Fatal record still throws after it is written.

Localization

Error-path messages from Logger, PsrBridge, PartsOrder and Log go through SugarCraft\Log\Lang, on top of the shared sugar-core lookup. The shipped catalogue is in English and 15 other locales. Level labels, timestamps and field text are never translated. The host sets the locale once at process start with SugarCraft\Core\I18n\T::setLocale().

Changelog and versioning

sugar-log is published from the monorepo together with its sugarcraft/ siblings, so version numbers line up across the family (see Install). The behaviour each release changes is described in the README section for the feature involved. The Levels section pins the integer values that thresholds rely on, so a change to those values is a breaking change for any consumer that compares levels numerically.
