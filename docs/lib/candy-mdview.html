candy-mdview is a Markdown viewer for the terminal. It renders a file, a directory's README, an http(s):// URL or stdin to ANSI text, or opens the result in a fullscreen pager that reflows on resize and reloads when the file changes on disk. Rendering comes from SugarMarkdown, scrolling from the SugarForms Viewport. The tool is the native-PHP counterpart of charmbracelet/glow: rendering, paging, themes and live reload are ported, while glow's directory browser, search, config UI and presentation modes are left out.

Install

composer require sugarcraft/candy-mdview   # binary lands in vendor/bin/candy-mdview

Requires PHP 8.3 or newer. For a single file, the rolling latest phar is rebuilt on every push to master that changes the library. Verify it against the .sha256 sidecar before running it:

wget https://github.com/detain/sugarcraft/releases/download/candy-mdview/latest/candy-mdview.phar
wget https://github.com/detain/sugarcraft/releases/download/candy-mdview/latest/candy-mdview.phar.sha256
sha256sum -c candy-mdview.phar.sha256
php candy-mdview.phar README.md

The .phar.commit sidecar names the exact tested commit each dev build was cut from. Both sidecars are published only from CI-green pushes to master. A monorepo checkout needs no install step for a quick look: cd candy-mdview && php bin/candy-mdview README.md runs straight from the tree.

Quickstart

candy-mdview README.md                        # render to stdout (the default)
candy-mdview -p README.md                     # open in a fullscreen pager
git log -1 --pretty=%B | candy-mdview -p      # pipe stdin; the pager keys still work
candy-mdview --theme dracula README.md
candy-mdview --width 80 --no-hyperlinks README.md

Stdout mode is pipe-friendly and exits cleanly. Pager mode arms the alternate screen and mouse tracking, so it needs a real terminal. Stdin can feed the pager because the keyboard is read from /dev/tty.

Concepts

Every input is a document. A file path, a directory (resolved to one README), an http(s):// URL and stdin all pass the same gate: DocumentGate refuses non-text (binary) input and anything over 64 MiB, and a leading YAML front-matter block is removed before Markdown parsing, whichever door the bytes came through. A URL is fetched with a 10 second transfer deadline, at most 5 redirects, TLS verification on, and a 2xx final answer. Its remote origin earns no special trust.

The rendered text then goes one of two ways. Stdout mode writes it and exits. Pager mode hands it to MdViewModel, a Model whose body is a SugarForms Viewport, so the view is a window onto the text rather than a copy of it. Resizing re-wraps the document when no --width is pinned.

Output is always sanitized. SugarMarkdown strips escape, control and OSC bytes from the rendered output, and this tool never turns that default off. A hostile Markdown file therefore renders as data: it cannot move the cursor or restyle the stream.

Input doors and their limits

  • File: a regular file. A directory, FIFO or device is refused with exit 2.
  • Directory: resolves to README.md, then README.markdown, then index.md, then a single unambiguous *.md. Recursive trees are not walked, and several competing candidates refuse with exit 2.
  • URL: fetched as above. Auto-reload and the file · scroll% header are local-file features, so a pager opened on a URL watches nothing.
  • Stdin: the default when no file argument is given. The pager reads keys from /dev/tty and has no header row.

Tasks

Read a file in the pager and let it reload on save

candy-mdview -p docs/guide.md

A fixed 0.5 second tick (MdViewModel::RELOAD_POLL_SECONDS) compares the file's (mtime, size) pair against the last one seen. A change queues one re-read and re-render for the following tick, so a burst of saves coalesces into one render of the newest bytes. A rewrite that keeps both the second-granularity mtime and the byte size is invisible to that check. Press r to force a reload in that case.

Pin the column width

candy-mdview --width 72 CHANGELOG.md   # wrap at 72 columns, resizing moves only the clip window
candy-mdview --width 0 table-heavy.md  # no wrap: long lines are cut, and the pager scrolls them sideways

Without --width, stdout wraps at min(terminal width − 2, 80) and the pager wraps at the live column count. --width accepts 1 to 9999; 0 disables wrapping, and anything non-numeric is a usage error.

Load a custom theme file

candy-mdview --theme-config ./my-theme.json README.md

A theme file is read as a regular file of at most 1 MB. Two shapes are detected automatically: a Glamour-style document with a top-level "document" block, which GlamourTheme maps onto a SugarMarkdown theme, and the flat shape, one style object per element slot, which Theme::fromJsonString() reads. themes/solarized.json in the repository is a worked flat starting point. A payload that matches neither shape refuses with exit 2 instead of quietly rendering the stock theme.

Persist preferences and remap pager keys

{
  "theme": "dracula",
  "width": 80,
  "pager": false,
  "keymap": { "reload": "ctrl-r", "help": "h" }
}

Save that as $XDG_CONFIG_HOME/mdview/mdview.json (or ~/.config/mdview/mdview.json), or point MDVIEW_CONFIG at it. Flags beat environment variables, and environment variables beat the file. The keymap block maps the actions quit, reload and help to a chord written x, ctrl-x or alt-x. The Escape and Ctrl+C quit paths are fixed and stay available whatever the map says.

Render a URL

candy-mdview https://example.com/README.md
candy-mdview -p https://example.com/README.md   # pager on a fetched URL: no auto-reload

API reference

The public classes live in SugarCraft\MdView\. The pager is a SugarCraft Model, so MdViewModel follows the usual init(), update(Msg) and view() contract, and the tests drive it that way. The other classes are static helpers or value objects.

Keys and keybindings

The pager reads the keyboard from /dev/tty, so piped input stays scrollable. The table lists the default bindings.

KeyAction
↑ / kLine up
↓ / jLine down (Alt+j too)
Mouse wheelThree lines per notch in either direction
PgUp / bPage up (Ctrl+B too)
PgDn / space / fPage down
Ctrl+U / Ctrl+DHalf page up or down
Home / g, End / GTop, bottom
← / h, → / lScroll horizontally in no-wrap mode
rForce a reload of the watched file (unmodified only)
?Show or hide a one-row strip that condenses these keys (unmodified only)
q / Esc / Ctrl+CExit. Shift+q, Alt+q and Ctrl+Q do not.

The scroll letters match on their rune alone, so Ctrl+B and Alt+j work as their plain counterparts. A document taller than the screen grows a scrollbar along the right edge, and the header row reads file · scroll% plus ↻N after N auto-reloads. A ↻! means the last change was refused and the frame is stale.

Theming

Twelve stock themes ship: ansi, ascii, plain, notty, dark, light, dracula, tokyo-night, pink, solarized, monokai and github. The aliases no, auto-no and tokyonight resolve to plain, notty and tokyo-night. Names match case-insensitively, and _ is accepted for -. solarized, monokai and github load JSON files from themes/. Each built-in name maps to the SugarMarkdown preset of the same name.

candy-mdview --theme solarized README.md
candy-mdview --style github README.md          # --style is the Glamour-style alias for --theme
candy-mdview --theme dark --width 80 README.md

Three tiers exist for color. ansi is the terminal-native palette. ascii keeps structure, so bold and italic survive while color does not. plain is undecorated bytes. With no theme named, the implicit walk picks ansi on a decorated, color-capable stream, ascii on a decorated stream without color, and plain on an undecorated one.

./examples/render-readme.sh README.md         # the same README in several themes, side by side

The gate that says whether a stream is decorated has three inputs. --ansi opens it and --no-ansi closes it. Otherwise CLICOLOR_FORCE or FORCE_COLOR open it at any value other than 0, even on a pipe. NO_COLOR and CLICOLOR=0 do not close the gate. They only answer the color-capability question. An explicit theme names its palette everywhere, so --theme dark piped into a file still writes SGR bytes.

Examples

The examples/ directory holds four runnable programs. The three PHP examples load the Composer autoloader, so run them from a checkout or a project that has run composer install.

  • examples/render-string.php renders a Markdown string with Renderer::dark() and withWordWrap(60), and prints the ANSI output. Run it with php examples/render-string.php.
  • examples/pager-model.php builds MdViewModel::fromContent() from rendered text, sends two j key messages and a q, and prints each frame. It runs with no terminal.
  • examples/theme-json.php builds a theme from the flat JSON shape with Theme::fromJsonString() and renders a sample through it.
  • examples/render-readme.sh renders a README through several themes with the bundled binary. It needs bash and bin/candy-mdview or a global install.
php examples/render-string.php
php examples/pager-model.php
php examples/theme-json.php

Testing

The suite lives in tests/ and runs under PHPUnit 10. Run it once from the package root, with stdin redirected so a stray read cannot hang the run:

cd candy-mdview && vendor/bin/phpunit < /dev/null

The tests cover the pieces named above. MdViewModelTest and MdViewModelReloadTest drive the pager Model through update(). FileWatcherTest covers the (mtime, size) tuple law. GoldenRenderTest pins rendered output, GlamourThemeTest and ThemeLoadTest cover theme loading, HttpFetchTest covers the URL door, and LocaleParityTest checks that all sixteen lang/ catalogs carry the English key set.

Troubleshooting

"needs a terminal" error with -p

The pager needs a real terminal, either stdout or /dev/tty. When neither is available the run exits 2. Drop -p to render to a pipe or file, which is what a CI job or a redirect wants.

No color in a pipe or redirect

Without a flag, a piped stream is undecorated, so the output is plain. Force decoration with --ansi, or set CLICOLOR_FORCE=1 or FORCE_COLOR=1. Forced decoration also writes the OSC 8 hyperlink envelopes into the file. Add --no-hyperlinks to drop them.

Edits to the file do not appear in the pager

Auto-reload runs only when the pager was opened on a local file, not on stdin or a URL. A rewrite that keeps the same mtime and byte size does not trigger a reload, so press r. If the header shows ↻!, the last change was refused and the frame is stale. Fix the file, then press r.

Exit 2 when --theme-config is refused

The path must be a regular file no larger than 1 MB, and its JSON must be an object that matches one of the two accepted shapes. A directory, a FIFO, a scalar, a JSON list, or an object that matches neither schema refuses with exit 2. The refusal is deliberate: the stock theme is never rendered in its place.

A directory argument refuses

A directory resolves only when it holds one of README.md, README.markdown, index.md, or exactly one *.md file. Several competing candidates refuse with exit 2, and the message names what was searched. Pass the file itself instead.

Leading --- block is missing from the output

That is the front-matter rule. The YAML block is stripped before rendering so it does not become a heading. Pass --show-front-matter to print the block verbatim above the rendered document.

Architecture

Render before the view

Rendering happens once per document load, and the pager scrolls the finished string. The view never re-parses Markdown on a keystroke. A resize is the one exception that repeats the work: when no width is pinned, the Model re-wraps through the reflow closure it was given.

Refuse before painting

A usage error, an oversized document or a binary input stops the run before the alternate screen is armed. A pager that has already painted cannot print a usage message cleanly, so every refusal happens while the terminal is still a plain stream.

Fixed-cadence reload

The reload tick is fixed at 0.5 seconds. Each tick does one non-blocking pollTuple() probe, so the pager never waits on the filesystem and keystrokes keep flowing during a save burst.

Changelog and versioning

The rolling candy-mdview.phar is the version that tracks master. Its .sha256 and .phar.commit sidecars name the exact build. A tagged phar reports its release stamp through --version, and a rolling phar reports dev- followed by its short commit, so --version tells two dev builds apart by commit. A bare checkout or a vendor install reports the fallback 0.1.0, and so does a phar stamped only with the dev-build sentinel.
