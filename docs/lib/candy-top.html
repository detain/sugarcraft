📈 CandyTop

Terminal system monitor

inspired by aristocratos/btop system-monitor tui graphs linux freebsd

Originally inspired by btop (v1.4.7 plus a set of adopted upstream pull requests) and built on the SugarCraft stack, candy-top is a full-screen terminal system monitor in pure PHP. cpu, memory + disks, network, process and containers boxes, up to six multi-vendor GPU / NPU boxes, a server BMC (ipmi) band and a VM dashboard, drawn with braille / block / sextant graphs, gradient meters and themes in the btop tradition, fed by Linux /proc + /sys or FreeBSD sysctl collectors and driven by the SugarCore Model/Cmd runtime. It reads btop's config format, so a btop.conf works unchanged.

Install

composer require sugarcraft/candy-top

Run

vendor/bin/candy-top                      # the live host
vendor/bin/candy-top --config ~/top.conf  # another config file (also the save target)
vendor/bin/candy-top --fake               # deterministic demo data, never the real host
vendor/bin/candy-top --help               # options + the full key list
vendor/bin/candy-top --version            # version line, no tty needed
php candy-top.phar self-update            # phar installs: swap in place, no tty needed

What's in the box

cpu boxUpper/lower dual-sample graphs (any /proc/stat field), per-core grid with mini graphs and temperatures, load / uptime, frequency (aggregate and per-core, value or graph), battery badge with watts, GPU sub-graphs for the GPUs without a box of their own.
mem + disksUsed / available / cached / free as graphs or meters, a single focused metric (mem_selected), swap + zswap, ZFS ARC, per-mount meters with read/write/busy readouts and a big-graph io mode.
net boxDownload/upload graphs with hysteresis auto-scale and sync, interface cycling, totals zeroing, interface IP in the title.
proc boxSortable list (cpu lazy/direct, memory, io, …), tree view with collapse, live substring / regex filter, detailed view with cwd and IO, signals, renice, follow, pause, IO/R + IO/W columns, per-process Gpu% / GMem columns with a mini GPU graph, gpu / gpu memory sorts and a GPU-only filter (g).
ipmi boxThe server's BMC through ipmitool, run in the background one child at a time: a braille power gauge with the BMC's min / avg / max window and a draw history, per-PSU in → out bars with efficiency, temperatures filled to each sensor's own critical limit, fans with the redundancy state, centred voltage deviation bars, chassis fault chips and the event-log fill. A band under the cpu box toggled with I; degrades from four sub-panel columns to one line each.
gpu boxesUp to six GPU / NPU boxes toggled with 5–0, laid out side by side (gpu_box_columns) at Full, Compact or Minimal detail, each retargetable with its ← gpuN → title arrows. NVIDIA via nvidia-smi, AMD and Intel GPUs plus Intel / AMD NPUs via sysfs.
Containers + VMsProcesses tagged [engine:name] from their cgroup — docker, podman, k8s, lxc, nspawn — and KVM/QEMU guests by name; one key hides them all. The containers box (x) lists each container's — and each libvirt guest's — processes, memory and cpu from cgroup v2, with docker names from the socket and VMs named by domain; [ / ] pick one and the proc box shows only its processes. Running inside a container, the cpu title shows its engine.
btop's menusMain menu, a tabbed options menu with grouped headings and live preview, paged help, signal chooser, renice and warning boxes — over a dimmed backdrop.
Presets + layoutp / P cycle layout presets (with btop #1476's proc width field); Shift/Alt/Ctrl+Shift arrows resize the proc box; boxes toggle with 1–4, the containers box with x, the VM dashboard with v, the ipmi box with I, gpu boxes with 5–0.
Themes + TTY modecandy-top's own pastel theme is the default: bright pastels on a deep plum background, with box outlines that flow from one colour to the next. The 42 ported btop themes are bundled too, Default and TTY are built in rather than files, and you can add your own .theme files. TTY mode (16 colours, stepped gradients, tty glyphs) is used on a real console or with force_tty.
Config that persistsbtop-format config.conf, atomic save on exit (also on SIGTERM / SIGHUP), ctrl+r hot reload, every key documented; the reference tables track the program exactly.
MouseEvery border button, list rows, tree markers, a draggable scrollbar, the wheel, and menu tabs and entries all respond to the mouse.

Threshold colour is a gradient, but no information rides on hue alone: every threshold reading carries its number, and the loudest states add words — a full SEL prints full, a starved guest gets a textual psi cpu 23% badge, an unmeasured field prints n/a. The monitor is designed for sighted users though: the braille, block and sextant graph runs carry no text alternative, and tty_mode, the tty graph_symbol and NO_COLOR step the decoration down without adding narration — every numeric readout stays intact.

Adopted upstream btop PRs

zswap (#1739), per-core frequency (#1785), interface IPs (#1573), command basename (#1859), per-process IO columns and sorts (#1823), container tags, filter and the containers box (#1873), block2 sextant graphs (#1783), focused mem graph (#1747), disks_order (#1700), cwd in the detail view (#1546), tree branch sorting, option headings and tree-state persistence in an XDG state file (#1791), proc box width and presets W field (#1476), digit option tabs (#1411), reload repaint (#1849), the mellow theme (#1683), WSL nvidia-smi discovery (#1869), GPU boxes with slots and target arrows (#1730), the GPU box grid and detail levels (#1881), Intel and AMD NPUs (#985, #1839), AMD sysfs and multi-Intel GPUs (#1854, #1888), per-process GPU columns, sorts and filter (#1552), the FreeBSD memory and battery fixes (#1851, #1728, #1830, #1787), keep-last-good on a failed read (#1008), process names with spaces or parentheses (#1856), hidden boxes never sampled (#1858), and the gpu-graph clamping and lower-graph width split (#1614). The README lists the key, config key and theme tables, which track the program exactly. It also covers data sources, permissions, and every deviation from btop.
