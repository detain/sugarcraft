Sugar MCP Client

MCP client core — JSON-RPC codec, stdio transport, server narrowing

component-package mcp json-rpc

  • Install
  • Quickstart
  • The model
  • Use it for
  • Source
  • API

A Model Context Protocol client core the whole ecosystem can share: JSON-RPC 2.0 envelopes, a newline-framed stdio transport with a bounded child lifecycle, the initialize/tools handshake, and deny-before-allow server narrowing — tool rosters follow servers. Here "client" means the tool-CALLING side: this library spawns and drives an MCP server child process; it does not host one. Extracted from candy-code's src/MCP stack and McpMessage codec, so every surface that talks to an MCP server rides the same framing and the same handshake-and-deadline doctrine wherever the transport is stdio. First-party — MCP is a spec, not a Go port.

Install

composer require sugarcraft/sugar-mcp-client

Quickstart

use SugarCraft\Core\Util\Sanitize;
use SugarCraft\McpClient\StdioMcpServer;

$server = new StdioMcpServer(
    name: 'everything',
    command: 'npx',
    args: ['-y', '@modelcontextprotocol/server-everything'],
);

$server->start();              // initialize → notifications/initialized → tools/list, one 60 s clock
foreach ($server->listTools() as $tool) {
    echo $tool->name, ' — ', Sanitize::untrusted($tool->description), PHP_EOL;  // server-authored prose
}

$result = $server->callTool('echo', ['message' => 'hi']);
// normally ['content' => [['type' => 'text', 'text' => '…']]], or ['error' => …]
// naming the CAUSE — a failed call never throws and never answers bare.

$server->stop();               // close pipes first, then TERM→KILL→reap — bounded teardown (see Fork safety for the SIGKILLed-owner residual).
// __destruct calls stop() for you if you forget.

The example spawns npx -y @modelcontextprotocol/server-everything, so it needs Node.js on PATH; the library itself depends only on PHP 8.3 and sugar-core — substitute any stdio MCP server command (name, command, argv list) for a dependency-free trial, or run php examples/echo.php, which is the whole trial in one file: it acts as the client when run plainly and as the stdio server when run with --serve, with nothing to install or download.

The model

McpMessageJSON-RPC 2.0 envelope: parse() / request() / notification() / success() / error(); a resultSet sentinel keeps explicit "result": null representable; toJson() is the wire and fails closed on unencodable payloads, toArray() is inspection.
McpTool / McpServerOne tool definition value object with a well-typedness gate that refuses malformed server output — control bytes in names are rejected at parse; descriptions are free-form prose that passes through verbatim, so display them through sugar-core Sanitize::untrusted — plus the McpServer interface: lifecycle, tool surface, and the shared raw legs request()/notify().
StdioMcpServerargv-array proc_open child, newline-delimited (NDJSON) framing, 64 KiB rolling stderr tail absorbed on every wait set, one monotonic (hrtime) deadline across the whole handshake, protocol-version negotiation, and a per-second handshake beat via start(onWait:).
ExchangeLockSerialises whole request/response exchanges when forked processes share one stdio connection; records a W/R phase so the next holder resynchronises after a killed one; the file is created at mode 0600, verified before any payload, and a filesystem that refuses the mode fails the open loudly.
McpRouterDeny-before-allow SERVER narrowing over any set of McpServer instances — tool rosters arrive whole, so rosters follow servers; fnmatch globs; empty allowlist means allow-all; malformed entries fail loud.
Server requests & trustA server's own requests (ping, roots/list, elicitation/create) are answered inline while a call is in flight — default ping acknowledged, anything else refused "Method not found" — with the handler's wall clock excluded from the call's budget. Running a configured stdio entry executes third-party code as the invoking user with the FULL parent environment: see the README's Trust boundary.

Use it for

  • Speaking MCP from any PHP process — spawn a stdio server child, handshake, list and call tools, with the framing and timeout discipline already fought for.
  • Agent tool surfaces — narrow which servers each agent may see with globs and deny-before-allow, tool rosters following servers, the same semantics candy-code builds on.
  • Bounded subprocess I/O — the transport doubles as a reference for newline-framed JSON-RPC over pipes with deadlock-free pumping and bounded child teardown (TERM→KILL→reap on stop and on destruct); the named residual is external — a process SIGKILLed mid-use leaves its child to the embedding process manager.
