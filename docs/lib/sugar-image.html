Image-to-cell renderer for the terminal. It decodes PNG, JPEG, GIF (still and animated), APNG, WebP and BMP, then renders through the best available tier: Sixel, Kitty graphics, iTerm2 inline images, the chafa CLI, or a Unicode text tier (half-block, quarter-block, an ASCII character ramp, or the symbol-map engine). It mirrors charmbracelet/x/mosaic (Go), and the symbol engine is a port of chafa's coverage-class symbol matching.

Install

composer require sugarcraft/sugar-image

Requires PHP ^8.3, ext-gd, ext-mbstring and react/promise, all declared in composer.json. Without GD every pure-PHP tier refuses with a readable message instead of an undefined-function error. The chafa CLI is never required: the chafa tier is opt-in and is the only external binary the library runs to produce image output.

Quickstart

use SugarCraft\Image\Mosaic;
use SugarCraft\Image\ImageSource;

$mosaic = Mosaic::halfBlock();
$image  = ImageSource::fromFile('examples/fixture-gradient.png');
$ansi   = $mosaic->render($image, width: 40, height: 20);
echo $ansi;

The output is an ANSI byte string your program owns. Write it to stdout, to a socket, into a text frame, or into a file. Nothing is printed on your behalf.

Concepts

Every tier is one of two kinds. Graphic tiers (Sixel, Kitty, iTerm2) send the terminal's own image escape sequences, so the picture is pixels. Text tiers (half-block, quarter-block, ASCII ramp, symbol map) send glyphs with 24-bit or 256-color SGR, so they work in any Unicode terminal and survive a plain pipe. Use a graphic tier when the terminal supports it, and a text tier as the floor when it does not.

Mosaic::probe() picks the tier from the environment and a DA1 capability query, and Mosaic::auto() runs the same ladder. Both are fail-soft: the result is always a usable tier. Force a tier when you know the terminal, or when a probe answer is not what you see on screen.

Tasks

Pick a tier explicitly

use SugarCraft\Image\Mosaic;

$mosaic = Mosaic::probe();            // best tier for this terminal
$mosaic = Mosaic::fromModeString('quarterblock');  // a named tier, or null if unknown

Choose a color depth for a text tier

use SugarCraft\Image\Renderer\AsciiColorMode;
use SugarCraft\Image\Symbol\CanvasMode;

$sixteen = Mosaic::ascii(AsciiColorMode::Ansi16);    // 16-color character ramp
$mono    = Mosaic::ascii();                           // monochrome ramp (the default)
$symbols = Mosaic::symbols(CanvasMode::Ansi256);      // symbol map on a 256-color canvas

Text tiers emit 24-bit or 256-color SGR with no palette negotiation. On a limited-color terminal, pick the canvas explicitly. NO_COLOR changes which graphic protocol is detected, but no renderer reads it to reduce the colors it emits.

Place an image by id on Kitty

use SugarCraft\Image\KittyOptions;

// Store the image once, then reference it at many offsets.
$store = KittyOptions::transmit(7)->withUseVirtual(true);
$place = KittyOptions::place(7, x: 4, y: 2);

The storing transmit carries the payload once, and each place() is a control-only frame that never resends it. Use withCompression(1) to zlib-compress the PNG payload before base64 encoding, which helps large images on slow links.

Render from a remote URL safely

ImageSource::fromUrl() and fromUrlAsync() refuse any scheme outside the allowlist, re-check the scheme on every redirect hop, and refuse any host that resolves to a private, loopback, link-local or reserved address, including cloud metadata addresses. The security note in the README lists the residuals: the host check runs at guard time, not connect time.

API reference

Mosaic

use SugarCraft\Image\ImageSource;
use SugarCraft\Image\Mosaic;
use SugarCraft\Image\Renderer\AsciiColorMode;
use SugarCraft\Image\Renderer\QuarterBlockRenderer;

$image  = ImageSource::fromFile('examples/fixture-gradient.png');

// Probe terminal once, pick best protocol
$mosaic = Mosaic::probe();

// Force a specific backend
$mosaic = Mosaic::sixel();
$mosaic = Mosaic::kitty();
$mosaic = Mosaic::iterm2();
$mosaic = Mosaic::halfBlock();
$mosaic = Mosaic::quarterBlock();
$mosaic = Mosaic::ascii();                          // character ramp, monochrome
$mosaic = Mosaic::ascii(AsciiColorMode::Ansi256);   // ...or Ansi16 / TrueColor chars
$mosaic = Mosaic::symbols();      // chafa symbol engine, default 676-glyph corpus
$mosaic = Mosaic::chafa('--colors=256');  // external chafa CLI (opt-in)

// Render — returns ANSI bytes
$ansi = $mosaic->render($image, width: 40, height: 20);

// Builder for fine-grained control; withResize() sets the default cell box
// render() uses when called without a width
$mosaic = Mosaic::builder()
    ->withRenderer(new QuarterBlockRenderer())
    ->withResize(width: 40, height: 20)
    ->build();
$ansi = $mosaic->render($image);          // 40×20 cells
$ansi = $mosaic->render($image, 60);      // explicit width wins; height from aspect

What's in the box

Sixel rendererxterm, foot, mlterm, contour support; mlterm and foot are recognized from TERM alone.
Kitty graphics protocolkitty, ghostty, wezterm support.
iTerm2 inline imagesOSC 1337 support for iTerm2 and mintty.
Unicode half-blockFallback for any Unicode-capable terminal using ▀ + 24-bit fg/bg, where the terminal honors cell geometry; the auto() floor of the fallback ladder is the symbol-map tier.
Unicode quarter-blockHigher fidelity using ░▒▓█ 2×2 sub-pixel rendering, again where cell geometry is honored (an explicit choice, not an auto() rung).
ext-gd integrationPNG, JPEG and static GIF via GD. ImageSource::fromString() also accepts anything imagecreatefromstring() decodes (WebP, BMP and others) with its real MIME in format; the Kitty and iTerm2 renderers re-encode any payload that is not PNG by signature. Pixel allocations are bounded before GD is asked for them.
Protocol detectionMosaic::probe() checks environment variables and the DA1 capability query on every call; Detect::cached() memoizes the answer per process.
Kitty virtual-image placementStore once with KittyOptions::transmit(id)->withUseVirtual(true), then reference it at many offsets with KittyOptions::place(id, x:, y:).
Kitty zlib compressionCompress the PNG payload with zlib before base64-encoding via KittyOptions::withCompression(1), emitted as f=100,o=z. Useful for large images on slow links.
Half-block transparencyTransparent pixels (alpha=127) emit no SGR codes, so the terminal default background shows through. This enables overlay compositing on existing terminal content.
Sixel 256-color fallbackPass maxColors (1–256) to the SixelRenderer constructor to limit palette size on terminals with limited truecolor support. It rides the builder: Mosaic::builder()->withRenderer(new SixelRenderer(maxColors: 64))->build().
Symbol-map engine (chafa parity)Unicode braille, sextant, octant and block glyph cells chosen by Hamming-distance candidate search. Pure inline SGR that reaches any Unicode terminal. Glyph fidelity depends on the font's coverage, so restrict the corpus with symbols: when needed. Mosaic::symbols(canvas:, workFactor:, symbols:) selects the color canvas, candidate budget and chafa's --symbols= tag grammar.
ASCII character rampMosaic::ascii() maps one luminance sample per cell onto a character ramp. AsciiColorMode::Ansi16 | Ansi256 | TrueColor carries pixel colors on the characters themselves.
chafa CLI tierChafaRenderer shells out to the chafa command with option passthrough. Output is bounded and the child is reaped on a TERM→KILL ladder. Binary discovery is gated (see Configuration). Opt-in only; the pure-PHP tiers never shell out for pixel data.
Remote imagesImageSource::fromUrl() and fromUrlAsync() (ReactPHP) with a security floor: scheme allowlist re-checked every redirect hop, and any host resolving to a private, loopback, link-local or reserved address (including cloud metadata) is refused.
Render cachesDiskCache stores finished bytes keyed by URL, size and protocol (plus the mode detail) for cross-process redraws. AdaptiveImage is the in-session LRU. ImageLayer reserves marker blocks so images ride inside a text frame without wrecking layout.
tmux passthrough automationtmux panes swallow DCS, APC and OSC graphics unless allow-passthrough is on. TmuxPassthrough turns it on for the pane during the render and restores it (or unsets it) on retire. It is fail-soft and never throws.
Decode budgetsDecoding untrusted input is capped. The limits are listed under Configuration, and each refusal is pinned by a test.
Animation supportAnimation (immutable frame sequence) and AnimationDriver (a Model with tick-based frame timing). Use KittyRenderer::renderFrame() for stable per-frame ids that support targeted redraws.

Configuration

Environment variables

Environment variables that sugar-image reads.
VariableEffect
SUGAR_IMAGE_CHAFAOperator override for the chafa binary. An absolute path must be an executable file, and a broken absolute override is refused rather than replaced. A bare name authorizes a PATH lookup for that one value only.
SUGAR_IMAGE_TMUXBinary override for the tmux consults. Same absolute-path gate as chafa.
SUGAR_IMAGE_STTYBinary override for the terminal-state round trip. Same absolute-path gate.
SUGAR_IMAGE_TMUX_PASSTHROUGH_TTLSeconds between re-checks of tmux allow-passthrough. Default 30. 0 re-verifies before every frame. A negative or unparsable value falls back to the default.
Identity variables (TERM, TERM_PROGRAM, TERM_PROGRAM_VERSION, LC_TERMINAL, TERMINAL_NAME, TMUX, KITTY_WINDOW_ID, KITTY_PID, XTERM_VERSION, KONSOLE_VERSION, VTE_VERSION, MLTERM, GHOSTTY_BIN_DIR, WEZTERM_EXECUTABLE, ComSpec)Probe inputs for Mosaic::probe(). The table-driven identity stage reads exactly these fifteen names. The live DA1 round trip on the TTY decides what the table cannot.
NO_COLOR, CLICOLORConsulted only by the terminfo sixel-detection ladder. They can change which protocol is detected, never which colors are emitted.

Chafa binary discovery

The chafa tier is the one place sugar-image executes an external program to produce image output. The binary is chosen through a strict gate, and a bare chafa argv[0] is never spawned, so a rogue chafa earlier on PATH never runs. The order is: the SUGAR_IMAGE_CHAFA override, then a fixed roster of absolute candidates (/usr/bin/chafa, /usr/local/bin/chafa, /opt/homebrew/bin/chafa), each checked for being a file and executable. When nothing resolves, ChafaRenderer::available() returns false and render() throws a chafa.not_found failure. The gate is POSIX-shaped, so the chafa tier does not run on Windows.

Styling and color depth

sugar-image does not ship a theme. Its styling choices are the color depth and the dither mode. The depth is set by the text-tier factory (AsciiColorMode for the ramp, CanvasMode for the symbol map). The dither mode is set on the Sixel renderer, and Mosaic::withDither() changes it on a built Mosaic.

use SugarCraft\Image\Dither;
use SugarCraft\Image\Mosaic;

$sixel = Mosaic::sixel(Dither::Ordered, intensity: 0.6);
$sixel = $sixel->withDither(Dither::FloydSteinberg);

Mosaic::sixel(dither, intensity) exposes the dither axis. intensity (0.0–1.0) biases the Ordered and Noise dithers, and null keeps the chafa default of 1.0.

Examples

  • examples/inline-image.php <image-file> [width-in-cells] (default width 80) prints one image on the terminal's best tier. It is the shortest read of the detection path. Its exit codes are listed under Troubleshooting.
  • examples/text-tiers.php [width-in-cells] (default 24) renders the committed fixture through the half-block, quarter-block, ASCII (mono and ansi16) and symbol-map tiers, one labeled block each. It needs no graphics protocol and no chafa binary, so its output can be captured or piped.
  • examples/fixture-gradient.png is a committed image, so the quickstart and both scripts run against the checkout without a separate file.
php examples/text-tiers.php 16 | head -n 5
php examples/inline-image.php examples/fixture-gradient.png 40

Testing

cd sugar-image && composer install && vendor/bin/phpunit

The suite bootstraps from tests/bootstrap.php and covers the renderers, the decode budgets and the tmux passthrough. The main caps (MAX_BYTES, MAX_PIXELS and Animation::MAX_FRAMES) are pinned by boundary tests, so a change that loosens one fails the suite. The README Limits section lists the few caps that are not pinned.

Troubleshooting and FAQ

Exit codes from inline-image.php

Exit codes the example script returns.
ExitMeaning
0The image rendered and its bytes were written to stdout.
1Usage: no image path given, a width that is not a positive integer of cells, or no file at the given path.
2ext-gd is not loaded. This check runs before argument parsing.
3The path exists but is not a readable regular file, the bytes did not load as a supported image, or the render refused at the requested size (for example, the canvas ceiling guard).

The image appears as escape-sequence noise

The probe chose a graphic tier, but the terminal does not render it. Force a text tier with Mosaic::halfBlock() or Mosaic::symbols(), and report the terminal to the probe tables if it should have been detected.

Graphics vanish inside tmux

tmux swallows graphics escapes unless allow-passthrough is on for the pane. Leave TmuxPassthrough in its default auto mode, which turns the option on during the render and restores it afterwards. If you manage tmux yourself, set SUGAR_IMAGE_TMUX_PASSTHROUGH_TTL=0 to re-check on every frame, or call Detect::setAutoPassthrough(false).

A render refuses with a message about GD

Without ext-gd, every pure-PHP tier refuses with a readable message. Install the extension and check it with php -m.

An animated WebP is refused

ImageSource::fromAnimatedFile() refuses animated WebP by name. Use chafa for it, or sugar-video's AnimatedWebpDecoder, which decodes animated WebP for playback.

The chafa tier does not run

The chafa binary is found only through the discovery gate. Set SUGAR_IMAGE_CHAFA to an absolute path of an executable file. A broken absolute override is refused on purpose, so the library never falls back silently to a different program. Check ChafaRenderer::available() to see whether a binary resolved.

Architecture

SugarCraft\Image
├── Mosaic / MosaicBuilder     # facade: probe, auto, builder, render
├── ImageSource                # bytes, metadata and decode budgets
├── Animation / AnimationDriver# frame sequences and their Model
├── Detect / TermDb / Capability  # capability detection and quirks tables
├── DiskCache / AdaptiveImage  # render caches (on disk; in-session LRU)
├── ImageLayer                 # marker blocks that ride inside a text frame
├── Renderer/                  # Sixel, Kitty, iTerm2, half-block, quarter-block,
│                              # ASCII, symbol map, chafa
├── Symbol/                    # symbol map, tables, canvas modes, corpus
├── Dither/                    # Ditherer and the Dither enum
├── Passthrough/               # tmux passthrough packetizer and decorators
└── Support/                   # binary gates (chafa, tmux, stty) and GD probe

The renderers share one interface, so a Mosaic is a renderer plus a sizing policy. Graphic renderers emit protocol bytes, and text renderers emit glyphs. Nothing writes to a terminal on your behalf. The caller owns the output stream, which is what makes the same render usable over ssh, inside tmux or down a CI pipe.
