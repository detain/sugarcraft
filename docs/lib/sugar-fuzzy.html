Fuzzy string matching that returns matched character indices plus the match score. The matcher extracts the Smith-Waterman core from sugar-forms and adds a second algorithm, Sahilm, whose scoring shape follows sahilm/fuzzy. The matched indices enable filter-highlighting UIs that score-only matchers cannot offer. The back-compat shims in sugar-forms and sugar-treelist delegate here, and new code should depend on sugar-fuzzy directly.

Install

composer require sugarcraft/sugar-fuzzy

The manifest requires PHP ^8.3 and nothing else.

Quickstart

use SugarCraft\Fuzzy\Matcher\SmithWatermanMatcher;
use SugarCraft\Fuzzy\Highlighter;

$matcher = new SmithWatermanMatcher();

// Single match: returns null when no match
$result = $matcher->match('foo', 'foobar');
// $result->score     === 19   (3 × matchScore + 2 × adjacentBonus = 19)
// $result->indices() === [0, 1, 2]  (0-based character positions)
// $result->haystack  === 'foobar'

// Match all candidates, sorted by score desc then candidate asc
$results = $matcher->matchAll('ab', ['apple', 'banana', 'cabbage']);
// cabbage (11, the adjacent "ab") before apple (3) and banana (3)

// Opt in to full-query mode for type-to-filter pickers: every query
// character must land, in order
$picker = SmithWatermanMatcher::new()->withRequireFullQuery();
$picker->match('bxz', 'abcdef');               // null — "x" and "z" never land
$picker->match('gst', 'git status')->indices(); // [0, 4, 5]

// Use Highlighter to mark matched runs with ANSI codes
$highlighter = new Highlighter();
echo $highlighter->highlight($result, fn($s) => "\e[1;31m{$s}\e[0m");
// Output: 'foobar' with positions [0,1,2] highlighted in bold red
// The highlighter is presentation-neutral: sanitize candidate text (strip
// \x1b/control bytes) before display — see Security below

Concepts

A matcher takes a query and a candidate and returns a MatchResult or null. The result carries a score, which is higher for better matches, and the 0-based code-point offsets of the matched characters in the original candidate. Matching is case-insensitive by default, and the offsets stay valid even when the case fold would change the length of a string.

The two algorithms differ in what they accept. Smith-Waterman is local alignment: by default a candidate matches as soon as any run of the query aligns with it, so match('bxz', 'abcdef') scores 3 on the b alone. Full-query mode makes it require the whole query. Sahilm always requires the whole query to land, in order. Pick the algorithm by the behavior you want, not by the score.

Scores have no absolute meaning. Compare them only within one matcher and one weight profile, and use matchAll() to rank candidates for the same query.

Tasks

Rank candidates for an autocomplete list

matchAll() returns the survivors sorted by score, highest first. Equal scores fall back to the candidate in ascending order, and numeric-looking candidates sort numerically. A $limit keeps only the best N. The runnable example examples/rank-matches.php shows the ranking with a highlighter.

Build a type-to-filter picker

Use SmithWatermanMatcher::forFiltering(), which turns on full-query mode. A candidate survives only when every typed character lands, in order. examples/full-query-picker.php shows the difference against local alignment.

Match file paths

Use SahilmMatcher for paths. Its separator and camelCase bonuses reward a query that lines up with word starts. examples/sahilm-paths.php ranks a list of files, selecting the matcher through FuzzyMatcherFactory::named().

Tune the weights

use SugarCraft\Fuzzy\Matcher\SmithWatermanMatcher;
use SugarCraft\Fuzzy\ScoringProfile;

$strict  = new SmithWatermanMatcher(ScoringProfile::strict());
$custom  = new SmithWatermanMatcher(ScoringProfile::canonical()->withAdjacentBonus(8));

Profiles are immutable, so with*() returns a copy. The matcher keeps the profile it was built with.

Length caps and modes
SettingDefaultEffect
maxQueryLength128Only the first 128 query characters take part in an alignment. Under full-query mode, a longer query never matches.
maxCandidateLength1000Only the first 1000 candidate characters are searched. A match that lies beyond the cap is missed.
requireFullQueryoffEvery query character must land, in order. The best alignment is forced to cover them all, and the score floors at 1.
SahilmMatcher capsnoneSahilm is a single linear pass and is uncapped. Bound hostile-size candidates in the host.

Over-cap input is truncated, never handed to a different algorithm, so the reported indices stay valid in the original candidate. The Smith-Waterman traceback costs about 1 KB per query row at the 1000-character candidate cap, which comes to about 128 KB at the default caps.

Styling and highlighting

Highlighter takes a styler callable. It wraps each matched run in whatever the caller returns, and it returns unmatched text unchanged. The highlighter emits no color of its own. Pair any color with a bold or underline cue, so that color-blind users still see the match. Expose matchedIndices and the deterministic matchAll() order to non-visual channels, such as a screen reader.

Sanitizing is the caller's job. The highlighter forwards unmatched text verbatim, and the styler receives raw matched substrings. Strip \x1b and other control bytes before display. Case folding maps malformed UTF-8 bytes to ?, so a literal ? in the query can match untrusted text. Validate UTF-8 on both sides when the input is hostile.

Troubleshooting and FAQ

A query that should match returns null in Sahilm

Sahilm needs every query character to appear in order. A query such as ctf against a path with no such ordered subsequence is refused, even if local alignment would accept part of it. Use SmithWatermanMatcher when partial hits should score.

Swapping matchers changes the result set

Both matchers implement FuzzyMatcher, but they do not agree. Local alignment accepts partial queries, and Sahilm does not. A swap at a call site therefore turns a scored partial hit into null. Check the behavior you need before you swap.

A long candidate misses a match near its end

The candidate cap is 1000 characters by default, and the search stops there. Raise maxCandidateLength if the text is trusted and long. Sahilm is uncapped, so it finds the match, though the input is then unbounded.

Scores differ from another version

The canonical Smith-Waterman profile matches the old sugar-forms scores for ASCII input. Two documented deviations exist. An empty candidate scores 0 here, where the old sugar-forms shim scored it negative. Case folding works one code point at a time, so U+0130 and final sigma keep their indices.

Highlighted text shows escape sequences

The styler's output is inserted as is, so a raw candidate that contains \x1b injects its own codes. Sanitize the candidate before you match it, or before you display it.

Upstream mapping

Sahilm follows the bonus model of sahilm/fuzzy, a Go matcher. The shape of the scoring is shared, but the weight values are this port's own, pinned by the characterization suites. Smith-Waterman is the port of the sugar-forms core, and it has no Go counterpart.

Architecture

The matchers do no I/O and hold no state beyond their configuration. Each MatchResult is an immutable value. matchAll() scores every candidate, then hands the survivors to MatchResultSorter, which applies the ranking and the limit. The generator form buffers everything, because the ranking needs the full set. CharFold sits under both matchers, so the indices match the original string.

Changelog and versioning

The library is pre-1.0 and has no tagged releases yet, so consume dev-master. The scoring behavior is pinned by the test suite, so a change to the weights shows up as a failing characterization test.
