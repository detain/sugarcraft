SugarDiff

Unified-diff engine — hunks, writer, patch scanner, and side-by-side row pairing for gutters/split viewers

component-package diff patch

  • Install
  • Quickstart
  • The model
  • Use it for
  • Source
  • API

A unified-diff engine the whole ecosystem can share: LCS line diffing, numbered context hunks, a GNU diff -u writer, and a scanner that numbers the rows of any patch. Extracted from candy-code's BuildsUnifiedDiff trait (now a delegating consumer) and the DiffGutter region model (D1a fold landed: the gutter's scan half delegates to UnifiedScan::lines(), fileHeaders() and isHunkHeader(); only the fixed-width gutter formatting stays app-side). First-party — there is no 1:1 Go counterpart.

Install

composer require sugarcraft/sugar-diff

Quickstart

use SugarCraft\Diff\Diff;
use SugarCraft\Diff\DiffOptions;
use SugarCraft\Diff\Reader\UnifiedScan;

$before = "Hello World\n";
$after  = "Hello PHP\n";
$diff = Diff::compute($before, $after);

$patchText = $diff->unified('file.txt');
echo $patchText;
// --- a/file.txt
// +++ b/file.txt
// @@ -1 +1 @@
// -Hello World
// +Hello PHP

// Immutable, fluent options — context width, folding and GNU
// annotations are all opt-in; see the README Fidelity notes for
// exactly which shapes the defaults pin.
$wide = Diff::compute($before, $after, DiffOptions::new()
    ->withContextLines(10)
    ->withIgnoreWhitespace()
    ->withNoNewlineMarker()
    ->withDevNullOnEmptySide());

// None of those four options bite this one-line change: the sides differ
// beyond whitespace, neither is empty, both end in a newline, and the single
// hunk fits any context window — so the wide-options patch is byte-identical:
echo $wide->unified('file.txt') === $patchText ? "same patch\n" : "wider patch\n";
// same patch

// Number the rows of an existing patch (gutter/viewer support):
foreach (UnifiedScan::lines($patchText) as $row) {
    // $row->old, $row->new, $row->fileHeader, $row->kind (ScanRowKind enum)
}

// Real files: (string) file_get_contents() both sides — a file() list side
// is terminated by construction and hides a missing final newline (README
// recipe).

The model

Diffcompute() entry point; lines, hunks, per-side counts and final-newline facts; isEmpty/addedLines/removedLines/unified/hunkText.
Hunk / Line / LineKindOne @@ block; one numbered row; eq/del/ins. All immutable value objects.
Writer\UnifiedFormatRenders the GNU diff -u shape: headers (path labels whose text carries control bytes, a double quote or a backslash are C-quoted git core.quotePath-style), @@ ranges with GNU count elision, opt-in "\ No newline" markers and /dev/null labels.
Writer\SideBySideFormat / SideBySideRowPairs a diff into [left?, right?] rows for split viewers — from a computed Diff or raw patch text, one shared pairing rule.
Reader\UnifiedScanWalks any rendered unified diff, honouring each hunk's declared counts and classifying every row with ScanRowKind — row classification and numbering, no drawing. The public isHunkHeader() predicate is the walk's own recognition pattern, published so consumers gate boundaries without a second regex to drift.

Use it for

  • Patch display in TUIs — numbered hunks feed gutters, diff panes, and review overlays without re-deriving line numbers; every row ships redundant non-colour channels (LineKind::marker(), ScanRowKind), so a viewer can tint with colour without ever making colour carry the change alone (WCAG 1.4.1).
  • Editing tools — the same engine candy-code's Edit, Write and ApplyPatch tools use to report changes to the model and the user.
  • Patch consumers — UnifiedScan answers "which file line is this row?" for arbitrary incoming diffs, including multi-file git output.
