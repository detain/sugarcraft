#SugarCraft keymaps

A fleet-wide index of where each app's keys are documented. This page is links only, on purpose: every app's key table is generated or guarded where it lives (for example candy-code's is pinned by KeyBindingDriftTest against its registry), and restating a table here would fork it — the fork would drift, and the drift would lie. So grab the chord list from the authoritative page, never from a copy.

#Making chords arrive at all

Whether Ctrl+Tab, Ctrl+Enter, or Alt+letter ever reach an app as themselves is a terminal question, not an app question:

  • Kitty progressive keyboard protocol (CSI >1u flags, disambiguate mode) — negotiated by apps like candy-code and candy-files at startup; support it or not, terminals either send the chord or send nothing new.
  • xterm modifyOtherKeys — the older fallback for the same problem.
  • Both (and the legacy encodings) are decoded in sugar-input; the byte-level state machine is sugar-ansi-parser.
  • Mouse: apps enable button+motion tracking (?1002h) with SGR encoding (?1006h); terminals without SGR mouse simply never answer — see candy-top's mouse section.

Every app that draws a menu bar keeps keyboard equivalents for every mouse affordance — if you find one that doesn't, that's a bug report, not a workaround.

#Color and reduced-motion env

The env-var hub for the fleet is the shared table in the sugar-core README; the color-depth ladder (TERM/COLORTERM/NO_COLOR/force flags/CI) is documented by sugar-colorprofile. REDUCE_MOTION / PREFERS_REDUCED_MOTION behaviour and the honest per-app NO_COLOR status are in GETTING-STARTED.md §Accessibility & reduced motion.
