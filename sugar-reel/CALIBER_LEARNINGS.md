# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern:reuse-rendering-stack]** sugar-reel is the video member of the family beside candy-flip (GIF) and candy-mosaic (images). Do NOT reimplement renderers, downsamplers, dithering, or color mapping — delegate: half-block/sixel/kitty/iterm2 via candy-mosaic `Renderer`/`Mosaic`, frame downscale + Floyd-Steinberg via candy-flip `Downsampler`/`Dither\FloydSteinberg`, RGB→256/truecolor SGR via candy-palette `Color`, and the playback Model + frame pacing (`Cmd::tick()`/`Cmd::every()`) via candy-core. The lib's own job is decode (ffmpeg/GIF) → `RgbFrame` → pick a reused renderer → pace.

- **[pattern:gate-external-binaries-in-tests]** ffmpeg/ffprobe/ffplay and the audio player are shelled out, so they cannot be assumed present in CI. Probe for the binary and skip live integration tests when it is absent; keep decoders pure and unit-testable by feeding canned `rgb24` byte buffers through a stream rather than spawning ffmpeg. Build every external-CLI invocation as an arg array for `proc_open`/`Cmd::exec` (no shell) — if a string is ever unavoidable, escape every field via `escapeshellarg()` so a hostile `$path` cannot inject. PHPUnit can hang on a stuck subprocess: use a backgrounded `pkill` watchdog, not `timeout`.

- **[pattern:which-late-static-binding]** `candy-core/src/Util/Editor.php:154` defines a `protected static function which()` that uses `static::` late static binding to let test subclasses override it without a DI container or traceable Command objects. Reuse this pattern verbatim: `protected static function which(string $cmd): ?string` with Windows `where` / Unix `command -v` split, `escapeshellarg()` on every argument, and `strtok` parsing the first line of output. `sugar-reel/src/Source/Probe.php` reuses it unchanged.

- **[pattern:ffprobe-json-edge-cases]** ffprobe JSON has three non-obvious shapes to handle: (1) `r_frame_rate` is a fraction string like `"30/1"` or `"30000/1001"` — parse with `explode('/', $rate, 2)` and divide; (2) `duration` is a string in the JSON even when numeric elsewhere; (3) `hasAudio` requires iterating all streams and checking `codec_type === 'audio'` — it is never a top-level boolean. Graceful degradation when ffprobe is absent: `probe()` returns `new self($path, 0, 0, 0.0, 0.0, false)` rather than throwing, so callers that depend on metadata still get a sane default object.

- **[pattern:chunk-framing-edge-case]** `fread()` can return fewer bytes than requested (short read), especially when the subprocess is flushing at end of stream. The loop `while ($bytesRead < $frameBytes) { $chunk = fread(...); ... }` accumulates until a full frame is available, and discards incomplete last frames.

- **[pattern:proc-open-array-form]** Passing `$cmdArray` directly to `proc_open` (not `implode(' ', $cmdArray)`) avoids the shell entirely — no element needs `escapeshellarg()`. Raw strings go directly as argv; the shell is bypassed. Use `implode(' ', $cmdArray)` + `escapeshellarg()` only when a shell string is required.

- **[pattern:gif-frame-size]** `FlipDecoder::decode()` already does area-average downsampling internally; `GifDecoder` receives frames at `cellsW × cellsH` (not `cellsH * 2` — that scaling is specific to the half-block ffmpeg path where ffmpeg scales to `cellsH * 2` rows so each terminal cell maps to 2 source rows).

- **[pattern:undersized-byte-buffer-warning-suppression]** `toGd()` clamps missing bytes to black rather than emitting `Uninitialized string offset` warnings when the byte buffer is shorter than `w*h*3`. This documents that `RgbFrame` is a trust-but-verify value object.

- **[pattern:foreach-on-iterable-objects]** `foreach ($decoder as $frame)` internally calls `getIterator()`, creating a fresh generator each iteration. To iterate an existing iterator, use `foreach ($iterator as $frame)` — not `foreach ($decoder as $frame)`.

- **[pattern:bt601-vs-bt709-luma]** The integer formula `(77*R + 150*G + 29*B) >> 8` used by tplay is BT.601 (SMPTE-C), not BT.709. Visually indistinguishable in practice but documented explicitly so future porters know why the spec formula differs.

- **[pattern:sgr-per-cell-reset]** Each cell in `AsciiRenderer` emits `\x1b[0m` after the char to prevent color bleed into adjacent cells — important for delta-repaint rendering.

- **[pattern:halfblock-cell-dimensions]** `cellDimensions(Mode::HalfBlock)` returns `[1, 2]` because each terminal cell maps to 2 source rows (the `▀` char uses top+bottom pixel). All other modes return `[1, 1]`.

- **[pattern:auto-probe-ci-warnings]** `Mosaic::diagnose()` and `Probe::colorProfile()` emit PHP warnings in non-TTY (CI) environments — tests for `auto()` may show warnings but still pass. These are environmental, not bugs.

- **[pattern:mosaic-delegation]** `HalfBlockRenderer` bridges `RgbFrame → ImageSource → MosaicHalfBlockRenderer`, reusing the full image rendering stack without reimplementing SGR output.

- **[pattern:backward-seek-requires-reopen]** Video decoders are forward-only streams. Seeking backward re-opens the decoder from the source file and skips forward to the target frame. This is O(n) but necessary — a frame cache would be a future optimization.

- **[pattern:view-must-be-pure]** The TEA `view()` function should only render, not update model state. In `sugar-reel`, delta repaint state (prevBuffer) is managed in `update()` via `withNewFrame()`, not in `view()`.

- **[pattern:sync-inline-math-after-speed-change]** After speed changes, the Sync object's internal speed was stale. Inlined the `targetFrame` computation directly in `updateTick()` using `$this->speed` so changes take effect immediately on the next tick.

- **[pattern:scripted-input-program-simulator-tea]** `ScriptedInput` (declares key sequence) and `ProgramSimulator` (runs a TEA Model through scripted input) from candy-testing enable behaviour-testing the Player without real video or a PTY.

- **[pattern:fake-decoder-isolated-testing]** A test helper implementing `Decoder` that yields synthetic `RgbFrame[]` allows unit-testing the Player without ffmpeg or live video files.

- **[pattern:audio-graceful-degradation]** `AudioPlayer.start()` is a silent no-op when no binary is found or when the video has no audio track. The `buildCommand() === null` pattern gates the early return — callers don't need to check `hasAudio` or binary presence separately.

- **[pattern:proc-open-pipe-fd-cleanup]** When `proc_open` returns `false` or `0` (binary missing), the three pipe handles may have been partially-created before failure. All must be `fclose()`d in the failure path to avoid FD leaks. Guard with `is_resource($pipe)` before each `fclose()`.

- **[pattern:fake-audio-player-test-double]** `FakeAudioPlayer` test double overrides `buildCommand()` to return a controlled command (or null), enabling testing of the start/stop/isPlaying lifecycle without live ffplay/mpv binaries.

- **[pattern:mosaic-kitty-static-factory]** Superseded (candy-mosaic upstream track, ai/mosaic-graphics-upstream): `Mosaic::kitty()` now EXISTS as a force factory mirroring `Mosaic::iterm2()` — use it for kitty mode instead of hand-minting `new Mosaic(new KittyRenderer(), Capability::universal(), null, null, null)`. Raw-GD pixels likewise enter via `ImageSource::fromRgb($bytes, $w, $h)` without a PNG round-trip (see `Render/GraphicsRenderer.php`). Always check the actual candy-mosaic API rather than assuming naming symmetry.

- **[pattern:kitty-uses-apc-not-dcs-not-osc]** The kitty graphics protocol uses APC (`\x1b_Ga=...`, xterm `ESC _`) — NOT DCS `\x1bP` (that introducer is sixel/DECSIXEL and other vendor strings) and NOT the OSC `\x1b]1337;` that iTerm2 uses. These are distinct protocols — kitty uses APC `G` frames while iTerm2 uses OSC 1337. (SugarCraft emitted the DCS form behind the wrong `kittyGraphicsBegin()` introducer until the ANSI audit fix #10 moved it onto real APC frames; candy-testing's `KittyStream` still decodes legacy DCS captures.)

- **[pattern:graphics-renderer-cell-dimensions-always-1x1]** The graphics protocols fill the terminal with the image; they don't use a cell grid. cellDimensions returns [1,1] meaning "one virtual cell = the whole image".

- **[pattern:synthetic-gif-for-example-without-binary-deps]** `examples/play.php` generates a rainbow-gradient GIF using ext-gd and saves it to `/tmp` when run without a video argument. This allows the full player to be demonstrated without any video files or external binaries in the example. The player shelled out to ffprobe during open() — if ffprobe is absent, `VideoSource::probe()` gracefully returns defaults and playback still works (audio just won't be detected).

- **[pattern:vhs-tape-shows-help-or-static-output]** For a TUI player with keyboard interaction, the VHS demo (`play.tape`) shows the `--help` output rather than a video playback — it produces clean static terminal output that's perfect for GIF encoding. The player is demonstrated to work via the examples/play.php, not necessarily via the VHS tape.

- **[pattern:player-open-vs-open-for-test]** `Player::open()` wraps `VideoSource::probe()` + `DecoderFactory::create()`, requiring an actual file path and optionally ffprobe. `Player::openForTest()` takes a Decoder directly and bypasses VideoSource::probe(), used in unit tests with FakeDecoder. The example (not tests) uses `Player::open()` with the generated synthetic GIF path — ffprobe is optional for the GIF path since `VideoSource::probe()` degrades gracefully.

- **[pattern:rowspercell-contract]** `Mode::rowsPerCell()` (returns 2 for HalfBlock, 1 for all others) is the single source of truth for "source pixel rows per terminal cell". The decoder, Player, and renderers must all call this method rather than hardcoding — hardcoding caused F5 (GIF at half height in HalfBlock) and F2 (mode-switch corrupts geometry).

- **[pattern:rebuilddecoderat-single-helper]** `Player::rebuildDecoderAt(int $cellsW, int $cellsH, Mode $mode, int $frameIndex)` is the single helper for ALL decoder recreation: backward-seek, mode-switch, and WindowSizeMsg resize. It branches on the decoder's OWN capability — `$this->decoder->reopensInPlace()` — NOT on a `videoPath === '/fake'` string or `instanceof FakeDecoder`. Reopen-in-place decoders (synthetic in-memory test streams) are `reopen()`ed at the new geometry; factory-owned decoders (ffmpeg/GIF) are `close()`d then recreated via `DecoderFactory::create()` (prevents F21 — backward-seek process leak). Every code path that creates a new decoder must use this helper.

- **[pattern:windowsizemsg-authoritative]** `Player::update()` receives `WindowSizeMsg` from candy-core's `Program::run()` at startup (Program.php:173) and on every SIGWINCH. The initial size passed to `Player::open()` is a provisional override — the first WindowSizeMsg is the authoritative size. `updateResize()` clamps cols≥10, rows≥5 to prevent zero-area buffers.

- **[pattern:devnull-sinks]** All child subprocesses (ffmpeg, ffplay, ffprobe, mpv) must have stderr directed to `/dev/null` (or `NUL` on Windows) using `['file', $devNull, 'w']` descriptor spec. This prevents pipe buffer deadlocks (F7 — ffmpeg stderr blocking) and SIGPIPE when audio subprocess writes to a closed pipe end (F8).

- **[pattern:sgr-coalescing]** `AsciiRenderer::render()` now emits color SGR codes only when the color changes between adjacent cells (run-length coalescing), with a single `\x1b[0m` at end-of-line. This reduces output size by ~60% for typical frames. Verified by `testTrueColorCoalescingEmitsColorOncePerRun` — adjacent same-color pixels share one SGR sequence.

- **[pattern:kitty-image-gated-on-kittykeyboard]** The Kitty image protocol is exposed via `Capability::KittyKeyboard` in candy-palette, not a dedicated `KittyGraphics` capability. This means the terminal must support keyboard-based Kitty image rendering to use image output in sugar-reel. If candy-palette later adds a `KittyGraphics` capability, this gating can be revisited.

- **[pattern:parse-http-headers-at-the-boundary]** `Reel::openUrl($url, $headers)` / `Player::open(..., headers:)` thread an HTTP header map down to `FfmpegDecoder::buildCommand()`. The map is parsed ONCE into the immutable `Source\HttpHeaders` value object at the point of entry (`HttpHeaders::parse()`), which rejects CR/LF/NUL in any name or value (HPP / request-line injection; NUL would truncate the argv at exec level), an empty name, a colon in a name, or a malformed field line — all via `Lang::t('header.*')` — so no defensive re-check is needed deeper in the argv assembly; the raw name is line-break-checked BEFORE trimming, so `"X-Foo\r\n" => …` is rejected rather than silently sanitised. `buildCommand()` then emits `-headers` (all non-`User-Agent` fields joined as `Name: value\r\n`) and, only when a UA is present, `-user_agent`, both BEFORE `-i` and only for `isNetworkSource()`. A local path silently drops the headers (logged via `Lang::t('header.ignored_local_source')`, worded protocol-agnostically so a remote-but-in-process source can't be mislabelled) rather than throwing, because headers are meaningless there. Keep the validation at the boundary; the decoder only ever sees a trusted `HttpHeaders`. TWO boundary-specific traps learned in review: (1) `Reel::openUrl`'s headers slot OCCUPIED the old `allowedHosts` position — `['cdn.example:8443']` parses as a legal junk header and the SSRF allowlist would vanish silently, so openUrl rejects `array_is_list()` headers outright with a migration message (`header.openurl_positional`); shape-guards belong wherever a parameter reorder happened. (2) `DecoderFactory` routes http(s) sources to FfmpegDecoder even for `.gif` extensions — GifDecoder has no transport, and an authenticated remote GIF must reach the only decoder that can carry its headers.

- **[pattern:capability-not-type-check-for-test-seam]** Where the Player once branched on `instanceof FakeDecoder` / `videoPath === '/fake'` to decide how to recreate the frame source on a seek/resize, the `Decoder` interface now carries `reopensInPlace(): bool`. The Player asks the decoder, never inspects its concrete type or a magic path string. Synthetic in-memory decoders return `true` (reopen at new geometry, no subprocess); ffmpeg/GIF/factory-owned return `false` (close + `DecoderFactory::create`). This keeps test-only concepts out of production control flow while letting `frameAt()` work uniformly for any injected decoder — and where a factory-owned player has no real path (a pure stream), `frameAt()` throws a clear `LogicException` instead of silently returning null. BC NOTE: this round also WIDENED the interface (`open()`/`reopen()` gained a trailing `array $headers = []`; `reopensInPlace()` is new) — default parameters protect *callers*, not *implementers*, so an out-of-tree `Decoder` class must add the method and widen its signatures or it fatals on load. All in-repo implementers were updated; acceptable pre-1.0, call it out in release notes.

- **[pattern:blessed-seam-over-test-only-factory]** `Player::fromDecoder(...)` is the public, blessed frame-injection seam: it takes the render `Mode` as an argument and builds the matching `FrameRenderer` via `RendererFactory::create()`, so a host can drive a custom decoder (a live capture, a network stream, a synthetic generator) from its own candy-core program. `Player::openForTest()` is retained ONLY as a `@deprecated` thin alias that forwards to `fromDecoder()` with `Mode::HalfBlock` — do not add new test call sites against it; point them at `fromDecoder()`.

- **[pattern:embed-without-owning-the-loop]** `Reel::toPlayer(): Player` hands back the TEA model PAUSED — note the source is opened while building, so the decoder's `ffmpeg` child is ALREADY SPAWNED and an abandoned mount must still `stop()` — so a host with its own `Program`/loop can mount it, instead of `Reel::play()` which builds its own `Program` and blocks. The host owns resize (`WindowSizeMsg` → `updateResize` clamps to MIN/MAX cols/rows and rebuilds off the render hot path), the quit-key policy (must still call `Player::stop()` to release ffmpeg/audio children), and starts playback via `Player::play()`. `toPlayer()` FAILS FAST — throws `InvalidArgumentException` (`Lang::t('player.no_source_for_embedding')`) for an unbound `Reel::new()` rather than substituting the synthetic pattern that `play()` uses, because an embedding host expects a real source, not a test card.

- **[pattern:audio-pause-terminate-respawn-with-tracked-position]** `AudioPlayer` pause/resume no longer uses `SIGSTOP`/`SIGCONT` (absent on Windows; unreliable under a PTY; `proc_terminate` reports success even on a stopped child). EVERY teardown of a running subprocess — `pause()`, `resume()`'s terminate-and-restart, and `stop()` — first banks the elapsed time into `$seekMs` via a private `bankElapsed()`, reading an injectable `?\Closure $clock` (defaults to `hrtime()` — monotonic, so an NTP step cannot bank a negative elapsed and rewind the respawn `-ss`; overridable in tests without sleeping). Resume re-spawns `ffplay`/`mpv` from the advanced position; seconds args are built with integer math (`sprintf('%d.%03d')`), not locale-sensitive float formatting. `position()` exposes the tracked ms. Trade-off documented: a short re-open latency on resume and a clock quantised to the bank boundary — never silent audio that drifts out of sync with paused video. Note the asymmetry reviewers caught: an early version banked only in `pause()`, so a double `Player::play()` (which calls `resume()` unconditionally) discarded the in-flight segment — bank on EVERY path that ends a running child.

- **[pattern:bounded-pipe-drain-fail-closed]** Two synchronous subprocess reads are now time-bounded so a stalled producer surfaces as end-of-stream/default rather than hanging the whole PHP process (the codebase runs on a shared ReactPHP loop upstream). `FfmpegDecoder` reads stdout under `stream_select()` with a `READ_TIMEOUT_SEC` deadline and keeps a persistent `$rawBuffer`, so a partial RGB frame reassembles across bounded reads WITHOUT desyncing the frame grid (tested by seeding `rawBuffer` and asserting the resume). CRITICAL PAIRING: a select deadline is only real if the stream is `stream_set_blocking($pipe, false)` — on a BLOCKING pipe `fread()` loops internally until it has all requested bytes, so a trickling producer defeats the deadline entirely and the reassembly path is dead code. `VideoSource::probe()` drains ffprobe stdout via `drainWithTimeout()` (`PROBE_TIMEOUT_SECONDS`), and on deadline expiry kills the child (`BoundedReaper::terminateNow`) and returns the zeroed default — fail CLOSED, the same graceful-degradation contract used when ffprobe is absent. The read side is not the whole bound: `reapWithGrace()` (`PROBE_EXIT_GRACE_SECONDS`) waits for an already-drained child to exit and escalates-kill past the grace, because `proc_close()` on a child that printed JSON then wedged blocks unboundedly. Keep BOTH halves bounded; never reintroduce an unguarded `fread`/`file_get_contents`/`proc_close` on a child.

- **[pattern:decode-catch-up-budget]** `Player::open(..., frameBudgetMs:)` caps how many frames a single lagging tick will decode inline while catching up to wall clock: the catch-up loop checks a deadline after each frame and breaks, leaving the remaining progress to converge over subsequent ticks (so one slow frame can't stall the loop). `0.0` (the default) preserves the legacy unbounded catch-up. The budget is pinned through `mutate()` so it survives seek/resize/mode-change rebuilds — add any future per-player field to BOTH the constructor and `mutate()` or it silently resets on the next immutable copy.
