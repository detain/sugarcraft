## Per-step notes

**N-P0.** `LAYERED_KEYS` has **21** keys now and `PROJECT_TIER_KEYS` has **5**: `theme`, `disabledSkills`, `parallelToolCalls`, `parallelToolDeadlineSeconds`, `disabledTools`. That changes the design's invariant. `titleModel`/`summaryModel` were removed from the project tier in audit 15d-24 (docblock :455-466), so classify them as **Spend**, not Tuning. The new layered keys also need risk classes: `secretEnvAllowlist` (Security), `contextWindow` (Tuning, user-only), `extraBody` (Egress), `thinkingBudget` (Spend), `promptCache` (Spend). With 4 trust keys, 2 permission keys, 3 `claudeMcp*` and `enabledSkills`, that is 31 rows. Keep the constants as the source in P0 and only assert them equal to the schema. Deriving them (P2+) means editing the pinned docblocks. **Store dotted keys flat on disk** (`"compaction.autoPercent"`): `merge()` :731 is key-wise and `only()` :931 filters by exact key. Design §4.4 contradicts this ("stored as nested objects"); VIII.1 wins. **Name collision with 1.C-3:** foundations proposes a `queueMode` key and N proposes `steering.mode`. Pick one name before either lands.

**N-P1.** `/config` cannot be a `CommandSpec` alias, because no alias field exists. Aliases (`/agent`, `/quit`) are dispatched in Chat and advertised only in parentheses in README :897. Add the `settings` spec and handle `config` in `dispatchCommand`. **Key collisions:** the design's editor keys `Ctrl+S` (save) and `Ctrl+R` (reset) are already shell bindings: `shell.skills` :503 and the session picker :440. The editor has to claim the keyboard through `shellOwnsKeyboard` :354 before the shell map runs, or use other keys. Pick the keys before `KeyBindingDriftTest` observations are written. **i18n conflict:** Part IX.2 records 15b-14 (no i18n) as "deferred by decision until after the roadmap". The N-P1 `src/Lang.php` + `lang/en.php` scaffold would override that decision. Either get sign-off, or keep `labelKey`/`helpKey` on `SettingDefinition` with literal English for now (and drop the "every labelKey exists in lang/en.php" invariant).

**N-P2 (model persistence, user decision 4).** Proposed shape: `models: {provider: modelId}`, user-tier only (Spend). Keep a top-level `model` absent so `testNoKeyIsLayeredThatNothingReads` :78 still holds. Resolution order: `--model` > `SUGARCRUSH_MODEL` > `models[provider]` > provider default. Apply it at both sites that share `selectedModelName()` (`backendFor` :3134 and the label :8728), or the caption drifts. **Docs and tests that pin "no model is persisted":**
- `docs/SETTINGS.md` :517-525 ("There is no top-level `model` key… **No model is persisted anywhere**… Only `provider` and `theme` are ever written to `config.json`");
- `docs/SETTINGS.md` :67-69 ("exactly two keys are ever written… a third, `layout`") and :91 ("Exactly two keys are ever written there… two producers");
- README :191 and :738; `docs/ENVIRONMENT.md` :35;
- source docblocks `LayeredSettings.php` :60 and :398-405, `Bootstrap.php` :3554-3563;
- tests `LayeredSettingsTest` :71-89, `ConfigWriteProducerDocumentationDriftTest` (enumeration span keyed on "two producers" :438, DOORS :445, retraction rules :612), `ChatConfigChangeDoorsDocumentationDriftTest`, `ThemePersistenceFramingTest` :241, `TrustKeyDocumentationDriftTest` count words :377 ("twenty-one" at README :219 and SETTINGS :196, :847).

Rewrite prose in place and follow those tests' retraction convention. Run `vendor/bin/phpunit tests/Config tests/Chat/ChatConfigChangeDoorsDocumentationDriftTest.php` after every doc edit. Keep `provider`/`theme` on `onConfigChange` so the census :290 stays `['provider','theme']`. The new writer gets its own `SettingsWriterCensusTest`. The writer must round-trip strict keys through the `permissionConfigLayers` :5905 parser.

**N-P3a (land early).** Fix: `Bootstrap::chat` hands Chat a `\Closure(string $provider): Backend` that captures skills, `rulesState`, `agentManager()`, a pool rebuilt for the new provider's `workerProvider`, the gate and the root. `selectPaletteProvider` calls the closure, and falls back to `backendFor` for embedders. Today `rulesState` is dropped, so `/rules` toggles stop reaching the engine after a switch. `TaskTool` is dropped too, because `tools()` :7834 only adds it when `taskManager !== null`. The size is S and the regions are disjoint from 1.C's.

**N-P3b.** The model axis: `/model <provider> <model>` plus a model list in the palette, and it persists `models[provider]` through the new writer. This needs `EngineBackend::withModel()`, which roadmap 4.1 also adds, so whichever of the two lands first owns it. Without `withModel`, a model change rebuilds the backend through the N-P3a factory.

**N-P3.** A backend swap while `inFlight` must be deferred. The completion closures in `scheduleBackendCompletion` :11360 capture the old backend. The session overlay is a static on `Bootstrap`, so add it to the reset list that `StatusLineCommand`/`usePermissionMode` tests already observe. Mid-turn edits apply from the next turn. Settings feedback never becomes a transcript row, because those rows are sent to the model.

**N-P4 (split by subsystem; each sub-step is schema rows + plumbing + tests).**
- **a: engine and watchdog.** This shares `completeAsync`'s timer (:2016-2033) with **1.C-1**, which suspends `$resetTimeout` during an ask. One owner per wave. It also interacts with **0.4** heartbeat frames. Never introduce a total request timeout on LLM calls; connect and idle timeouts only. `maxToolSteps` as NextTurn conflicts with the documented rule in `resolvedMaxToolSteps` (TaskTool's raised ceiling must win), so keep it Restart or LiveBackendSwap.
- **b: compaction.** **2.1** (step-level threshold `min(0.8W, W−maxOut−64k)`), **2.9** (absolute thresholds, per-model), **2.10** (background summary at 70%) and **3.B** (`contextPruning.*`) all redefine these knobs. Ship the keys with Wave 2, not before it.
- **c: tools and caps.** **0.4** says Bash `timeout` defaults to 120 s (max 600); the design says `tools.bash.timeoutSeconds` 300. Reconcile on 0.4's values. **2.8** (spill-to-file, window-scaled caps) rewrites the same `TruncatesOutput` constants.
- **d: memory, rules and env.** **5.1** replaces "12 newest bodies" with an index of ≤200 lines/25 KB, which makes `memory.promptMaxEntries`/`promptMaxBytes` obsolete. **1.A** splits `EnvironmentBlock` (so `env.*` keys follow the split). **5.3** and **5.5** change the memory and repo-map blocks.
- **e: git guidance.** This is **0.3** verbatim. Do not plan it twice.
- **f: sub-agents.** **4.1** (`subagentModel`, per-call model), **4.3** (background), **4.7** (depth and concurrency caps 8/5, wrap-up at 80–90%).
- **g: UI and safety.** **DEF-MODE** changes the `permissionMode` default row. The `maxCostUsd` key overlaps `/budget` (README :992 says the cap is "deliberately not persisted", which is a contract to update).
