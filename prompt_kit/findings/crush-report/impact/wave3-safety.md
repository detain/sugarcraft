## Per-step notes

**3.A.** `/rewind` exists (`CommandRegistry` :282, `Chat::handleRewindCommand`). It restores only the transcript and draft (checkpoint rows in the `checkpoints` table, interned via `checkpoint_blobs`). Left to do: the git snapshot, ref pinning and the CLI surface. Risks:
- (a) `git stash create` on a large repo inside `update()` will stall the TUI. Run it as a Cmd before `scheduleBackendCompletion`, ordered before the turn fork.
- (b) Ref lifecycle must follow the row lifecycle: `pruneOldCheckpoints` :1397, `restoreCheckpoint` :1315 (deletes `index >= n`), `deleteSession` :254, `forkSession`/`copySessionState` :141. Otherwise refs leak or `/branch` restores the wrong tree.
- (c) `/redo` cannot be built on today's restore, which deletes the forward checkpoints.
- (d) `/undo` is claimed by both 3.A and 3.G. Ship one handler: revert the last auto-commit if HEAD is ours, else restore the last checkpoint's files.

DEF-MODE (foundations) waits on 3.A-1.

**3.B (L, split per DCP §13.2 K).**
- 3.B-1 = phase 1 = foundations 1.B-1/1.B-2 plus refs and the id allocator.
- 3.B-2 = phase 2 (ledger + projector + turn-start strategies + `/context`, `/sweep`, `/pruning`, config + env).
- 3.B-3 = phase 3 (`Prune` + `ledger` fork frame + badges).
- 3.B-4 = phase 4 (`Compress` + blocks + nudges + `/compress`/`/decompress`/`/recompress` + Kilo `/compact --self`).
- 3.B-5 = phase 5 (sub-agent ephemeral ledger, `Recall`, cache telemetry, Compactor receipts).

**Assumption (no `context-engine.md` yet):** Wave 2 item 2.2 ("replace the no-op `removeToolResults()` with a projector rule"; still a no-op at `ContextCompactor::removeToolResults` :1092) and 2.3 (path-keyed dedup and stale-read) ARE DCP phase 2's projector and strategies.

**3.C.** The roadmap names "dormant `TaskList`", but `src/Agents/TaskList.php` is the flock-locked SQLite TEAM task queue that fires `TaskCreated`/`TaskCompleted`. Do not reuse it for the todo. Use `SessionMeta::$tasks` (dormant: `getSessionMeta`/`saveSessionMeta` have no caller).

- Re-injection every ~6 steps needs 1.A's turn-context row.
- Classify `Todo` as no-ask in PermissionGate :922, or it prompts under `default`.

**3.D.** What exists:
- `ScriptHook` exit codes: 0 sends stdout to `additionalContext` (shown to the model through `Runtime::settle` and `Chat::applyPostToolUse`); 2 blocks with a stderr reason; 3 asks; 4 rewrites with a JSON object (≈ `updatedInput`).
- `HookResult::$refusedBy` (DONE per brief).

What is missing:
- JSON-envelope parsing (`decision`/`reason`/`continue`/`hookSpecificOutput.additionalContext`/`updatedInput`).
- `continue:false`/`stopReason` on `HookResult`.
- Any live dispatch of Stop/SubagentStop/SessionEnd. `HookDispatcher::dispatch*` exist but `HookDispatcher` is never constructed; the live chain is `HookManager`, which lacks these methods.

Risks:
- Parsing JSON on exit 0 changes what an existing hook that prints JSON-as-context does. Require a top-level object with a known key.
- The Stop hook runs in the turn child (`runTurn` :1208). Its 8-block cap must share the loop-guard and maxSteps accounting.
- SessionEnd must fire once at process exit (`bin/sugarcrush` :505, `NonInteractive::run`), not at the seven `Cmd::quit()` sites in Chat.
