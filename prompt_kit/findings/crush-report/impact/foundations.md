## Per-step notes

**1.A.** Today `<env>` is already last (`systemPromptSections` :3457) and diffs are suppressed after no-write steps (`Runtime::markWriteSinceLastRender`, called from `EngineBackend::runTurn` :1285), but git status/log/date still sit inside system message 0, and `Stability::PerTurn` covers both env and the skill listing. Work: split `EnvironmentBlock::render()` into static (cwd/OS/PHP/model/date) and volatile (git, diffs, later context %, todos, recently-modified files) parts. Emit the volatile part as a `<turn-context>` user row that `runTurn` appends to `$app->messages` only when its bytes change. Appending it in `Runtime::run` instead would rebuild it every step. **Key risk:** `Runtime` is built fresh per turn inside the forked child (`runTurn` :1074), so a "per-session memo" has to be captured in the parent and held on `EngineBackend` before the fork. Cross-turn stability also needs the turn-context row to come back in the result frame and be persisted, and today only the final assistant text comes back. That is why 1.A's cross-turn guarantee depends on 1.B-2. Rendering System rows in place: Sglang currently hoists every history System row into message 0 (`formatMessages` :2336-2358), so each cancellation marker or compaction notice voids the whole prefix. Custom leaves them in place as `role:system` mid-history, which Qwen chat templates reject. Render both as user-role `<system-notice>` rows. Verify with `cached_tokens` live on skynet2.

**1.B.** `uiOnly` is done. Remaining is the real gap: Chat stores tool output as `Message::assistant(result)->withToolResults()` (`toolResultMessage`), and `toTypedMessages` :2878 replays it as `AssistantMessage($content)`. The model therefore reads its own tool output as prose, with no `tool_calls`/`tool` pairing, and interim narration is lost because `runTurn` returns only `$lastAssistant->content`. Split: **1.B-1** adds identity fields and transcript `v:2` (plus a v1 loader that marks legacy tool rows display-only). **1.B-2** has the result frame carry the per-step typed transcript. Chat stores those rows `userVisible=false, agentVisible=true` and flags the display rows `agentVisible=false` (Goose split, which keeps Renderer changes small). **1.B-3** makes compaction flag rows hidden instead of deleting them. Risk: the frame size of a long transcript, so encode arrays only (`allowed_classes=>false` holds). The OpenHands "resumable stop" alternative for 1.C needs 1.B-2.

**1.C-1.** The socket is used one way: only the child calls `writeFrame` (:2450). Add a parent write path, the frame kinds `ask/ask_reply/steer/steer_ack/cancel_soft/cancel_tool/usage/step` (O §5.1), and a `ChildChannel::ask()` that blocks on `stream_select` and buffers steers. The 120 s watchdog (`$resetTimeout`, `COMPLETE_TIMEOUT_SECONDS`) pauses while an ask is pending. EOF from the parent counts as `DenialKind::Unanswered`. **Risk:** a parallel Task grandchild inherits the bound approver through `turnTools`' `$this->mutate()` (:1579-1581), so without a pid guard it would interleave frames on the turn socket. Fail it closed with a clear reason until 1.C-5. Bind `askId` to a hash of `{toolCallId, tool, args}`.
**1.C-2.** The Chat modal already exists for Command backends (`beginToolCalls` :3211 → `requestPermission`). The engine path needs a second arm in `answerPermission` that replies through `PendingAsk`. Chat already has an exact-call session memo (`permissionGrants` + `permissionGrantKey` :5010), and `Runtime::taskGrantMemoKey` :2474 covers Task. "Always" with a pattern needs `SessionPermissionMemo` → `PermissionGate::withSessionRules()`. `HookManager::resolveAsk` already takes `$feedback`, but the approver contract returns `bool` (`settleAsk` :3191), so the verdict type has to widen across `Runtime`, `AgentManager`, `HeadlessPermissionPrompt` and `NonInteractive`.
**1.C-3.** The busy Enter currently always queues (`submit` :8800). Steers drain at the top of each step and before each sequential tool. A steer that misses the last boundary converts to a queued prompt. Pick the queue modifier carefully: `Alt+Enter` is already "newline", and Ctrl runes are census-pinned (`chatCtrlRunes`). This adds a `queueMode` config key.
**1.C-4.** Per-step `usage`/`step` frames feed live cost and the step counter (and later O-3 `usage` events and P-B stats). `cancel_soft` makes the first Esc graceful, and the second Esc stays SIGKILL (`$teardown`).
**1.C-5.** Small once RELAY exists: the turn child routes `ask` and `ask_reply` over the per-job socket. Without RELAY, keep failing closed.

**RELAY.** Today `subAgentEmitter` is pid-bound (`turnTools` :1557-1565), so parallel Task activity is dropped, and parallel Task batches are kept alive only by `ExemptFromParallelDeadline`. DGRAM pairs keep frame boundaries without reassembly. Drain all datagrams before `release()` so a `finished` op arrives before `ToolFinished`, since Chat's ordered event chain depends on that. Build it once: 1.C-5, P-B, P-C and the O-6 sub-agent tree all consume it. Risk: fd leaks and forks under ext-uv. Run the new pcntl tests with `LoopPin` (already in `tests/bootstrap.php`) and the backgrounded pkill watchdog locally.

**DEF-MODE.** The change itself is one line (`DEFAULT_PERMISSION_MODE` :173 → `Default` or `AcceptEdits`; decision still open). It also hits `-p` and the background daemon, which use the console approver and refuse when there is no terminal. A CI-style `-p` run would then start refusing writes, so decide between a TUI-only default and a global one. **Pins to edit:**
