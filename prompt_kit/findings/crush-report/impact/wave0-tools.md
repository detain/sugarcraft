## Per-step notes

**0.3.** Keep the generic `$safety` lines (:144-148: failed hook means no commit, so do not `--amend`; no `--no-verify`; no force-push to the default branch, not just `master`; no `git add -A`) and the heredoc template without `<lib>:`. Delete `$cadence` (:130-140) and the `composer validate --strict` line (:150). The SugarCraft cadence is already in `/home/sites/sugarcraft/AGENTS.md` :57-59 and :67, so "move" means delete plus checking that nothing generic is lost. Settings: `includeGitInstructions` (bool, default true → whole `<git_commits>` block omitted when false, so the fragment returns `''` and `Runtime::toolGuidanceSection` :3812 drops it) and `attribution` (`{commit: string, pr: string}`, empty string = no trailer; rendered into the template). Risks: the root AGENTS.md is Caliber-managed and Caliber is skipped on this machine, so a hand-edit there is fine but must not be regenerated away. Settings rows must be added with the TrustKey 3-column shape. Changing the fragment changes the Static prompt bytes once, which is expected.

**0.6.** The class docblock's privacy argument (user notes follow the operator into every repo) is a real decision, not an oversight. Ship user-scope injection with a stated budget split (for example ≤4 entries / ≤1 KB for user notes inside the 12 / 4096 cap) and the user group rendered first, as the roadmap asks. Consider gating it on a settings key later (N-P4d). The "never injected" warning becomes: `/memory add --scope agent` replies "agent-scope notes are listable but never reach the prompt". `/memory import` already lands in agent scope on purpose (docblock :15179-15190), so keep that and only refresh the stale line cite. Default `list` scope should flip to `project` together with `add`, or the help text contradicts itself.

**0.7.** The tool name and arguments are already on the row (`Chat::toolResultMessage` :4639 → `ToolResult::$name/$arguments`, `src/ToolResult.php` :108-120). Only `Message::toWire` (:731) drops them, so the fix needs no 1.B ids. Add the key in `compactionWire` and do **not** add it to `Message::toWire`, which providers consume. `compactFileReferences` rebuilds rows as `{role,content}`, so the extra key disappears after stage 4 (fine). Both stages must leave `role=user` rows untouched; add a regression test with a user message `"ls the files\ncd later"`.

**0.8.** Bash gets every write-only pattern too (HOOKS.md :878-882), so after this change `cat .mcp.json`, `ls .sugar-crush/skills` and `git add .sugar-crush/skills/x` in Bash are refused. That is a real usability cost in this monorepo, whose own project skills live in `/home/sites/sugarcraft/.sugar-crush/skills/`. `mcp__*` string leaves that mention `.mcp.json` are refused too. `SafetyClassifier::CATEGORY_PROTECTED_PATH_WRITE` (PERMISSIONS.md :256) already Asks for `.sugar-crush`/`.mcp.json` in gated modes, so 0.8 only adds bypass-mode coverage. After 1.C-2 and DEF-MODE, move these patterns from deny to always-Ask.

**0.11 / 3.I split.** 0.11 owns the failure branches (:209-239) and creates `EditMatcher` with two stages (exact, uniform-indent). 3.I later owns `inputSchema` :82-101 (`edits[]`), the matcher chain (appends stages to `EditMatcher`), the replace at :241, the staleness ledger and `ApplyPatch`. The two are disjoint if 0.11 lands first. If 3.I goes first, the uniform-indent retry moves into 3.I's "indentation-flexible" stage and 0.11 keeps only the hints. Bound the diagnostic output (≤3 windows × ≤12 lines) because it is replayed every step.

**0.12.** The default page shrinks from 1 MiB to 2000 lines / 50 KB, so the "truncated" wording in `description` and `promptGuidance` changes. `BaseSystemPromptTest` and `ToolDescriptionGuidanceTest` pin those texts. Keep `maxBytes` as the hard ceiling. A page is the min of the line limit, the byte limit and `maxBytes`. `offset` past EOF is an error naming the line count. `isParallelSafe` and session state (:49-102) are unaffected.

**X-35a design.** `/share [md|html|json] [path]` writes `~/.sugar-crush/exports/<session-id>-<UTC-ts>.<ext>` (0700 dir, 0600 file, because a transcript can hold secrets) or `<path>` jailed to the project root. The reply names the path. HTML is self-contained with escaped text and no remote assets. `ShareUploader` stays as a documented dormant opt-in (the no-removal rule). 5.14 keeps its other sub-items.

**X-37a.** One audit helper, one aggregated launch-notice row per format ("3 skills set `allowed-tools`, which sugar-crush does not enforce: a, b, c"), and did-you-mean for unknown keys (`permisionMode`). Imported `.claude`/`.opencode` files are noisy (`allowed-tools` is common), so aggregate them and never refuse the file. The `INERT` constants become the single source that 4.1 / Part II #23 edit when they honour a field, and the new drift test ties the docs' "Inert" rows to them. Inert today, by grep: preset `effort`, `permissionMode` (sub-agent), `background`, `memory`, and `model` on the engine path (verify inside 4.1); skill `allowed-tools`, `disallowed-tools`, `effort`, `model`, `context: fork`; command `model`, `subtask`.
