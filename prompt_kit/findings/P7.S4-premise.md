## THE MATCHER (code as measured)

`candy-code/src/Skills/Skill.php:90-102`:

```php
public function matchesPrompt(string $prompt): bool
{
    // Simple keyword matching on description
    $keywords = array_filter(explode(' ', strtolower($this->description)));

    foreach ($keywords as $keyword) {
        if (strlen($keyword) > 3 && stripos($prompt, $keyword) !== false) {
            return true;
        }
    }

    return false;
}
```

The needle side is the lowercased DESCRIPTION split on single spaces; `strlen` is a BYTE length (a multibyte caveat for non-ASCII tokens); the prompt itself is never tokenized — each needle is an unanchored `stripos` substring probe.

`candy-code/src/Skills/SkillRegistry.php:251-280` (`findForPrompt`): skips non-auto-invocable skills, keeps each `matchesPrompt` hit, then `usort`s by `substr_count(strtolower($a->description), strtolower($prompt))` desc. That sort key uses the WHOLE PROMPT as the needle — realistically never a substring of any one-line description, so the count is 0 for every skill every time and the "relevance sort" is effectively an input-order no-op. The function has ZERO production callers (dormant, per plan).

## BATTERY (52 prompts, embedded in measure.php section 2)

- 15 NEUTRAL — everyday chat unrelated to any skill (e.g. "what's the weather like today"). Any firing = FP.
- 12 OBVIOUS — one intended-true-positive per skill. Intended skill firing = TP; every OTHER skill firing on the same prompt = FP.
- 25 BOUNDARY — one of the skill's OWN description tokens embedded in an off-domain sentence (e.g. "handle this package with care at the airport" ← `port`). Any firing = FP.

## THE DECISIVE SPLIT

Of the 62 CURRENT off-domain false pairs: **11 (17.7%)** are substring artifacts whole-word deletes (`port` in airport, `work` in working, `over` in cover, `check` in checking, `service` in services); **51 (82.3%)** are genuine whole words that whole-word KEEPS — `'when'` ×10 pairs, `'patterns'` ×4, and singles `that / audit ×2 / services / with ×2 / coverage / blade / authentication / event / working / over / changes / files / file / reviewing / security / container / mock / composer / modern / setting / under / check / form / protocol / designing / structure / responses`. Whole-word anchoring fixes the wrong thing: the dominant failure is not substring bleeding, it is common English words living in descriptions.

## TOKEN-LENGTH INSIGHT

Length-4 needles are 48/239 = 20% of the corpus and are function-ish English (`when/with/that/form/best/type`). Raising the floor 3→5 would drop them — but kills nothing domain-useful either, and the 5-char class (`audit/check/event/blade/port/over`) keeps firing. **The length floor is not the lever; description-as-keyword-bag is the flaw.**

## ORCHESTRATOR DECISION (2026-09-06)

**Outcome: deliberately-left-dormant WITH THE NUMBER.** The plan authorizes exactly this: "the worklog carries the measurement showing the false-positive rate and the step closes as 'deliberately left dormant, here is the number'" (`prompt_plan.md:2628-2630`).

Why improve-and-wire is FALSIFIED by the measurement:

- Whole-word is insufficient. W1 still fires on 20/25 boundary prompts (80%); W2 — the "realistic" KeywordTrigger variant — raises boundary FP back to 24/25 (96%) with precision 0.167, WORSE than W1 and barely above CURRENT. The 51-of-62 genuine-word mass is unreachable by predicate surgery.
- Wiring precision 0.214 is a NET NEGATIVE versus wiring nothing's 0. A dormant matcher's live FP rate is zero by construction; promoting W1 to production would inject ~4-5 spurious skill fires per 25 off-domain prompts into every turn.
- Plan lesson §16: do not half-fix unused machinery. A small, mechanically testable swap that maxes at 0.214 precision and preserves recall 1.000 is exactly the half-fix that buys an FP stream without buying a usable feature.

What the step SHIPS INSTEAD (`/home/sites/sugarcraft/prompt_kit/briefs/P7.S4-step-brief.md`):

- Pin tests for the CURRENT semantics — both `matchesPrompt` polarities, the pathological boundary cases pinned AS FEATURES (documenting the substring rule), and the `findForPrompt` input-order sort no-op pinned so any future change is a visible diff.
- Landmine docblocks on `SkillRegistry::findForPrompt()` and `Skill::matchesPrompt()`: WHY-dormant + here-is-the-number, citing this premise and the artifacts. DOCBLOCK-ONLY — zero behavior change.
- The two dormant callers — `SkillManager::getSkillsForTask()` (`candy-code/src/Skills/SkillManager.php:143`) and `App::findSkillsForTask()` (`candy-code/src/App/App.php:424`) — stay UNTOUCHED (§1.10: nothing removed, stubbed or deprecated).

The anchor primitive is right; the INPUT (raw description as keyword bag) is undisciplined. That is a feature-design step, not this close-out.
