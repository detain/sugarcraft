## M1 (MAJOR) — the `Host:` "pin" is claimed in three places and absent from the wire; its pin is vacuous

`src/Hooks/HttpHook.php::pinnedPost()` (:648-670) builds header lines from the configured headers + `Content-Type` + `Content-Length` only, then dials `$scheme://[$address]:$port$origin` with NO `'header' => "Host: …"` arm. The guard it says it mirrors — `PublicUrlGuard::transferPinned` — DOES write it (`src/Support/PublicUrlGuard.php:460`: `'header' => "Host: $hostHeader\r\n"`, port omitted on scheme default, docblock :417 "The `Host:` header keeps virtual hosting … working against the literal"). Because `requestHeaders()`/HookConfig refuse `Host` as a transport-owned field, no code path can put the resolved name into Host on the real wire: PHP defaults Host to the dial authority, i.e. the bracketed literal + port.

The claim is asserted in: HttpHook class docblock (:37-39 "the same `Host:` pin"), pinnedPost docblock (:633-636 "`Host:` carrying the name … so virtual hosting survives the address pin"), and the NEW `tests/Support/ReadPathCensusTest.php` row (fopen NOT_A_FILESYSTEM_PATH sentence: "the Host header carries the virtual name"). The test `testTheDialIsTheValidatedLiteralAndTheHostHeaderKeepsTheName` asserts only the `'host'` KEY of the seam request array — it stays green with zero Host behavior, the exact whole-wire-vacuity hazard class this repo has been burned on.

Impact: not a security hole (dial is the validated literal, SNI peer_name carries the name on https, 3xx never followed; a vhost mismatch fails closed into deny/notice). It IS a functional break of the advertised capability (HTTP vhost routing behind one IP cannot route) plus a 3-site doc-truth falsehood and a named-vacuous pin.

Fix: in pinnedPost, `$hostHeader = ($scheme==='https'?443:80)===$port ? $request['host'] : $request['host'].':'.$port;` and prepend `"Host: $hostHeader\r\n"` into the context header (mirror transferPinned exactly). Re-arm the pin structurally per the house precedent PublicUrlGuardTest:361-364 (source-scan of pinnedPost for the Host line + `'max_redirects' => 0` + `peer_name`), or assert the built lines. Truth-flip the three claims only AFTER the wire carries it.
