## Q4 Jail correctness (JailPaths) — PASS, no bypass constructible

`JailPaths::gitDirs()` (JailPaths.php:56) is a byte-faithful relocation — I diffed it against the deleted `Bubblewrap::gitDirs()`/`absolute()`/`normalise()` (removed lines in the pick `068a7d204` diff): same statements, only visibility changed to public. The `.git` FILE is not believed: the linked gitdir is accepted only when `<gitdir>/gitdir` normalises to exactly this root's `.git`, and the common dir only when `dirname($gitDir)` is literally `worktrees` and `<common>/HEAD` exists — `commondir` is never followed.
- **Symlink escape**: `normalise()` (JailPaths.php:88) calls `realpath()` first, so both the root and every bind/hatch parameter are the resolved target before they reach `--bind`/`(subpath …)`; a `root/link → /etc` cannot be used to widen a rule, because the rule text carries the resolved path. Unresolved tails keep the joined string, which is the pre-existing behaviour.
- **`..` after resolution**: `absolute()` (JailPaths.php:101) joins then `realpath()`s, so `gitdir: ../../../home/me/.git` collapses to a concrete path before the back-pointer test runs — and the test still requires `<gitdir>/gitdir` to name this `.git`, which a clone cannot plant outside its own tree.
- **Absolute-path arguments**: `gitdir:` values that are absolute go through the same `absolute()`/back-pointer path; nothing is bound writable from an unverified absolute path.
- **Applies to the command's operands, not just the declared root**: the jail is enforced by the OS over the spawned process (`--ro-bind / /` + per-path `--ro-bind-try` for bwrap; `(deny file-write*)` + ordered allows/denies for Seatbelt), so EVERY file operand of the command is judged, not only the paths the caller declared. The hatch set is bound for both shapes of git directory, and the `$readOnlyBinds`/`$chdir` arms are contract-complete with a loud throw where Seatbelt cannot honour `$chdir`.
- Constructed-escape attempt I chased and rejected: a jailed macOS command can rewrite `root/.git` to point at a writable directory (Seatbelt shares `/private/tmp`), but planting the required `<gitdir>/gitdir` back-pointer is only possible where the jail already writes, and `commonDir = dirname($gitDir, 2)` of such a path is itself inside that same writable subtree — so it grants nothing new. On Seatbelt that is a real capability gap in the jail generally (shared /tmp), and the code says so in prose rather than hiding it (`Seatbelt.php:26-31`, PERMISSIONS.md "There is no private /tmp … the escape-hatch paths above are re-denied after the allows").
- NIT-1: the Seatbelt hatch parameters concatenate `$root . '/' . $relative` (Seatbelt.php:283, 289) while the bwrap twin uses `rtrim($root, '/') . '/' . $relative`; when the root is exactly `/` — which the probe itself uses (`Seatbelt.php:212`, `wrap('/usr/bin/true', '/', …)`) — that yields `//.candy-code`, a subpath that can never match a canonicalised vnode path. No privilege delta (a `/` root jails nothing anyway, and the probe's command writes nothing), but it is an inconsistency with the logic it was ported from. Fix: use `rtrim($root, '/')` in both Seatbelt concatenations.
- NIT-2: the `SandboxBackend::probe()` docblock states the family law "A backend unavailable on this OS must answer from that fact alone, BEFORE touching any binary"; `Seatbelt` obeys, `Bubblewrap::probe()` (Bubblewrap.php:231-239) still checks `resolvedBinary()` first, so a Windows host without bwrap answers "not found on PATH" rather than the OS fact. Both refuse — prose overclaims the family. Fix: reorder Bubblewrap's two gates, or scope the sentence to Seatbelt.
