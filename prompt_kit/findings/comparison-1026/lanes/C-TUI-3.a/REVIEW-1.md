## Findings

### MAJOR — raw, unsanitized transcript content reaches the system clipboard
- `candy-code/src/Chat.php:12553-12570` (`handleCopyCommand`): `$selection['text']` is raw `$message->content` and is passed to BOTH clipboard legs — `Cmd::setClipboard()` (OSC 52, base64-wrapped so safe for THIS terminal) and `SystemClipboard::copy($text)` (piping/writing raw bytes to xsel/xclip/termux — the payload lands in the user's editor/browser verbatim).
- Why this is a defect, not a preference: the repo treats stored transcript text as untrusted. The renderer paints every row through `untrusted() = Sanitize::stripZoneSentinels(Sanitize::untrustedForDisplay(...))` (`src/Tui/Renderer.php:97`, `:1622-1624`); `Chat.php` carries a sanitizeSessionField for stored rows that strips U+E000–U+F8FF "the security half" (forged `Mark::zone` sentinels / OSC-8 in model or fetched-page output are the explicit threat model). The DRAG copy — the precedent this design rides — gets its text from `Renderer::selectableLines()`, i.e. already-sanitized screen text. And `/export`, the nearest external-sink precedent, sanitizes before writing outside the trust boundary: `Sanitize::untrustedForDisplay(Sanitize::stripPrivateUse($body))` with a docblock invoking "the same hygiene the renderer applies to untrusted frames" (`src/Commands/ExportCommand.php:39-40`, `:189`). `/copy` is the ONLY path where raw stored content escapes to an external sink unsanitized: hostile tool output containing C0/C1, ESC/OSC-8, or PUA zone sentinels escapes via `/copy` where both drag and export strip it.
- Cure (fixer, small): in `handleCopyCommand`, sanitize ONCE before both legs, mirroring ExportCommand —
  `$text = Sanitize::untrustedForDisplay(Sanitize::stripPrivateUse($selection['text']));`
  plus one pin in `CopySlashCommandTest`: seed an assistant reply whose body contains `\x1b]8;;http://evil\x07` and U+E000/U+E001 sentinels, assert the captured SystemClipboard argv text and the OSC-52 decoded payload are the stripped bytes (the existing byte-exact OSC52 assertion shape already discriminates: dropping the sanitizer reddens it). Sanity note: sanitizing does NOT break legit copy — the visible screen already lost those bytes, so sanitized `/copy` output is byte-parity with what drag would have copied for the same reply.
- Builder disclosure check: REPORT.md does not mention sanitization anywhere; not anticipated by the design block; tests contain no ANSI/PUA fixture. Confirmed gap, not documented tradeoff.
