## Hard constraints - all four load-bearing, all four come from measured upstream failures, each
gets its own test per the plan:
1. THE WIPE. Anthropic caps `cache_control` at 4 blocks per request; without clearing first, a
   multi-step agentic turn accumulates breakpoints and the API 400s. Test: run 20 simulated
   steps feeding apply() output back in, assert the count never exceeds 4 at any step.
2. Automatic caching consumes one of the four slots - budget three when both modes are used.
   Encode this as a documented constant plus a test that a request already carrying an
   automatic-cache breakpoint gets at most 3 explicit marks.
3. A breakpoint on a varying block is never a hit. Assert the marked block's bytes are identical
   across two consecutive requests built from the same fixture prefix.
4. 20-block lookback: each breakpoint walks back at most 20 content blocks; a single turn adding
   more than 20 blocks silently misses. Place an intermediate breakpoint every ~15 blocks in
   long turns and TEST the greater-than-20-block turn (assert coverage of every 15-block window).
- Determinism: same inputs produce byte-identical output (no clocks, no randomness, no fs).
- Idempotence of apply(apply(x)) is NOT required (the wipe makes it stable by construction) but
  if it holds, pin it.
