## HARD CONSTRAINT 1 — the seed must not be able to throw (the trap in the nearest precedent)

`LayeredSettings::only()` (`:761-771`) preserves absence and validates NOTHING about values. But
`RulesState::new()` runs every entry through `parsePack()` (`:189-200`), which **THROWS
`InvalidArgumentException`** on a non-string OR on `trim($pack) === ''`. `Bootstrap::chat()` is the launch
path and `readUserConfig()`'s own docblock (`:2516-2521`) promises the launch is **tolerant and
non-throwing**.

The seductive mistake is to copy the sibling `disabledSkills` read at `Bootstrap.php:2840-2843` verbatim:

```php
$disabled = self::readUserConfig()['disabledSkills'] ?? [];
if (is_array($disabled)) {
    $manager->disableFromConfig(array_values(array_filter($disabled, 'is_string')));
}
```

That filter admits `""` and `"   "`. `SkillRegistry::disable('')` accepts a blank harmlessly;
`RulesState::new([''])` **crashes the launch**. So the seed must be strictly narrower: keep an entry only if
`is_string($v) && trim($v) !== ''`, wrap the whole thing in an `is_array()` guard so a scalar/`null`/nested
object value degrades to "nothing disabled", and `array_values()` the result.

**Do NOT reach for `try`/`catch` here.** Filter up front. A new `catch` would (a) be the worse design and
(b) feed the derived `AssertionSwallowingCatchTest` census for no reason.

Prove every case with a real test and a real value: `["terse"]`, a non-array string, an int, `null`,
`["", "  "]`, `[0 => 5, 1 => "terse"]`, a nested array entry, and the **key-absent** case (no notice, no
behaviour change).
