# P6.S1 — The trigger union (step brief)

**Plan reference:** `prompt_plan.md` Phase 6, P6.S1 (plan lines 2062-2083). **Sources:** `prompt_expand.md` §4.20 (lines 1706-1735), §7.5 (3287-3306), §9.7 (3569-3584), §9.13 (3653-3678). **Read before coding:** `prompt_plan.md` §1.10, §1.11, §16, §17, and this repo's `AGENTS.md` code conventions.

## Step text (verbatim from the plan)

> **Goal** Model the three trigger families as a discriminated union rather than three parallel loaders:
> ```php
> KeywordTrigger { array $words; }        // whole-word match on the user prompt, lifetime dedup
> PathTrigger    { array $globs; }        // fires when a matching file enters context
> IntentTrigger  { string $description; } // in the listing; the model decides
> ```
> **Hard constraint** Keyword matching is **whole-word anchored**. The historical unanchored `includes()` matched "rethinking" inside "thinking". Test that case explicitly.
> **Done when** each trigger type has a test including its adversarial case: keyword substring, glob matching a path outside the repo root, and an intent description long enough to need truncation.

## Hard requirements

1. **Whole-word anchoring is the point of the step.** Anchor on BOTH sides (`preg_quote()` the word, `/\b<word>\b/i`) and correctly: MATCH `think` in `"re-think"`, `"think!"`, `"Think."`, `"we should think"`; NOT MATCH `think` in `"rethinking"`, `"thinking"`, `"bethinks"` (verify what `\b` actually gives you and pin exactly that). Cover **UTF-8 deliberately**: `\b` is ASCII-oriented and `strlen()` is byte-based (the old `Skill` `> 3` filter counts bytes) — add the `u` modifier or document the boundary behaviour you chose, and pin at least one non-ASCII case. Do NOT "fix" `Skill::matchesPrompt` in this step.
2. **Each family gets its adversarial case, per the plan's done-when:** (a) keyword-substring (the `rethinking`/`thinking` pair); (b) a glob matching a path **outside the repo root** — decide and pin what your `PathTrigger` does with an `/etc/passwd`-style path (match vs refuse) and record the decision in the docblock, because `PathTrigger` is a matcher, not a gatekeeper, and the containment gate belongs to P6.S2's loader; (c) an `IntentTrigger` description **long enough to need truncation** — implement the truncation, assert the exact emitted length/boundary, and pin that truncation never splits a multi-byte character.
3. **Lifetime dedup: implement and PIN.** State key, scope, and fork-merge semantics in a docblock, following or deliberately differing from `SkillPathNudge::markAnnounced()`'s union-on-fork, with a test that goes red if the semantics change.
4. **§1.11 — what counts as a test.** No `@covers`/`@test` annotation as evidence; no `class_exists()`, `method_exists()`, `is_callable()`; no `assertNotNull`/`assertIsArray`/`assertTrue(count(...) > 0)` shape checks standing in for behaviour. Every test CALLS the thing and asserts an exact value/count, both polarities, plus the pathological input. **Run the deletion experiment**: replace the anchoring with naive `stripos()`, show a test goes RED, restore, show GREEN; paste both runs.
5. **§1.10 — removal is NOT an available outcome.** Do not delete, stub, deprecate, or drop any dormant/unwired/unreachable code — yours or anyone else's. These four classes are UNWIRED by design at this step (the consumer lands in P6.S2): ship them unwired, do not wire them into the assembler, and do not tidy away `Skill::matchesPrompt`. If you believe existing code must be removed or redesigned to finish, STOP and report it as a §1.10 escalation with `file:line`, what calls it, and the options — that is a COMPLETED outcome for this step, not a failure.
6. Every public method gets ≥1 test. Public classes `final` unless extension is the contract.
