## THE TWO THINGS MOST LIKELY TO MAKE THIS STEP WRONG

1. **The widget entering the transcript.** The status line is a per-frame render; the transcript is
   billed history. Any design where the segment's text — or anything computed for it — is appended
   as a message reproduces the exact /context ~1.6k-token-per-call tax the step text names as the
   cautionary tale. The constraint is testable, so it is graded as testable: clause 4 above.
2. **A vacuous zero-transcript test (ANTI-VACUITY).** An absence assertion is worthless unless it
   can notice the presence. The zero-transcript test **must carry a known-positive control through
   the SAME assertion machinery**: demonstrate that planting ONE transcript-appending side-effect
   into the render path makes that exact test go **RED**, and include that mutation proof in your
   final report. Lesson reference: this plan just closed finding **RR4-F2**, where an absence test
   stayed green against a renderer stubbed to return the empty string. A green absence test with no
   demonstrated red-on-plant is a FAILED step, however correct the code is.

## §1.11 — WHAT COUNTS AS A TEST HERE. READ THIS TWICE.

These do **not** count: annotations (`@covers`, `@test`); existence checks (`method_exists()`,
`class_exists()`, `is_callable()`, `property_exists()`); shape assertions (`assertNotNull`,
`assertIsArray`, `assertTrue(count(...) > 0)`). A real test calls the thing, asserts the **value**
and **exact counts**, covers **both polarities** + **pathological input**, goes red when reverted.

**Deletion experiments this step MUST run and report** (each: exact edit, command, red test name
and count, restoration confirmed):

- **Deleting the new segment registration** must RED **exactly the render test and nothing else.**
- **Planting a transcript message in the render path** must RED **exactly the zero-transcript
  test.** This doubles as the ANTI-VACUITY mutation proof — report it under both names.
- Hit-rate math: feed a `Usage` with known buckets and assert the EXACT rendered numbers; change
  one bucket and assert the numbers move as the docblock formula says they must.

An unstated or unrun deletion experiment fails the step regardless of how green the suite is.
