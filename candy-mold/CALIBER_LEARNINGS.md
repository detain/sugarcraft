# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention:candy-mold]** candy-mold is `composer type: project` (a create-project skeleton), NOT `type: library` like its 51 siblings. Its namespaces are deliberately `App\` / `App\Tests\` (`src/Counter.php`, `tests/CounterTest.php`) — a sanctioned deviation from the `SugarCraft\<Lib>` PSR-4 rulebook so that code forked downstream keeps the user's app namespace. Never "fix" these namespaces, and never register mold classes under a `SugarCraft\Mold` alias.
- **[pattern:candy-mold-docs-as-code]** The template IS its own tutorial: `src/Counter.php`'s class docblock is the "read in one screen" walkthrough (Elm pattern, immutability, `Cmd::quit()`), ending with the numbered "To extend: 1. field, 2. Msg handler, 3. view()" recipe, and `bin/start`'s header tells the forker exactly which line to swap. Keep every mold file readable in one screen — length is a defect here, terseness is the feature.
- **[pattern:candy-mold-quit-semantics]** Exact quit matrix, pinned by `tests/CounterTest.php`: plain `q` quits; **alt+q also quits** because `shouldQuit()` excludes only `ctrl` (`testAltQTriggersQuit`); Shift+q = rune `'Q'` does NOT quit (`testShiftQDoesNotQuit`); Escape quits **regardless of modifiers** — `testAltEscapeDoesNotQuit`/`testShiftEscapeDoesNotQuit` are misnomers whose bodies assert a non-null quit cmd ("escape alone still triggers quit via escape"); `ctrl+c` quits; every other ctrl combo is inert. When extending the template, copy the rune-exact comparisons — the modifier gaps are intentional teaching surface.
- **[gotcha:candy-mold-audit-vs-tests]** `findings/candy-mold.md` (2026-06-30) Findings 1–3 prescribe `strtolower()` rune normalization and claim "upstream Bubble Tea quit is rune-insensitive"; `findings/plan_candy-mold.md` Phase 1.1 repeats it. The committed test suite pins the OPPOSITE behavior as deliberate. Do not apply that plan phase blindly — reconcile intent with the pins first (this file's [pattern:candy-mold-quit-semantics] row is the reconciliation).
- **[gotcha:candy-mold-subscriptions]** `Model::subscriptions()` is an abstract contract member, not optional: commit d67be88b2 had to sweep `subscriptions(): ?Subscriptions { return null; }` stubs across 32 models. A new skeleton model that omits it is an instant fatal; returning `null` means "static subscription set".
- **[pattern:candy-mold-instanceof]** `if ($msg instanceof KeyMsg === false)` (`src/Counter.php:46`) is the house shape after commit 60577d747 swept implicit-boolean/`!`-with-`instanceof` Codacy complaints repo-wide — write `=== false`, not `!($x instanceof Y)`.
- **[pattern:candy-mold-overflow-teaching]** Boundary tests live at `PHP_INT_MAX - 1` / `PHP_INT_MIN + 1` with the in-file warning "PHP integer math wraps to float on overflow" (`CounterTest.php:475`) — an overflowing counter silently becomes a float and breaks the `int` type of the promoted readonly ctor. Keep any new numeric demo field pinned one step inside the boundary.
- **[bug:candy-mold-style-rebuild]** OPEN MEDIUM (`findings/candy-mold.md` Finding 4, `plan_candy-mold.md` Phase 2 not-started): `view()` rebuilds `Style::new()->border(Border::rounded())->padding(1,2)` on every frame — three throwaway `Style` objects per render. Negligible for the demo, but the template therefore *teaches* a per-frame-build anti-pattern; the planned fix is a memoized `private static ?Style` and a doc note. Until shipped, do not cite mold's `view()` as the reference for real apps — cite sugar-bits widgets instead.
- **[gotcha:candy-mold-gif]** Repo law says "don't commit GIFs", and 61363c7c4 untracked `.vhs/start.gif` — but 1636755f4 re-added a real VHS render and the `vhs.yml` regeneration loop (mold is in both the `all=(...)` array and the lib matrix) keeps re-committing it. At current tip the gif IS tracked; expect churn commits titled "vhs: regenerate demo GIFs" touching it and do not "tidy" it away without also addressing the regen loop.
- **[env:candy-mold-autoload]** `bin/start` resolves `vendor/autoload.php` via a two-candidate IIFE (cwd-relative, then `__DIR__ . '/../'`) so the same script works both as a fresh `composer create-project` app (run from project root) and inside the monorepo (`cd candy-mold && bin/start`) — see the file before "simplifying" it (Finding 6 informational). Known defect kept honest: the not-found error line still says `candy-template:` instead of `candy-mold:` (open LOW Finding 5, `bin/start:25`).
- **[pattern:candy-mold-panic-optin]** The crash handler is opt-in by design: `Log::installPanicHandler()` ships commented in `bin/start` because candy-log is NOT a template dependency (pulling it would force `composer require sugarcraft/candy-log`, and in-monorepo a path-repo note too). README used to overstate it as default — fixed in 7ff64eeb1 together with the PHP badge; keep docs aligned to the commented-by-default reality.
- **[convention:candy-mold-deps]** Sibling deps (`sugarcraft/candy-core`, `sugarcraft/candy-sprinkles`, `dev-master`) resolve from Packagist; per-lib `repositories[]` path-repo blocks were swept out (b8b1dbeba, 2fa678a7f) and are re-injected by CI only — never commit one into `candy-mold/composer.json` (it would break every `create-project` consumer). Note mold's constraint is `php: >=8.3` (project flavor), while libraries pin `^8.3`.
- **[env:candy-mold-phpunit]** mold's `phpunit.xml` intentionally has NO `failOnWarning` — removed repo-wide by c8fcf8c56 across 58 libs even though the AGENTS.md skeleton snippet still lists the attribute; and there is no `tests/bootstrap.php` because `Counter` arms no timers. Add the `LoopPin::pinStableClock()` bootstrap (candy-async family) only if a future demo grows timer-bounded waits.
- **[pattern:candy-mold-coverage-style]** 863ded99d "boost coverage" grew the suite to 59 exhaustive test methods over a 92-line `Counter.php` (full rune × modifier matrix for quit paths, `testNumbersAsRunes`/`testSymbolRunes`/`testEmptyRuneWithCharType`, `testIntegerBoundaryPositive/Negative`, `testViewRenderingDoesNotAffectState` purity pin). For a template this breadth doubles as the living reference for the "every public method ≥1 test" law — when extending the model, extend the matrix, not just happy paths.
